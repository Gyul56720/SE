# lol — 승률은 **판단이 아니라 계산이다**

`brief/` 가 일반 층이라면 여기는 **한 영역을 끝까지 판 사례**다. 물음이 "T1 과 HLE 중
누가 이기냐" 처럼 **모델을 세워야 답이 되는** 것일 때 무엇이 더 필요한지를 보여 준다.

```
경기 원장 ──> Elo 걸음 ──> 승률
     │            │
     │         **예측이 갱신보다 먼저** (look-ahead 없음)
     │            │
     └──────> 백테스트 ──> 기준선과 견줌 ──> 못 이기면 그렇게 적는다
```

## 왜 심판이 예측기보다 먼저인가

`law/exam.py` 가 적어 둔 그대로다 — 자기가 만든 자로 자기를 재면 자가 놓친 것은 영영
안 보인다. 승률에서는 더 나쁘다: **어떤 숫자를 내놓아도 그럴듯해 보인다.** 55% 라고
하면 55% 같고 62% 라고 하면 62% 같다. 그래서 `score.py` 가 먼저 있고, `predict.py` 는
승률 옆에 **그 승률의 성적**을 반드시 같이 찍는다.

```
  A팀 가 블루     58.3%
  진영 모름       55.1%   (잰 진영 이점 +12.4 Elo)

  이 모델의 성적: 브라이어 0.2213 · 기준선 0.2500 · 정확도 0.631 (412경기 백테스트)
                  -- 기준선을 이긴다
  모델이 안 보는 것: 로스터 교체 · 선수 부상 · 패치 변화 · 밴픽 상성 · 대회 중요도 · ...
```

## 자가 진짜 가르는가 — RED/GREEN

`law/mutate.py` 의 규율: **어긋남 0 은 그 자체로 아무것도 증명하지 않는다.** 관문이
좋아서 0 일 수도, 아무것도 못 잡아서 0 일 수도 있다. 그래서 정답을 아는 세계를 두 벌
만들어 돌린다(`tests/test_lol_score.py`, 실측):

| 합성 원장 | 브라이어 | 기준선 | 판정 |
|---|---|---|---|
| 실력차가 진짜 있다 (1,185경기) | **0.1417** | 0.2500 | 이긴다 ✓ |
| 동전던지기 (1,185경기) | 0.2575 | 0.2499 | **못 이긴다** ✓ |

둘째가 요점이다. 무엇을 넣어도 "이겼다" 고 말하는 심판은 심판이 아니라 장식이다.

세기를 되찾는지도 같은 방식으로 잰다(`tests/test_lol_elo.py`, 실측): 진짜 레이팅
`S 1800 · A 1650 · B 1500 · C 1350 · D 1200` 에서 뽑은 1,200경기로 걸었더니
`S 1837 · A 1629 · B 1521 · C 1260 · D 1254` — 순서를 되찾았고 S–D 폭도 583(참값 600).

## look-ahead — 이 파이프라인에서 틀리기 제일 쉬운 자리

경기를 걸으며 레이팅을 갱신할 때 **그 경기로 갱신한 뒤에** 그 경기를 예측하면 답을 보고
찍는 것이다. 그러면 백테스트가 아름답게 나오고 실전에서 무너진다 — 이 저장소가 부르는
이름으로는 **검사하지 않은 초록불**이다. 그리고 화면에서는 안 보인다, 점수가 좋아 보일
뿐이다. `elo.walk()` 가 예측을 먼저 적고 갱신하며, 검사가 그 순서를 붙든다.

## 이 파일의 절반은 **거절**이다

```
python3 lol/predict.py T1 HLE
```

숫자를 내는 조건을 코드가 쥔다. 하나라도 안 되면 **끝값 3, 화면에 숫자 없음**:

| | |
|---|---|
| 원장에 두 팀이 다 있는가 | 없으면 후보 이름을 대신 보여 준다 |
| 이름이 **하나로 좁혀지는가** | 여럿이면 안 고른다 — 딴 팀의 승률이 되기 때문 |
| 각 팀이 몸풀기(5경기)를 치렀는가 | 아니면 1500 에서 안 움직인 레이팅이다 |
| 원장이 낡지 않았는가 | 낡았으면 **며칠 낡았는지 적고** 낸다 |

별칭(`HLE` → `Hanwha Life Esports`)은 **원장에 실재하는 이름으로만** 풀린다. 표에
있어도 원장에 없으면 안 푼다 — 없는 이름으로 낸 승률은 없는 승률이다.

## 쓰는 법

```bash
python3 lol/fetch.py --진단 --대회 'LCK/2026 Season'   # 받되 저장 안 한다
python3 lol/fetch.py --대회 'LCK/2026 Season'          # 원장에 넣는다 (열쇠 불필요)
python3 lol/fetch.py --파일 받은것.csv --출처 'Oracle Elixir'   # 손으로 넣기
python3 lol/corpus.py --팀                             # 원장에 있는 이름 그대로
python3 lol/score.py                                   # 기준선을 이기나 (호출 0회)
python3 lol/predict.py T1 HLE --세트 5                 # 승률 (호출 0회)
```

`fetch.py` 는 저장 전에 **`winner` 가 `blue`/`red` 와 글자 그대로 같은지** 본다.
Cargo 필드 이름이 하나만 바뀌어도 승자가 빈 값이 되고, 그것을 저장하면 레이팅이 조용히
기운다 — `law/fetch.py` 가 인증키 오류 XML 로 겪은 그 자리다. 안 맞으면 저장하지 않고
받은 첫 줄을 그대로 찍는다.

## 한계 — 정직하게

- **Elo 는 원장에 적힌 승패만 본다.** 로스터·부상·패치·밴픽·대회 중요도를 하나도 모른다
- **다전제는 세트 독립을 가정한다.** 실제로는 밴픽이 이어지므로 아니다. 화면에 같이 적는다
- **소환사 개인 전적은 아직 없다.** Riot API 는 `RIOT_API_KEY` 가 있어야 하고, 열쇠가
  없으면 `brief/source.py` 의 규약대로 **미검증으로 끝난다** — 다른 값으로 안 메운다
- **네트워크 경로는 이 컨테이너에서 못 돌려 봤다** (egress 정책이 lol.fandom.com 을
  막는다, 실측 2026-09-09 `connect_rejected`). 파싱·검사·셈·심판은 네트워크 없이
  검사했다 — 네 벌 **104개 항목**:
