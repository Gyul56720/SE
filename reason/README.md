# reason — 데이터가 아니라 **배경지식**으로 결론을 끌어낸다

```
스키마(요건표 + 양측 입장) ──> 두 정거장 ──> 결론
                                   │
                              갈리는 자리 ──> 뒤집기 ──> **쟁점**
```

`brief/` 는 원장에서 수를 받아 통계로 판정한다 — **데이터 분석**이다. 여기는 다르다.
요건표와 양측 입장만으로 "어느 요건이 결론을 지고 있나" 를 계산한다. **데이터가 한
줄도 안 들고 LLM 호출도 0회다.**

## 이미 있던 것을 도메인 밖으로 뺐다

`law/issue.py` 가 그것이었다. 법에 묶여 있던 것은 **단계 이름**뿐이었고, 나머지는
이미 도메인을 몰랐다.

| 법 | 여기 |
|---|---|
| 권리근거 · 구성요건 · 적법요건 | **세움** — 다 서야 주장이 선다 |
| 권리장애 · 위법성조각 · … | **무너뜨림** — 하나만 서도 주장이 무너진다 |
| 재항변(`defeats`) | **무너뜨림 대상** — 이미 도메인을 몰랐다 |

그래서 채용·계약·논증 어디서든 돈다. 주장하는 쪽과 다투는 쪽이 있고 요건이 걸려
있으면 같은 모양이다.

## 두 정거장 — 추론의 심장

```
세우는 쪽 진술만으로     결론이 무엇인가
다투는 쪽 진술까지 넣으면 결론이 무엇인가
```

**갈리면 그 사이에 다툴 거리가 있다.** 안 갈리면 둘 중 하나다 — 세우는 쪽이 애초에
못 세웠거나, 상대 주장이 결론을 못 바꾸거나. 어느 쪽이든 말해 줄 것이 있다.

독일 Relationstechnik 의 Klägerstation/Beklagtenstation 이 원형이다(`law/METHOD.md` 1-4).

## 뒤집기 — 무엇이 결론을 지고 있나

다투어진다고 다 중요한 것이 아니다. **답이 갈릴 때 결론이 갈리는 경우가 하나라도
있어야** 결론에 닿아 있다. 없으면 곁가지다.

실측(`tests/test_reason.py`): `x` 가 다투어져도 `r` 이 늘 서서 `x` 를 죽이면 `x` 는
곁가지로 걸러진다. 조합이 상한을 넘으면 **남기는 쪽으로** 답한다 — 못 찾은 것이지
없는 것이 아니고, 과잉 기각하는 심판은 맞는 답도 버린다.

## 받아치기는 한 번으로 안 끝난다

주장 ← 반박 ← 재반박 ← 재재반박. `살아있나()` 가 사슬을 따라간다. 실측:
`r2` 가 `r` 을 무너뜨리면 `r` 이 죽고 **그래서 `x` 가 되살아난다.**

## 스키마가 참인지는 못 본다 — 그래서 보여 준다

모든 분야에 원장을 만들 수는 없다. 그러면 남는 것이 무엇인가.

| | |
|---|---|
| 스키마가 참인가 | **관할 밖.** 외적 정당화다(`law/METHOD.md` 1-7) |
| 스키마에서 결론이 따라 나오는가 | **기계가 본다.** 내적 정당화다 |

결론은 **스키마에 조건부**다. 그래서 보고서의 **첫 절이 스키마**다 — 결론만 보이고
전제를 숨기면 검사받지 않은 전제 위에 검사받은 결론이 얹힌다.

## 검사하는 것은 '내용' 이 아니라 '성함' 이다

| | | |
|---|---|---|
| S001 | 요건 id 가 겹치지 않는가 | hard |
| S002 | 무너뜨림이 실재하는 요건을 가리키는가 | hard |
| S003 | 무너뜨림에 되돌이가 없는가 | hard |
| S004 | 양측 입장이 다 적혔는가 | soft |
| **S005** | **요건마다 출처가 적혔는가** | soft |

**S005 가 원장 대조를 대신하는 자리다.** 대조는 못 해도 어디서 왔다고 말했는지는 남길
수 있고, 안 남겼으면 **화면에 크게 적을** 수는 있다 — 검사가 아니라 표시다.
`hard` 가 있으면 도출을 아예 안 돌린다(되돌이 위에서 낸 결론은 뜻이 없다).

## 쓰는 법

```bash
python3 reason/ask.py --프롬프트 "<물음>"    # 모델에게 줄 것 (호출 0회)
python3 reason/ask.py --표 스키마.json       # 검사하고 도출한다
python3 reason/ask.py --표 - --짧게 < 스키마.json
python3 tests/test_reason.py                 # 배선 검사
```

끝값: `0` 냈다 · `1` 스키마에 hard 위반(안 돌렸다) · `3` 못 읽었다

## 모델은 표만 세우고 답을 안 낸다

프롬프트에 `쟁점`·`곁가지`·검사 이름이 **한 글자도 없다**. 무엇이 통과하는지 알려 주면
통과하는 스키마가 나오고, 그러면 스키마가 사양서가 된다 — `law/write.py` 가 생성자에게
관문을 안 알려 주는 것과 같은 규율이고, 검사가 그것을 고정한다.
