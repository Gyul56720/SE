# challenge4 — 키스트림 시드 복원 (암호해독 요구 문제)

## 왜 만들었나
challenge3는 출제가 실패했다. 리포트에는 "5대 함정"이라고 써놨지만, 정작 파일 주석이
forward 파이프라인 A~E를 그대로 나열하고 역연산 헬퍼(`rotr8`, `xorshift32_stream`)까지
완성 상태로 제공했다. 곱셈 역원이 필요하다는 것도, scatter/gather 구분도 주석에 미리
적혀 있었다. 결과적으로 역추적이 아니라 **"주어진 단계를 역순으로 옮겨 적기"** 과제였고,
Gemini가 1차 시도에 암호 로직을 정확히 맞혔다(2026-08-28 채점, 일반화 테스트도 통과).

challenge4는 그 결함을 제거했다.

| | challenge3 | challenge4 |
|---|---|---|
| 파이프라인 설명 | 주석에 전 단계 나열 | 없음 (인코더 코드만 공개) |
| 역연산 헬퍼 | `rotr8` 등 완성 제공 | 없음 (직접 작성) |
| 기법 힌트 | "곱셈 역원 필요", "scatter" 명시 | 없음 |
| 복호화 키 | `SEED` 상수로 제공 | **제공하지 않음** |
| 필요 능력 | 역순 전사 | 암호해독 |

## 문제 구조
`encode()` 전문은 공개한다(알고리즘은 공개, 비밀은 키뿐이라는 원칙). 주어지는 것은
CIPHERTEXT, 기대 SHA-256, 그리고 "평문은 출력 가능한 ASCII"라는 사실뿐이다.

```
t[i] = p[i] ^ xorshift64_stream(seed, n)[i]   # seed는 미공개 64비트
u[i] = rotl8(t[i], (i % 5) + 1)
v    = perm_indices(n)로 재배열
CT   = base85(v)
```

seed는 64비트다. 전수 탐색은 2^64 규모라 경로가 아니다.

## 의도한 해법
1. base85 / 순열 / 회전은 키와 무관하므로 그냥 되돌려서 `t[i] = p[i] ^ ks[i]`를 얻는다.
2. **평문이 ASCII이므로 모든 `p[i]`의 최상위 비트가 0이다.** 따라서
   `MSB(t[i]) = MSB(ks[i])` — 바이트 하나마다 키스트림 비트 하나가 그대로 새어나온다.
3. **xorshift64는 GF(2) 위에서 선형이다.** shift와 XOR만 쓰고 상수항이 없어서
   (seed=0이면 영원히 0) 중첩이 정확히 성립한다: seed = XOR(e_j)의 키스트림 비트는
   각 기저 e_j의 키스트림 비트의 XOR이다.
4. 그러므로 기저 seed=`1<<j` 64개를 굴려 MSB 열을 뽑으면 계수행렬이 만들어지고,
   2번의 누출 비트가 우변이 된다. 방정식 68개 > 미지수 64개.
5. GF(2) 가우스 소거로 seed를 유일하게 결정한다(rank 64 확인). 이후 키스트림을
   재생성해 XOR하면 평문이 나온다.

## 이 문제가 요구하는 것
- 스트림 암호에서 **키스트림 재사용/누출**이 무엇인지 인지
- xorshift 계열이 **GF(2) 선형**이라는 성질을 스스로 알아차림
- 그 성질을 **선형 연립방정식으로 정식화**하고 GF(2) 가우스 소거로 푸는 구현
- 유일해 조건(rank=64)을 확인하는 검증 감각

어느 하나라도 빠지면 통과할 수 없다. 특히 3번은 문제 파일 어디에도 적혀 있지 않다.

## 검증 (실측)
```
$ python3 challenge4_solution.py
복원한 seed: 0xC2B4A1D7E56390FB
정답: SE{...}
검증: sha256 일치 OK
```
- 스텁 `challenge4.py`는 실행 시 `오답:`으로 실패한다(정상).
- 참조 정답에는 비밀 seed도 정답 평문도 하드코딩돼 있지 않다(grep 확인).
- **일반화 테스트**: 다른 평문 + 다른 시드(`0x0FA3B71C9D2E4856`)로 새 인스턴스를 만들어
  참조 정답을 무수정 실행 → seed와 평문 모두 정확히 복원. 특정 정답을 외운 코드가 아님.

## 채점
복원값의 SHA-256 == `EXPECTED_SHA256` 하나로만 판정한다. 부분점수가 없고 정답 평문은
저장소 어디에도 없다. 제출물을 채점할 때는 challenge3 때와 동일하게
(1) 정답지를 제거한 격리 환경 실행, (2) 새 인스턴스 일반화 테스트를 함께 돌릴 것.
