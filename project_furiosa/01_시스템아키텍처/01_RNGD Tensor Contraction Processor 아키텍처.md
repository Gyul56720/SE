# 01. RNGD Tensor Contraction Processor 아키텍처

## 1. 왜 알아야 하는가

기존 GPU는 텐서를 2D 행렬로 변환(flatten)한 뒤 GEMM으로 연산하기 때문에 다차원 구조의 병렬성이 파괴되고 대역폭 및 에너지 효율이 저하되는 문제가 발생합니다. FuriosaAI의 RNGD 칩에 적용된 Tensor Contraction Processor(TCP) 아키텍처는 다차원 텐서 구조와 병렬성을 그대로 유지하면서 연산을 수행하므로, 생성형 AI 모델(예: LLaMA-2)에서 뛰어난 전력 대비 성능과 프로그래밍 유연성을 제공합니다. 따라서 실무와 면접에서 고성능 AI 가속기의 하드웨어-소프트웨어 코디자인 방식을 이해하기 위해 이 아키텍처를 반드시 학습해야 합니다.

## 2. 정의와 구조

### Tensor Contraction Processor (TCP) 핵심 정의와 구조

TCP는 퓨리오사AI의 제2세대 AI 가속기 칩(제품명: RNGD, TSMC 5nm 공정, 1.0GHz 클럭)에 적용된 코어 아키텍처로, 텐서 축약(tensor contraction) 연산을 근본적으로 처리하기 위해 설계된 거칠은 입도(coarse-grained)의 처리 요소(Processing Element, PE)들로 구성됩니다. GPU와 달리 텐서를 2D 행렬로 강제로 변환하는 단계를 거치지 않기 때문에, 다차원 텐서의 고유한 병렬성을 온전히 보존할 수 있습니다.

### SoC 및 Processing Element (PE) 구성

TCP SoC는 총 **8개의 PE**로 구성되며, 각 PE는 호스트로부터 독립된 장치로 작동할 수 있습니다(SR-IOV를 통해 최대 8개 독립 인스턴스 지원). 또한 최대 4개의 PE를 융합하여 하나의 거대한 단일 PE로 구성하는 것도 가능합니다. 각 PE 내부에는 다음 구성 요소가 포함됩니다:

- **CPU 코어**: 64 KB L1 I/D 캐시, 256 KB L2 캐시, 그리고 예측 가능한 성능을 위해 캐시 미스 페널티를 줄이도록 스크래치패드에서 코드를 실행할 수 있는 3.5 MB 스크래치패드 메모리.
- **Tensor Unit (TU)**: 대규모 텐서 연산을 수행하며, 32 MB의 SRAM을 내장하고 64 TOPS의 연산 성능을 가짐. TU는 64개의 활성 슬라이스와 수율 향상을 위해 예비로 예약된 1개의 슬라이스를 포함하여 총 64+1개의 슬라이스로 구성됨.
- **Tensor DMA Engine (TDMA)**: 텐서의 고속 전송을 담당.

### Tensor Unit 미세구조와 슬라이스 내부

각 슬라이스는 메인과 서브의 두 실행 컨텍스트를 가지며 비동기 병렬로 실행됩니다. 슬라이스 내부는 다음과 같은 하위 블록으로 구성됩니다:

- **Data Memory (DM) slice**: 16개의 뱅크(각 8B 너비)로 구성되어 슬라이스당 최대 128GB/s의 SRAM 대역폭을 제공하며, 가상 주소 지원(페이지 테이블)을 통해 동적 연속 메모리 할당을 수행함.
- **Fetch Unit (FU)**: 슬라이스당 2개의 FU가 존재하며, 텐서 연산 시 회선 교환(circuit-switched) 방식으로 동작하여 엄격하게 정렬된 중재(arbitration)를 통해 네트워크 혼잡이 발생하지 않음.
- **Contraction Engine (CE)**: 8개의 DPE(dot-product engines)를 포함하며, 리덕션 트리를 통해 공간적으로 원소별 곱셈 결과를 합산함. 8개의 DPE는 피드 Unit으로부터 입력을 공유하고, 레지스터 파일(RF)로부터는 개별 입력을 받음. 누산기는 총 1024개의 누산기를 포함함.
- **Vector Engine (VE)**: 슬라이스당 8-way INT32 및 4-way FP32 처리량을 가지며, 소프트맥스(softmax)나 레이어 노름(layer-norm) 같은 핵심 LLM 연산을 빠르게 처리하기 위해 INT32/FP32 닷 프로덕트 및 산술 연산을 지원함.
- **Transpose Engine (TE)**: 슬라이스 내에서 텐서의 마지막 축을 다른 축들과 전치(transpose)함.
- **Commit Unit (CU)**: 커밋 사이즈 파라미터를 통해 8B/16B/32B/cycle 중 저장 대역폭을 선택할 수 있으며 패딩을 제거한 압축 저장을 지원함.

### RTL 구현 관련 명시

본 칩은 팹리스 기업 제품으로 RTL 게이트 레벨 구현이나 실리콘 레이아웃 자체(넷리스트)는 공개되지 않았으며, 논문은 마이크로아키텍처를 블록 다이어그램과 표 수준으로 공개한 것입니다.

## 3. 핵심 사실 (Killing Fact)

$$ \boxed{\ \text{PE} = 8, \quad \text{SRAM} = 256\text{MB}, \quad \text{HBM3} = 48\text{GB}, \quad \text{TDP} = 150\text{W}\ } $$

근거 자료에 명시된 RNGD 칩의 핵심 하드웨어 스펙 수치(8개의 PE, 256MB 온칩 SRAM, 48GB HBM3 용량, 150W TDP)를 나타내는 관계식으로, TCP 아키텍처의 전력 효율성과 대규모 메모리/연산 자원 배치를 정의하는 기준이 됩니다.

## 4. 핵심 설계 기법

### 기법 A: 회선 교환형 Fetch Network

텐서 연산 중에 회선 교환(circuit-switched) 네트워크 방식으로 동작하여 고정된 토폴로지를 유지하며, 엄격하게 정렬된 중재 방식을 사용하여 네트워크 혼잡이 발생하지 않도록 설계됨.

**왜 이렇게 설계했는가:** 연산 유닛 간 데이터 재사용을 유연하게 활성화하고 네트워크 병목 현상을 방지하여 고성능 텐서 축약 연산을 효율적으로 지원하기 위함.

### 기법 B: 입력 버퍼 브로드캐스트 및 멀티캐스트

각 슬라이스의 SRAM에서 다른 슬라이스로 데이터를 멀티캐스트하여 추가적인 DRAM 읽기 없이 더 큰 데이터 재사용을 가능하게 함 (예: QK^T 연산 시 Query와 Key 텐서를 DRAM에서 단 한 번만 가져와 SRAM에 저장 후 반복 재사용).

**왜 이렇게 설계했는가:** DRAM과 칩 처리 요소 간의 데이터 전송은 연산 자체보다 현저히 많은 에너지를 소모하므로(최대 10,000배), 에너지 소모의 주원인인 DRAM 접근 횟수를 최소화하기 위함.

### 기법 C: 레이어 간 온칩 캐싱 (Layer-to-Layer Caching)

한 레이어의 출력 활성화 값을 추가적인 DRAM 접근 없이 온칩 메모리 내에서 다음 레이어의 입력 활성화 값으로 직접 사용함.

**왜 이렇게 설계했는가:** 중간 데이터가 DRAM을 거치면서 발생하는 대역폭 낭비와 전력 소모를 원천적으로 차단하기 위함.

### 기법 D: 하드웨어 기능 단위 기반 5단계 End-to-End 컴파일러

원시 연산자 변환, 텐서 커널 생성(연산자 융합), 저수준 연산자 생성, 커맨드 생성, 스케줄링 및 리소스 할당(휴리스틱+ILP+유전 알고리즘 혼합)의 5단계 파이프라인을 거쳐 모델 전체를 단일 융합 연산으로 처리함.

**왜 이렇게 설계했는가:** 방대한 프레임워크 연산자를 하드웨어 기능 단위(fetch, contraction, vector, transpose engine 등)에 1:1 대응하는 커맨드 리스트로 자동 최적화하여 컴파일 및 배포의 용이성을 확보하기 위함.

## 5. 자주 하는 오해 / 주의할 점

처음 TCP 아키텍처를 접할 때 GPU처럼 텐서를 강제로 2D 행렬(flatten)로 바꾸어 GEMM 연산으로더 효율적으로 처리할 수 있을 것이라고 오해하기 쉽습니다. 하지만 TCP는 다차원 텐서 구조를 유지하며 직접 축약(contraction)을 수행하는 구조이므로, GPU식 접근은 오히려 다차원 병렬성을 파괴하고 대역폭 효율을 떨어뜨립니다. 또한, TCP는 면적 및 전력 오버헤드 문제로 인해 파인 그레인(fine-grained) 스파스성 대신 덴스(dense) 모델에 집중하고 있음을 놓치기 쉽습니다.

## 6. 대표예제 (추론 연습)

### 예제 1

RNGD 칩에서 대규모 LLM 어텐션 연산(예: QK^T)을 수행할 때, Query와 Key 텐서가 DRAM에서 반복적으로 읽히지 않고 온칩 SRAM에 캐싱되어 재사용되는 메커니즘을 설명하시오.

**풀이:**

1단계 — TCP 아키텍처는 텐서를 2D로 평탄화하지 않고 다차원 병렬성을 유지한 채로 처리한다. 2단계 — Query와 Key 텐서는 DRAM에서 단 한 번만 페치(fetch)되어 각 슬라이스의 SRAM에 저장된다. 3단계 — SRAM에 저장된 데이터는 회선 교환형 Fetch Network와 멀티캐스트 메커니즘을 통해 다른 슬라이스로 브로드캐스트되어 추가적인 DRAM 읽기 없이 반복 재사용된다.

**답: Query와 Key 텐서는 DRAM에서 단 한 번만 페치된 뒤 SRAM에 저장되고 멀티캐스트되어, DRAM 전송 대비 에너지 효율을 극대화하면서 반복 재사용된다.**

### 예제 2

RNGD 칩의 8개 PE 중 일부를 활용하여 멀티테넌시 환경에서 독립적인 가상 머신(VM) 인스턴스를 구성할 때 사용되는 가상화 기술의 이름을 쓰시오.

**풀이:**

1단계 — RNGD 아키텍처는 SoC 내에 8개의 독립된 PE를 제공한다. 2단계 — 각 PE는 호스트와 독립된 장치로 동작할 수 있다. 3단계 — 이를 다중 VM 환경으로 나누어 지원하기 위해 SR-IOV(Single Root I/O Virtualization) 기술이 활용된다.

**답: SR-IOV (Single Root I/O Virtualization)**

## 7. 유제 (면접 예상 질문)

1. GPU가 텐서를 2D 행렬로 변환하여 GEMM을 수행하는 방식과 비교했을 때, TCP가 다차원 텐서를 직접 다루는 것이 병렬성과 에너지 효율 측면에서 가지는 근본적인 이점은 무엇인가? *(힌트: 텐서 병렬성 파괴 여부와 DRAM-칩 간 에너지 소비 차이(최대 10,000배)를 고려할 것.)*
2. TCP의 End-to-End 컴파일러 파이프라인에서 연산자 융합(Operator Fusing)이 레이어 간 텐서 이동 및 성능 최적화에 기여하는 원리를 설명하시오. *(힌트: 출력 활성화 값의 온칩 메모리 직접 재사용과 중간 DRAM 접근 최소화 관점에서 접근할 것.)*
3. TCP 아키텍처가 파인 그레인(fine-grained) 스파스성 대신 덴스(dense) 모델에 집중하고 그 저정밀도(low precision)를 채택한 하드웨어 설계상의 이유는 무엇인가? *(힌트: 면적 및 전력 오버헤드 측면과 LLM 기준 정밀도의 효과성을 연관 지을 것.)*

## 8. 다음 챕터와의 연결

이 챕터에서 학습한 RNGD Tensor Contraction Processor의 하드웨어 구조와 컴파일러 최적화 기법은, 이어지는 챕터인 'RNGD SDK 프로그래밍 인터페이스 및 컴파일러 파이프라인'에서 소프트웨어 명령어 세트와 5단계 컴파일 흐름을 구체적으로 구현하는 기반이 됩니다.
