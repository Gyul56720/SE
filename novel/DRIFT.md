# DRIFT — 자유 연속 집필 오케스트레이션

> 줄거리를 먼저 짜지 않는다. 첫 문장 하나에서 끝까지 흘러간다.

`novel/` 의 다른 방식(`episode.py` — 결말을 정하고 거꾸로 비트를 쌓는 조립)과 **반대로**
간다. 조립은 인과가 튼튼한 대신 문장이 칸에 갇힌다. 씬마다 분량이 할당되고, 회차마다
구조가 요구되고, 관문 아홉이 매번 판정한다. 그렇게 나온 원고를 두고 나온 평이 이 방식의
출발점이었다 — *"무겁고 단조롭다. 스타일리쉬하지 못하다."*

이름은 다섯 부품의 머리글자이면서, 이 방식 자체를 가리킨다.

| | 부품 | 파일 | 하는 일 |
|---|---|---|---|
| **D** | Diffusion (확산) | `diffusion.py` | 세계를 넓히고 앞엣것을 다시 키운다 |
| **R** | Rhythm (리듬) | `rhythm.py` | 문장 길이와 대사 분포를 잰다 |
| **I** | Intrusion (충격) | `shock.py` | 2,000자마다 제3자가 들이닥친다 |
| **F** | Freewriting (자유) | `flow.py` | 줄거리 없이 덩어리를 이어 붙인다 |
| **T** | Truth (원장) | `flow._merge` | 앞에서 쓴 것과의 모순만 잡는다 |

## 첫 번째 규칙 — 자유도

축이 여럿이고 뽑기가 많지만, **그것들은 전부 출발점이지 각본이 아니다.** 이름이 표류인
이유가 그것이다 -- 정해진 데로 가는 것이 아니라 흘러가는 것이 목적이다.

  · 뽑힌 것이 안 어울리면 비틀거나 버린다. 목록을 채우려고 쓰지 않는다.
  · 자는 **재서 돌려주되 원고를 죽이지 않는다.** 끝내 안 고쳐지면 제일 나은 것을 채택한다.
  · 게이트는 최소로만 개입한다. 놓친 모순은 사람이 읽다 발견하지만, 과잉 기각은 글
    자체를 없앤다.

꺾이지 않는 것은 둘뿐이다. **앞에서 쓴 것과 어긋나지 않기**(모순), **우연이 문제를 풀지
않기**(편의주의). 나머지는 전부 자유다.

## 왜 이렇게 생겼나 — 수리소설학

이 구조는 **수학의 확장 방식을 소설로 옮긴 것**이다. 자연수에서 복소수까지, 기하에서
위상수학까지, 대수에서 대수기하까지 — 수학은 세계를 지우고 다시 짓지 않는다. **앞의
것을 품은 채로 바깥을 넓힌다.** 정수는 자연수를 부정하지 않고, 복소수 안에서 실수는
여전히 실수다. 그러면서 전에는 물을 수 없던 것을 물을 수 있게 된다.

DRIFT 의 부품들이 정확히 그 자리에 하나씩 놓인다.

| 수학 | DRIFT |
|---|---|
| 공리계 | **원장** — 한 번 놓인 것은 참으로 남는다 |
| 무모순성 | **모순 게이트** — 새 문장이 옛 문장과 부딪히면 기각 |
| 보존적 확장 | **확산** — 앞의 것을 부정하지 않고 그 바깥을 넓힌다 |
| 정의의 세분 | **자란 이름** — 웅포 → 웅포 소금 공장. 구조를 품은 채 좁아진다 |
| 새 공리의 도입 | **사건 · 급발진** — 앞과 안 부딪히되 예측되지 않는 것 |
| 미증명 명제 | **열린 것** — 던져지고 아직 안 닫힌 것. 이야기가 갚지 않은 빚 |
| 서로 다른 분야의 다리 | **연결** — 따로 자라던 둘이 실은 이어져 있었다 (오일러) |
| 반례 | **예외** — 통칙을 한 번 깬다. 규칙은 지워지지 않고 정교해진다 |
| 공리의 독립성 | **의심** — 뒤집지 않고 지반을 흔든다 (비유클리드) |
| 보조정리 | **수단** — 앞엣것이 언급되는 것이 아니라 쓰인다 |
| 정리에 의한 공리 갈음 | **압축** — 통칙 하나가 낱낱의 사실을 대신한다 |
| 증명의 흐름 | **표류** — 결론을 정해 두지 않고 한 줄이 다음 줄을 부른다 |

그래서 이 파이프라인이 판정하는 것은 **취향이 아니라 무모순성**이다. "재미있는가" 는
기계가 못 본다. 그러나 "이 문장이 앞의 문장과 양립하는가" 는 정확히 볼 수 있다 —
그것이 취향이 아니라 사실이기 때문이다. 수학이 아름다움을 증명하지 않고 참을 증명하듯,
여기서도 기계는 참만 본다. 아름다움은 사람이 읽는다.

수학의 확장에는 방향이 하나 더 있다. **점점 추상해진다** — 자연수를 세다가 구조를 보고,
도형을 재다가 연결만 남기고, 마침내 대상을 지운 자리에 관계만 남긴다. 그리고 **철학은
그 상승 안에 숨어 있다.** 어느 수학책도 "이것은 존재에 관한 물음이다" 라고 쓰지 않지만,
연속을 정의하는 순간 이미 그것을 하고 있다.

소설도 그렇게 간다. 첫 덩어리는 지포 라이터 하나로 시작하고, 그 라이터가 몇 번 손을
옮기고 나면 그것은 더 이상 라이터가 아니라 **빚, 혹은 약속, 혹은 사람 사이의 어떤
구조**가 된다. 물건은 그대로 있는데 층이 올라간 것이다.

그래서 이 저장소의 씨앗에는 `depth` 축이 있고, **거기 적힌 사상가의 이름은 프롬프트에
절대 실리지 않는다.** 명제를 셋으로 갈라 `claim`(사람만 읽는다) · `test`(플롯이 그것을
시험하는 방식) · `cover`(겉으로 보이는 가벼운 재미)로 두고, 모델에게는 뒤의 둘만 준다.
이름이 실리면 모델이 그 낱말을 본문에 쓰고, 그 순간 소설이 강의가 되기 때문이다.
**철학은 인용되는 것이 아니라 선택으로 시험되는 것이다.** 그것이 상승 안에 숨는 방식이다.

두 가지가 이 비유에서 따라 나오고, 실제로 코드가 그렇게 되어 있다.

**하나. 확장은 앞의 것을 보존해야 한다.** 새 설정이 옛 설정을 부정하면 그건 확장이
아니라 다른 체계다. 그래서 모순만은 하드 게이트다 — 리듬도 농도도 원고를 죽이지 않지만
모순은 죽인다.

**둘. 정의는 한 번만 한다.** 수학에서 정의한 기호를 다시 정의하지 않듯, 지어낸 낱말과
인물의 조건은 한 번 정해지면 그 뒤로는 **쓰기만 한다.** 다시 설명하는 것은 확장이
아니라 반복이고, 그래서 메아리 자가 그것을 잡는다.

## 30초 사용법

```bash
/home/ubuntu/SE/scripts/drift.sh start      # 새 원고 (8,000자)
/home/ubuntu/SE/scripts/drift.sh status     # 어디까지 왔나
/home/ubuntu/SE/scripts/drift.sh read       # 읽는다
/home/ubuntu/SE/scripts/drift.sh go 50000   # 이어서 5만 자까지
```

런은 백그라운드로 돈다. 터미널을 닫아도, 세션이 끝나도 계속 쓴다.

## 명령 전부

| 명령 | 하는 일 |
|---|---|
| `drift.sh start [글자수]` | 새 원고. 쓰던 것이 있으면 `.bak` 으로 옮겨 둔다. 기본 8,000자 |
| `drift.sh go [글자수]` | **하던 원고를 이어 쓴다.** 세계·인물·사건 번호가 전부 이어진다. 기본 50,000자 |
| `drift.sh status` | 살아 있는지 · 덩어리 수 · 글자 수 · 사건 횟수 · 세계 크기 · 최근 로그 |
| `drift.sh read` | 지금까지 쓴 원고를 화면에 |
| `drift.sh save <파일>` | 원고를 파일로 (VM 안에) |
| `drift.sh send [이름]` | **원고를 Discord 로 보낸다** — VM 밖으로 빼는 길 |
| `drift.sh watch` | 로그를 실시간으로 따라간다 |
| `drift.sh stop` | 멈춘다. **원고는 남는다** — `go` 로 이어 쓴다 |
| `drift.sh world` | 세계가 어떻게 자랐나 (★ 는 주요 인물) |
| `drift.sh open` | 아직 안 닫힌 것들 — 이 이야기가 갚지 않은 빚 |

**세계가 자라는 네 방향.** 넓히기(새것) · 세분(웅포 → 웅포 소금 공장) · **접기**(따로 있던
둘을 잇는 것) · **압축**(통칙이 낱낱을 갈음하는 것). 앞의 둘은 세계를 크게 하고, 뒤의 둘은
세계를 **깊게** 한다. 수학이 커지는 방식이 정확히 그 넷이다.

바꿀 수 있는 것:

```bash
SE_DIR=/path/to/SE   # 저장소 위치 (기본 /home/ubuntu/SE)
BOOK=/path/book.json # 원고 파일  (기본 $SE_DIR/novel/drift.json) — 여러 편을 따로 쓸 때
FIRST="첫 문장."     # 첫 문장 (start 에서만)
```

여러 편을 동시에 쓰려면 `BOOK` 을 갈라 준다. 다만 **같은 파일에 두 런이 붙지 못하게**
막아 두었다 — 그러면 서로를 덮어쓴다.

## 어떻게 돌아가나

한 덩어리(약 1,400자)가 한 바퀴다.

```
   꼬리 1,200자 ─┐
   세계 원장    ─┼→  [화자: Gemini]  →  본문
   이번 지시    ─┘                        │
                                          ├→ [추출기: Gemini] → 원장에 더한다
                                          │        │
                                          │        └→ 모순인가?  ─예→ 기각, 다시
                                          │
                                          └→ 리듬·농도를 잰다  ─못 미치면→ 숫자를 돌려주고 다시
                                                   │
                                                 채택 → 다음 덩어리
```

**"이번 지시" 가 매번 달라진다.** 평소엔 확산, 2,000자마다 사건.

### 1. 확산 — 넓히면서 깊게

넓히기만 하면 산만하고(연결 없는 나열), 회수만 하면 제자리를 돈다. 둘을 함께 요구한다:

- 새로 놓는 것 **3개 이상** — 새 사람·장소·물건·사실, 이름과 연도와 상표를 대고
- 앞에서 나온 것 **2개 이상**을 다시 만지되 **한 단계 키운다** — 그냥 놓여 있던 것이
  쓰이거나, 망가지거나, 다른 사람 손에 있거나, 그것 때문에 일이 생긴다

핵심은 **식은 소품**이다. 꼬리 1,200자 밖으로 빠진 소품을 원장에서 골라 이름으로 짚어
프롬프트에 다시 올린다. 원장이 금지 목록이 아니라 **연료**로 쓰이는 자리가 여기다.

### 2. 리듬 — '-다' 가 아니라 길이를 센다

기준으로 삼은 문장(하루키)을 재보면 서술문의 86%가 '-다' 로 끝나고 여섯이 내리 이어진다.
그런데 단조롭지 않다 — 그 '-다' 의 71%가 마흔 자를 넘기 때문이다. **단조로움의 정체는
종결어미가 아니라 길이였다.** 그래서 세는 것은 '-다' 가 아니라 **짧은 '-다'** 다.

| 자 | 기준 |
|---|---|
| 40자 넘는 문장 | 서술문의 15% 이상 |
| 짧은 '-다' | 62% 아래 |
| 짧은 '-다' 연속 | 4번 이하 |
| 대사 | 전체 줄의 10% 이상 |
| 긴 대사 (55자+) | 1개 이상 — 소품의 유래가 여기서 나온다 |
| 짧은 대사 (20자−) | 2개 이상 — 끊고 받아친다 |

### 3. 충격 — 점층을 끊는다

약 2,000자마다, 또는 원장이 부풀어 프롬프트가 무거워지면 **사건이 터진다.** 그 덩어리는
확산을 걷어내고 사건 하나만 시킨다. 공간이 바뀌고, **다음 덩어리부터 새 환경에서 다시
점층한다.** 사건은 방향을 바꾸는 것이 아니라 한 번 끊는 것이다.

사건은 미리 정해두지 않는다 — 목록 하나를 돌려 쓰면 세 번째부터 예측된다. 축을 갈라
조합한다: **누가(30) × 어떻게(33) × 무엇이 남나(21) × 어느 규모(9) × 어떤 온도(8)**,
149만 가지. 씨앗에 묶여 있어 이어 쓰기에도 같은 순서로 재현된다.

제약은 하나뿐이다 — **사건은 문제를 풀지 않는다.** 딱 맞춰 나타나 화자를 구해주는 것은
편의주의다. 사건은 문제를 만들거나, 바꾸거나, 엉뚱한 데로 옮긴다.

### 4. 원장 — 모순만 잡는다

취향은 사람이 보면 되지만 **모순은 길어질수록 사람도 못 본다.** 세 덩어리 뒤에 인물
이름이 바뀌고, 죽은 사람이 걸어 들어오고, 겨울이 여름이 된다. 그것만 코드가 잡는다.

**게이트는 최소로 만든다. 자유도가 이 방식의 전부다.**

| | |
|---|---|
| 기각한다 | **주요 인물**(3덩어리 이상 등장 + 카드 3칸 이상)의 **핵심 칸** — 나이·생사·가족·직업·이름·성별 |
| 넘긴다 | 그 밖의 전부 — 주변 사물, 스쳐 간 인물, 장소, 잡다한 사실, 성격·취미·말투 |

핵심 칸 안에서도 너그럽다. `42` 와 `42세` 는 같은 나이고, 자세해진 것은 통과시키며
**자세한 쪽을 남긴다.** 애매하면 통과다 — 놓친 모순은 사람이 읽다 발견하지만,
**과잉 기각은 글 자체를 없앤다.**

> 실측: "은색의 불규칙한 소리를 내는 물건" 이 "1950년대 독일 잡화점에서 판매된 은색
> 모델" 로 자세해진 것을 기각했다. 그건 같은 라이터고, 그런 기각이 원고를 못 나오게 한다.

**리듬과 확산은 원고를 죽이지 않는다.** 다시 써보라고 하되 끝내 안 고쳐지면 그중 제일
짙은 것을 채택한다. 취향 때문에 8,000자를 버릴 수는 없다.

## 인물 카드

대사가 인물마다 달라지려면 그 사람이 누구인지가 프롬프트에 있어야 한다. 추출기가 글에
드러난 칸만 채워 원장에 적는다 — 나이·키·성격·혈액형·가족·과거·트라우마·좋아하는 것·
싫어하는 것·취미·전공·직업·**말투**·버릇·겉모습.

> "거칠게" 는 **한 인물의 특징이지 소설의 규칙이 아니다.** 마흔둘 정비공과 스물셋
> 대학원생과 예순의 어머니는 같은 문장을 쓰지 않는다.

5만 자를 쓰면 스쳐 간 사람이 쉰 명씩 쌓인다. 그들의 카드까지 매번 펼치면 프롬프트가
원장으로 차서 꼬리와 지시가 뒤로 밀린다. 그래서 **주요 인물만 펼치고 조연은 한 줄로
접는다.** 접혀도 이름은 남으니 확산의 연료로는 그대로 쓰이고, 다시 자주 나오면 저절로
펼쳐진다.

## 모델 배치 — 산문은 절대 Claude 가 쓰지 않는다

| 역할 | 모델 | 왜 |
|---|---|---|
| 화자 · 추출기 | **Gemini** | 토큰의 대부분이 여기다 |
| 디렉터(주제·시나리오) | Claude | 호출 6회 중 1회, 출력 300토큰 남짓 — DRIFT 는 주제를 미리 안 정하므로 쓰지 않는다 |

`drift.sh` 는 시작 전에 Gemini 키를 확인하고, 없으면 **사실대로 실패한다.** Claude 로
대신 쓰지 않는다. 저장소 규칙이다(`CLAUDE.md`).

## 원고를 손에 넣기

원고는 VM 안의 JSON 에만 있다. `read` 는 화면에 쏟아질 뿐 파일이 되지 않는다.

```bash
drift.sh send             # Discord 에 파일로 올린다 -- 폰이든 노트북이든 거기서 받는다
drift.sh send 1화.txt     # 이름을 붙여서
```

자격증명은 이미 있는 것을 쓴다(`DISCORD_BOT_TOKEN` + `DISCORD_CHANNEL_ID`, 또는
`DISCORD_WEBHOOK_URL`) — `overnight.py` 의 알림이 쓰는 것과 같다. 봇 게이트웨이는 띄우지
않는다. 그러면 이미 도는 봇과 세션이 겹친다.

SSH 를 쓸 수 있으면 **로컬 기계에서** 이렇게 당겨도 된다:

```bash
scp ubuntu@<VM주소>:/home/ubuntu/SE/novel/drift.json .
ssh ubuntu@<VM주소> '/home/ubuntu/SE/scripts/drift.sh read' > 소설.txt
```

## 고장났을 때

| 증상 | 뜻 | 할 일 |
|---|---|---|
| 원고 파일이 없다 | **시작도 못 했다** (런은 시작하자마자 한 번 저장한다) | `tail -40 logs/drift.log` |
| `status` 가 "돌고 있지 않다" 인데 글자 수는 늘어 있다 | 목표를 채웠거나 시간 상한 | `drift.sh go` 로 이어 쓴다 |
| 로그에 `RPM/일시장애 -- 기다렸다 다시 돈다` | 정상. 풀이 다른 키·모델로 돌고 있다 | 그냥 둔다 |
| 로그에 `모순을 못 풀었다 -- 멈춘다` | 주요 인물의 핵심 칸이 세 번 연속 어긋났다 | `drift.sh world` 로 원장을 보고, 잘못 적힌 칸을 손으로 고친 뒤 `go` |
| 사건이 안 터진다 | 아직 2,000자를 안 썼다 | `grep 사건 logs/drift.log` |

덩어리마다 저장하므로 **중간에 멈춰도 잃는 것이 없다.** 쿼터가 마르든 12시간을 넘기든
같은 `go` 로 이어 간다.

## 직접 부를 때

```bash
python3 /home/ubuntu/SE/novel/flow.py --out book.json --chars 8000
python3 /home/ubuntu/SE/novel/flow.py --resume book.json --chars 50000 --hours 12
python3 /home/ubuntu/SE/novel/flow.py --read book.json
python3 /home/ubuntu/SE/novel/flow.py --out book.json --first "첫 문장을 여기에."
```

**백그라운드로 띄울 때는 반드시 `setsid`** — `command &` 만 쓰면 부모가 끝날 때 같이
죽는다. 확인은 `ps -p $!` 가 아니라 `pgrep` 으로 한다(`setsid` 가 fork 하므로 `$!` 는
이미 끝난 래퍼의 PID 다). 자세한 것은 저장소 `CLAUDE.md`.
