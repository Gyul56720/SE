# 도파민 -- 라노벨을 24시간 양산할 때 재미가 어디서 나오는가 (2026-09-08 저녁)

사용자: "너무 재미가 없어. 지금 있는 그대로 대사는 좋아. 액션씬 전투씬 스킬 직함 세계관 설정
더 자세히. 복수극도 좋고, 거지가 왕궁 들어가서 권력 탈취하는 것도 좋고(예시야 하드코딩하지마)
이런 문법들을 더 모으라고. 그리고 중간에 주인공을 구해주는 잘생긴 히로인도 없고 너무 도파민
요소가 없어. 도파민이 마구마구 뿜어지도록 라노벨 양산법을 알려줘."

## 한 줄 진단

파이프라인은 **모순을 안 내는 것**과 **문장의 결**을 잘 지킨다(대사가 좋다는 평이 그것이다).
재미없는 이유는 그 둘이 아니라, 회차 카드가 **무엇을 통쾌하게 만들지**를 한 번도 요구하지
않았기 때문이다. 질문 · 방해 · 비트 · 답 · 갈고리 -- 전부 긴장을 쌓는 칸이고, **푸는 칸이 없었다.**
쌓기만 하면 고구마다. 웹소설이 사이다라고 부르는 것은 "쌓은 만큼보다 조금 더 돌려주는 것"
이고(HIKI.md ざまぁ 회계), 그것을 회차마다 **한 자리** 요구하면 된다.

## 도파민의 회계 -- 세 가지 규칙

1. **회차마다 쾌감 하나.** 지는 회차에도. 큰 것을 잃는 회차에 작은 것 하나를 되갚는다 --
   잔 하나 · 말 한마디 · 물러선 걸음. Ely (2015) 의 분산이다: 믿음이 한 방향으로만 가면
   서스펜스가 0 이다. 카드의 `쾌감` · `쾌감자리` 칸이 이것이다. 갈고리와 같은 계약 --
   **벌어진 문장**이어야 한다. 질문 · 예감 · 미소는 되묻고, 두 번 틀리면 카드는 살리되
   쾌감만 비운다.
2. **격(格)이 보여야 한다.** 통쾌함은 낙차에서 온다 -- 얕보이던 자가 위인 것으로 드러나는
   낙차, 무릎 꿇던 자리에서 무릎 꿇리는 낙차. 그러려면 **누가 누구보다 위인가**가 매 장면에
   보여야 하고, 그것이 직함 · 등급 · 이명 · 부르는 말이다. 다만 숫자 창은 없다(style.py) --
   격은 부르는 말과 물러서는 걸음과 첫 합으로 보인다.
3. **구원은 심어 둔 사람만 한다.** "중간에 구해 주는 히로인" 은 DRIFT 의 편의주의 금지
   (우연은 문제를 풀지 않는다)와 정면으로 부딪히는 것처럼 보이지만 아니다 -- 우연이 아니면
   된다. 소문 → 실루엣 → 한 마디로 먼저 심고, 제 사정으로 오고, 구한 값을 받는다. 구해진
   쪽이 진 빚이 다음 회차의 관계다. 그것이 빌드업이고, 빌드업이 있어야 구원이 울린다.

복수와 왕좌는 **줄기 열여덟 중 둘**이다. 씨앗마다 다른 넷이 디렉터에게 보이고, 디렉터는
하나를 고르거나 둘을 섞거나 목록 밖을 짓는다. 예를 박지 않는다는 요구가 이렇게 지켜진다 --
줄거리가 아니라 **시작 → 끝의 꼴**만 있고, 꼴은 "시작에서 못 하던 것을 끝에서 한다" 하나다.

## 어디에 실리나 -- 호출은 안 는다

```
serial.plan   (원고당 1회)   [줄기 본보기 4]  →  "줄기" 칸. 끝은 되찾고 · 편을 늘리고 · 인정받는 자리
beat.card     (회차당 1회)   [전투 2] [세계 2] [쾌감 3] [설정집]  →  "쾌감" "쾌감자리" "전투" "설정" 칸
beat.brief    (덩어리마다)   쾌감 자리 · 싸움이 있으면 전투 문법 2 · 이번 설정 · 설정집 이름들
hooks.KINDS   (회차당 5개)   + 무릎 · 구원 · 승급 · 되갚음 · 힘의 폭로 · 전리품 · 복종 · 도전장 · 한 방 · 각성
genre.lanobe  (덩어리마다)   관계 · 사건 · 부름(직함 서른) · 세간(무기) · 화법(기술은 외친다 …)
```

**설정집은 원장으로 돈다.** 카드가 `설정`(이름 + 규칙 한 줄)을 내면 `book["codex"]` 에
쌓이고, 다음 카드와 화자가 그 이름을 그대로 쓴다. 같은 이름을 다시 세우면 설정집의 것이
이긴다 -- 값이 둘이면 그것이 모순이다. 세우는 것은 **쓰기 한 회차 앞**이다: 처음 나온
이름의 기술이 결착을 내면 그것이 뜬금없음이다(SPACE.md 의 "처음 나온 이름은 판을 뒤집을
수 없다" 와 같은 규칙).

## 양산법 -- 24시간

```bash
HOURS=24 GENRE=lanobe drift.sh start 200000        # 라노벨 · 격 · 전투. 약 40회차
HOURS=24 GENRE=ropan STYLE=ropan drift.sh start 200000   # 로판. 문법은 같은 카드로 실린다
drift.sh arc      # 줄기 · 끝 · 빚 -- 어디로 가는지
drift.sh card     # 이번 회차 -- 쾌감이 있나 · 싸움이 있나 · 무엇을 세웠나
drift.sh codex    # 설정집 -- 직함 · 등급 · 기술 · 법칙이 쌓이는가
```

원고를 읽기 전에 `card` 와 `codex` 를 본다. **회차마다 쾌감이 없거나 설정집이 안 자라면**
그 런은 재미없는 런이다 -- 그것은 읽지 않아도 안다. 로그에는 `[회차]   쾌감(비트 2): …` ·
`[회차]   전투: …` · `[회차]   설정: …` 으로 남는다.

## 재지 않는다

쾌감이 **실제로 산문에 벌어졌는지**는 안 잰다 -- 재려면 호출이 든다(STORY.md 의 D 안).
지금 검사가 보는 것은 배선뿐이다: 칸이 요구되는가 · 꼴이 틀리면 되묻는가 · 설정집에 남는가 ·
화자에게 실리는가(`tests/test_space.py` [도파민]). 그리고 이 문서의 수(회차마다 하나 · 넷씩
보여 준다)는 잰 것이 아니라 정한 것이다. 30화를 뽑아 사람이 읽고 "어디서 멈췄는가" 를 받는
것이 다음이다(SUCCESS.md B층).
