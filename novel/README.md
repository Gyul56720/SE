# `novel/` — 검증된 장편 소설 생성 오케스트레이션

이 저장소의 다른 오케스트레이션(`orchestrator/`, `mathgen/`, `compression/`)과 **같은 원칙**
위에 서 있다: **생성자와 심판을 분리하고, 심판은 절대 LLM 이 아니다.**

**겉은 가볍고 속은 무겁다.** 씨앗에 `depth` 축이 있다 -- 한 사상가의 명제를 셋으로 갈라
`claim`(사람만 읽는다) · `test`(플롯이 그것을 시험하는 방식) · `cover`(겉으로 보여야 하는
가벼운 재미)로 둔다. **프롬프트에는 test 와 cover 만 실린다.** 이름과 개념어는 절대 싣지
않는다 -- 프롬프트에 그 말이 있으면 모델이 텍스트에 그 말을 쓰고, 그 순간 소설이 강의가
된다. `tests/test_depth.py` 가 여섯 개 프롬프트 전부에서 누출이 없는지 본다.

**씨앗도 사이다다.** 반칙(`IMPOSSIBLE`)의 셋째 칸은 **대가가 아니라 조건**이다 -- 쿨타임,
범위, 발동 요건. 주인공이 손해를 감수하는 순간 그것이 고구마이고, 사이다에서 고구마는
독자가 떠나는 이유다. 제약은 남기되(무제한이면 긴장이 없다) 주인공을 다치게 하지 않는다.
결말도 마찬가지다: "제 손으로 법을 쓰고 대가를 치른다" 가 아니라 **되찾고, 편을 늘리고,
누군가 그것을 인정하는 것**으로 닫는다.

소설에서 그것이 왜 가능한가. "재미있는가" 는 기계가 못 본다. 그러나 **"세계가 자기모순인가"
는 정확히 볼 수 있다** — A 와 B 가 사귀는데 어느 순간 C 가 A 와 사귄다, 죽은 인물이
다음 화에 걸어 들어온다, 모르는 비밀을 인물이 말한다. 이것들은 취향이 아니라 사실이다.
그래서 여기서는 취향을 판정하지 않고 **모순만** 잡는다.

## 30초 요약

**VM 에서는 절대경로로 쓴다.** 상대경로는 어느 디렉토리에서 쳤느냐에 따라 조용히 다른 것을
가리킨다 -- 홈에서 실행하니 `python3 novel/watch.py` 가 `/home/ubuntu/novel/watch.py` 를
찾다 죽었고, PATH 가 깨진 셸에서는 `pgrep` 이 `$PWD/pgrep` 으로 해석됐다(실측).

```bash
/home/ubuntu/SE/scripts/run_novel_vm.sh --restart --wipe   # 기록 삭제 + 새 씨앗 -> 1~5화
/home/ubuntu/SE/scripts/novel_status.sh             # 살아있나 · 로그 · 자수 한 번에
/home/ubuntu/SE/scripts/novel_status.sh -f          # 로그를 계속 따라간다
/home/ubuntu/SE/scripts/novel_status.sh --read      # 지금까지 쓴 원고를 읽는다
```

로컬(저장소 안에서)에서 부분을 따로 돌릴 때:

```bash

python3 novel/read.py  --path novel/seeded.json --ep 1-5  # 읽기
python3 novel/profile.py --path novel/seeded.json    # 병목 재기
```

## 파이프라인

```
씨앗(코드)      축 7개를 무작위 조합 -> 9,400만 가지. 기계가 최소한만 거른다
   ↓
세계(코드)      인물·비밀·법·목소리·결말 블록으로 편다
   ↓
조립            결말 하나를 회차들로 **역방향**으로 편다 (원인은 결과 뒤에 찾는다)
   ↓ 디렉터(Opus, claude -p) : XML 입력 -> Markdown 시나리오
   ↓ 추출기(Gemini)          : Markdown -> JSON
집필            씬마다 배우 턴 -> 관문 -> 화자 산문 -> 관문 -> 수리
   ↓ 배우·화자(Gemini)
관문 9개        모순만 본다. 위반 목록을 돌려준다. hard 는 기각, soft 는 기록만
```

**형식 세금**: 창작은 Markdown 으로 받고 구조화는 별도 호출로 뽑는다. 출력 형식을 JSON 으로
강제하면 모델이 문장을 지으면서 동시에 문법을 지켜야 해서 개방형 창작의 품질이 떨어진다.
JSON 의 우위는 **추출 태스크에 한정**된 이야기라, 두 태스크를 갈라 각자 유리한 형식을 쓴다.

## 문체 — `style.py` (페르소나)

관문이 취향을 판정하지 않기로 한 뒤, 문체는 **쓰기 전에 주는 규율**로 옮겼다. 규율은 한
벌이 아니다 -- 같은 파이프라인으로 전혀 다른 소설을 쓰려면 통째로 갈아끼워야 하므로,
`PERSONAS` 에 이름표를 달아 나란히 두고 `--persona` 로 고른다.

| 페르소나 | 무엇 |
|---|---|
| `cider` (기본) | **하루키 문장에 사이다 템포를 이식한 것.** 건조한 단문·마이너스 퇴고는 그대로 두고, 속도(지연 금지)와 농담만 얹었다. 상태창은 없다 |
| `hardboiled` | 하드보일드 마술적 리얼리즘. 건조한 단문 · 하나뿐인 불가능 |

층을 나눈 기준은 "누가 그것을 실행할 수 있는가" 다:

| 층 | `cider` 가 받는 것 |
|---|---|
| 화자 `narrator()` | **문장론 6개**(아래) + 건조한 단문 · 마이너스 퇴고 · 느낌표 금지 · 수치·상태창 금지 · 주저·딜레마 금지 · 농담은 무표정하게 |
| 배우 `actor()` | 한 번에 한두 문장 · 메아리 화법 · 설정을 대사로 증명 · **놀라고 감탄하는 것은 조연** · 반동은 분명하게 |
| 디렉터 `director()` | 매 장면이 한 걸음 · 다음 화로 미루지 않음 · 선역이라도 반동으로 규정 · 대가를 치르게 하지 않음 · **반칙은 수치가 아니라 '먼저 아는 것'** |
| 회차 `episode_brief()` | **3화 법칙** -- 1화 곤경과 손실 / 2화 관계 프레임 확정 / 3화 규칙 마찰 |

### 화자의 문장론 6개

규칙만 주면 모델은 규칙을 요약해서 지킨다. 그래서 **전부 예시와 함께** 싣는다
(`tests/test_style.py` 가 예시가 빠지지 않았는지 본다).

1. **모든 것을 상황으로** — 좌표(몇 살의 언제·어디·어떤 자세)를 먼저 놓는다. 나쁜 예와
   좋은 예를 나란히 준다. "나는 아팠다" 는 성의가 없다고 못박는다.
2. **'-다' 의 단조로움 깨기** — 짧은 '-다' 문장이 두 번 이어지면 셋째에서 바꾼다.
   생각을 붙이거나("아, 또 독일인가 하고 나는 생각했다"), 대사를 붙이거나, 문장을
   끝내지 않는다("…돌이킬 수 없는 지난 기억들을").
3. **점층** — 문장은 독립적이지 않다. 네 줄짜리 예시에 (좁힌다)/(키운다)/(뒤집어 더
   키운다) 이름표를 달아 준다. 점층은 끊길 때 끝난다.
4. **전환** — 점층이 끝나면 외현에서 내현으로. 비율은 1:1·1:3·3:1 무엇이든, 다만
   **매 회차 달라야 한다.**
5. **몽글함** — "-요" 를 쓰는 친절한 인물 하나, 외국어 병기. 건조함만으로는 안 읽힌다.
6. **가짜를 진짜처럼** — 없는 책도 제목과 내용을 짓고 개인적 경험을 붙인다. 흐릿하게
   써도 좋다("1959년이었는지 1960년이었는지 모르겠지만, 상관없다").

**상태창은 뺐다.** 등급 D→C, 호감도 12→41 같은 블록은 문장을 통째로 UI 로 바꾼다 --
필력을 살리자고 한 판인데 그 자리가 제일 먼저 죽는다. 씨앗의 반칙에서도 "능력치가 숫자로
보인다" 류를 걷어내고 **먼저 아는 것**(다음 수가 보인다 · 숨긴 의도가 떠오른다)으로 바꿨다.

**분량 배분은 지시로 주지 않는다.** "겹치지 마라" 를 넣어도 절반쯤만 지켜졌던 실측이 있다.
코드가 씬마다 종류를 배정하고(`Scene.kind`) **그 종류의 규율 하나만** 싣는다.

| `cider` 의 종류 | 목표 | 무엇 |
|---|---|---|
| `cider` | 40% | 걸림돌을 그 자리에서 치운다. 제시-처리-결과를 한 씬 안에 |
| `pingpong` | 25% | 지문 최소, 거의 전부 대사. 농담이 나오는 자리 |
| `routine` | 20% | 손이 하는 일(국수·다림질·음반). **짧게** — 여기서 멈추지 않는다 |
| `praise` | 15% | 조연이 방금 일을 놀라며 되짚는다. 화자는 한 줄로 받는다 |

고르는 방법은 무작위가 아니라 **결손 최대**(`pick_kind`)다 -- 회차당 3씬이라 표본이 작아
무작위로는 비율이 안 맞고 재현도 안 된다. 300씬 실측이 목표와 오차 3%p 안이다.
`cider` 는 척추와 서브플롯 두 풀에 다 들어간다: 척추가 씬의 1/3뿐이라 척추 전용으로 두면
사이다가 최대 33%로 묶인다 -- 이 장르에서 성취 장면이 소수파가 되는 것은 오류다.

블록의 **결말 씬**만 배분에서 빼고 페르소나가 지정한 종류를 쓴다(`finale_kind()`) --
사이다는 가장 큰 성취, 하드보일드는 증발하는 해결이다.

모르는 페르소나 이름은 **사실대로 실패한다.** 조용히 기본값으로 물러서면 엉뚱한 문체로
몇 시간을 쓰고도 아무도 모른다. `tests/test_style.py` 가 층별 적재·종류 격리·페르소나
교체·규율 누수 없음을 회귀로 고정한다.

## 이 설계가 배운 것 (2026-09-04 실측)

전부 실제로 밤을 날리거나 원고를 지운 것들이다. 다음 사람이 같은 곳에 빠지지 않게 적는다.

1. **산문 수리로 못 고치는 것을 산문 수리 루프에 넘기지 마라.**
   V003 이 감정 봉투를 **씬마다** 물어 25회, V009 가 선언(`relation_ops`)의 문제로 16회
   되돌려보냈다. 문장을 백 번 고쳐도 선언은 안 바뀌므로 시도 횟수를 다 쓰고 결정론적으로
   실패한다. 선언은 **조립 시점**에 되먹임으로 강제하고, 씬 관문에서는 soft 로만 본다.

2. **좌표를 하나 더 주면 모순이 사라진다.**
   `misbelieve` 가 진실과 믿음을 갈라 "X 를 믿는데 사실은 Y" 를 모순이 아니게 만들었다.
   시간 되감기도 같다 — `Scene.branch` 와 `Novel.timeline()` 이 시간선을 가르고, 되감은
   사람만 기억을 갖고 넘어온다(`carry`). 그 비대칭이 정보 격차를 통째로 만든다.

3. **requires 와 steps 는 다르다.**
   하나로 겸했더니 앞 블록이 갚아버려 열린 조건이 0이 되고, 척추가 결말 하나로 끝났다 --
   200화 중 585씬이 인과 없는 곁가지였다. `requires` 는 블록 간 의존성, `steps` 는 이 블록
   안에서 세울 단계다.

4. **같은 프롬프트는 같은 답을 낸다.**
   서브플롯 프롬프트에 "이미 쓴 것" 을 안 실었더니 세 회차가 전부 같은 소재였다. 겹치지
   말라는 지시는 **비교 대상이 있어야** 지킬 수 있고, 그것마저 절반쯤 지켜지므로
   difflib 로 재서 되돌려보낸다.

5. **분량 할당량은 희석 지시다.**
   화자 프롬프트의 "짧게 끊지 마라 -- 정적·냄새·소리로 채워라" 가 곧 "채워라" 다.
   프로토타입(2,000자)이 더 재미있었던 이유의 절반이 여기 있다.

6. **관문은 바닥을 지키지 천장을 만들지 않는다.**
   다 통과한 텍스트가 지루할 수 있다. 재미는 씨앗(무엇을 쓸 것인가)과 디렉터
   시나리오에서 나오고, 관문은 그것이 무너지지 않게만 한다.

7. **운영에서 겪은 것**: 두 벌이 같은 원고를 쓰면 나중에 저장한 쪽이 상대의 산문을 통째로
   지운다(코드가 막는다). `pgrep -af` 는 `test_overnight.py` 도 잡는다. 알림 실패가 런을
   죽이면 안 된다. `claude -p` 는 부모를 죽여도 타임아웃까지 남는다.
