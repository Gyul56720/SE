# `lab/` — 흐름을 끝까지 돌려 보는 자리

```bash
python3 lab/run.py                  # 아홉 단계 전부 (약 8초)
python3 lab/run.py --stage sta      # 거기까지만
python3 lab/run.py --json out.json  # 결과를 파일로
python3 tests/test_lab.py           # 낸 수를 다시 재서 붙든다
```

| 03 | 플로어플랜 | `se/floorplan.py` | 코어·행·자리 · 파워링/스트라이프 · IR/EM |
| 04 | 배치 | `se/place.py` | 전역 배치 → 합법화 · HPWL · 겹침 |
| 05 | CTS | `se/cts.py` | 삽입지연 · 스큐 · 균형 맞추는 값 |
| 06 | 배선 | `se/route.py` | 전역(gcell) → 상세 → 탐색수리 · 혼잡 |
| 07 | 사인오프 | `se/signoff.py` | 기생 재추출 → 재STA · 표류 · 밀도 |
| 08 | DFT | `se/dft.py` | 스캔 · 고장 시뮬 · 커버리지 · 시험시간 |
| 09 | DV | `se/dv.py` | UVM 꼴 환경 · 커버리지 · **변이검사** |

## 왜 파이썬으로 직접 짓나

이 컨테이너에 **yosys · iverilog · verilator · ngspice 는 있고 OpenROAD ·
klayout · magic 은 없다.** 없는 도구를 깔라고 사람에게 시키지 않는다
(저장소 규칙: "사람에게 설치를 시키지 마라").

그리고 그게 오히려 낫다. 상용 도구를 부르면 안이 안 보여서 **"돌렸다" 말고는
잴 것이 없다.** 직접 지으면 단계마다 수가 나오고, 그 수를 `tests/test_lab.py`
가 다시 잰다 — 이 저장소가 교재에서 지키는 규율을 실습에서도 지킬 수 있다.

흐름은 상용 도구를 **끼워 넣을 수 있게** 갈라 두었다. `se/place.py` 를
OpenROAD 호출로 바꿔도 뒤 단계는 그대로 돈다.

## 라이브러리는 손으로 적지 않았다

`lab/lib/se10.lib` 는 `lab/se/mklib.py` 가 **RC 모형 하나에서 계산해** 낸다.

```
지연 = 0.69·R·(C자체 + C부하) + 0.5·입력천이,   R = R단위/d,  C자체 = d·p·C단위
R단위 = 8 kΩ,  C단위 = 2 fF   ->   FO4 = 55.2 ps   ->   180 nm 언저리, VDD 1.8 V
자리(SITE) 0.660 × 5.040 µm   (강의 화면의 LEF 그대로)
```

고치려면 `.lib` 가 아니라 **모형**을 고치고 `python3 lab/se/mklib.py` 를 돌린다.

## 여기서 일부러 망가뜨려 볼 것

교안의 결론이 진짜인지 확인하는 가장 빠른 길이다.

1. `se/floorplan.py` 의 `점유율` 을 0.95 로 → 합법화가 터진다
2. `se/place.py` 의 `밀도세기` 를 0.1 로 → 전역 HPWL 은 좋아지고 합법 뒤는 나빠진다
3. `se/dv.py` 의 스코어보드에서 done 횟수 점검을 빼면 → 변이 m3 가 빠져나간다
4. `lab/rtl/dsp_top.v` 를 손으로 고치면 → 기준과 달라져 `test_lab.py` 가 빨개진다

## 이 실습이 **못** 하는 것 (교안 T23.3 과 같은 목록)

- 상용 P&R 이 없다 — 배치·배선·CTS 는 교육용 구현이고 절대 품질은 비교 대상이 아니다
- 추출이 한 가지다 — Fmax 가 37 % 떨어지는 수에 **독립 대조가 없다**
- DRC·LVS 가 없다 — 제조 가능성은 아무것도 주장하지 못한다
- 고착고장만 — 천이·브리징 고장은 안 돌린다
- 무작위 ATPG 만 — 남은 고장은 결정론적 ATPG 가 있어야 잡힌다
- 전력이 가정이다 — DV 가 아는 토글률이 플로어플랜으로 **아직 안 넘어간다**
