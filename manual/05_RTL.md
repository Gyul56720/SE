> **끝나면**: `verilator --lint-only -Wall` 경고 0.

---

> **먼저**: [13_설계주의점.md](13_설계주의점.md) 를 한 번 읽는다.
> 거기 있는 여덟 자리가 IP 통합 실패의 대부분이고, **다섯 개가 알고리즘이
> 아니라 경계(클럭·리셋·핸드셰이크·폭) 문제**다. RTL 을 쓰고 나서 읽으면
> 다시 쓰게 된다.

## 시작은 뼈대를 복사하는 것이다

```bash
cd /home/user/SE
mkdir -p work/rtl
cp manual/템플릿/rtl/block.v    work/rtl/<블록이름>.v
cp manual/템플릿/rtl/block_tb.v work/rtl/<블록이름>_tb.v
```

> **파일 이름 = 모듈 이름.** 파일 안의 `module block` 도 같이 바꾼다.
> verilator 의 `DECLFILENAME` 이 요구하고, 모든 빌드 도구가 이 규칙을 가정한다.

뼈대에는 **돌아가는 최소 예제**(`y = 포화(2x)`)가 들어 있다. 복사하자마자
06단계 검증이 통과한다. 거기서 알고리즘만 갈아 끼우면 된다 —
**빈 파일에서 시작하지 않는 것**이 요점이다.

## 늘 지킬 열 줄

이 열 개는 예외가 없다. 아홉 개는 `verilator -Wall` 이 자동으로 잡는다.

| # | 규칙 | 안 지키면 |
|---|---|---|
| 1 | 순차 논리는 `<=`, 조합 논리는 `=`. **섞지 않는다** | 평가 순서에 따라 결과가 달라진다(경주) |
| 2 | 한 신호는 **한 always 블록**에서만 구동 | 시뮬에서 `x`, 실리콘에서 단락 |
| 3 | 조합 블록은 **모든 갈래를 채운다** | 래치가 생긴다 |
| 4 | 부호 있으면 `signed` 를 **반드시** 적는다 | 입력의 절반(음수)에서 틀린다 |
| 5 | 연결 `{}` 결과는 unsigned → `$signed()` 로 감싼다 | 위와 같음 |
| 6 | `generate` 블록에 **이름**을 붙인다 | 루프를 추가하면 계층 이름이 전부 밀린다 |
| 7 | 포트는 **이름으로** 잇는다 (`.clk(clk)`) | 포트 추가 시 조용히 어긋난다 |
| 8 | 한 파일에 한 모듈, 파일명 = 모듈명 | 도구가 못 찾는다 |
| 9 | `casex` 금지. `casez` 또는 명시 비교 | 합성 전후 동작이 달라진다 |
| 10 | 폭을 **전부** 적는다. 매직 넘버 대신 `parameter` | 네 군데 중 세 군데만 고치게 된다 |

### 4번과 5번을 따로 강조하는 이유

```verilog
logic        [7:0] p = 8'hFF;   // 255 로 읽힌다
logic signed [7:0] q = 8'hFF;   // -1 로 읽힌다
```

**같은 비트, 다른 답.** 그리고 경고가 없다. 설계는 합성되고 시뮬도 돌고,
**입력이 음수인 절반에서만** 틀린다. 양수만 넣는 directed 테스트로는 절대 안 잡힌다.

그리고 함정 하나 더: **연결 `{}` 의 결과는 안에 뭐가 들었든 unsigned 다.**

```verilog
wire signed [8:0] a0 = {x0[7], x0} + {x3[7], x3};          // 틀렸다
wire signed [8:0] a0 = $signed({x0[7], x0}) + $signed({x3[7], x3});  // 맞다
```

SystemVerilog 에서 가장 흔한 조용한 버그 중 하나다.
**식에 unsigned 가 하나라도 섞이면 식 전체가 unsigned 가 된다.**

## 순서: 작게 만들고 자주 돌린다

하루에 한 번 큰 덩이를 쓰지 않는다. **10~30분마다** 이 고리를 돈다.

```bash
cd work/rtl
verilator --lint-only -Wall --top-module <모듈> <모듈>.v   # 1초
iverilog -g2012 -o sim.out <모듈>_tb.v <모듈>.v && vvp sim.out
```

lint 가 1초이므로 **저장할 때마다** 돌려도 된다. 시뮬에서 찾을 결함의
상당수를 lint 가 1초에 잡는다.

---

## 조합 고리를 만들지 않는다 (back-pressure 를 쓸 때)

valid/ready 를 쓰면 반드시 지킬 것 하나:

> **`in_ready` 가 `in_valid` 에 조합으로 의존하면 안 된다.**

어기면 두 블록을 이었을 때 `A.ready → B.valid → B.ready → A.valid` 로
고리가 닫힌다. 합성이 안 되거나 시뮬이 멈춘다.

해법은 **skid buffer** — 레지스터 한 단을 끼워 고리를 끊는다.
처음이면 back-pressure 없는 스펙(`valid` 만)으로 시작하는 것을 권한다.

## lint 경고 읽는 법

| 경고 | 뜻 | 대개의 원인 |
|---|---|---|
| `WIDTHEXPAND` / `WIDTHTRUNC` | 폭이 암묵적으로 바뀐다 | **가장 중요.** 조용한 잘림은 전부 여기 |
| `UNUSEDSIGNAL` | 안 쓰는 신호/비트 | 배선 실수이거나, 의도한 버림 |
| `LATCH` | 조합 블록이 갈래를 안 채웠다 | 거의 항상 실수 |
| `MULTIDRIVEN` | 두 곳에서 구동 | 시뮬 `x`, 실리콘 단락 |
| `BLKSEQ` | 순차에 `=` 를 썼다 | 경주 |
| `DECLFILENAME` | 파일명 ≠ 모듈명 | 이름을 맞춘다 |
| `GENUNNAMED` | generate 에 이름이 없다 | `begin : gen_xxx` |

### 의도한 경고를 끄는 법

정말로 의도한 것이면 **그 줄에만** 끄고 **왜인지 적는다.**

```verilog
// acc[6:0] 은 일부러 안 쓴다 -- Q3.14 를 Q1.7 로 내릴 때 버리는 소수 7비트다.
/* verilator lint_off UNUSEDSIGNAL */
wire signed [16:0] acc = a0 * 8'sd111 + a1 * 8'sd111;
/* verilator lint_on UNUSEDSIGNAL */
```

**파일 전체나 경고 종류 전체를 끄지 않는다.** 그러면 나중의 진짜 배선
실수까지 같이 묻힌다. 끄는 것과 이유를 적는 것은 **한 동작**이다.

## 막히면

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| `syntax error` near `always_ff` | `-g2012` 없음 | 붙인다 |
| 출력이 계속 `x` | 리셋이 안 걸렸거나 초기화 안 됨 | 리셋 절을 본다. 극성 확인 |
| 음수 입력에서만 틀림 | `signed` 누락, 또는 `{}` 가 unsigned | 4·5번 규칙 |
| 큰 입력에서만 틀림 | 중간 폭이 좁다 | 8+8=9비트. 폭을 한 줄씩 |
| 첫 줄만 틀림 | 리셋 직후 첫 입력을 놓쳤다 | 리셋 뒤 여유 클럭 |
| 전부 틀림 | 리셋 극성이 반대 | 스펙 8절과 맞춘다 |
| 시뮬이 안 끝난다 | `while` 탈출 조건, 또는 조합 고리 | `$finish` 경로 확인 |
| `틀림` 수가 벡터 수와 같다 | 출력을 한 클럭 일찍/늦게 잰다 | TB 의 `@(posedge clk)` 위치 |
