## "틀림 0" 은 아직 정보가 아니다

`틀림 0` 이 뜻하는 것은 둘 중 하나다:

1. RTL 이 맞다
2. **검사가 안 돈다**

둘을 구분하기 전까지 `틀림 0` 은 정보가 아니다. 이 단계는 그 구분을 한다.

네 가지를 순서대로 한다. 뒤로 갈수록 강하다.

| # | 검사 | 답하는 질문 | 시간 |
|---|---|---|---|
| ① | **자해검사** | 이 비교가 틀린 것을 잡기는 하나? | 1분 |
| ② | **경계·자극 점검** | 밟아야 할 곳을 밟았나? | 30분 |
| ③ | **처리량 검사** | 값은 맞는데 느려지지 않았나? | 30분 |
| ④ | **변이 점수** | 검사가 **문다**는 것을 수로 | 1~2시간 |

## ① 자해검사 — 가장 싸고 가장 중요하다

정답을 일부러 한 줄 망가뜨려, 검사가 **반드시 빨개지는지** 본다.

```bash
cd work/rtl
cp vec.txt 정답백업.txt
awk 'NR==7{$2=$2+1} 1' 정답백업.txt > vec.txt     # 7번째 줄 정답을 1 틀리게
vvp sim.out
cp 정답백업.txt vec.txt                            # 반드시 되돌린다
```

* `틀림 1` 이상 → **통과.** 이제 앞의 `틀림 0` 이 뜻을 가진다.
* `틀림 0` → **검사가 DUT 를 안 본다.** 앞의 모든 결과를 버린다.

> `틀림 0` 이 나오는 흔한 원인: 시뮬을 `vec.txt` 가 없는 디렉터리에서
> 돌렸다 / TB 가 파일을 못 읽고 조용히 0줄 읽었다 / 비교문이 항상 참이다.

**이것을 자동으로 돌게 만든다.** 사람이 기억하는 절차는 반드시 잊힌다.

```bash
cat > 검증.sh <<'EOF'
#!/usr/bin/env bash
# 검증.sh -- 회귀 + 자해검사를 한 번에.  자해검사가 안 물면 **실패로 낸다.**
set -u
N=${1:-400}
SEED=${2:-1}
../model/golden vec "$N" "$SEED" > vec.txt || exit 2
iverilog -g2012 -o sim.out *_tb.v $(ls *.v | grep -v '_tb\.v$') || exit 2

GOOD=$(vvp sim.out | grep -oE "틀림 [0-9]+" | head -1 | grep -oE "[0-9]+")
cp vec.txt .good.txt
awk 'NR==7{$2=$2+1} 1' .good.txt > vec.txt
HURT=$(vvp sim.out | grep -oE "틀림 [0-9]+" | head -1 | grep -oE "[0-9]+")
cp .good.txt vec.txt; rm -f .good.txt

echo "회귀 틀림 $GOOD"
echo "자해검사 틀림 $HURT"
if [ "$GOOD" != "0" ]; then echo "실패: 회귀가 틀렸다"; exit 1; fi
if [ "$HURT" = "0" ]; then echo "실패: **자해검사가 안 문다 -- 검사가 DUT 를 안 본다**"; exit 1; fi
echo "통과"
EOF
chmod +x 검증.sh && ./검증.sh
```

## ② 자극이 밟아야 할 곳을 밟았나

무작위 자극은 경계를 거의 안 밟는다. **밟아야 할 곳을 목록으로 적고**
자극에 강제로 넣는다.

| 종류 | 예 | 안 밟으면 |
|---|---|---|
| 값 경계 | 최대, 최소, 0, ±1 | 포화 논리를 지워도 통과한다 |
| 길이 경계 | 길이 1, 2, 최대 | 마지막 원소 처리가 틀려도 통과한다 |
| 상태 경계 | 리셋 직후, 오버플로 직후 | 초기화 결함을 놓친다 |
| **놀고 있는 구간** | `valid=0` 이 연속 | `valid` 를 가짜로 띄우는 결함을 놓친다 |
| 연속 동작 | 쉼 없이 N개 | 이월(carry) 결함을 놓친다 |

> **실측**: `valid=0` 구간을 한 번도 안 밟은 테스트벤치가 있었다.
> `out_valid <= valid & ~err` 를 `|` 로 바꾼 변이가 **그대로 통과했다** —
> 노는 사이클에 출력이 유효하다고 거짓말하는 결함인데, 노는 사이클을
> 아예 안 봤기 때문이다. 뼈대 TB 가 노는 사이클을 관찰하는 이유다.

확인하는 법 — 골든모델이 **몇 가지 값을 냈는지** 센다:

```bash
../model/golden vec 2000 1 | awk '{print $2}' | sort -u | wc -l
```

출력 가짓수가 한두 개면 자극이 얕은 것이다. 스펙상 가능한 출력 범위와 비교한다.

## ③ 처리량 — 값만 보는 회귀는 느려지는 결함을 못 잡는다

**실측**: `s_ready = ~(m_valid & ~m_ready)` 의 `&` 를 `|` 로 바꾼 변이가
회귀를 통과했다. 나오는 값은 **전부 맞고** 처리량만 1.45배 나빠졌다.

뼈대 TB 는 `cycles.txt` 에 사이클 수를 적는다. 한계를 정해 검사한다.

```bash
# 성한 판에서 씨앗 셋으로 재고, 20% 여유를 준다
for s in 1 7 99; do
  ../model/golden vec 1000 $s > vec.txt && vvp sim.out >/dev/null
  echo "씨앗 $s: $(cat cycles.txt) 사이클"
done
```

흩어짐이 몇 % 안이면 그 값에 **1.2배** 를 곱해 한계로 삼는다.

> **한계는 재서 정한다.** 어림으로 크게 잡으면 변이가 그대로 통과한다 —
> 실제로 한 번 5 사이클/바이트로 어림잡았다가 변이(3.16)를 놓쳤고,
> 재서 2.6 으로 조인 뒤에야 잡혔다.

## ④ 변이 점수 — 검사가 문다는 것을 수로

RTL 을 **일부러 조금씩 망가뜨려**(`&`→`|`, `<`→`<=`, `+`→`-`),
검사가 몇 %를 잡는지 센다. 이 저장소에 도구가 있다.

```bash
cd /home/user/SE/edu/agent
python3 -c "
import sys, importlib.util as iu
sys.path.insert(0, '/home/user/SE/edu/agent')
spec = iu.spec_from_file_location('blk', '<내 블록의 block.py 경로>')
b = iu.module_from_spec(spec); spec.loader.exec_module(b)
import mutscore
m = mutscore.점수(b, 시행=1200, 씨앗들=(1,7), 최대변이=40, 시간제한=120)
print({k:v for k,v in m.items() if k!='탈출'})
for e in m.get('탈출', []): print('탈출:', e['규칙'], '줄', e['줄번호'], e['후'][:70])
"
```

| 점수 | 뜻 |
|---|---|
| 90% 이상 | 좋다 |
| 70~90% | 탈출을 하나씩 본다 |
| 70% 미만 | **자극이 얕다.** 벡터를 늘리지 말고 **종류**를 늘린다 |

### 탈출을 만났을 때

탈출(안 잡힌 변이)은 둘 중 하나다.

1. **진짜 구멍** → 자극이나 관찰을 고친다
2. **등가 변이** → 바꿔도 같은 함수다. 이건 못 잡는 게 맞다

등가 변이는 **증명하고 기록한다.** 조용히 빼면 안 된다.

> 예: `(lo5==17)|(lo5==18)` 를 `^` 로 바꾼 변이. `lo5` 는 한 값만 가지므로
> 두 항이 배타적이고, 배타적이면 OR 와 XOR 가 같다. 주장으로 두지 않고
> **입력 64가지 전부에서 차이 0** 임을 확인한 뒤 이유와 함께 적었다.

`판정된탈출.py` 를 **DUT 파일 옆에** 둔다:

```python
판정 = [
    {"규칙": "OR / XOR", "줄번호": 98, "파일": "block.v",
     "이유": "두 항이 배타적이라 OR 와 XOR 가 같다. 입력 64가지 전수 확인, 차이 0."},
]
```

## 막히면

| 증상 | 뜻 | 하는 법 |
|---|---|---|
| 자해검사가 `틀림 0` | 검사가 DUT 를 안 본다 | 디렉터리·파일 읽기·비교문을 본다 |
| 변이점수 50% 미만 | 자극이 얕다 | 벡터 수가 아니라 **종류**를 늘린다 |
| 탈출이 전부 한 줄에 | 그 줄이 관찰되지 않는다 | 그 신호를 출력에 실어라 |
| 처리량 한계를 못 정하겠다 | 재지 않았다 | 씨앗 셋으로 재고 ×1.2 |
| 회귀는 통과, 통합에서 실패 | 배선·리셋·핸드셰이크 | C++ 로는 못 보는 것들. 스펙 4·7·8절 |
| 변이 도구가 TB 를 망가뜨린다 | DUT 만 대상이어야 한다 | `소스들()[0]` 이 DUT 인지 확인 |
