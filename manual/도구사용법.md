# 도구 사용법 — 이 저장소에 있는 것을 어떻게 쓰나

> **"뭐가 있는지는 알겠는데 어떻게 쓰는지 모르겠다"** 에 답하는 문서.
> 각 도구마다 **무엇 / 언제 / 정확한 명령 / 나오는 것 / 읽는 법** 다섯 칸이다.
> 여기 있는 명령은 전부 실제로 돌려 확인한 것이다.

---

## 0. 일단 이것부터 (3분)

```bash
cd ~/SE && git pull origin main      # 받은 자리가 다르면 그 자리로
bash manual/지금어디.sh
```

이 한 줄이 **지금 어디까지 왔고 다음에 뭘 할지**를 답한다.
모르겠으면 언제나 이것부터 친다.

아무 도구도 안 깔렸으면 0단계가 전부 `[ ]` 일 것이다.
→ [`00_설치.md`](00_설치.md) 로 간다. 30분이면 된다.

## 도구 지도 — 무엇이 무엇을 위한 것인가

```
   ┌─ 지금 어디? ──────────  manual/지금어디.sh
   │
   ├─ 만들 때 ──────────────  edu/house/regmap.py     레지스터 맵 → RTL·C·문서
   │                          edu/sch.py              회로도·파형 그리기
   │
   ├─ 검사할 때 ────────────  edu/agent/harness.py    골든모델 대 RTL
   │                          edu/agent/mutscore.py   검사가 무는가 (변이 점수)
   │                          edu/agent/agent.py      24시간 자동 검증
   │
   ├─ 재고 합성할 때 ───────  edu/house/synth.sh      lint + 합성 + 주파수
   │
   ├─ 팔 수 있나 볼 때 ─────  edu/house/release.sh    납품 관문 전체
   │
   ├─ 밀기 전에 ────────────  scripts/precheck.sh     HEAD 에서 전체 검사
   │                          scripts/pr_merged.sh    머지됐는지 조회

   └─ 책 만들 때 ───────────  edu/buildE.py           교재(이론+실무+코드)
                              edu/buildT.py           이론서만
```

## 1. `manual/지금어디.sh` — 지금 어디까지 왔나

| | |
|---|---|
| **무엇** | 저장소 상태를 읽어 진행도를 답한다 |
| **언제** | 매 세션 첫 명령. 뭘 할지 모를 때 |

```bash
bash manual/지금어디.sh
```

**나오는 것**

```
── 0단계  연장이 있는가 (manual/00_설치.md) ──
  [o] verilator (lint + 빠른 시뮬)
  [ ] yosys     (합성)
...
  통과 6 개 / 남은 것 10 개
  다음에 할 일: 위에서 [ ] 가 붙은 맨 위 한 줄.
```

**읽는 법**: `[ ]` 가 붙은 **맨 위 한 줄**만 본다. 괄호 안 문서를 연다.
여러 개를 동시에 하지 않는다.

## 2. `edu/house/synth.sh` — lint · 합성 · 주파수

| | |
|---|---|
| **무엇** | verilator lint → yosys 합성 → nextpnr 배치배선을 한 번에 |
| **언제** | RTL 을 고친 뒤 면적·주파수를 알고 싶을 때 |

```bash
# 면적까지 (몇 초)
bash edu/house/synth.sh edu/model/fir4_hand.v fir4_hand

# 주파수까지 (몇 분)
bash edu/house/synth.sh edu/model/fir4_hand.v fir4_hand --pnr
```

**나오는 것**

```
== 1. verilator lint ==
   경고+오류 0
   lint rc=0
== 3. yosys iCE40 매핑 ==
   SB_CARRY   48
   SB_DFFSR    9      ← 플립플롭 수. 세어서 맞아야 한다
   SB_LUT4   200      ← 이것이 면적
```

**읽는 법**
- **플립플롭 수를 제일 먼저** 본다. 예상과 다르면 의도 안 한 상태가 생긴 것이다.
- `SB_LUT4` 가 면적이다. 2단계의 `Number of cells` 는 **면적이 아니다**(기술 독립 게이트).
- `ERROR ... FAIL at 300 MHz` 는 고장이 아니라 "300 에 못 미쳤다" 는 뜻.

**조절하는 것**

```bash
PNR_SEED=2 bash edu/house/synth.sh ...    # 배치 씨앗 (셋을 돌려 평균)
PNR_FREQ=50 bash edu/house/synth.sh ...   # 목표 주파수
SYNTH_OUT=/tmp/로그 bash ...               # 로그 둘 자리
```

> **주파수를 제대로 재려면 타이밍 껍데기가 필요하다.** 안 씌우면 10배 틀린 수가
> 나온다. [`07_합성과타이밍.md`](07_합성과타이밍.md) 참고.

## 3. `edu/agent/harness.py` — 골든모델 대 RTL

| | |
|---|---|
| **무엇** | C++/파이썬 정답과 Verilog 를 같은 자극으로 돌려 비교 |
| **언제** | 블록 하나를 회귀할 때 |

**파이썬에서 부른다** (스크립트가 아니라 모듈이다):

```bash
cd edu/agent && python3 -c "
import sys, importlib.util as iu
sys.path.insert(0, '.')
spec = iu.spec_from_file_location('blk', 'blocks/enc8b10b/block.py')
b = iu.module_from_spec(spec); spec.loader.exec_module(b)

import harness
r = harness.잰다(b, 시행=3000, 씨앗=7)
print(r.dict())
print('자해검사:', harness.자해검사(b, 시행=300, 씨앗=999))
"
```

**나오는 것**

```
{'이름': 'enc8b10b', '시행': 3000, '틀림': 0, '서로다른출력': 519,
 '성능실패': None, '쓸모있나': True}
자해검사: (True, None)
```

**읽는 법**
- `틀림 0` 만 보면 안 된다. **`자해검사: (True, None)` 이 같이 나와야** 그 0 이 뜻을 가진다.
- `서로다른출력` 이 1 이면 자극이 아무것도 안 본 것이다.
- `쓸모있나: False` 면 결과를 버린다.

## 4. `edu/agent/mutscore.py` — 검사가 **무는가**

| | |
|---|---|
| **무엇** | RTL 을 조금씩 망가뜨려(`&`→`|` 등) 검사가 몇 %를 잡는지 센다 |
| **언제** | 회귀가 통과한 뒤. "이 검사를 믿어도 되나" 를 물을 때 |

```bash
cd edu/agent && python3 -c "
import sys, importlib.util as iu
sys.path.insert(0, '.')
spec = iu.spec_from_file_location('blk', 'blocks/enc8b10b/block.py')
b = iu.module_from_spec(spec); spec.loader.exec_module(b)

import mutscore
m = mutscore.점수(b, 시행=1200, 씨앗들=(1,7), 최대변이=40, 시간제한=120)
print({k:v for k,v in m.items() if k != '탈출'})
for e in m.get('탈출', []):
    print('탈출:', e['규칙'], '줄', e['줄번호'], e['후'][:60])
"
```

**나오는 것**

```
{'변이수': 16, '잡힘': 16, '안잡힘': 0, '점수': 1.0, '등가로판정됨': 5}
```

**읽는 법**

| 점수 | 뜻 |
|---|---|
| 90% 이상 | 좋다 |
| 70~90% | 탈출을 하나씩 본다 |
| 70% 미만 | **자극이 얕다.** 벡터 수가 아니라 **종류**를 늘린다 |

`탈출` 은 안 잡힌 변이다. 둘 중 하나다:
1. **진짜 구멍** → 자극이나 관찰을 고친다
2. **등가 변이**(바꿔도 같은 함수) → **증명해서 기록**한다. 조용히 빼지 않는다

등가로 판정하려면 DUT 파일 **옆에** `판정된탈출.py` 를 둔다:

```python
판정 = [
    {"규칙": "OR / XOR", "줄번호": 98, "파일": "block.v",
     "이유": "두 항이 배타적이라 OR 와 XOR 가 같다. 입력 64가지 전수 확인, 차이 0."},
]
```

## 5. `edu/agent/agent.py` — 24시간 자동 검증

| | |
|---|---|
| **무엇** | 블록들을 계속 회귀하고, 실패하면 고쳐 보고, 원장에 적는다 |
| **언제** | 밤새 돌려 두고 싶을 때 |

```bash
# 보기만 (파일을 안 고친다) -- 처음에는 이렇게
python3 edu/agent/agent.py --시간 1 --시행 2000

# 고친 것을 실제로 파일에 쓴다
python3 edu/agent/agent.py --시간 8 --적용

# 블록을 골라서
python3 edu/agent/agent.py --블록 enc8b10b crc32_stream --시간 2
```

| 깃발 | 뜻 |
|---|---|
| `--시간 N` | 몇 시간 돌릴지 |
| `--시행 N` | 한 바퀴에 벡터 몇 개 |
| `--블록 ...` | 고른 블록만 |
| `--적용` | **편집을 실제로 파일에 쓴다** (없으면 보고만) |
| `--쉼 N` | 바퀴 사이 쉬는 초 |

**밤새 돌리려면** (셸이 닫혀도 안 죽게):

```bash
mkdir -p logs
setsid nohup python3 edu/agent/agent.py --시간 8 --적용 \
       > logs/agent.log 2>&1 < /dev/null &
disown
pgrep -af "agent.py"          # 살아 있는지 **확인부터** 한다
```

> `ps -p $!` 로 확인하면 안 된다. `setsid` 가 fork 하므로 `$!` 는 이미 끝난
> 래퍼의 PID 다. `pgrep -af agent.py` 를 쓴다. 패턴에 **한글을 넣지 않는다**
> (안 맞는다).

**상태 보기**

```bash
bash edu/agent/status.sh
```

```
== 프로세스 ==       (돌고 있나)
== 상태 ==           (status.json)
== 최근 빨간불 ==    (원장)
```

## 8. `edu/sch.py` — 회로도·파형 그리기

| | |
|---|---|
| **무엇** | 게이트·트랜지스터·파형·블록도를 SVG 로 |
| **언제** | 문서에 그림이 필요할 때 |

```bash
python3 -c "
import sys; sys.path.insert(0, 'edu')
import sch

# 파형
open('/tmp/파형.svg','w').write(sch.파형([
    ('clk', '_^_^_^_^'),
    ('d',   '__^^__^^'),
    ('q',   '___^^__^'),
]))

# 블록도
open('/tmp/블록.svg','w').write(sch.블록도(
    [['ADC','FFE','슬라이서']], 설명={'FFE':'우리 IP'}))

# 완성된 회로도
open('/tmp/낸드.svg','w').write(sch.씨모스낸드())
print('냈다')
"
```

**파형 글자**: `_` 낮음 · `^` 높음 · `x` 모름

**이미 만들어진 그림** (인자 없이 부른다):
`씨모스인버터()` `씨모스낸드()` `전가산기()` `동기화기()` `다중비트깨짐()`
`리셋동기화기()` `조합고리()` `스키드버퍼()` `폭성장()` `파이프라인전후()`
`시스템아키텍처()`

**매뉴얼 그림을 다시 내려면**

```bash
python3 manual/그림만들기.py
```

> **SVG 글자에 마크다운(`**굵게**`)을 쓰지 않는다.** 별표가 화면에 그대로 보인다.
> 강조는 `굵게=True` 나 색으로 한다.

## 9. `scripts/precheck.sh` — 밀기 전에

| | |
|---|---|
| **무엇** | **HEAD 를 임시 워크트리로 꺼내** 거기서 검사한다 |
| **언제** | `git push` 하기 직전 |

```bash
bash scripts/precheck.sh            # 빠른 길 (몇 분)
bash scripts/precheck.sh --전부     # 전부 (6분+)
```

**왜 임시 워크트리인가**: 내 작업 디렉터리에는 `git add` 안 한 파일이 있어
검사가 초록을 낸다. **남이 받아 가는 것은 커밋된 나무뿐이다.**
이 저장소는 그 병을 다섯 번 앓았다.

**나오는 것**

```
빠른 검사 216 개 통과.
```

또는

```
**내가 깬 것 1 개** -- 밀지 마라
```

→ 이러면 **밀지 않는다.** 고치고 다시 돌린다.

## 디스코드에 물어보기 — 봇이 **교재를 열어 놓고** 답한다

물어보면 봇이 먼저 `textbook` 도구로 교재에서 근거 절을 꺼내고, 그 절을 보며
답한다. 기억으로 답하지 않는다.

```
준안정 상태 MTBF 는 어떻게 계산하고, 동기화기 두 단이면 언제 모자라?
클럭 도메인 넘길 때 그레이 코드를 왜 써? 다중 비트면 뭐가 깨지나?
DFE 를 언롤링하면 타이밍이 왜 풀리나? 탭 수와 면적은 어떻게 커지나?
고정소수점 비트폭을 어떻게 정해? 반올림 방식마다 뭐가 달라지나?
8b/10b 의 running disparity 규칙을 표까지 보여 줘
AXI 에서 outstanding 과 burst 가 처리량을 어떻게 정하나?
```

**한국어로 물어도 된다.** 교재는 영어인데 `edu/용어.py` 가 한국어 말을
영어 말로 바꿔서 찾는다(305개). 바꾸지 못한 말은 답 위에 그대로 적힌다 —
엉뚱한 답이 왔을 때 **왜 엉뚱한지** 바로 보인다.

### 답이 어떤 꼴로 오나 (여덟 칸)

1. 무엇을 묻는 것인지 · 재는 양의 이름
2. **지배식** — 기호마다 뜻과 단위, 어디서 온 식인지
3. 어디에 쓰나 (블록 · 흐름의 자리 · 사인오프 검사)
4. 언제 묶이나 (지배하는 영역 / 무시해도 되는 영역)
5. 어떻게 적용하나 — 따라서 다시 계산할 수 있는 수 하나
6. 산업 코드/제약 (SystemVerilog · SDC · Liberty · UPF · C++)
7. 여기서 틀린다 — 구체적인 고장 방식
8. **아직 안 밝혀진 것** — 잰 것과 주장만 한 것을 갈라서

### 안 덮는 주제는 안 덮는다고 말한다

교재가 못 덮는 자리가 있다(`edu/kb/빈자리.md` 에 적혀 있다 — SRAM 의
SNM, ESD 보호 등). 그 자리를 물으면 답 첫머리에 **"교재가 안 덮는다"**
가 먼저 뜨고, 제1원리로 답하되 그렇게 표시한다. 그 장을 쓰는 순간
`tests/test_kb.py` 가 빨개져서 목록을 고치게 한다.

### 여기서 직접 물어볼 수도 있다

```bash
python3 edu/kb.py --묻기 "준안정 MTBF"     # 근거 절 다섯 개
python3 edu/kb.py                           # 색인 크기·지은 때
```

교재 장을 새로 쓰면 색인을 다시 짓는다(2분 30초, **이 저장소 밖 자료가
필요하므로 VM 이 아니라 개발 자리에서**):

```bash
python3 edu/kb.py --짓기 && git add edu/kb && git commit -m "교재 색인 다시"
```

안 지으면 `tests/test_kb.py::test_새_장을_쓰고_색인을_안_지으면_걸린다`
가 빨개진다 — 새 장이 봇에게 영영 안 보이는 것을 막는다.
