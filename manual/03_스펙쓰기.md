## 스펙은 설명서가 아니라 계약서다

초보가 쓰는 "스펙"은 대개 만들고 나서 쓴 **설명서**다. 그건 스펙이 아니다.

> **스펙 = 다 만들었을 때 "맞다"를 판정할 기준을, 만들기 전에 적은 것.**

그래서 스펙의 모든 줄은 **검사 가능**해야 한다.

| 스펙이 아닌 것 | 스펙인 것 |
|---|---|
| "빠르다" | "1 클럭에 1 바이트. back-pressure 없음" |
| "정확하다" | "y = sat₈((Σ h[i]·x[n−i]) >> 7). 입력 2³² 가지 전수 대조" |
| "AXI 를 지원한다" | "AXI4-Stream slave. tvalid/tready/tlast. tkeep 없음" |
| "리셋된다" | "동기 리셋, **active high**, 최소 4 클럭 유지" |
| "작다" | "iCE40 HX8K 에서 200 LUT4 이하" |

오른쪽은 전부 **기계로 확인할 수 있다.** 왼쪽은 말다툼이 된다.

## 반드시 들어가야 하는 12줄

빠뜨리면 반드시 나중에 문제가 되는 것들이다. 각각 왜인지 적는다.

| # | 항목 | 안 적으면 생기는 일 |
|---|---|---|
| 1 | **함수** (수식 또는 알고리즘) | 검증의 기준이 없다 |
| 2 | **입력** 폭·부호·형식·단위 | 모델과 RTL 이 다른 것을 계산한다 |
| 3 | **출력** 폭·부호·포화/wrap | wrap 이면 부호가 뒤집혀 다음 블록이 정반대로 판단한다 |
| 4 | **인터페이스** 프로토콜 | 고객 SoC 에 안 붙는다 |
| 5 | **처리량** (클럭당 몇 개) | 값만 맞고 느린 블록이 나온다. 회귀가 못 잡는다 |
| 6 | **지연** (입력→출력 클럭 수) | 고객이 파이프라인 계획을 못 세운다 |
| 7 | **클럭** 개수·엣지 | CDC 가 필요한지 아무도 모른다 |
| 8 | **리셋** 동기/비동기, 극성, 길이 | **가장 흔한 통합 실패**. 아래 참고 |
| 9 | **오류 동작** | 잘못된 입력에 조용히 이상한 값을 낸다 |
| 10 | **목표 면적·주파수** | "충분히 작은지" 판정을 못 한다 |
| 11 | **검증 방법과 통과 기준** | 언제 끝났는지 모른다 |
| 12 | **범위 밖** (안 만드는 것) | 고객이 있는 줄 알고 산다 |

### 8번(리셋)을 따로 강조하는 이유

실제로 겪은 것:

> HLS 도구가 낸 RTL 을 직접 쓴 테스트벤치에 붙였더니 `done` 이 **한 번도
> 안 왔다.** 400개 벡터가 400개 다 실패했다. 원인은 **리셋 극성**이었다 —
> 도구 기본값이 active **low** 인데 내 테스트벤치는 active **high** 였다.

극성 한 글자다. 그런데 증상은 "블록이 통째로 안 돈다" 라 원인이 멀어 보인다.
**스펙에 "동기, active high, 최소 4클럭" 이라고 적혀 있었으면 5분에 끝날 일**이었다.

## 함정: 처리량과 지연을 헷갈리지 않는다

| | 뜻 | 예 |
|---|---|---|
| **지연(latency)** | 한 입력이 출력으로 나오기까지 클럭 수 | 3 |
| **처리량(throughput)** | 클럭당 몇 개를 삼킬 수 있나 | 1/clk |

둘은 **독립**이다. 지연 10, 처리량 1/clk 인 파이프라인이 흔하다.
스펙에 **둘 다** 적는다. 하나만 적으면 고객이 다른 하나를 가정한다.

그리고 **처리량은 회귀에 넣는다.** 값만 보는 회귀는 느려지는 결함을
절대 못 잡는다 — 실제로 `s_ready` 의 `&` 를 `|` 로 바꾼 변이가
"출력 값은 전부 맞고 1.45배 느린" 블록을 만들었는데 회귀가 통과했다.

## 할 일

### 1. 템플릿을 복사한다

```bash
cd /home/user/SE
mkdir -p work
cp manual/템플릿/스펙.md work/스펙.md
$EDITOR work/스펙.md
```

### 2. TODO 를 하나씩 없앤다

**모르면 모른다고 적지 말고, 정한다.** 스펙은 사실을 적는 문서가 아니라
**결정을 적는 문서**다. "리셋은 아마 비동기?" 가 아니라 "동기, active high" 로 정한다.
정한 것이 나중에 틀리면 그때 고치면 된다. 안 정하면 영원히 안 정해진다.

### 3. 목표 면적/주파수는 **범위**로 적는다

아직 아무것도 안 만들었으므로 정확한 수를 모른다. 그래서 이렇게 적는다:

```
목표: iCE40 HX8K 에서 LUT4 300 이하, 50 MHz 이상
근거: 비슷한 규모 블록(FIR 4탭)이 200 LUT4 / 47 MHz 였다
07단계에서 실측으로 이 줄을 갱신한다
```

07단계가 끝나면 **실측값으로 이 줄을 덮어쓴다.** 목표와 실측을 같은 칸에
두면 나중에 어느 쪽이 사실인지 모르게 된다.

- 리셋을 몇 클럭 넣어야 하나? 극성은?
- 입력을 매 클럭 넣어도 되나? 기다려야 하나?
- 입력을 넣고 몇 클럭 뒤에 결과를 읽나?
- 넘치는 입력을 주면 어떻게 되나?
- 이 블록이 **안 하는** 일은 무엇인가?

| 상황 | 하는 법 |
|---|---|
| 처리량을 모르겠다 | 일단 `1/clk` 로 정한다. 못 지키면 07단계에서 고친다 |
