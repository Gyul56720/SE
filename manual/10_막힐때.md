## A. 도구와 스크립트

### A1. 셸 스크립트가 한 줄도 안 돈다 {#a1}

```
/bin/bash: line 30: 파일=x: No such file or directory
/bin/bash: line 31: bad substitution
```

**원인**: 셸 변수 이름에 한글을 썼다. bash 는 식별자로
`[A-Za-z_][A-Za-z0-9_]*` 만 받는다. `파일=x` 는 **대입이 아니라 명령어**로
파싱된다.

**고치는 법**: 변수 이름을 전부 아스키로. `SRC`, `TOP`, `OUT`.

> **`bash -n` 은 이것을 안 잡는다.** 문법상으로는 "명령어 하나" 라 멀쩡하다.
> 실제로 이 저장소는 규칙을 문서에 적어 두고도 다시 물렸다.
> **셸 스크립트는 임시 디렉터리에서 실제로 돌려서 검사한다.**

### A2. `pgrep` 이 도는 프로세스를 못 찾는다 {#a2}

**원인 둘**:

1. **패턴에 한글이 들어갔다.** `/proc/<pid>/cmdline` 의 바이트를 로캘이
   못 읽어 `?????` 가 된다. 한글 패턴은 **영영 안 맞고**, 안 맞는 것은
   "없다" 로 읽힌다 → 도는 작업을 죽은 줄 알고 두 벌 띄운다.
2. **패턴이 자기 셸을 잡는다.** `pgrep -f "build.py"` 를 실행한 셸의
   명령줄에도 `build.py` 가 들어 있어, 무한히 자기를 찾는다.

**고치는 법**: PID 로 기다린다(`kill -0 <PID>`). 패턴을 써야 하면
**아스키만 든 토막**을 쓴다. 그리고 `pkill -f <패턴>` 은 조심한다 —
**자기 셸까지 죽인다**(실측: exit 144).

### A3. 도구 종료 코드가 141 {#a3}

**원인**: `| head` 로 받았다. head 가 파이프를 닫으면 도구가 SIGPIPE 로
죽고 141 이 된다. **통과했는지 실패했는지 알 수 없게 된다.**

**고치는 법**: 파일로 받고 나서 자른다.

```bash
verilator --lint-only -Wall --top-module M M.v > lint.log 2>&1
RC=$?
head -40 lint.log
echo "rc=$RC"
```

### A4. yosys 가 셀 수를 안 찍는다 {#a4}

**원인**: `-q` 를 붙였다. `stat` 출력까지 삼킨다.

**고치는 법**: `-q` 를 뺀다. 조용하게 만들려다 재려던 것을 잃는다.

> 관련 함정: `grep SB_LUT4` 로 세면 안 된다. yosys 가 셀 라이브러리를
> 읽으며 `Generating RTLIL representation for module \SB_LUT4` 같은 줄을
> 찍어서 **그것까지 센다.** `stat` 덩이 안에서만 본다:
> `awk '/=== M ===/{g=1} g'`

## B. 기능이 틀릴 때

### B1. 출력이 전부 틀리거나 전부 안 나온다 {#b1}

**가장 먼저 의심할 것: 리셋 극성.**

**실측**: HLS 도구가 낸 RTL 을 붙였더니 `done` 이 한 번도 안 왔다.
400개 벡터가 **400개 다 실패**했다. 도구 기본값이 active **low** 인데
테스트벤치는 active **high** 였다.

**고치는 법**: 스펙 8절과 RTL 과 TB 의 극성을 맞춘다. 셋 다.

> 증상이 "블록이 통째로 죽었다" 라 원인이 멀어 보인다. 그런데
> **전부 틀리는 것은 대개 배선/극성이고, 일부만 틀리는 것이 알고리즘이다.**
> 이 구분이 디버그 시간을 반으로 줄인다.

### B2. 첫 줄만 틀린다 {#b2}

**원인**: 리셋을 뗀 직후 첫 입력을 FSM 이 놓쳤다.

**실측**: 리셋 해제 후 한 클럭만 주었더니 **첫 벡터 하나만** `done` 이
안 왔다. 나머지 399개는 전부 맞았다.

**고치는 법**: 리셋 해제 뒤 여유 클럭을 준다 (`repeat (4) @(posedge clk);`).

> **하나만 틀리는 결함이 가장 비싸다.** "가끔 틀린다" 로 읽혀서
> 재현을 못 하고 몇 주를 먹는다.

### B3. 음수 입력에서만 틀린다 {#b3}

**원인 둘**:

1. `signed` 를 빠뜨렸다. `logic [7:0] q = 8'hFF` 는 **255**,
   `logic signed [7:0] q = 8'hFF` 는 **−1**. 같은 비트, 다른 답, 경고 없음.
2. **연결 `{}` 의 결과는 언제나 unsigned 다** — 안에 뭐가 들었든.

```verilog
wire signed [8:0] a0 = {x0[7], x0} + {x3[7], x3};                    // 틀렸다
wire signed [8:0] a0 = $signed({x0[7], x0}) + $signed({x3[7], x3});  // 맞다
```

**규칙**: 식에 unsigned 가 하나라도 섞이면 **식 전체가** unsigned 가 된다.

### B4. 큰 입력에서만 틀린다 {#b4}

**원인**: 중간 폭이 좁다. 8비트 둘을 더하면 **9비트**가 필요하다
(127+127 = 254).

**C++ 쪽 원인**: 정수 승격. `int8_t a=100, b=100; auto c = a+b;` 의
`c` 는 `int` 이고 **200** 이다. 모델은 안 넘치고 RTL 만 넘친다.

**고치는 법**: 넓은 폭에서 계산하고 **마지막에 한 번** 포화한다.
중간마다 자르면 조용히 틀린다.

### B5. 시뮬은 통과, 값이 가끔 다르다 {#b5}

**원인**: 자극을 넣는 엣지와 재는 엣지가 같다 → 경주.

**고치는 법**: 자극은 `negedge`, 관찰은 `posedge`.

```verilog
@(negedge clk);  in_data = x; in_valid = 1;
@(negedge clk);  in_valid = 0;
@(posedge clk);  // 여기서 잰다
```

## C. 검증이 약할 때

### C1. 자해검사가 안 문다 {#c1}

정답을 망가뜨렸는데 `틀림 0` 이 나온다. **검사가 DUT 를 안 보고 있다.**

| 원인 | 확인하는 법 |
|---|---|
| 시뮬을 `vec.txt` 없는 곳에서 돌렸다 | TB 가 파일 열기 실패를 찍는지 본다 |
| TB 가 0줄 읽고 조용히 끝났다 | `잰것 N` 의 N 이 0 인지 본다 |
| 망가뜨린 열이 비교에 안 쓰인다 | 다른 열을 망가뜨려 본다 |
| 비교문이 항상 참이다 | `!==` 인지 `!=` 인지 (4-state 는 `!==`) |
| **인클루드가 원본을 집었다** | 아래 참고 |

> **실측**: 헤더를 임시 디렉터리에 망가뜨려 복사하고 `-I<임시>` 를
> 앞에 붙였는데 **rc=0 (안 물림)** 이 나왔다. 원인은 `#include "x.h"` 가
> **그 파일이 있는 디렉터리를 먼저** 뒤지기 때문. 원본 헤더가 잡혔다.
> 고치는 법: **소스도 같이 임시 디렉터리로 복사**한다.

### C2. 변이 점수가 낮다 {#c2}

**벡터 수를 늘리지 않는다. 종류를 늘린다.**

| 탈출이 몰린 곳 | 대개의 원인 |
|---|---|
| 경계 처리 | 경계값을 자극에 안 넣었다 |
| `valid`/`ready` 논리 | **노는 사이클을 관찰 안 한다** |
| 리셋 경로 | 리셋을 한 번만 건다 |
| 특정 상태 | 그 상태에 못 들어간다 |

> **실측**: `out_valid <= valid & ~err` 를 `|` 로 바꾼 변이가 통과했다.
> 노는 사이클에 출력이 유효하다고 거짓말하는 결함인데,
> 테스트벤치가 `valid=0` 구간을 **한 번도 안 밟았다.**
> 노는 사이클 관찰 네 줄을 넣자 71.4% → 100%.

**등가 변이**(바꿔도 같은 함수)는 잡는 게 아니라 **증명하고 기록**한다.
`판정된탈출.py` 를 DUT 파일 **옆에** 둔다(변이 도구가 거기를 본다).

### C3. 회귀는 통과인데 느려졌다 {#c3}

**값만 보는 회귀는 느려지는 결함을 절대 못 잡는다.**

**실측**: `s_ready = ~(m_valid & ~m_ready)` 의 `&` 를 `|` 로 바꿨더니
나오는 값은 **전부 맞고** 처리량만 1.45배 나빠졌다. 회귀는 통과했다.

**고치는 법**: TB 가 사이클 수를 세어 `cycles.txt` 에 적고, 한계를 검사한다.
한계는 **재서** 정한다 — 씨앗 셋으로 재고 ×1.2.

> 어림으로 크게 잡으면 소용없다. 한 번 5 사이클/바이트로 잡았다가
> 변이(3.16)를 놓쳤고, 재서 2.6 으로 조인 뒤에야 잡혔다.

## D. 합성과 타이밍

### D1. 주파수가 비현실적으로 높다 / `Max frequency` 줄이 없다 {#d1}

**원인**: 타이밍 껍데기가 없다. nextpnr 은 **레지스터 사이 경로만** 잰다.

**실측**: 껍데기 없이 **455 MHz**, 씌우고 **47 MHz**. 10배 차이.
455 는 아무 상관 없는 짧은 경로의 수였고, **씨앗을 바꿔도 안정적이었다.**

> **재현되는 수가 맞는 수는 아니다.** 주파수를 말할 때는 언제나
> "어느 레지스터에서 어느 레지스터까지인가" 를 답할 수 있어야 한다.

**증상으로 알아채는 법**: 레지스터를 **더 넣었는데 주파수가 떨어지면**
거의 확실히 이 문제다. 레지스터가 늘어 느려질 수는 없다.

### D2. `Unable to find a placement location` {#d2}

**원인**: 핀이 모자라다. `up5k/sg48` 은 I/O 가 39개뿐이다.

**고치는 법**: `--hx8k --package ct256`.
**이것은 설계 품질 문제가 아니다.**

### D3. 면적이 예상의 4배 {#d3}

**C++/HLS 에서 왔다면**: 인자 타입이 `int` 다. C 의 정수 승격이
8비트 신호를 **32비트 데이터패스**로 만든다.

**실측**: 같은 알고리즘인데 인자를 `int` → `signed char` 로 바꾸자
**1218셀 → 338셀 (3.6배)**. 포트 폭이 32 → 8 로 줄었다.

**손으로 쓴 RTL 이라면**: 중간 폭이 넓거나, 계수를 상수가 아닌
포트로 받아 진짜 곱셈기가 박혔다.

## E. HLS (선택)

### E1. pragma 를 거부한다 {#e1}

```
rc=11  Loop pipelining pragma not supported
```

**원인**: pragma 방언은 도구마다 다르다. Xilinx `#pragma HLS` 를
다른 도구가 안 받는다. **한 줄만 추가해도 실패한다** (1변수 대조로 확인).

**고치는 법**: **pragma 를 소스에 안 넣는다.** 알고리즘은 이식 가능한
C++ 로 두고, 도구별 설정은 **명령줄**로 준다. 그래야 같은 헤더가
`g++`(골든모델)에도 HLS 에도 들어간다.

### E2. 크래시하거나 멈춘다 {#e2}

| 무엇 | 결과 | 대안 |
|---|---|---|
| `hls::stream` | `rc=1` 크래시 | **우회 불가.** 배열 인터페이스로 |
| 깊은 `ap_fixed` 템플릿 | `rc=124` 40분 타임아웃 | 손으로 적은 고정소수점 |
| `ap_uint` | **된다** | 그냥 쓴다 |
| 순수 C / C++ 템플릿 | **된다** | 이쪽으로 짠다 |

## F. 납품

### F1. 빈 디렉터리에서 납품물이 안 돈다 {#f1}

**가장 흔한 납품 사고이고, 원인은 거의 항상 파일 누락이다.**

내 작업 디렉터리에는 그 파일이 있으니 검사가 통과한다. 그런데 고객이
받는 것은 묶음뿐이다.

**고치는 법**: 납품 전에 **반드시** 빈 디렉터리에서 풀어 돌린다(08단계 6번).
이 저장소는 같은 병을 다섯 번 앓았다.

```bash
cd /tmp && rm -rf 납품시험 && mkdir 납품시험 && cd 납품시험
tar xzf <묶음>.tar.gz && cd 납품
# 여기서 검증이 돌아야 한다
```
