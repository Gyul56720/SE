## 왜 C++ 을 먼저 쓰나 — 재 본 수로 답한다

| 길 | 초당 벡터 | RTL 대비 |
|---|---|---|
| C++, 계산만 | 144,419,484 | **1,616배** |
| C++, printf 로 파일에 | 5,110,455 | 57배 |
| RTL (iverilog) | 89,345 | 1배 |

같은 알고리즘, 같은 기계에서 잰 값이다. 읽는 법:

* **알고리즘 결함은 C++ 에서 죽인다.** 거기서 1,600배 싸다.
* **RTL 에서는 배선만 본다** — 핸드셰이크, 리셋, 폭. C++ 로는 못 보는 것들.
* 그리고 **`printf` 가 알고리즘보다 28배 비싸다.** 파일을 거치는 순간
  1,600배가 57배로 떨어진다. 대량 확인은 파일 없이 메모리에서 한다.

> 파일 탓이 아니다. `/dev/null` 로 버려도 같았다(5,398,353/초). 십진수
> 문자열 변환이 비싼 것이다.

## 골든모델의 조건 세 가지

### 1. RTL 과 **독립**이어야 한다

RTL 을 보고 쓰거나, RTL 출력을 저장해 정답으로 쓰면 **자기 자신과
비교하는 것**이라 아무것도 검증하지 않는다.
스펙만 보고 쓴다. 가능하면 남이 만든 구현(`zlib` 등)을 쓴다.

### 2. **고정폭 정수**만 쓴다

`float` 이나 파이썬 큰 정수를 쓰면 모델은 안 넘치고 RTL 만 넘친다.
증상은 "가끔 1 틀림" 이고, 이것이 몇 주를 먹는다.

```c
int8_t a = 100, b = 100;
auto c = a + b;      // c 의 타입은 int8_t 가 아니라 int. 200 이 된다
```
C 의 정수 승격 규칙이 `char`·`short` 를 전부 `int` 로 올린다.
**모델이 하드웨어보다 관대해진다.** 그래서 `sat(v, 8)` 로 직접 못박는다.

### 3. **시프트는 시프트로** 적는다

```c
acc / 128     // 0 쪽으로 자른다.  -1/128 = 0
acc >> 7      // 아래로 자른다.    -1>>7 = -1
```
음수에서 둘이 다르다. RTL 은 `acc[16:7]` 즉 시프트를 하므로 모델도 시프트다.
나눗셈으로 적으면 **음수 절반에서 틀린다** — 등화기처럼 0 근처를 오가는
신호에서는 거의 항상 틀린다는 뜻이다.

## 할 일

### 1. 뼈대를 복사한다

```bash
cd /home/user/SE
mkdir -p work/model
cp manual/템플릿/model/golden.cpp work/model/golden.cpp
$EDITOR work/model/golden.cpp
```

뼈대에 TODO 가 다섯 군데 있다:
1. 폭 (`IN_W`, `OUT_W`)
2. **알고리즘 본체** (`골든()`)
3. 경계값 목록
4. 자극 생성 (폭에 맞게)
5. 출력 열 개수

### 2. 컴파일하고 자기확인을 돌린다

```bash
cd work/model
g++ -O2 -I. -o golden golden.cpp && ./golden self
```

나와야 하는 것:

```
출력이 여러 가지인가: 예
포화가 일어나는가:   예
```

**`출력이 여러 가지인가: 아니오` 면 멈춘다.** 그 모델로 아무리 많은
벡터를 돌려도 검증이 아니다 — 늘 같은 값이 나오는 것과 비교하는 것은
아무것도 안 보는 것이다.

### 3. 벡터를 내 본다

```bash
./golden vec 20 1
```

**눈으로 본다.** 첫 몇 줄이 경계값(0, 최대, 최소)인지, 정답이 손으로
계산한 것과 맞는지. 여기서 한 줄이라도 이상하면 RTL 로 가지 않는다.

### 4. 가능하면 **독립 대조**를 붙인다

정답을 두 번째 길로 한 번 더 구해 비교한다. 이것이 붙는 블록은 검증 강도가
한 단계 올라간다.

```bash
# 예: CRC-32 를 파이썬 zlib 과 대조 (zlib 은 남이 표준에서 만든 구현이다)
./golden vec 1000 7 | python3 -c "
import sys, zlib
bad = 0
for line in sys.stdin:
    hexstr, got = line.split()
    ref = zlib.crc32(bytes.fromhex(hexstr)) & 0xFFFFFFFF
    if ref != int(got, 16): bad += 1
print('독립대조 틀림', bad)
"
```

`틀림 0` 이면 **내 모델이 남의 구현과 비트까지 같다**는 뜻이다.
이 문장을 데이터시트에 쓸 수 있는 블록은 많지 않다.

### 5. 입력 공간이 작으면 **전수**로 확인한다

입력이 2³² 이하면 C++ 로 30초 안에 전부 훑을 수 있다.
표본을 뽑을 이유가 없다.

```c
for (int64_t v = 0; v < (1LL<<32); v++) { /* 두 구현을 비교 */ }
```

실제 예(`edu/model/equiv.cpp`): 같은 필터를 세 구조로 적고
**4,294,967,296 가지 전부에서 비트까지 같음을 29.7초에** 확인한다.

## 막히면

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| `출력이 여러 가지인가: 아니오` | 알고리즘이 상수를 낸다 | `골든()` 이 입력을 실제로 쓰는지 본다 |
| 벡터가 매번 다르다 | `rand()` 를 썼다 | `xorshift32` 로 바꾼다. libc 마다 수열이 다르다 |
| 음수에서만 틀린다 | `/` 를 썼다 | `>>` 로. 또는 `asr()` |
| 큰 입력에서만 틀린다 | 정수 승격 | 중간값마다 `sat(v, 폭)` |
| `int8_t` 인데 200 이 나온다 | 승격. 정상 동작이다 | 폭을 명시적으로 자른다 |
| 전수가 너무 느리다 | `-O2` 를 빼먹었다 | **`-O2` 가 검증 전략을 바꾼다.** 없으면 분 단위 → 표본으로 후퇴하게 된다 |
