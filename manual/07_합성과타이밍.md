## 무엇을 읽나

```
== 3. yosys iCE40 매핑 ==
   Number of cells:   257
     SB_CARRY          48
     SB_DFFSR           9      ← 제일 먼저 보는 줄
     SB_LUT4          200      ← 이것이 면적이다
```

### 플립플롭 수부터 본다

**세어서 맞아야 한다.** 위 예는 출력 8비트 + done 1개 = 9개다.

예상과 다르면 **의도 안 한 상태가 생긴 것**이다. 원인은 대개 셋 중 하나:

* 조합 블록이 갈래를 안 채워 **래치**가 생겼다
* 쓰지도 않는 신호를 레지스터에 담았다
* 파라미터가 예상과 다르게 풀렸다

면적보다 이 줄을 먼저 본다. 면적은 크면 줄이면 되지만, **의도 안 한
상태는 기능 결함**이다.

### 기술 독립 셀 수는 면적이 아니다

2단계의 `Number of cells: 780` 은 **면적이 아니다.** 소자에 매핑하면
257로 줄어든다. 데이터시트에 780 을 적으면 거짓말이 된다.
**적는 것은 3단계의 수다.**

## 주파수는 타이밍 껍데기 없이 재지 않는다

이것이 이 단계에서 가장 중요하다.

`nextpnr` 이 내는 `Max frequency` 는 **레지스터 사이 경로만** 잰다.
입력 핀에서 첫 레지스터까지의 긴 조합 경로는 제약이 없어 **안 센다.**

> **실측**: 어떤 블록을 껍데기 없이 쟀더니 **455 MHz** 가 나왔다. 씨앗을
> 바꿔도 안정적이고 재현되는 수였다. 껍데기를 씌우고 다시 재니 **47 MHz**.
> 10배 차이다. 455 는 아무 상관 없는 짧은 곁가지 경로의 수였다.
>
> **재현되는 수가 맞는 수는 아니다.**

### 껍데기 만드는 법

입력과 출력을 레지스터로 감싸, 모든 경로가 레지스터-레지스터가 되게 한다.
`edu/model/fir_shell.v` 를 본뜬다.

```verilog
module my_shell (input clk, input rst,
                 input v_i, input [7:0] d_i,
                 output reg v_o, output reg [7:0] d_o);
    reg v_q; reg [7:0] d_q;
    always @(posedge clk) begin v_q <= v_i; d_q <= d_i; end   // 입력 끊기

    wire v_w; wire [7:0] d_w;
    block dut (.clk(clk), .rst(rst), .in_valid(v_q), .in_data(d_q),
               .out_valid(v_w), .out_data(d_w));

    always @(posedge clk) begin v_o <= v_w; d_o <= d_w; end   // 출력 끊기
endmodule
```

```bash
cat my_shell.v work/rtl/block.v > /tmp/shell.v
bash edu/house/synth.sh /tmp/shell.v my_shell --pnr
```

### 씨앗을 셋 돌린다

배치기는 난수를 쓴다. 하나만 보면 표본이 하나다.

```bash
for s in 1 2 3; do
  PNR_SEED=$s bash edu/house/synth.sh /tmp/shell.v my_shell --pnr 2>&1 | grep MHz | tail -1
done
```

흩어짐이 10% 안이면 평균을 쓴다. 크면 **설계가 배선에 민감한 것**이니
그 사실 자체를 데이터시트에 적는다.

### `FAIL at 300 MHz` 는 고장이 아니다

`synth.sh` 는 기본으로 `--freq 300` 을 건다. 목표를 안 주면 nextpnr 이
12 MHz 를 기본으로 잡고 **그것만 넘으면 최적화를 멈춰** 의미 없는 수를 낸다.

`ERROR: ... FAIL at 300.00 MHz` 는 "300 에 못 미쳤다" 는 뜻일 뿐이다.
읽을 수는 그 줄의 MHz 값이다. 현실적 목표를 주려면 `PNR_FREQ=50` 처럼.

## 처리량으로 바꿔서 판단한다

MHz 는 그 자체로 아무 뜻이 없다. **스펙이 요구하는 것으로 환산한다.**

```
처리량 = Fmax × (클럭당 처리하는 양)
```

> **실측 예**: 8b/10b 부호기가 84.9 MHz, 1바이트/클럭이었다.
> 1000BASE-X 는 125 Mbyte/s 를 요구한다.
> 84.9 Mbyte/s = **요구의 68%. 못 미친다.**
>
> 초안에는 "gigabit 를 여유 있게 넘는다" 고 적혀 있었다. 곱해 보니 틀렸다.
> **작고 깨끗한 것이 빠른 것을 뜻하지 않는다.** 산술만이 답한다.

못 미치면 고치는 길은 셋이고, 순서가 있다:

| 길 | 얻는 것 | 잃는 것 |
|---|---|---|
| 1. **데이터패스를 넓힌다** (2바이트/클럭) | 2배 | 면적 ~2배. 대개 가장 쉽다 |
| 2. **파이프라인을 넣는다** | 임계경로가 짧아진다 | 지연 증가 |
| 3. 더 빠른 소자로 | 전부 | 그 소자 고객만 |

## 막히면

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| `Max frequency` 줄이 없다 | 레지스터-레지스터 경로가 없다 | **껍데기를 씌운다** |
| 주파수가 비현실적으로 높다 | 엉뚱한 경로를 쟀다 | 같음 |
| `Unable to find a placement location` | 핀이 모자라다 | `--hx8k --package ct256` |
| 플립플롭이 예상보다 많다 | 래치 또는 의도 안 한 상태 | lint 의 `LATCH` 를 본다 |
| 셀 수가 예상의 4배 | 폭이 넓다 (32비트 데이터패스) | 포트·중간값 폭을 줄인다 |
| yosys 가 아무 수도 안 찍는다 | `-q` 를 붙였다 | 뺀다 |
| 씨앗마다 30% 씩 다르다 | 설계가 배선에 민감하다 | 파이프라인을 넣거나, 그 사실을 적는다 |
