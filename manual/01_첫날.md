# 01. 첫날 — 전 과정을 한 바퀴 (3시간)

> **여는 때**: 설치가 끝난 직후, 딱 한 번.
> **끝나면**: 한 블록을 **처음부터 끝까지** 통과시켜 본 상태가 된다.
> **중요**: 오늘은 아무것도 **만들지 않는다.** 이미 있는 것을 돌려 본다.

---

## 왜 남의 블록부터 돌리나

자기 제품을 먼저 고르면 두 가지를 동시에 배우게 된다 — **무엇을 만들지**와
**어떻게 만드는지**. 둘 다 모르는 상태에서 둘 다 하면 어디서 막혔는지
구분이 안 된다.

오늘은 **어떻게**만 배운다. 제품 고르기는 내일([02_제품고르기.md](02_제품고르기.md))이다.

오늘 돌릴 블록: `edu/model/` 의 **4탭 FIR 등화기**.
고속 링크 수신단에서 신호 번짐을 펴 주는 필터다. 작지만 **진짜 IP 가 가진
것을 다 가지고 있다** — 고정소수점, 포화, 핸드셰이크, C++ 골든모델, 합성 결과.

---

## 전체 흐름 — 오늘 이 순서로 여섯 번

```
   ① C++ 모델 ─────> ② 정답 벡터 파일
        │                    │
        │                    v
        └──> (나중에 HLS)   ③ RTL 시뮬 ──> 맞나?
                                 │
                            ④ 자해검사 ──> 검사가 물기는 하나?
                                 │
                            ⑤ 합성 ──> 얼마나 큰가?
                                 │
                            ⑥ 배치배선 ──> 얼마나 빠른가?
```

**③ 과 ④ 의 순서가 뒤바뀌면 안 된다.** ③ 이 "틀림 0" 이라고 말해도,
④ 를 안 하면 그 0 이 "맞다"는 뜻인지 "검사가 안 돈다"는 뜻인지 모른다.

## ① C++ 골든모델을 짓는다

**골든모델 = 정답.** RTL 이 맞는지 비교할 기준이다.
여기서 중요한 것은 골든이 **RTL 과 독립**이라는 것이다. RTL 에서 뽑아낸
정답으로 RTL 을 검사하면 자기 자신과 비교하는 것이라 아무것도 안 본다.

```bash
g++ -O2 -I$M -DFIR_VARIANT=2 -o vectors $M/vectors.cpp && echo "모델 컴파일 성공"
```

`-DFIR_VARIANT=2` 는 "접은 구조"를 고른다는 뜻이다. 같은 함수를 세 가지
구조로 적어 두었고, 셋이 **비트까지 같다는 것을 전수로 증명해** 두었다.
직접 확인해 본다 (약 2초):

```bash
g++ -O2 -I$M -o equiv $M/equiv.cpp && ./equiv 32
```

나와야 하는 것:

```
본것 134217728
다름01 0
다름02 0
출력값가지수 256
```

* `다름01 0` `다름02 0` → 세 구조가 **같은 함수**다
* `출력값가지수 256` → 확인이 **여러 값을 봤다.** 이 줄이 1 이면 그 확인은
  아무것도 안 본 것이다. (걸음 `1` 을 주면 전체 42억 가지를 30초에 훑는다)

---

## ② 정답 벡터를 뽑는다

```bash
./vectors 400 1 > vec.txt
head -3 vec.txt
wc -l vec.txt
```

한 줄이 `x0 x1 x2 x3 y` 다 — 입력 넷과 **정답** 하나.

```
127 127 127 127 127
-128 -128 -128 -128 -128
127 -128 127 -128 -1
```

맨 앞 열 줄이 **경계값**인 것에 주목한다 (전부 최대, 전부 최소, 엇갈림).
무작위만 뽑으면 포화 경계를 거의 안 밟는다 — 그러면 포화 논리를 통째로
지워도 검사가 초록이다.

---

## ③ RTL 을 돌려 비교한다

```bash
iverilog -g2012 -DDUT=fir4_hand -o sim.out $M/fir_tb.v $M/fir4_hand.v
vvp sim.out
```

나와야 하는 것:

```
잰것 400  틀림 0
```

`-g2012` 를 빼면 SystemVerilog 문법에서 죽는다. 항상 붙인다.

## ④ **자해검사** — 오늘 가장 중요한 단계

방금 "틀림 0" 을 봤다. 그런데 저 비교가 **정말로 DUT 를 보고 있나?**
정답 파일을 한 줄 망가뜨려서, 검사가 **반드시 빨개지는지** 확인한다.

```bash
cp vec.txt 정답백업.txt
awk 'NR==7{$5=$5+1} 1' 정답백업.txt > vec.txt   # 7번째 줄 정답을 1 틀리게
vvp sim.out
cp 정답백업.txt vec.txt                          # 되돌린다
```

나와야 하는 것:

```
FAIL x=-128,0,0,-128  기대 37  얻음 36
잰것 400  틀림 1
```

**`틀림 1` 이 나와야 한다.** `틀림 0` 이 나오면 그 검사는 DUT 를 안 보는
것이고, ③ 의 결과는 **버려야 한다.**

> 이 저장소의 규율 1번이 이것이다.
> *검사하지 않은 초록불이 검사한 빨간불보다 나쁘다.*
> 빨간불은 고치면 되지만, 검사가 안 도는 초록불은 몇 주를 먹는다.

## ⑤ 합성 — 얼마나 큰가

```bash
bash $H/synth.sh $M/fir4_hand.v fir4_hand
```

세 단계가 순서대로 돈다. **싼 것부터 돈다** — lint 는 1초, 합성은 몇 초,
배치배선은 분 단위다. 싼 데서 죽는 것을 비싼 데까지 안 끌고 간다.

나와야 하는 것 (숫자는 도구 버전에 따라 조금 다를 수 있다):

```
== 1. verilator lint ==
   경고+오류 0
   lint rc=0

== 2. yosys 기술독립 합성 ==
   Number of cells:   780

== 3. yosys iCE40 매핑 ==
   Number of cells:   257
     SB_CARRY          48
     SB_DFFSR           9
     SB_LUT4          200
```

> **lint 가 `경고+오류 0` 이 아니라면** 그것도 정보다. 이 블록은 처음에
> `UNUSEDSIGNAL: acc[6:0]` 하나가 떴었다 — Q3.14 를 Q1.7 로 내리며 **일부러
> 버리는 소수 7비트**라 맞는 경고였다. 고친 방법은 그 한 줄에만 좁게
> `/* verilator lint_off UNUSEDSIGNAL */` 을 걸고 **왜 끄는지 옆에 적는 것**이다.
> 파일 전체나 경고 종류 전체를 끄면 진짜 배선 실수까지 같이 묻힌다.
> **경고를 끄는 것과 이유를 적는 것은 한 동작이다.**

읽는 법:

* **`SB_DFFSR 9`** — 플립플롭 9개. 세어 보면 맞다: 출력 8비트 + done 1개.
  **이 수가 예상과 다르면 의도 안 한 상태가 생긴 것이다.** 제일 먼저 보는 줄이다.
* **`SB_LUT4 200`** — 실제 논리 자원. 이것이 면적이다.
* `Number of cells: 780` (2단계) 은 **면적이 아니다.** 기술 독립 게이트라
  실제 소자에 매핑하면 257로 줄어든다. 데이터시트에 780 을 적으면 거짓말이 된다.

## ⑥ 배치배선 — 얼마나 빠른가

```bash
bash $H/synth.sh $M/fir4_hand.v fir4_hand --pnr 2>&1 | tail -6
```

`Max frequency` 줄이 **안 나올 수도 있다.** 그러면 그것이 정상이다 —
이 블록은 출력만 레지스터에 담고 입력은 핀에서 바로 오기 때문에,
레지스터-레지스터 경로가 없다.

**주파수를 제대로 재려면 타이밍 껍데기를 씌운다.**

```bash
cat $M/fir_shell.v $M/fir4_hand.v > shell.v
bash $H/synth.sh shell.v fir_shell --pnr 2>&1 | grep -E "ICESTORM_LC:|MHz"
```

이제 나온다:

```
Info: 	         ICESTORM_LC:   252/ 7680     3%
Info: Max frequency for clock 'clock...': 49.73 MHz (FAIL at 300.00 MHz)
ERROR: Max frequency for clock 'clock...': 47.39 MHz (FAIL at 300.00 MHz)
```

**`ERROR` 와 `FAIL` 에 놀라지 않는다.** 저것은 "설계가 고장났다"가 아니라
"네가 요구한 300 MHz 에 **못 미쳤다**" 는 뜻이다. `synth.sh` 가 기본으로
`--freq 300` 을 건다 — 목표를 안 주면 nextpnr 이 12 MHz 를 기본으로 잡고,
그것만 넘으면 최적화를 멈춰 **아무 의미 없는 수**를 내기 때문이다.

우리가 읽을 수는 **47.39 MHz** 다 (두 줄 중 뒤엣것 = 배선까지 끝난 값).
목표를 현실적으로 주고 싶으면:

```bash
PNR_FREQ=50 bash $H/synth.sh shell.v fir_shell --pnr 2>&1 | grep MHz
```

> **오늘 두 번째로 중요한 것**: 껍데기 없이 재면 이 설계가 **455 MHz** 로
> 나온다. 씨앗을 바꿔도 안정적이고 재현되는 수다. 그런데 **그 수는 거짓이다** —
> nextpnr 이 레지스터 사이 경로만 재는데, 진짜 데이터패스는 핀에서
> 들어오는 제약 없는 경로에 있기 때문이다.
>
> **재현되는 수가 맞는 수는 아니다.** 주파수를 말할 때는 언제나
> "어느 레지스터에서 어느 레지스터까지인가" 를 답할 수 있어야 한다.

## 오늘 배운 것 세 줄

1. **골든모델은 RTL 과 독립이어야 한다.** 아니면 비교가 자기 자신을 본다.
2. **자해검사 없는 "틀림 0" 은 정보가 아니다.** 검사가 물 수 있음을 먼저 보인다.
3. **면적과 주파수는 도구를 돌려 나온 수만 적는다.** 그리고 어느 경로의
   수인지 말할 수 있어야 한다.

이 셋이 나머지 전부의 뼈대다. 04~07 단계는 이 여섯 걸음을
**자기 블록에 대해** 다시 하는 것뿐이다.

## 막히면

| 증상 | 고치는 법 |
|---|---|
| `vec.txt 를 못 연다` | 시뮬을 `vec.txt` 가 있는 **그 디렉터리에서** 돌려야 한다. `cd /tmp/첫날` |
| `syntax error` near `always_ff` | `iverilog` 에 `-g2012` 를 붙인다 |
| ④ 에서 `틀림 0` | 파일을 잘못 고쳤다. `head -7 vec.txt` 로 7번째 줄이 바뀌었는지 본다 |
| `synth.sh: 파일=...: No such file` | 셸이 한글 변수명을 만난 것. 이 저장소의 `synth.sh` 는 고쳐져 있다. 직접 쓴 스크립트라면 변수명을 아스키로 |
| 합성 수가 크게 다르다 | yosys 버전 차이. **경향**(플립플롭 9개)이 맞으면 된다 |
| ⑥ 에서 `ERROR: Max frequency ... FAIL at 300` | 정상이다. 300 MHz 목표에 못 미쳤다는 뜻일 뿐. 읽을 수는 앞의 MHz 값 |
| lint 가 `UNUSEDSIGNAL` 을 낸다 | 정말 안 쓰는 비트인지 본다. 의도한 것이면 **그 줄에만** `lint_off` 하고 이유를 적는다. 아니면 배선 실수다 |

더 많은 것은 [10_막힐때.md](10_막힐때.md).
