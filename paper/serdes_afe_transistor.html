전류가 어디로 흐르고, 왜 그 소자가 있고, 논문의 손잡이가 회로의 무엇인가

0왜 트랜지스터까지 내려가나

논문에는 손잡이가 여럿이다. 압축 세기 κ, 슬루율 S, CTLE 피킹, 지터 rjUI. 지금까지 그것들은 그냥 숫자였다. "κ=2.0 에서 교차점" 이라고 적어도 그것이 실리콘에서 무엇인지 — 입력 스윙 몇 mV 인지, 출력 시상수 몇 ps 인지 — 는 어디에도 없었다. 그러면 결론이 물리에 닿지 않는다.

여기서는 블록마다 회로를 놓고 전류가 어디로 흐르는지, 그 트랜지스터가 없으면 무엇이 깨지는지, 그리고 소자 파라미터에서 논문의 손잡이가 닫힌 꼴로 어떻게 나오는지를 잇는다. 대응은 전부 afe.py 에 있고 tests/test_afe.py 가 serdes.py 와 맞대 본다 — 그림은 검사가 아니다.

고쳐 적는다: SPICE 와 PDK 가 있다

처음에는 "SPICE 도 공정 모델도 없으니 전부 1차 손계산" 이라고 적었다. 확인해 보니 틀렸다. 이 컨테이너에 ngspice-42 가 이미 깔려 있고, SkyWater sky130 의 BSIM4 모델 카드와 코너 파일(tt·ff·ss·fs·sf)이 PyPI 휠 안에 그대로 들어 있다(파일 머리말이 "for use by ngspice using the .lib statement" 라고 적어 놓았다). GitHub 도 apt 도 막혀 있지만 PyPI 는 열려 있다.

pdk.py 가 그것을 스스로 받아 푼다(필요한 셀만 34.5 MB). 그래서 §3 의 κ 대응은 진짜 소자 모델로 다시 쟀고, 손계산 하나가 고쳐졌다.

그래도 여기 없는 것: 레이아웃 · 기생 추출(PEX) · 몬테카를로 미스매치 · 실측 실리콘. 기하와 배선이 빠진 회로도 수준 시뮬레이션이다.

1TX CML 드라이버 — 전류를 좌우로 던진다

1.1 전류가 어디로 흐르나

꼬리 전류원 M₃ 이 I_SS 를 뽑고 있다. 입력이 높은 쪽 스위치가 그 전류를 통째로 받는다. 받은 쪽 드레인이 V_DD − I_SS·R_eff 로 내려가고 다른 쪽은 V_DD 에 남는다. 그래서 차동 스윙이

V_swing(차동) = 2·I_SS·R_eff, R_eff = R_D ∥ (Z₀/2)

다. 스위치는 증폭하지 않는다 — 전류의 길을 고를 뿐이다. 전압 이득 단이 없고 노드가 늘 두 값 중 하나라서 CML 이 빠르다.

1.2 M₃ 이 없으면 무엇이 깨지나

꼬리 전류원을 빼면 스위치 두 개가 그냥 저항 분배기가 된다. 그러면 출력 스윙이 입력 공통모드를 따라 흔들린다 — 온도·공정·앞단 바이어스가 바뀔 때마다 송신 진폭이 바뀐다. 스윙을 I_SS·R 로 못 박는 것이 그 트랜지스터 하나의 일이고, 대가는 헤드룸 V_DS,sat 한 칸이다. 규격이 송신 진폭을 좁게 묶으므로(예: 800 mVppd ± 얼마) 이 소자는 협상 대상이 아니다.

1.3 논문의 S 가 회로에서 무엇인가 — 그리고 말이 안 된다

출력 노드에 C_L(패드·ESD·패키지)이 매달려 있고 전류가 I_SS 로 막혀 있으므로 최대 기울기가 I_SS/C_L 이다. 한 표본 시간 T_s 동안 움직일 몫을 스윙으로 나누면 serdes.슬루 의 정규화된 S 이고, V_swing = I_SS·R_eff 를 넣으면 전류가 약분된다:

S = (I_SS/C_L)·T_s / (I_SS·R_eff) = T_s / (R_eff·C_L)

S 는 전류가 아니라 시상수의 문제다. 꼬리 전류를 키우면 스윙과 슬루가 같이 커져 정규화된 S 는 그대로다. 그런데 이 식으로 논문이 쓴 S 를 되짚으면:

2CTLE — 올리는 것이 아니라 저주파를 깎는 것

축퇴 저항 R_S 는 저주파 이득을 g_m R_D/(1+g_m R_S/2) 로 깎는다. 주파수가 오르면 C_S 가 소스를 단락시켜 축퇴가 사라지고 이득이 g_m R_D 로 돌아온다.

ω_z = 1/(R_S C_S)　　ω_p1 = (1+g_m R_S/2)/(R_S C_S)　　ω_p2 = 1/(R_D C_L)　　피킹 = 1 + g_m R_S/2

CTLE 는 신호를 올리는 것이 아니라 저주파를 깎는 것이다. 그래서 잡음도 같이 올라가고, 피킹을 올린다고 BER 이 계속 좋아지지 않는다 — serdes.CTLE 머리말이 적은 그 사실의 회로적 까닭이 여기다.

그런데 serdes.CTLE 는 이 회로가 아니다 — 3.73 dB 어긋난다

시뮬레이터는 1영점 2극점 꼴을 쓰지만 두 극점을 극점비·A 와 극점비·2 로 묶어 둔다. 부하 극점 1/(R_D C_L) 을 따로 줄 수가 없다. gm=20 mS · R_D=500 Ω · R_S=400 Ω · C_S=80 fF · C_L=40 fF (피킹 14.0 dB)로 맞춰 보면 대역 안에서 최대 3.73 dB, Nyquist 에서 −3.73 dB 어긋난다.

그러므로 회로값으로 시뮬레이터를 몰 수 없다. 이것을 "같다" 고 적으면 거짓이 된다. 회로 그대로의 응답이 필요하면 afe.ctle적용() 을 쓴다 — 같은 파형에 진짜 전달함수를 건다.

3VGA · AFE — tanh 는 근사가 아니다

차동쌍의 대신호 전달은 영역에 따라 두 꼴이다.

약반전 · BJT　I_od/I_SS = tanh( v_id / (2 n V_T) )　　　（정확）
강반전　　　　I_od/I_SS = (v_id/√2V_ov)·√(2−(v_id/√2V_ov)²)/√2,　|v_id| < √2·V_ov

약반전에서는 tanh 가 근사가 아니라 정확한 답이다 — 전류가 전압의 지수이기 때문이다. serdes.압축하기 가 쓰는 그 함수가 이것이고, 맞대 보면 최대 차이가 0(부동소수점 한계 2×10⁻¹⁶)이다.

한계 스케일이 소자가 정하므로 논문의 κ 가 입력 스윙으로 번역된다:

κ = V_in,rms / V_lim,　　V_lim = 2nV_T ≈ 67 mV (약반전, n=1.3, 300 K)　또는　√2·V_ov ≈ 141 mV (강반전, V_ov=100 mV)

3.1 SPICE 가 고쳐 준 것 — V_lim 은 상수가 아니다

sky130 nfet_01v8(BSIM4, tt 코너, L=1 µm · W=10 µm)로 차동쌍 대신호 전달을 DC 스윕했다. 먼저 기본이 맞는다 — 약반전 gm/ID 가 30.5 1/V 로 이론 최대 1/(nV_T)=29.7 과 3 % 안에서 맞고(그래서 n≈1.27), 전류가 완전히 쏠린다(|Iod/ISS| → 1.000).

그래서 표 2 를 이렇게 읽어야 한다

"κ=2.0 = 입력 134 mV rms" 는 약반전 극한의 값이다. 20 GBd 앞단은 소자당 수백 µA 를 쓰므로 V_lim ≈ 300 mV 쪽이고, 거기서는 κ=2.0 이 입력 600 mV rms 다. κ 를 mV 로 옮길 때는 바이어스를 같이 적어야 한다 — 그리고 그만큼 스윙이 커야 그 압축이 걸린다는 뜻이므로, 논문의 교차점은 생각보다 먼 자리다.

4샘플러 — StrongARM 래치는 증폭하지 않는다

네 단계로 돈다. ① 리셋(clk 낮음): PMOS 넷이 내부 노드를 V_DD 로 올려 놓고 꼬리는 꺼져 있다 — 정적 전류 경로가 없다. ② 표본(clk 오름): 꼬리가 켜지고 입력쌍이 입력 차이에 비례해 두 노드를 서로 다른 속도로 끌어내린다. 여기서 초기 차이 ΔV₀ 가 생긴다. ③ 재생: 교차결합 인버터가 켜지면 ΔV(t) = ΔV₀·e^(t/τ), τ = C_L/g_m 으로 지수로 벌어진다. ④ 유지: SR 래치가 붙든다.

이 회로에는 증폭기가 없다. 이득을 만드는 것이 아니라 작은 차이를 시간으로 키운다. 그래서 정적 전력이 0 이고 아주 빠르다.

여기서 내 예상이 틀렸다 — 바닥의 원인은 비교기가 아니다

"§17.2 의 오류 바닥을 이 재생 한계가 정한다" 고 적어 두었다가 재 보니 아니었다. g_m=5 mS · C_L=25 fF 면 τ=5 ps 이고 50 ps 안에 10τ 만큼 벌어져 감도가 41 µV 다. 그런데 7비트 ADC 의 LSB 는 AFE 입력 rms 67 mV 에서 2,617 µV 다.

비교기 감도 41 µV　≪　ADC LSB 2,617 µV　　(64배)

바닥을 정하는 것은 양자화 계단이다. 이것은 실측과도 맞는다 — §17.2 의 바닥이 ADC 비트에 따라 1.13e−2 → 5.7e−3 → 1.1e−3 으로 내려갔다. 비교기가 원인이었다면 ADC 비트를 올려도 안 움직였어야 한다. 회로 쪽 계산이 어느 기구가 지배하는지 먼저 맞혔고, 측정이 그것을 확인했다.

5CDR — 남는 것은 루프 대역 위다

Alexander(2× 오버샘플) 위상검출기 → 전하펌프 → 루프필터 → 위상보간기. 위상검출기는 빠른가 늦은가 한 비트만 낸다. 전하펌프가 그 한 비트로 커패시터에 전하를 넣거나 뺀다. 여기도 곱셈기가 없다.

루프가 저역통과로 위상을 따라가므로 남는 것은 1−H(f) 다 — 루프 대역 아래 지터는 따라가고 위는 그대로 남는다.

6FFE — 키르히호프가 덧셈을 한다

아날로그 FFE 는 탭마다 차동쌍 하나를 두고 드레인을 한 노드에 묶는다. 각 탭의 꼬리 전류가 그 탭의 계수이고(w_k ∝ I_k), 부호는 차동 출력을 꼬아서 고른다.

V_out = R_L · Σ_k ±I_k · tanh(v_k / V_lim)

덧셈기가 따로 없다 — 전류를 한 노드에 모으면 키르히호프가 해 준다. 그리고 곱셈기도 없다. 그런데 이것은 §16.4 의 분산 산술과도, 이 논문의 판정 표와도 다른 종류다: 여기서는 계수가 전류의 크기이고 곱셈을 소자의 선형 영역이 한다.

대가가 둘이다. (ㄱ) 탭마다 꼬리 전류를 상시로 먹는다 — 11탭 × 200 µA = 2.2 mA 가 신호와 무관하게 흐른다. (ㄴ) tanh 의 선형 구간 안에 있어야 하므로 입력 스윙이 제한된다 — κ 가 커지면 탭 자체가 비선형이 되어 계수의 뜻이 흐려진다. §3 의 κ 와 여기가 같은 제약이다.

7DFE — 1 UI 안에 닫혀야 한다

t_latch + t_DAC + t_wire + t_setup ≤ 1 UI

RTL 쪽에서 본 것과 같은 사실이다. eqrtl.ffe_dfe 의 파이프라인 단을 FFE 쪽에는 넣을 수 있어도 DFE 되먹임에는 못 넣는다고 적은 그 줄의 회로적 까닭이 여기다. FPGA 든 커스텀이든 되먹임 고리는 한 심볼 시간 안에 닫혀야 한다는 제약이 같다.
