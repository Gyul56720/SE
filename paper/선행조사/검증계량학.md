# 선행조사 -- 검증 계량학 (Phase 1 종료판)

**이 문서의 1판은 주장을 과하게 잡았다.** 아래는 못 본 칸 여덟 개를 닫고 고친 것이다.
고친 이유와 무엇이 틀렸는지를 지우지 않고 남긴다.

**읽은 수준**: 전문을 읽은 것은 없다. `[출처:조각]` 검색 요약, `[출처:목록]` 제목만.

## 1판에서 틀린 것 -- 지우지 않고 적는다

> (1판) "설계 검증에는 이 수가 없습니다."

**틀렸다.** 미국특허 **US7865849B2** (2008, TI) *System and method for estimating test
escapes in integrated circuits* 가 이미, 기존 Williams-Brown 이 **여러 시험을 독립적으로밖에
합성하지 못하는 문제를 지적하고**, 생산 실패 데이터와 고장커버리지를 결합해 **중복
검출(overlap)을 고려한 combined coverage 와 test escape rate** 를 추정한다.
그러니 **"여러 검증층을 합쳐 잔여 결함을 수치화한다" 는 그 자체로 신규성이 아니다.**

1판은 이 특허를 "제목만 봤다" 고 적어 두고도 그 위에 주장을 세웠다. 못 본 것을 적는
것만으로는 부족하다 -- **못 본 칸이 주장의 밑동이면 주장을 세우지 말아야 한다.**

## 2판의 잘못 -- 업계가 내는 것을 얕봤다 (사용자 지적)

> (2판, 대화) "지금 업계가 내는 것은 커버리지 99.5%, 통과 한 줄입니다."
> (2판, 대화) "이게 실리콘이 돌아온 뒤 터지는 종류입니다."

**둘 다 틀렸다.**

*하나 -- 한 줄이 아니다.* 기능검증 사인오프는 line/branch/condition/toggle/FSM 을 따로 내고,
기능 커버리지를 covergroup·coverpoint·**bin** 단위로 계층별로 낸다. 검증계획(vPlan)에 물려
구멍 분석을 하는 것이 일상이다. Accellera 가 **UCIS 1.0 을 2012-06 에** 내서 벤더 간
커버리지 DB 교환까지 표준화했고, 그 문서가 검증팀의 역할을 "이 **다수의** 커버리지 데이터를
모으고 병합하고 해석하는 것" 으로 적는다 [출처:조각, Accellera / Semiconductor Engineering].
**층별·등급별로 갈라 보는 일은 이미 업계의 일상이다.**

*둘 -- "실리콘 돌아온 뒤 터진다" 는 아무 근거 없이 말했다.* 재지 않았고 인용도 없다. 취소한다.
이 저장소의 규칙이 금지하는 바로 그것이다 -- 사소한 설명을 죽이지 않고 수를 말했다.

*셋 -- 그리고 `LOD` 열도 비어 있지 않았다.* ISO 26262 는 고장을 단일점(SPF)·잔여(RF)·
잠재/다중점으로 **분류**하고, **고장모드별 진단커버리지 DC** 를 "그 고장모드가 존재하는 모든
조건 중 검출되는 비율" 로 정의한다. SPFM/LFM 으로 롤업하고 ASIL 별 목표치가 있다
[출처:조각, ISO 26262 Academy / einfochips / In Compliance]. 형식검증 기반 고장캠페인도 있다
[출처:목록, Siemens *It's not my fault!*]. **등급별 검출확률 + 목표 + 증명서 롤업이 이미 있다.**

### 그런데 고쳐 보니 빈 자리가 더 선명해졌다

ISO 26262 는 이 정량 기계를 **무작위 하드웨어 고장에만** 쓴다. 계통적(설계) 결함은
정량화를 **명시적으로 거부한다** -- "계통 고장은 무작위 하드웨어 고장 지표 계산에서
제외된다", "무작위 고장은 확률로 모형화할 수 있으나 계통 고장(예: 결정적 소프트웨어)은
그렇게 모형화할 수 없다" [출처:조각]. 계통 결함은 **프로세스**(ASIL 별 개발 요구)로 다룬다.

| | 무작위 HW 고장 | **계통(설계) 결함** |
|---|---|---|
| 등급별 검출확률 | 있다 (고장모드별 DC) | **없다** |
| 다층 롤업 | 있다 (FMEDA → SPFM/LFM) | **없다** |
| 목표치 | 있다 (ASIL 별) | **원칙적으로 거부** |
| 증명서 | 있다 (지표 + 안전사례) | 프로세스 준수 증거 |

규격의 거부 이유는 **제품의 고장확률**에 대해서는 맞다 -- 결정적 버그는 있거나 없다.
그러나 그것은 **검증이 그 결함을 얼마나 잡는지**를 확률로 말 못 할 이유가 아니다.
고장 모집단을 우리가 만들기 때문이다(변이검사가 이미 그렇게 한다).

## β 라는 이름을 쓰지 않는다

IEC 61508 의 β-인자는 **하드웨어 CCF 모델의 파라미터**이고 1oo2 구성과 묶여 있으며 값도
구성·평가방식에 따라 달라진다 [출처:조각]. 검증층 사이의 의존을 β 라고 부르면
"왜 검증층 의존이 하드웨어 CCF 와 같은 확률모형을 따른다고 가정했는가" 에 답해야 한다.
**답이 없다.** 그래서 이름과 지위를 바꾼다.

    D_ij = 층 i, j 사이의 **실측된** 의존 (같은 고장 모집단에 대한 공동 검출로 관측)

    관측량:  P(A∩B) · P(A|B) · P(B|A)      -- 세는 것이다. 모형이 아니다
    쓰임:    기존 보수적 추정량의 **입력**
    β 와의 관계: 나중에 **비교**한다. 가정하지 않는다

## 우리가 그것과 다른 점 -- 주장을 이렇게 바꾼다

> 기존 검증 연구는 커버리지 지표, 잔여결함 추정량, 개별 신뢰도 모형을 제공한다. 그러나 그
> 방법들만으로는 **이종 검증층 · 실측된 층간 의존 · 고장등급별 검출한계 · 불확도**를
> 비교 가능한 하나의 잔여 유출량으로 묶은, **경험적으로 교정된 증명서**가 나오지 않는다.

그리고 한 걸음 더 물러선다. **새 추정량을 만들지 않는다.**
보수적 베이즈 추정량이 더 낫다 -- 우리가 만드는 것은 **그 추정량이 요구하는 입력을 실제로
재는 계측기**다. 저쪽은 추정량이 있는데 입력이 전문가 판단이고, 이쪽은 입력을 셀 수 있다.

## 남은 신규성 후보 -- 3판

정정을 거치고 남은 것은 **두 개**다. 1판·2판에서 든 것과 다르다.

**(가) 계통(설계) 결함 쪽으로 정량 기계를 옮기는 것.**
무작위 HW 고장에는 등급별 DC · 다층 롤업 · ASIL 목표 · 증명서가 다 있다. 계통 결함에는
하나도 없고, 규격이 정량화를 **명시적으로 거부**한다. 거부 이유("결정적 버그는 확률로 모형화
못 한다")는 *제품의 고장확률*에는 맞지만 *검증의 검출능력*에는 해당되지 않는다 -- 고장
모집단을 우리가 만드니까. 그래서 옮길 수 있는지, 옮기면 무엇이 깨지는지가 물음이다.

       C(f, θ)   f 결함등급(제어흐름·연산·CDC·리셋·희소 프로토콜 …), θ 운용조건
       LOD = min{ f : P_detect(f) >= p0 }

**(나) "상호보완적" 을 수로 만드는 것.**
형식검증과 시뮬레이션이 서로 보완한다는 말은 어디에나 있다 -- 시뮬레이션은 코너를 놓치고
형식검증은 소진적이라고. 그런데 **같은 결함 모집단에서 둘의 중복을 잰 연구를 찾지 못했다.**
검색 요약이 그렇게 적었다: "어느 방법이 어떤 버그를 찾는지, 검출능력의 중복 정도를 같은
시험집합에서 정량화한 실증연구는 결과에 없다" [출처:조각]. **한 번의 검색이다.**
이것이 Phase 2 가 재려는 바로 그 표다.

       fault_id | class | mutation | random | formal
       -> P(A∩B) · P(A|B) · P(B|A)      세는 것이다. 모형이 아니다

**빠진 것(공학이지 논문 아님)**: 거부 의미론, 양성대조(SST)를 증명서의 선행조건으로,
자격 만료일. 2판에서 이것을 신규성 후보에 넣었는데 빼는 게 맞다.

## 아직 못 지운 가능성

- `LOD` 가 비었다는 것은 **검색 한 번의 결과**다. 나온 것은 고장주입 *공격* 탐지(보안)와
  IACR 2023/1722 *Quantitative Fault Injection Analysis* 뿐이었다. 소프트 오류(SDC) 문헌에
  고장등급별 확률이 있을 가능성이 크다 -- **안 봤다.**
- **상관 capture-recapture** (*Estimating the number of undetected software errors via the
  correlated capture-recapture model*, EJOR 2006) -- 제목만 봤다. 여러 검사자를 "층" 으로
  보면 우리가 말하는 것과 같을 수 있다. **읽어야 한다.**
- Bühlmann 신뢰도이론을 보증 증거에 쓴 사례를 못 찾았다(신용위험·자율차 책임보험 요율에는
  있다: arXiv:2606.17451). 그러나 검색 한 번이다.
- Good-Turing 의 **의존성 과대추정** 후속 지적(Seongmin Lee) [사용자 제공] -- 원문 미열람.
- Certitude 최신판의 다층 합성 여부 -- 제품 문서 등록 필요, 미열람.
- 규격 원문 전부 미열람: DO-254/ED-80, ICH Q2(R2), IEC 61508-6, ISO/IEC Guide 98(GUM),
  IEC 61511-3.
- 변이검사 서베이(Jia & Harman, *Mutation Testing Advances*)는 **변이적합도 점수**와
  기계학습 기반 변이점수 예측까지 확인했으나, "변이점수 → 잔여결함 확률" 합성은 못 찾았다.
  **서베이 본문을 안 읽었다.**

## 다음 실험 (Phase 2) -- 가장 작은 것

공개 RTL 하나, **두 층만**. 같은 고장 모집단을 두 층에 똑같이 먹인다.

    Layer A = 변이검사(mutation)
    Layer B = 지시/무작위 시험(directed/random)

    기록: fault_id | class | A_detect | B_detect

이 표 하나에서 `P(A∩B)` · `P(A|B)` · `P(B|A)` 가 바로 나온다. **모형 없이 세는 것이다.**
Phase 3 에서 형식검증 또는 고장주입을 세 번째 층으로 붙인다.
**D_ij 를 코드로 짓기 전에, 이 표가 실제로 갈리는지부터 본다.**
