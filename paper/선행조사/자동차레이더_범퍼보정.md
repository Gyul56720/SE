# 자동차 레이더 범퍼/오정렬 보정의 하드웨어 비용 -- 선행조사

조사일 2026-09-18. 검색 조각 수준(전문 미확인, arxiv·nature·ncbi·frontiers 전부 egress 차단).

## 검사한 가설

**H**: "온라인 레이더 보정 알고리즘(CNN·NLMS)의 하드웨어 구현 비용(전력·자원·지연)을
잰 연구가 드물다. 알고리즘 논문은 정확도만 보고한다."

## 결과 -- 대부분 죽었다

### [죽음 1] NLMS/LMS 하드웨어 비용 -- 완전히 점유됨

FPGA 구현 문헌이 다수이고 **자원·전력 수치까지 공개**돼 있다. `[출처:조각]`
  · 직렬 구조: FPU 9개, 플립플롭 27.41% 절감, **주기당 7.823 uW**
  · 병렬 구조: FPU 98개, 수렴시간 85.88% 절감, **주기당 65.133 uW**
  · Distributed Arithmetic 으로 곱셈기를 메모리로 대체하는 것까지 있음
  · "FPGAs can provide superior performance in both power utilization and throughput
     compared to GPU or DSP implementations"
-> **"NLMS 하드웨어 비용을 모른다" 는 거짓이다.**

### [죽음 2] 레이더 DSP 의 FPGA 구현 -- 성숙함

  · CFAR FPGA: **8260 LUT, 3823 레지스터, 0.6 us** `[출처:조각]`
  · FMCW 레이더용 FFT 프로세서 FPGA 구현
  · Chirp-scaling SAR 실시간 FPGA
  · 77 GHz MEMS 3모드 레이더용 FPGA 컨트롤러 (RF 스위치 제어까지 같은 FPGA 에)
  · **HLS 로 FMCW 레이더**: PYNQ-Z2 + Vitis HLS 사례가 2026-03 에 갱신됨
  · "FPGA-based algorithms can be implemented in ASICs which can be batch fabricated"
-> **HLS 로 레이더 신호처리를 짓는 것 자체가 새롭지 않다.**

### [죽음 3] CNN 임베디드 추론 비용 -- 이미 측정됨

  · 레이더 HAR CNN on Zynq Z-7007S: 지연 **107.5 us**, 처리율 **9.3k inference/s**,
    총 온칩 전력 **0.104 W**, 동적 전력 **15 mW** `[출처:조각]`
  · MCU(nRF52840) 대비 추론당 **819 uJ, 4배 이상 효율**, 95.5 ms, 3배 빠름
  · 임베디드 자동차 플랫폼의 CNN 패키지 성능/전력 평가 논문 존재 (arXiv:2310.08401)
-> **"CNN 을 차량 하드웨어에서 돌리는 비용을 모른다" 도 거짓이다.**

## 살아 있어 보이는 것 -- 그러나 얇고 확인 안 됨

**보정 알고리즘 자체를 하드웨어로 구현한 논문**은 이 검색에서 안 나왔다.

  · AutoRAD-Net (Sensors 25(2):353, 2025-01, 서강대) -- CV-CNN, 오프셋 -3~+3도,
    **오차 0.15도 이하**. 장비 TI AWR1642 + DCA1000. **구현 비용 언급 없음** `[출처:조각]`
  · DNN-Based Estimation for Misalignment State (Sensors 2023, doi:10.3390/s23146472)
    -- 수직 기울기각 분류, **정확도 99.08%**. **구현 비용 언급 없음** `[출처:조각]`
  · Unsupervised Online Misalignment + Bumper Error Compensation
    (Sensors 23(15):6785, 2023) -- 지그 불필요. **전문 못 봄(PMC 차단)**
  · NLMS 채널 불균형 (arXiv:2506.10841 -> IEEE Trans. Radar Systems 2026)
    -- mu0=0.1, **약 1000 반복 수렴**, 다중표적 허용

검색 결과가 스스로 적었다: "the search results did not specifically contain papers that
address... FPGA implementation details, embedded hardware deployment costs, or
comprehensive cost analysis for automotive inference."

**그런데 이건 '조합의 틈' 이다.** CNN 을 FPGA 에 올리는 것은 이미 푼 문제이고,
레이더 DSP 를 FPGA 에 올리는 것도 이미 푼 문제다. 둘을 합치는 것은 기술적으로 자명하다.
**자명한 조합은 논문이 되기 어렵다** -- 이 대화에서 여섯 번 확인한 패턴이다.

## 더 근본적인 문제 -- 전제가 흔들린다

사용자의 원래 전제는 "보정 스위칭 회로의 전력 소모가 크다" 였다. 그런데:

  1. 양산 77 GHz 레이더는 **아날로그 위상천이기를 대부분 안 쓴다** (TDM-MIMO + 디지털
     빔포밍). Infineon RASIC 은 "without dedicated phase shifters" 라고 명시
  2. 고전적 보정은 **위상 계수 몇 개를 곱하는 것**이다 -> 연산 비용이 거의 0
  3. 비싼 것은 CNN 방식인데, 그건 **선택 사항**이고 이미 FPGA 비용이 측정돼 있다

-> **"보정이 전력 병목이다" 를 뒷받침하는 공개 근거를 못 찾았다.**
   병목이 있다면 위상천이기의 **삽입손실 보상 증폭기** 쪽이고, 진짜 제약은 **열**이다
   ("heat dissipation becomes increasingly prominent... need for reduced energy
   consumption and less heat generation").

## 아직 못 지운 가능성

1. **복소 신경망(CV-CNN)의 하드웨어 구현**을 따로 안 팠다. AutoRAD-Net 이 복소 CNN 인데,
   복소 CNN 의 FPGA 구현 문헌이 실수 CNN 만큼 많은지 확인 안 했다.
2. **기능안전(ISO 26262) 관점**을 안 팠다. "An ISO 26262 compliant built-in self-test for
   77 GHz automotive radar sensors" 가 걸렸는데 안 열어 봤다. 보정이 안전 요건과 얽히면
   비용 구조가 달라질 수 있다.
3. **범퍼 보정이 실제로 얼마나 비싼 연산인지** 재 본 적이 없다. 위 3번 추론은 내 판단이지
   측정이 아니다. 고전적 보정이 정말 계수 몇 개인지 확인해야 한다.
4. **OEM/Tier1 의 실제 구현**은 공개되지 않는다. 공개 문헌의 공백이 산업의 공백은 아니다.
5. **arXiv:2602.12584** (설치 상태 반구 각도 매핑, 2026-02) 전문을 못 봤다. 가장 최신이다.

## 판정

**이 방향으로 논문을 쓰자고 권하지 않는다.** 부품이 전부 이미 있고, 남은 틈은 자명한 조합이며,
출발 전제("전력 병목")를 뒷받침하는 근거를 못 찾았다. 다만 **HLS 로 레이더 블록을 짓는 것**
자체는 배울 거리로 유효하고, PYNQ-Z2 + Vitis HLS 사례가 있어 시작점도 있다.
