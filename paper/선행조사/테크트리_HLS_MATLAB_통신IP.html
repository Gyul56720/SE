통신 IP 설계 테크트리

HLS 와 MATLAB 이 통신 IP 개발에서 실제로 먹은 층은 어디까지인가. 결론부터: 알고리즘과 중속 데이터패스는 먹었고, 고속 PHY 는 못 먹었다. 그리고 둘 중 쓸 만한 것으로 판명된 것은 예외 없이 하드 IP 나 블록 라이브러리로 굳어, HLS 를 한 층 위로 밀어 올렸다. 그 반복이 이 테크트리의 줄거리다.

세 갈래가 서로를 밀어냈다

같은 문제(사양에서 실리콘까지)를 세 진영이 다른 방향에서 공격했다. 아래 테크트리는 같은 시대 띠 안에서 세 갈래를 나란히 놓는다 — 한 갈래의 성공이 다음 시대에 다른 갈래를 어떻게 바꿨는지가 가로로 읽힌다.

HLS — C/C++ 에서 RTL 로

알고리즘을 소프트웨어로 쓰고 하드웨어를 뽑는다. EDA 업계가 30년 민 방향.

MATLAB — 모델에서 RTL 로

통신 알고리즘의 모국어에서 바로 내려간다. 황금 모델과 구현이 같은 자리에 있다.

IP · 디자인하우스

지금의 분업

층마다 주인이 다르다

이게 이 조사의 핵심 결론이다. 통신 수신기를 위에서 아래로 훑으면, 어느 층에서 HLS 와 MATLAB 이 멈추는지가 뚜렷하다.

층 1알고리즘 · 링크 설계
MATLABSimulink
황금 모델이 사는 곳. 이견 없이 MATLAB 의 영토다.
층 2베이스밴드 DSP · 등화 · 동기
HLSHDL CoderModel Composer

층 3FEC (LDPC · Polar · RS)
전문 IP 벤더하드 블록HLS(탐색용)
HLS 는 설계공간 탐색에 쓰이고 최종 제품은 IP 를 산다. RFSoC 는 아예 하드웨어로 굳혔다.
층 4PCS · MAC · FEC 카운터

층 5SerDes PHY (아날로그·혼성)

반복되는 패턴

층 2에서 HLS 로 탐색해 좋은 구조를 찾으면 → 층 3의 IP 벤더가 그것을 제품으로 만들고 → FPGA 벤더가 하드 블록으로 굳힌다(SD-FEC). 그러면 그 층은 HLS 의 대상에서 사라지고, HLS 는 한 층 위로 올라간다. HLS 의 영토는 넓어지는 게 아니라 위로 밀려 올라간다.

함의

이 지도에서 우리가 설 수 있는 자리

테크트리가 말해 주는 것

  • 층 2가 유일한 전장이다. HLS 와 MATLAB 이 겹쳐 싸우는 곳은 베이스밴드 DSP 층 하나뿐이다. 층 1은 MATLAB 것, 층 3~5는 IP 벤더 것이다. 우리가 낄 수 있는 자리가 있다면 층 2다.
  • HLS 의 약점은 문헌으로 못 박혀 있다 — 물리 인식의 부재다. 이건 추측이 아니라 TRETS 에 적힌 것이고, AutoBridge 가 +102% 로 그 크기를 쟀다. 약점이 명시돼 있다는 건 그 자리에 사람이 몰려 있다는 뜻이기도 하다.
  • "HLS 대 MATLAB" 비교 자체가 비어 있다. AMD 문서조차 Model Composer 와 Vitis HLS 를 "블록 설계자용 / C++ 설계자용" 으로만 가른다. 같은 통신 블록을 양쪽으로 짓고 동일 조건에서 PPA 를 재 본 공개 연구는 이 조사에서 안 나왔다.
  • 굳어 가는 층은 피한다. FEC 와 PCS 계측은 표준과 하드 IP 가 이미 먹었다. 거기서 새 계측기나 새 가속기를 제안하면 표준 재구현이 된다 — 앞서 한 번 확인한 바 있다.

이 문서의 한계 — 먼저 읽을 것

전부 검색 조각(snippet) 수준이다. 전문을 본 문헌은 하나도 없다. nature.com · dl.acm.org · arxiv.org 등이 이 환경에서 egress 차단이고 우회하지 않았다. 특히 연도는 조각에 적힌 것을 옮긴 것이라 ±1년 오차가 있을 수 있고, System Generator 와 HDL Coder 의 최초 출시 연도는 조각에서 확정되지 않아 "2000년대" 로만 적었다. 이 지도를 논문의 서론으로 쓰려면 각 항목의 1차 출처를 학교 망에서 다시 확인해야 한다.
