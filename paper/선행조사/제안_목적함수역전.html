비트를 줄일까 반복을 늘릴까

massive MIMO 검출기의 행렬 역변환 병목을 기존 반복법으로 없애고, HLS로 IP를 만든다. 그리고 정밀도와 반복 횟수가 서로 바꿔 쓸 수 있는지 잰다 — 분야가 아직 “미지”라고 적어 둔 칸이다.

A Matrix-Inversion-Free MMSE Detector IP in HLS: Trading Fixed-Point Word Length against Iteration Count

병목 = O(K³) 역변환알고리즘 = Gauss-Seidel MATLAB 황금모델Vitis HLS 작은 IP 하나
01 — 병목

안테나가 늘면 역변환이 터진다

massive MIMO 수신기에서 MMSE/ZF 검출은 K×K 채널 상관행렬을 역변환해야 한다. 그 비용이 O(K³) 다. 기지국 안테나가 128, 256으로 가고 RIS 소자가 수백 개로 가는 6G 방향에서 이건 그대로 벽이 된다.

문헌이 같은 말을 한다 — "ZF precoding in massive MIMO suffers from high implementation complexity of O(K³) owing to the inversion of a K×K channel correlation matrix", "linear MMSE detection achieves near-optimal performance but suffers from excessively high complexity due to the large-scale matrix inversion."

이건 우리가 발견한 병목이 아니다. 교과서에 적힌 병목이고, 그래서 이미 답도 나와 있다. 이 프로젝트는 그 답을 가져다 IP로 만드는 것이다.

02 — 쓰는 알고리즘

전부 남이 만든 것

역변환을 반복법으로 바꾸면 O(K³)가 O(K²)로 내려간다. 후보가 여럿이고 전부 수십 년 된 수치해석이다.

알고리즘성격문헌이 말하는 것
Gauss-Seidel반복, 역변환 자체가 없음 NSE보다 효율적이라고 보고됨. 1순위로 고른다
Neumann series (NSE)급수 전개 수렴이 느림. Newton 반복과 결합해 가속하는 변형들이 있음
Conjugate Gradient반복 OCD와 함께 복잡도 최저, 성능 수용 가능
Jacobi · SOR · Richardson반복 비교군으로 둔다
직접 역변환 (Cholesky)정확 황금 모델의 참값. 여기가 기준선

새 알고리즘은 하나도 만들지 않는다. Gauss-Seidel을 본체로 쓰고 나머지는 비교군이다.

03 — 우리가 묻는 것

작지만 아무도 답을 안 적어 뒀다

반복법에는 두 개의 손잡이가 있다. 반복을 몇 번 돌 것인가와 고정소수점 워드길이를 몇 비트로 할 것인가. 둘 다 정확도를 올리고, 둘 다 값이 든다.

그런데 값을 치르는 통화가 다르다. 반복을 늘리면 시간(지연·처리율)을 내고, 비트를 늘리면 면적을 낸다. 그러면 자연히 물음이 선다 —

“같은 BER을 얻는 데, 비트를 한 칸 줄이고 반복을 한 번 늘리는 게 싼가, 그 반대가 싼가?”

그리고 답이 기판에 따라 뒤집힐 수 있다. FPGA에서 반복 한 번은 이미 박혀 있는 DSP48을 한 번 더 쓰는 것이라 거의 공짜에 가깝다. ASIC에서 비트 한 칸은 곱셈기 면적에 그대로 붙는다. FPGA에서 고른 답이 칩에서 틀릴 수 있다.

04 — 그림

같은 BER, 다른 값

05 — 파이프라인

단계마다 나오는 물건

1단계 MATLAB 황금 모델 — 채널 생성 → Cholesky 직접 역변환(참값) → Gauss-Seidel 반복 BER 곡선으로 "반복 몇 번이면 직접 역변환에 붙나" 를 먼저 확인한다 산출 부동소수점 기준선 + BER 곡선 2단계 고정소수점 모델 — 같은 MATLAB 코드에 워드길이를 넣는다 산출 (워드길이 × 반복) 격자 위의 BER 표 — 03절 그림의 실제 데이터 3단계 HLS IP — ap_fixed 로 Gauss-Seidel. 워드길이·반복·병렬도를 파라미터로 C 시뮬레이션이 2단계 고정소수점 모델과 비트-정확 해야 통과 산출 합성 가능한 IP + 황금모델 대조 통과 4단계 값매김 — Vitis HLS 리포트(지연·II·자원) + Vivado 구현 + yosys/sky130 면적 산출 구성별 비용표. 03절 물음에 대한 답

1~3단계까지가 사용자가 말한 파이프라인 전부다. 4단계는 그 위에 얹는 값매김이고, 시간이 모자라면 Vitis HLS 리포트까지만 해도 이야기가 선다.

06 — 이미 있는 것

기준선이 숫자로 있다 — 좋은 일이다

이 분야는 빽빽하다. 그런데 이번엔 그게 유리하다 — 견줄 숫자가 이미 공개돼 있기 때문이다.

이미 있는 것우리에게 주는 것
Gauss-Seidel 검출기 FPGA 구현 — Virtex-7, 128 안테나 × 8 사용자, 732 Mb/s, MMSE에 근접한 오류율 비교 기준선. 우리 IP가 같은 조건에서 어디쯤인지 말할 수 있다
수정 NSE + tridiagonal 근사 — 상관 채널, 630 Mb/s 두 번째 기준선
알고리즘 비교 문헌 — GS가 NSE보다 효율적, CG·OCD가 복잡도 최저 어느 것을 고를지 우리가 정할 필요가 없다. 문헌이 정해 준다
워드길이 최적화 — MiniBit 등 20년 분야 저들의 손잡이는 비트 하나뿐이다. 우리는 비트 × 반복 격자를 본다

아직 확인 못 한 것 — 여기가 생사를 가른다

"워드길이와 반복 횟수의 맞바꿈"을 격자로 재 본 문헌이 이미 있는지 아직 모른다. 반복법 논문은 보통 반복 횟수만 쓸고, 워드길이 논문은 보통 반복을 고정한다 — 라는 것이 지금까지 본 조각들의 인상이지만, 확인한 것이 아니다. 이걸 먼저 파야 한다. 이미 있으면 이 프로젝트는 “IP를 만들어 공개한다”로 목표를 낮춘다.

07 — 한 층 더

회로가 아직 없는 자리 — 분야가 스스로 인정한 구멍

위 계획(Gauss-Seidel)은 안전하다 — 알고리즘도 회로도 이미 있다. 그래서 산출물이 “IP를 만들어 공개했다”에 머문다. 여기에 한 층을 얹으면 분야가 답을 모르는 질문에 닿는다.

Deep unfolding — 알고리즘은 있는데 회로가 거의 없다

Gauss-Seidel·CG 같은 반복법에 학습 가능한 스텝 크기를 붙여 반복 횟수를 줄이는 기법이 deep unfolding 이다. 여전히 기존 알고리즘이다 — 새로 만드는 게 아니다. 그런데 이 분야의 서베이가 이렇게 적는다:

“Hardware implementation complexity is typically not considered in the literature on deep unfolding, with only a few exceptions presenting FPGA and ASIC implementation results. It remains largely unclear how the additional trainable parameters required by unfolded algorithms affect the hardware implementation complexity and achieved throughput.”

우리 파이프라인이 정확히 이 질문에 답하는 모양이다. MATLAB 황금모델 → HLS → 자원/지연 리포트. 그게 곧 “학습 파라미터가 하드웨어로 얼마짜리냐”의 답이다.

다만 “최초 구현” 이라고 말하면 안 된다

같은 검색에서 반례가 나왔다 — deep-unfolding 으로 최적화한 Gram-domain 블록 좌표하강 검출기를 22 nm FD-SOI 로 실제 제작하고 측정까지 한 2025년 논문이 있다 (arXiv:2501.14861). 그러니 “아무도 안 했다”는 거짓이다. 안전하게 말할 수 있는 것은 “드물다” 와 “서베이가 미지라고 적었다” 까지다. 이 선을 넘지 않는다.

층 1 (안전) Gauss-Seidel 검출기 IP — 문헌 기준선(732 Mb/s)과 견준다 층 2 (질문) 같은 IP에 학습 스텝 크기를 붙인다(deep unfolding) — 반복은 줄고 비용은? 층 3 (답) (워드길이 × 반복 × 학습파라미터) 격자의 비용표 층 1만 해도 IP는 나온다. 층 2까지 가면 분야가 미지라고 적어 둔 칸을 채운다.
08 — 한계

먼저 말해 두는 약점

새 알고리즘이 없다

의도한 것이다. 산출물은 IP와 측정 데이터이지 알고리즘이 아니다. 그래서 이 작업은 “기여가 무엇이냐”는 질문에 알고리즘으로 답하지 않는다 — 공개된 IP, 재현 가능한 격자 데이터, 그리고 기존 구현과의 비교로 답한다.

sky130으로는 면적까지만

Liberty(.lib)가 없어 STA와 전력이 불가능하다(직접 확인: .lef 437개, .spice 437개뿐). 면적·게이트 수·논리 깊이까지만 말한다.

실패해도 IP는 남는다

격자를 다 재고 나서 “비트와 반복은 그냥 독립적이다”가 나와도, 합성 가능한 검출기 IP와 황금 모델과 격자 데이터는 그대로 남는다. 그리고 그 결론 자체도 아무도 안 적어 둔 것이다.
