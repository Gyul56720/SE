# evolve -- 진화는 새 경로가 아니다. 이미 있는 승격 경로가 진화다

```
진단 ──> 후보 검사(.py) ──> self_challenge prove (사고 트리에서 RED · 지금 트리에서 GREEN)
                                     │ PROVEN=1
                                     v
                            gates/ 로 승격 ──> 모든 커밋이 그 검사를 통과해야 한다
                                     │
                       eval 이 후퇴를 감시 · G020 이 삭제를 막는다
```

## 무엇이 진화하는가 -- 가중치가 아니라 읽힐 텍스트와 게이트

Claude Code 가 자기 미래 행동을 바꾸는 유일한 길이 스킬·CLAUDE.md(읽힐 텍스트)이듯,
SE 의 자기 개조도 두 가지 형태만 있다:

| 무엇 | 어떻게 | 지키는 것 |
|---|---|---|
| **게이트** (행동의 하한) | self_challenge RED/GREEN 증명 → gates/ 승격 | 증명 없는 게이트는 없다. PROVEN=0 이면 노트로도 안 남긴다 |
| **읽힐 텍스트** (digest.md · 역할표 · 물음 원장) | 원장에서 파생 -- 판정 간선·채택률·회귀 행이 내용을 정한다 | 원장이 진실, 텍스트는 파생. 손으로 고친 파생은 다음 밤일이 덮는다 |

## 상한 -- 채점표를 고쳐 실패를 없애는 길은 막혀 있다

| 게이트 | 막는 것 |
|---|---|
| G008 | self-improve 심판의 건전성 |
| G009 | 탐색 심판(verifier)의 약화 |
| **G020** | **판정 원장(eval·router·edges·intent)의 줄 삭제 · gates/*.py 파일 삭제** |

G020 자신이 이 절차로 태어났다(2026-09-11, 사고 트리에서 RED 2건 → 지금 트리 GREEN
→ PROVEN=1 승격). 파생 색인(graph/ledger.jsonl)은 대상이 아니다 -- 역사와 색인을
가르는 것이 요점이다.

## 절차 (그대로 따라 하면 된다)

```bash
# 1. 사고/진단을 후보 검사로 쓴다 (gates/__init__.py 의 규약: RULE_ID·TITLE·ORIGIN·check)
# 2. 사고가 살아 있는 트리를 짓거나 커밋을 찾는다
python3 self_challenge.py prove --candidate <후보.py> --broken-commit <사고커밋>
python3 self_challenge.py prove --candidate <후보.py> --broken-tree <디렉터리>
# 3. PROVEN=1 이면 자동으로 gates/ 에 승격된다. PROVEN=0 이면 진단이 틀린 것이다 --
#    다시 세워라. 증명 안 된 진단은 노트로도 남기지 마라.
```

디스코드: `!진화` (현황 -- 게이트 수 · 최근 승격 · 상한, 읽기라 공개 채널도 됨).

## intent 와의 관계

무엇을 진화시킬지(목표)는 intent 원장이 정하고 -- **승인된 목표만 집힌다** -- 어떻게
바뀌는지(수단)는 이 경로가 정한다. 목표가 승인 없이 실행되지 않는 것과 게이트가 증명
없이 생기지 않는 것은 같은 규율의 두 면이다.
