# intent -- 목표 원장. 승인 없는 목표는 집히지 않는다

```
제안(에이전트도 가능) ──> ledger.jsonl (append-only 사건) ──승인(사람)──> 집기()에 나온다
                                                              │
                                        끝: 판정명령 exit 0 이 정한다 (말이 아니라)
```

## 경계 -- 무엇이 코드로 지켜지고 무엇이 화이트리스트로 지켜지나

| 규칙 | 지키는 것 |
|---|---|
| 승인 없는 목표는 안 집힌다 | `store.집기()` -- 승인 사건이 원장에 없으면 안 돌려준다 |
| 승인 주체는 사람이다 | `!목표 승인` 이 관리 채널 화이트리스트 안에서만 들린다. CLI 승인은 셸을 가진 사람의 것이고, 원장에 누가 했는지 남는다 |
| "끝났다" 는 말이 아니라 명령이 정한다 | 판정명령이 있으면 그 exit 0 만 끝 사건을 적는다. 없으면(코드가 못 재는 목표 -- 관할 밖을 적는 규율) 사람 선언으로만 끝난다 |
| 역사는 안 지워진다 | 원장은 append-only. **G020 이 커밋 경로에서 강제한다** |

밤 루프·에이전트의 다음 일감은 `집기()` 로만 받는다: `python3 intent/store.py --다음`.

## 쓰기

```bash
python3 intent/store.py --목록
python3 intent/store.py --제안 "graph 밤일을 cron 에 건다" --판정 "crontab -l | grep -q night.sh"
python3 intent/store.py --승인 <id>       # 이때부터 집힌다
python3 intent/store.py --다음            # 승인된 미완 목표 (없으면 끝값 3)
python3 intent/store.py --끝 <id>         # 판정명령이 돌아 exit 0 이어야 끝난다
python3 tests/test_intent.py
```

디스코드: `!목표` / `!목표 다음` (공개 읽기) · `!목표 제안/승인/끝/버림` (관리 채널만).

## 읽힐 텍스트와의 융합

승인된 목표는 `graph/digest.md`(밤마다 원장에서 다시 지어지는 요지문)에 절로 얹힌다 --
에이전트와 사람이 같은 문서에서 "지금 무엇이 승인돼 있나" 를 읽는다. 원장이 진실이고
digest 는 파생이다(evolve 규율 그대로).
