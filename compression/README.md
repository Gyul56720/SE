# compression — 실제 가중치로 압축 코덱을 탐색한다

목표: **int8 을 압축력과 복원력 두 축에서 동시에 이기는 코덱**을 자가개선 루프로 찾는다.
JPEG 을 사람이 설계한 자리에 탐색을 놓되, 무엇이 더 나은가는 LLM 이 아니라 심판이 정한다.

```
실제 모델 가중치 ──> design 셋 ──> orchestrator 가 코덱을 쓴다
                                        │
                                  judge 가 격리 실행해 채점 (LLM 이 만든 심판이 아니다)
                                        │
                      통과 ──> holdout 셋으로 재채점 ──> 두 축 모두 이기면 챔피언 교체
```

## 파일

| 파일 | 역할 |
|---|---|
| `weights.py` | safetensors Range 요청으로 실제 모델 가중치의 행렬 몇 개만 받아 캐시. 종류별 층화로 design/holdout 분리 |
| `activations.py` | 레이어에 **실제로 들어오는 활성치** 표본. 심판이 왜곡을 재는 방향을 정한다 |
| `bounds.py` | 이론적 한계와 그 한계가 선 가정을 분리해서 잰다. 코덱을 만들지 않는다 |
| `judge.py` | **독립 심판.** 코덱을 별도 프로세스로 격리 실행해 실제 blob 길이와 `P(x)=P'(x)` 오차를 재고 int8 과 비교 |
| `_worker.py` | encode/decode 를 각각 따로 돌리는 자식 프로세스 |
| `search.py` | 자가개선 루프. orchestrator 런의 최종 노드 verifier 를 judge 로 **갈아끼운다** |
| `codecs/int8.py` | 기준선. 채널별 대칭 int8 (max-abs 스케일) |
| `codecs/fp16.py` | 상한 기준선. 16 bits, 오차 ~0 |
| `codecs/ternary_b158.py` | BitNet b1.58 3진 + 5진 패킹. 1.73 bits, 오차 0.78 |
| `codecs/int8_clip.py` | MSE 최적 클리핑 + fp16 스케일. 비트만 이기고 오차에서 진다(기각) |
| `codecs/hadamard_int.py` | **현 최선.** 블록 대각 아다마르 회전 + 7비트 블록 양자화 |

## 코덱 계약

```python
def encode(W: np.ndarray) -> bytes      # W 는 2차원 float32
def decode(blob: bytes) -> np.ndarray   # 같은 모양의 float32
```

`decode` 는 blob 말고 아무것도 받지 않는다. shape·스케일 등 복원에 필요한 모든 것이
blob 안에 있어야 한다. 표준 라이브러리 + numpy 만.

## 두 축

- **압축력** `bits/weight = 8 * len(blob) / W.size` — 코덱의 주장이 아니라 실제 바이트 수.
  압축배율의 **분모는 16** 이다. 실제 모델은 bf16 으로 배포되므로 원본이 16 bits/weight 다.
  (예전 코드는 32 로 박혀 있어 배율이 전부 2배 부풀어 있었다 — int8 이 3.9배로 표시됐고
  fp16 이 "2배 압축"으로 보였다. bf16 을 fp16 으로 바꾸는 건 압축이 아니다.)
- **복원력** `||W@X - W'@X|| / ||W@X||` — 행렬곱 출력의 오차. 레이어를 프로그램
  `P(x) = W@x` 로 보면 `P(x) ≈ P'(x)` 검사다.

  **`X` 를 무엇으로 두느냐가 이 축의 성격을 통째로 바꾼다.** `X ~ N(0,I)` 로 두면 이 값은
  `‖ΔW‖_F/‖W‖_F` 로 떨어진다(실측 비율 0.96) — 이름과 달리 가중치 오차를 재는 것이고,
  축이 둘인 척하지만 정보는 하나다. `activations.py` 로 실제 활성치를 붙이면 실제 입력
  방향으로 잰다. 심판은 두 값(`func_err`, `func_err_iso`)을 항상 나란히 남기고, 일부
  텐서에만 활성치가 있으면 지표가 섞이므로 **거부한다**.

집계는 텐서별 산술 평균이 아니라 **파라미터 수 가중 평균**이다. 산술 평균은 작은 텐서와 큰
텐서에 같은 표를 준다 — Qwen2.5-0.5B 한 레이어에서 MLP 가 87.7%, q+o 가 10.8%, GQA 라
k+v 는 1.5% 인데, 그것들을 동급으로 세면 작은 텐서에만 좋은 코덱이 이긴다. 가중 평균의
bits/weight 는 정의상 (전체 blob 비트)/(전체 파라미터) 라, "이 코덱으로 모델을 담으면 몇
비트인가"라는 원래 묻고 싶던 값이 된다.

한 축만 이기는 것은 통과가 아니다. 3진은 압축력을 4.7배 이기고 복원력에서 31배 진다.
fp16 은 복원력을 이기고 압축력에서 2배 진다. `int8_clip` 은 경계에 있다 — 비트는 확실히 이기지만(8.070 < 8.138) 오차가 int8 과 5번째
자리까지 동점이라, 등방으로 재면 기각되고 활성치로 재면 통과한다. **마진이 잡음인 코덱은
지표를 손볼 때마다 판정이 뒤집힌다.** 그래서 회귀 검사의 red 사례에서 뺐다.

## 심판이 막는 것 / 못 막는 것

**막는다** (실측으로 확인, `tests/test_compression_judge.py`)

| 부정행위 | 어떻게 막히나 |
|---|---|
| 원본을 모듈 전역에 숨기기 | encode/decode 가 **다른 프로세스**라 전역이 사라진다 |
| blob 에 원본 경로만 담기 | decode 전에 원본 `.npy` 를 **지운다** |
| 임시 디렉토리에 원본 은닉 | encode 전후 파일 스냅샷 비교로 잡는다 |
| 실행마다 다른 결과 | 두 번 encode 해서 blob 이 같아야 한다 |
| decode 가 모양을 잃음 | 원본 shape 과 비교한다 |
| 비트 수 속이기 | 실제 blob 길이로만 잰다 (원본 그대로 담으면 32 bits) |
| 설계한 행렬로 채점 | holdout 셋은 설계 과정이 보지 못한다 |
| 한 종류에만 좋은 코덱 | design/holdout 을 텐서 **종류**별로 층화한다 |

**못 막는다** — 코덱이 `/tmp` 밖 절대경로에 원본을 숨기는 것. 진짜 격리는 컨테이너/
네임스페이스가 필요하다. 여기서 막는 것은 "무심코 새는" 경로와 "그럴듯하게 속이는" 경로다.

## 쓰는 법

```bash
# 1. 실제 가중치를 받는다 (네트워크가 되는 곳에서 한 번)
python3 compression/weights.py fetch                      # 기본 Qwen/Qwen2.5-0.5B
python3 compression/weights.py fetch --repo <repo> --file model.safetensors

# 네트워크가 없으면 배관 시험용 합성 (실제 성능이 아니고 결과에 표시된다)
python3 compression/weights.py synthetic

# 2. 코덱 하나 채점
python3 compression/judge.py --codec compression/codecs/int8_clip.py
python3 compression/judge.py --codec <내_코덱.py> --json

# 3. 자가개선 루프 (GEMINI_API_KEY 필요)
python3 compression/search.py --status        # 현재 챔피언 점수
python3 compression/search.py --rounds 5

# 4. 심판 자신의 회귀 검사
python3 tests/test_compression_judge.py

# 활성치 (왜곡을 어느 방향으로 잴 것인가)
python3 compression/activations.py capture      # VM: 모델을 돌려 실제 활성치를 후킹
python3 compression/activations.py synthetic    # 여기: 배관 시험용 (실제 활성치 아님)

# 이론적 한계가 어디이고 어떤 가정에 매달려 있는가
python3 compression/bounds.py
```

## 합성 데이터로는 답이 안 나온다

합성 가우시안으로 채점하면 "가우시안을 잘 압축하는 코덱"이 나온다. 실제 LLM 가중치는
채널마다 스케일이 다르고 소수의 outlier 가 채널의 해상도를 잡아먹는다 — int8 per-channel 이
표준이 된 이유가 그 구조다.

실측: 처음 만든 합성 가중치는 행별 `max/std` 가 3.2 였고, 그 데이터에서는 MSE 최적 클리핑이
**단 한 채널도** 고르지 않았다(전부 비율 1.0 = 기존 max-abs). outlier 를 행마다 넣어
`max/std` 를 8.7 로 올리자 그때부터 클리핑이 의미를 갖기 시작했다. 실제 가중치의 분포는
그보다 더 극단적이다. `judge` 는 합성으로 돌면 결과에 `⚠ 합성 데이터`를 찍는다.

## 지금 상태

합성 데이터 기준 holdout 셋 (실제 가중치를 받으면 숫자가 달라진다):

| 코덱 | bits/weight | 압축 (bf16 대비) | 함수오차 | 판정 |
|---|---|---|---|---|
| `fp16` | 16.00 | 1.00x | 0.00021 | 복원력만 승 |
| `int8` (기준선) | 8.14 | 1.97x | 0.02595 | — |
| `int8_clip` | 8.07 | 1.98x | 0.02598 | 압축력만 승 |
| **`hadamard_int`** | **7.16** | **2.24x** | **0.01217** | **두 축 승** |
| `ternary_b158` | 1.74 | 9.21x | 0.79432 | 압축력만 승 |

`hadamard_int` 가 비트를 12% 줄이면서 오차를 절반으로 낮춘다. 회전 행렬은 `n` 하나로
결정되는 상수라 **blob 에 한 바이트도 담지 않는다** — 같은 크기의 서로 다른 두 행렬이
똑같은 `H` 를 받으므로 `H` 를 통해 `W` 의 정보가 새어나갈 수 없다. 학습된 회전은 이와 달리
`W` 에 의존하므로 저장해야 하고, `n=896` 이면 12.8M 비트가 든다.

### 왜 회전이 통하는가

`H` 가 직교면 `W' = quantize(W·H)·Hᵀ = W + E·Hᵀ` 이고 `‖E·Hᵀ‖_F = ‖E‖_F` 라 되돌려도
오차가 안 커진다. 그런데 `W·H` 는 `W` 보다 양자화하기 쉽다 — 블록 max-abs 의 스텝은
`Δ = 2·max|w|/(2^b−2)` 이고 블록 안 최댓값 하나가 그 블록 전체의 오차를 정하는데, 회전이
그 봉우리를 없앤다. 실측(256차원 합성): 첨도 596 → 9.8, 행별 `max/std` 8.50 → 2.79.

### 실제 차원은 2의 거듭제곱이 아니다

```
896 = 2^7 x 7      4864 = 2^8 x 19      151936 = 2^7 x 1187
```

실베스터 아다마르는 `2^k` 에서만 나온다. 그래서 `n` 을 나누는 가장 큰 2의 거듭제곱 크기로
**블록 대각** 아다마르를 쓴다. 블록 안에서만 섞이지만 실측상 손해가 거의 없다:

| 섞는 폭 | 256 | 128 | 64 | 32 | 16 |
|---|---|---|---|---|---|
| 오차 개선 | 3.42x | 3.56x | 3.31x | 3.04x | 2.65x |

128 이면 전체 회전과 동등하고 32 까지도 이득의 대부분이 남는다. 합성 가중치도 홀수부를
실제와 맞춰 만든다(224 = 2^5·7, 304 = 2^4·19) — 정사각 256 으로 시험하면 이 문제가
통째로 가려진다.

## 하한: 무엇이 정리이고 무엇이 가정인가

`bounds.py` 가 세 개를 구별해서 낸다. 합성 데이터 기준:

| | bits/weight | 압축 |
|---|---|---|
| (A) 가우시안 `R(D) = -log2(e)` | 5.443 | 2.94x |
| (B) 섀넌 하한 `h(X) − ½log2(2πeD)` | 5.426 | 2.95x |
| (C) 활성치를 아는 하한 (회전 없이) | **3.132** | **5.11x** |
| (C') 활성치를 아는 하한 (회전 후 남는 이득만) | 4.579 | 3.49x |

**(A) 는 하한이 아니라 상한이다.** 가우시안은 주어진 분산에서 엔트로피를 최대화하므로 어떤
분포든 그보다 작거나 같다. 한 번 반대로 적었다가 고쳤다.

**(C) 조차 하한이 아니다.** 남은 가정 둘:
- **i.i.d.** — 실측으로 깨진다. 왼쪽 이웃 문맥만으로 조건부 엔트로피가 0.065 bits 낮다
  (유한표본 편향 0.054 를 뺀 값).
- **`W` 를 복원해야 한다** — 압축 모델이 지켜야 하는 건 `W` 가 아니라 **함수**다. 레이어를
  통째로 재파라미터화해도 출력만 같으면 된다(BitNet 학습이 그것이다). 그러면 "W 복원"의
  율-왜곡 하한은 아무것도 말해주지 않는다.

### 설계 충돌: 회전 vs 활성치 비트배분

```
변환 부호화 이득   회전 전 2.294 bits  ->  회전 후 0.847 bits   (63% 파괴)
```

아다마르 회전은 가중치를 균질하게 만들어 양자화를 쉽게 하지만, **같은 이유로 활성치도
등방으로 만들어** "이 채널은 안 중요하다"를 표현할 수 없게 한다. 지금 챔피언
`hadamard_int` 는 이 1.45 bits 를 버리고 있다. 둘 다 가지려면 부분 이동(AWQ/SmoothQuant
의 α) 같은 중간점이 필요하다.

### 이 숫자들은 아직 내 가정을 되잰 것이다

활성치 이득은 outlier 구조에 **두 자릿수로** 민감하다:

| 큰 채널 비율 | 배율 | 이득 (bits) |
|---|---|---|
| 0.1% | 30 | 0.50 |
| 1% | 30 | 1.61 |
| 3.1% | 30 | **2.28** ← 합성이 쓰는 값 |
| 1% | 100 | 3.27 |
| 10% | 100 | 4.32 |

합성 활성치는 3.1% 채널을 30배로 둔 것이고 **그건 내가 고른 값**이다. 실제 값은 VM 에서
`activations.py capture` 를 돌려야 안다. 그것이 지금 가장 큰 미지수다.
