# router -- 역할이 모델을 고른다

```
부르기("디렉터", 물음) ──> claude -p (3연속 실패 -> gemini 강등, 탐침으로 복귀)
부르기("배우"|"화자", 글감) ──> orchestrator/llm_pool.call (쿼터·RPM·전적은 그 층이)
부르기("추출기", 쪽) ──> 같은 풀, prefer="gemma" (산문의 분당 한도를 안 깎는다)
부르기("판정기", ...) ──> **거절** -- 판정은 코드가 한다
        │
        └── 호출마다 ledger.jsonl: 역할·바탕·라벨·걸린초·글자수·성공 (+ 채택표시)
```

## 왜 있나

CLAUDE.md 의 분업(디렉터만 Claude, 산문은 Gemini)은 novel/ 안에 박혀 있었다. 같은
판단이 필요한 자리마다 다시 짜면 두 벌이 갈라진다. 여기는 그 판단을 **닫힌 역할표**
로 빼고, 실제 호출은 **이미 있는 층을 그대로** 쓴다:

| 층 | 어디 것 | 무엇을 지는가 |
|---|---|---|
| Gemini 풀 | `orchestrator/llm_pool.call` | 쿼터·RPM 간격·명부·전적·동시 발사 전부 |
| Claude | `novel/drive.claude_code_llm` | 구독 청구 · ANTHROPIC_API_KEY 안 물려주기 |
| 강등·탐침 | `novel/overnight.Director` 의 수학 | 3연속 실패 강등 · 탐침 복귀 · 간격 두 배 |

`판정기` 가 표에 있는 것이 요점이다 -- 모델을 달라고 하면 **거절하고 코드 심판
(verify.대조 · gatekeeper · 도메인 exit code)을 가리킨다.** thinking 예산 같은
칸은 표가 닫혀 있으므로 필요해질 때 표에만 더한다.

## 비용 원장 -- 배치가 옳은지는 말이 아니라 수가 정한다

호출마다 `router/ledger.jsonl` 에 남는다: 역할 · 바탕(claude / gemini / gemini(물러섬))
· 라벨(실제 모델) · 걸린초 · 글자수 · 성공. 부르는 쪽이 `채택표시(id, 채택여부)` 로
"그 답이 verifier 를 통과해 실제로 쓰였는가" 를 이어 적으면, `router/check.py` 가
심판한다:

- **물러섬 비율** -- 디렉터 최근 50건의 태반이 물러섬이면 빨강. claude 경로가 죽었는데
  답은 계속 나와서 화면에는 안 보이는 상태다.
- **채택률 역전** -- 표본이 차면(각 20건) 비싼 길의 채택률이 싼 길보다 낮을 때 빨강.
  분업의 근거가 뒤집혔다는 신호이고, 그때는 역할표를 내린다.

이 심판이 eval 의 `경로` 갈래로 돈다 -- 후퇴(초록→빨강)를 eval 원장이 잡는다.

## 쓰기

```bash
python3 router/call.py --표          # 역할표 (호출 0회)
python3 router/call.py --요약        # 비용 원장 요약 (호출 0회)
python3 router/check.py             # 심판: 0 성함 · 1 빨강 · 3 재료 부족
python3 tests/test_router.py        # 배선 검사 (가짜 호출기로 강등·복귀까지)
```

```python
from router import call as R
r = R.부르기("디렉터", "다음 회차 주제 한 줄")
R.채택표시(r["id"], 검증통과)
```

디스코드: `!경로` · `!경로 요약` · `!경로 심판` (전부 읽기라 공개 채널도 됨).

## 안 하는 것

- **--all-claude 류.** 산문을 비싼 모델로 돌리는 길은 표에 없다. CLAUDE.md 규율 그대로.
- **호출층 두 벌.** 여기는 표와 원장뿐이다 -- 재시도·쿼터 로직을 한 줄도 다시 짜지 않았다.
- **novel 즉시 이식.** novel/overnight.Director 는 그대로 둔다(돌고 있는 밤 런의 심장이다).
  다음에 novel 이 이 표를 부르게 옮기면 그때 그쪽 사본을 지운다.
