# jaso — 자기소개서를 **짓지 않고 도출한다**

```
경험 원장 ─┐
문항 분해 ─┼─> 재료만 준다 ─(Gemini)─> 여러 벌 ─> 심판(코드) ─> 통과한 것 + 못 본 것
JD 대조   ─┘        ↑                                  │
                    └── 관문을 모른다                  └── 위반 지목만 돌려보낸다
```

이 문서는 **설계와 재료 목록**이다. 코드는 아직 없다.

---

## 1. 왜 일반 LLM 이 자소서에서 지는가

"자소서 써 줘" 한 줄에 GPT/Claude/Gemini 는 **읽히는 글**을 낸다. 지는 자리는 문장력이
아니다. 여섯 군데다.

| | 실패 모드 | 무엇이 일어나나 | 기계가 볼 수 있나 |
|---|---|---|---|
| F1 | **수치 창작** | "매출 30% 향상". 사용자는 20% 라고 했거나 아예 안 잰 수다 | **볼 수 있다** — 원장 대조 |
| F2 | **역할 승격** | 원장은 '참여', 자소서는 '주도·총괄'. 면접에서 깨진다 | **볼 수 있다** — 낱말 대조 |
| F3 | **기간 충돌** | 같은 반년에 인턴 둘을 풀타임으로 했다고 적힌다 | **볼 수 있다** — 구간 겹침 |
| F4 | **문항 빗나감** | 문항이 요건 셋을 묻는데 하나만 답한다. 특히 "역량을 지목하라 + 그 역량을 기른 경험" 에서 **지목한 역량과 든 경험이 다른 것**이 된다 | **볼 수 있다** — 요건 대조 |
| F5 | **치환 가능** | 회사명·직무명만 바꾸면 다른 회사에 그대로 들어간다. 읽는 사람이 제일 먼저 알아본다 | **볼 수 있다** — 아래 P001 |
| F6 | **글자 수** | 1000자 제한에 1180자. 제출 폼에서 잘린다 | **볼 수 있다** — 셈 |

**여섯 다 문장력 문제가 아니라 대조 문제다.** 그리고 여섯 다 일반 LLM 은 **자기가
자기를 검사하지 않는다** — 한 방에 쓰고 끝낸다. 이 저장소는 이미 그 자리에 답을 갖고 있다.

### 오른쪽 칸이 비어 있다는 것을 적어 둔다

위 표에 "일반 LLM 에서 몇 %" 가 없다. **아직 안 쟀기 때문이다.** `law/METHOD.md` 4-1 은
법률 LLM 환각을 58~88% 로 **인용**할 수 있었지만(Dahl 외 2024), 자소서에는 그런 것이 없다.
지어내면 이 저장소가 금지한 바로 그 짓이다 — "연구에 따르면 78%가".

그래서 **재는 것을 5차 단계로 둔다**(`jaso/bench.py`). 그 전까지 위 표는 가설이라고 적는다.

## 2. 새로 만드는 것이 적다 — 네 모듈이 이미 있다

| 이 저장소에 이미 있는 것 | jaso 에서 무엇이 되나 |
|---|---|
| `law/corpus.py` 조문 원장 | **`jaso/ledger/` 경험 원장** — 사용자의 실제 이력 |
| `law/gate.py` L001 인용 실재성 | **J001 이 경험이 원장에 실재하는가** |
| `law/wording.py` W005 용어 치환('준용'→'적용') | **J004 역할 승격('참여'→'주도')** |
| `brief/gate.py` B004 다시 셈해도 같은가 | **J002 자소서의 수가 원장의 수와 같은가** |
| `law/issue.py` → `reason/` 요건표·두 정거장 | **`jaso/item.py` 문항을 요건으로 분해** |
| `law/write.py` **생성자가 관문을 모른다** | `jaso/write.py` 그대로 |
| `mathdrift/spread.py` 발산에 심판을 안 싣는다 | 한 문항에 **여러 벌** 뽑고 심판이 고른다 |
| `brain/route.py` R004 **관할 밖을 적었는가** | "합격하나" 는 판정 밖이라고 보고서에 적는다 |
| `dig/` 받기·뽑기 | 문항·작법·JD 수집 |

**새것은 둘뿐이다**: 문항 분해(`item.py`)와 치환 검사(`swap.py`).

## 3. 재료 — 다섯 가지, 그중 하나는 내가 못 만든다

### 재료 1. 경험 원장 (`jaso/ledger/*.json`) — **사용자만 줄 수 있다** ★

이것이 없으면 **나머지가 전부 무의미하다.** 원장이 없으면 J001~J004 가 전부 '미검증' 이
되고, 미검증 위에 쓴 자소서는 그냥 일반 LLM 출력이다.

`law/write.py` 가 조문 원문을 안 주면 모델이 기억에서 꺼내 온다고 적어 둔 자리와 같다.
자소서에서 "기억" 은 곧 **사용자의 인생을 지어내는 것**이다.

스키마 초안 — 항목 하나:

```json
{
  "id": "P-2025-추천",
  "갈래": "프로젝트",
  "이름": "사내 추천 시스템 개편",
  "곳": "○○ 인턴",
  "언제": ["2025-03", "2025-08"],
  "역할": "참여",
  "한일": ["로그 파이프라인 재작성", "A/B 지표 대시보드"],
  "잰것": [{"무엇": "클릭률", "전": 2.1, "후": 2.6, "단위": "%", "어떻게": "2주 A/B, n=48,000"}],
  "쓴것": ["Python", "BigQuery"],
  "같이": 4,
  "증빙": "커밋 로그 · 최종 보고서"
}
```

규약 세 개가 관문을 먹여 살린다:

- **`역할` 은 닫힌 목록이다** — `주도` · `참여` · `보조` · `관찰`. 자유 서술이면 J004 가 못 본다.
- **`잰것` 은 재는 법(`어떻게`)까지 적는다.** 없으면 그 수는 자소서에 못 쓴다. 안 잰 수를
  쓰는 것이 F1 이다.
- **`언제` 는 구간이다.** J003 이 겹침을 본다.

`증빙` 이 비어 있어도 원장에 **넣는다**. 다만 보고서에 "증빙 없음" 으로 표시한다 —
`reason/` S005 가 출처를 검사가 아니라 **표시**로 다루는 것과 같은 자리다.

### 재료 2. 문항 원장 (`jaso/corpus/문항/`)

실제 기업·공기업 자소서 문항과 글자 수 제한. 채용 공고문이 원본이다.

### 재료 3. 작법 원장 (`jaso/corpus/작법/`)

좋은 자소서·포트폴리오를 쓰는 법. **출처를 반드시 같이 적는다.**
대학 취업지원센터 공개 자료 · 고용노동부/워크넷 · NCS 기반 채용 안내서 · 공개된 채용 담당자 글.

> **선 하나를 여기서 긋는다 — 남의 합격 자소서 본문은 안 받는다.**
> 문항(공고문)과 작법(가이드)만 받는다. `dig/README.md` 의 "문을 부수지 않는다" 와 같은 선이고,
> 남의 자소서를 재료로 삼으면 그 문장이 새 자소서에 스며든다. 그것은 표절이지 참고가 아니다.

### 재료 4. JD (지원 공고) — 건마다

사용자가 URL 을 준다 → `dig/` 로 받는다. 요구역량·자격요건·인재상을 뽑아 P005 대조에 쓴다.

### 재료 5. Gemini 키

산문이 토큰의 대부분이다. `CLAUDE.md` 의 배치를 그대로 따른다 — **디렉터만 Claude, 산문은 Gemini.**
여기서 Claude 가 하는 것은 문항 분해 정도이고, 그것도 코드가 할 수 있으면 코드가 한다.

## 4. 여기서는 못 돌린다 — 실측

밀기 전에 이것부터 적는다. 이 저장소가 다섯 번 앓은 병이 "돌려 보세요" 였다.

```
$ python3 -c "... llm_pool.api_keys()"        키 개수: 0
$ python3 dig/run.py --url 'https://www.jobkorea.co.kr' --앞문만
    [못받음] 프록시가 끊었다 (Tunnel connection failed: 403 Forbidden)
```

| | 이 에이전트 컨테이너 | 사용자 VM |
|---|---|---|
| Gemini 키 | **0개** | 있다 |
| 나가는 길 | **막혔다**(프록시 403) | 열려 있다 |
| 그래서 여기서 되는 것 | 스키마·관문·분해·검사(가짜 LLM·가짜 원장) | 수집과 생성 |

**여기서 자소서를 지어내 보여 주지 않는다.** `CLAUDE.md` 의 소설 규칙과 같다 —
파이프라인이 만든 것이 아닌 것을 보여 주면 결과를 오해하게 만든다.

## 5. 모듈 배치

```
jaso/
  ledger.py    경험 원장 읽기·스키마 검사       ← brief/ledger.py
  schema.json  원장 스키마 (역할 닫힌 목록 등)
  fetch.py     문항·작법·JD 를 받아 원장에      ← law/fetch.py + dig/
  corpus.py    받은 것을 읽는 자리              ← law/corpus.py
  item.py      ★ 문항 → 요건표                 ← reason/schema.py 로 넘긴다
  plan.py      문항 × 원장 → 어느 경험을 쓸까(근거 지정)
  write.py     ★ 생성자. Gemini. 관문을 모른다  ← law/write.py
  gate.py      ★ 심판. LLM 안 쓴다             ← law/gate.py
  swap.py      ★ 치환 검사 (P001)              ← 새것
  wording.py   상투구·수동태·과장어 계량        ← novel/wording.py
  report.py    보고서(통과·미검증·관할밖)       ← brief/report.py
  mutate.py    RED/GREEN — 관문이 진짜 잡나     ← law/mutate.py
  bench.py     일반 LLM 한 방 vs 이 파이프라인  ← law/bench.py

dig/
  find.py      ★ 질의 → 주소들 (지금 저장소에 없다)
```

**`dig/find.py` 가 빠져 있다는 것이 이번에 드러났다.** `dig/` 는 주소를 받아 캐는 자리고,
"자소서 문항을 찾아라" 는 주소가 아니라 **질의**다. 그 한 걸음이 없어서 지금은 사람이
주소를 손으로 줘야 한다. 이건 jaso 만의 문제가 아니므로 `dig/` 안에 만든다.

## 6. 관문 — 초안

`law/gate.py` 의 3분법을 그대로 쓴다. **`hard` 기각 · `soft` 보고 · `미검증` 은 통과가 아니다.**

### J 계열 — 사실 (원장 대조)

| | | 무엇을 보나 | |
|---|---|---|---|
| J001 | 근거 실재 | 자소서의 경험·기관·기술이 원장에 있는가 | hard (원장 필요) |
| J002 | 수치 일치 | 쓴 수가 원장의 그 값과 같은가. **`잰것.어떻게` 가 빈 수는 쓰면 위반** | hard (원장 필요) |
| J003 | 기간 정합 | 원장과 맞는가 · 풀타임 구간이 겹치지 않는가 | hard (원장 필요) |
| J004 | 역할 승격 | 원장 `참여` 를 '주도/총괄/리드' 로 올려 썼는가 | hard (원장 필요) |
| J005 | 글자 수 | 문항의 상·하한 안인가 (공백 포함/제외 규약을 문항에서 읽는다) | hard |
| J006 | 문항 응답 | `item.py` 가 뽑은 요건에 본문이 다 닿았는가 | hard |
| J007 | 구조 | 상황·행동·결과가 다 있는가 | soft |
| J008 | 자기모순 | 한 벌 안에서 같은 경험에 다른 수·다른 역할을 달았는가 | hard |

### P 계열 — 설득력 (여기가 일반 LLM 을 넘는 자리)

| | | 무엇을 보나 | |
|---|---|---|---|
| **P001** | **치환 가능** | 회사명·직무명을 지우면 문단에 **원장에서 온 앵커가 하나도 안 남는가**(고유 수치·기간·기관·기술). 남는 게 없으면 그 문단은 어느 회사에나 들어간다 | hard |
| P002 | 주장-근거 | '열정적' · '책임감' 같은 형용사 주장 뒤에 원장 근거가 붙었는가 | soft |
| P003 | 상투구 | 실측 사전(`귀사의 인재상에 부합` · `어릴 적부터`) 밀도 | soft |
| P004 | 수동·명사화 | '~되었습니다' 밀도. 행위자가 사라지면 기여가 안 보인다 | soft |
| P005 | JD 대조 | JD 요구역량 중 몇 개에 닿았는가 | soft (JD 필요) |
| P006 | 재탕 | 한 벌의 여러 문항이 같은 경험을 돌려 쓰는가 | soft |

**P001 이 이 에이전트의 서명이다.** LLM 없이 판정된다 — 문단에서 원장 앵커를 세면 된다.
그리고 이것이 사람이 자소서를 읽고 3초 만에 내리는 바로 그 판정이다.

### 미검증을 통과로 세지 않는다

원장이 비면 J001~J004 는 판정이 아니라 **미검증**이다. 보고서가 검증한 수와 못 한 수를
**항상 같이** 적는다. `law/gate.py` 가 "코퍼스가 비었는데 인용을 통과시키면 심판이 있다는
착각만 생긴다" 고 적어 둔 자리다.

## 7. 생성자는 관문을 모른다 — 그리고 고쳐 쓰기의 함정

`law/write.py` 가 두 번 덴 기록을 그대로 물려받는다: 관문을 프롬프트에 실으면
`novel/gate.py` 처럼 원고가 균질해지고 `mathdrift/spread.py` 처럼 **발산이 사양서가 된다.**

그래서 `jaso/write.py` 의 프롬프트에는 J·P 이름이 **한 글자도 없다.** 주는 것은 셋뿐이다.

1. **문항 원문**과 글자 수
2. **그 문항에 쓸 원장 항목**(plan.py 가 고른 것) — 원문 그대로
3. 원장 밖은 지어내지 말고 **비워 두라**는 지시

`tests/test_jaso_write.py` 가 프롬프트에 관문 낱말이 안 실리는 것을 고정한다.

### 고쳐 쓰기에서 관문이 새는 자리

위반이 남으면 다시 쓰게 해야 하는데, "J002 를 고쳐라" 라고 하면 그 순간 관문을 알려 준
것이다. 그래서 **위반 이름을 안 주고 사실만 준다.**

```
고칠 것:  "클릭률을 30% 개선했습니다"
원장:     클릭률 2.1% -> 2.6% (2주 A/B, n=48,000)
지시:     이 문장이 원장과 다르다. 원장에 맞게 다시 써라.
```

모델은 무엇이 틀렸는지 알지만 **무엇을 검사받는지는 모른다.** 재작성은 **3회로 끊는다** —
그 뒤로도 남으면 고치지 말고 **보고서에 그대로 적는다.**

## 8. 한 벌이 아니라 여러 벌 — 발산과 판정을 가른다

일반 LLM 이 지는 마지막 자리가 이것이다. **한 번 쓰고 끝낸다.**

```
문항 하나 ──> n 벌 (온도·시점·고른 경험을 달리) ──> 관문 ──> hard 0 인 것들 ──> P 계열 점수로 고름
                       ↑                                              │
              심판을 안 싣는다                            고른 이유를 보고서에 적는다
```

`seek/` 가 부모·자식 판정으로 '도약' 을 기계 판정한 자리와 같은 배치다. 사람이 고르지 않는다.
다만 **고른 이유는 사람이 읽을 수 있게 적는다** — 어느 관문에서 다른 벌들이 떨어졌는지.

기본 `n=4`. 호출이 곧 쿼터이므로 `--벌 n` 으로 조절한다.

## 9. 관할 밖 — 시작할 때 적는다

`brain/README.md` R004 그대로. **어떤 물음도 통째로 기계 판정되지 않는다.**

| 갈래 | 이 파이프라인이 안 하는 것 |
|---|---|
| 전망 | **"이거 쓰면 붙나요"** — 안 잰다. 원장이 없다 |
| 가치 | 이 회사가 나에게 맞는가 · 어느 경험이 더 '멋진가' |
| 처방 | 무엇을 지원해야 하는가 |
| 인과 | 떨어진 이유 |

보고서 첫 절이 **원장과 문항**이고, 끝 절이 **안 본 것**이다. 결론은 원장에 조건부다.

## 10. 검사 계획 — "검사하지 않은 초록불이 검사한 빨간불보다 나쁘다"

| | 무엇을 붙드나 |
|---|---|
| `tests/test_jaso_ledger.py` | 스키마 위반(닫힌 목록 밖 역할 · `어떻게` 없는 수)이 **입구에서** 걸리는가 |
| `tests/test_jaso_item.py` | 문항 하나가 요건 여럿으로 갈리는가 · 교차 요건(F4)이 잡히는가 |
| `tests/test_jaso_gate.py` | **`mutate.py` RED/GREEN** — 성한 자소서에 20%→30% 를 심으면 J002 가 잡는가. 안 심으면 조용한가 |
| `tests/test_jaso_swap.py` | 앵커 0개 문단이 P001 에 걸리는가 · 앵커 있는 문단은 안 걸리는가 |
| `tests/test_jaso_write.py` | 프롬프트에 관문 낱말이 **안 실리는가** |
| `tests/test_dig_find.py` | 질의 → 주소 (망 안 타고, `fetch.한번` 을 갈아 끼워) |

**과잉 기각도 검사한다.** `seek/` 가 대조군(`P3` 재작성)을 둔 것과 같다 — 성한 문단에
초록불이 켜지는 것까지 봐야 판정이 뜻을 갖는다.

셸은 안 쓴다. 쓰더라도 **한글 변수명을 안 쓴다**(`CLAUDE.md` 실측: `초=25` 는 대입이 아니라
명령어로 파싱된다). 파이썬 쪽은 이 저장소 관례대로 한글 이름을 쓴다.

## 11. 단계

| 차 | 무엇 | 여기서 되나 |

## 12. 안 하는 것

- **합격을 약속하지 않는다.** 전망은 관할 밖이다.
- **남의 자소서를 재료로 안 받는다.** 문항과 작법만.
- **여기(에이전트 세션)에서 산문을 지어내 보여 주지 않는다.** 파이프라인이 만든 것만 보여 준다.
- **원장에 없는 것을 채우지 않는다.** 빈칸은 빈칸으로 두고 사용자에게 무엇이 없는지 말한다.
- **관문을 생성자에게 알려 주지 않는다.**

## 13. 지금 사용자에게 필요한 것

   주면 스키마로 옮기는 것은 이쪽이 한다. **다만 수치는 잰 방법까지** 적어 주면 그 수가
   자소서에 쓰인다(없으면 J002 가 막는다).

3. 수집·생성을 돌릴 곳이 **VM** 이라는 확인 (여기는 키도 망도 없다 — 4절).
4. (있으면) 예전에 쓴 자소서 — 문체 기준선과 P003 상투구 사전의 씨앗이 된다.
