## 형식을 감으로 정하지 않는다 — 그런데 **합격률은 못 잰다**

"가장 합격률이 높은 형식을 찾자" 는 옳은 방향이고, **지금 재료로는 겨눌 수 없는
과녁**이다. 세 가지가 막는다.

| | |
|---|---|
| **선택 편향** | 인터넷의 '합격 자소서' 는 **합격자만 올린다.** 불합격 쪽이 통째로 빠진 표본에서 "합격 자소서의 특징" 을 아무리 세도, 불합격 자소서도 같은 특징을 갖는지 알 수가 없다 |
| **교란** | 합격은 자소서가 정하지 않는다. 학점·전공·경력·자격·면접·TO·경쟁률이 대부분이다. "인턴을 쓴 자소서가 합격률이 높다" 의 원인은 형식이 아니라 **인턴** 이다 |
| **딥러닝이 가린다** | 편향된 라벨에 큰 모델을 붙이면 편향이 사라지는 것이 아니라 **더 자신 있게 재현된다.** 그리고 왜 그렇게 골랐는지 물어볼 수도 없어진다 |

`brain/README.md` R004 의 갈래로는 **전망** — 관할 밖이다. 관할 밖이라고 답을 못 하는
것이 아니라 **판정 없이 답한다고 말하고 답하는 것**이다.

### 합격 자소서에서 문법을 캔다 — **본문은 안 남기고**

편향은 위에 적은 대로다. 그래도 **거기서 나올 것이 하나 있다: 형식 후보.**

```bash
python3 jaso/mine.py --질의 "합격 자소서 예시" --몇 12   # VM 에서
python3 jaso/mine.py --분포          # 문단 수 · 첫 문장 갈래 · 수 밀도 …
python3 jaso/mine.py --문법후보      # forms.py 에 붙일 초안
```

**문법은 문장이 아니라 구조다.** 문단이 몇 개인가 · 첫 문장이 장면인가 결론인가 ·
100자에 수가 몇 개인가 — 전부 세면 나오고, 세고 나면 본문이 필요 없다. 그래서
**재고 버린다.** 담기는 것은 잰 수와 출처뿐이다.

| | |
|---|---|
| M001 | 담긴 것에 **본문이 없는가** | hard — 있으면 안 담는다 |
| M002 | 출처가 적혔는가 | hard |
| M003 | 표본이 결론을 낼 만한가 | 표시 — 적으면 적다고 화면에 적는다 |

**M001 하나가 무너지면 나머지가 다 무너진다** — 남의 글이 사본으로 남고, 언젠가 생성
재료로 새어 들어가고, 표절 검사가 바로 잡는다. `tests/test_jaso_mine.py` 가 담긴
파일에 원문이 한 조각도 없는 것을 본다.

캔 형식은 **가설이지 결론이 아니다.** `forms.py` 에 후보로 붙이고 — **손으로 붙인다.
자동으로 읽어 오지 않는다** — 순위는 아래 `bench.py` 가 관문으로 낸다.

### 문법은 문장이 아니라 **차례**다

`novel/beat.py` 가 회차를 비트 차례로 쓰는 자리와 같다. 자소서 한 편도 문단마다 하는
일이 다르다 — 장면을 세우는 자리 · 한 일을 적는 자리 · 수로 결과를 대는 자리 ·
깨달은 것을 적는 자리. **문법은 그 차례다.**

```bash
python3 jaso/beats.py --차례        # 무엇 다음에 무엇이 오나
python3 jaso/beats.py --문법후보    # forms.py 에 붙일 초안
```

**박자 종류를 하드코딩하지 않는다.** `novel/arc.py` 의 `STAGES` 는 손으로 적은
목록이다 — 소설에서는 3막 8시퀀스가 밖에 있는 이론이라 그래도 됐다. **자소서에는 그런
것이 없다.** 내가 '상황·행동·결과' 를 적으면 그 순간 그것이 사양서가 되고, 캐 온
자료는 내 목록을 확인해 주는 데밖에 못 쓰인다.

```
문단 ─> 아홉 축으로 잰다 ─> 무리짓기 ─> 무리 하나가 박자 하나
                                          이름은 **중심에서 저절로 나온다**
```

아홉 축은 **말의 꼴**이지 박자가 아니다(수가 있나 · 과거형인가 · 전환어가 있나).
`수·과거` 같은 이름은 그 무리가 어느 축에서 두드러지는지에서 나온 것이지 내가 붙인
뜻이 아니다. k(박자 개수)도 팔꿈치로 데이터가 정한다.

**흔들리면 문법이 아니다.** 무리짓기는 시작점에 따라 답이 달라지는데, 돌릴 때마다 다른
박자가 나오면 그 잡음으로 만든 프롬프트를 사람이 믿게 된다. 그래서 시작점을 자리가
아니라 **자료에서** 정한다(평균에서 제일 먼 점부터) — 실측으로 편 차례만 뒤집어도
무리가 갈렸고, 그것을 회귀 못으로 박았다.

### 오래 돌며 모으기 — 그리고 **어디에 담기나**

```bash
mkdir -p ~/SE/logs
setsid nohup python3 ~/SE/jaso/crawl.py --분 60 --씨앗 "합격 자기소개서 예시" \
    > ~/SE/logs/jaso_crawl.log 2>&1 < /dev/null &
disown
pgrep -af jaso/crawl.py          # **`ps -p $!` 로 보지 마라 — 거짓 음성이 난다**
tail -f ~/SE/logs/jaso_crawl.log
```

멈추려면 `jaso/corpus/보기/.그만` 을 만든다. `pkill -f` 는 쓰지 마라 — 명령줄에 그
패턴이 들어 있으면 자기 셸까지 죽는다(`CLAUDE.md` 실측).

**목록 쪽을 주면 그 집 안쪽으로 판다.**

```bash
python3 jaso/crawl.py --분 60 --씨앗주소 'https://<게시판·태그·목록 쪽>' --따라 30
```

검색 창구를 안 거치므로 **창구가 막혀도 돌고**, 한 집에서 여러 편이 나온다.

> **`dig/run.py --url '<검색 결과 쪽>' --따라 5` 는 안 된다.** `dig` 의 `--따라` 는
> **같은 host 안으로만** 판다(`dig/run.py` 의 `안쪽링크`: `p.netloc != 바탕.netloc`
> 이면 건너뛴다). 검색 결과 쪽에 걸면 **창구 자기 살림 쪽만 돌고 결과로는 영영 못
> 간다.** 검색 결과에서 주소를 꺼내는 자리는 `dig/find.py` 다 — 감싼 주소
> (`/l/?uddg=`)를 풀고 창구 자기 집 주소를 걸러낸다. 그래서 **질의는 `--씨앗`,
> 주소는 `--씨앗주소`** 로 길을 따로 둔다.

**질의를 코드에 안 박는다.** 씨앗을 안 주면 있는 것에서 뽑고(문항 원장의 흔한 낱말 ·
이미 받은 쪽의 제목 · 준 회사·직무·학과), 하나도 없으면 **그렇다고 말하고 멈춘다.**
그리고 받아 온 쪽의 제목에서 다음 질의를 만든다 — **한 바퀴 돌 때마다 물을 것이 는다.**

같은 쪽을 두 번 안 받는다(주소 · 본문 해시). 요청 사이에 `--틈`(기본 3초)을 둔다 —
빨리 긁으면 그 쪽이 막고, 막히면 아무것도 못 받는다.

#### 담는 자리는 둘이고 **계약이 다르다**

| | 무엇이 담기나 | 저장소에 |
|---|---|---|
| `jaso/corpus/잰형식/` | **잰 수만**(M001) | 담아도 된다 (지금은 `.gitignore`) |
| `jaso/corpus/보기/` | **본문** | **절대 안 담긴다** (K001) |

**K001 이 그 자리를 지킨다.** `keep.py` 는 쓰기 전에 `git check-ignore` 로 물어보고,
무시 규칙이 그 자리를 안 잡고 있으면 **한 자도 안 쓴다** — 한 번 커밋되면 `git rm` 을
해도 히스토리에 남기 때문이다. 규칙을 적어 놓고 추적을 안 끊는 사고를 이 저장소가 이미
겪었고(`gates/G018`), 여기서는 그 사고가 **남의 이력을 공개 저장소에 올리는 일**이 된다.

```bash
python3 jaso/keep.py --목록
python3 jaso/bench.py --표 원장.json --문항 "..." --예시 $(python3 jaso/keep.py --내보내기) --맨
python3 jaso/keep.py --지우기        # 다 쓰고 나면
```

### "긁어와서 그렇게 만들어줘" 는 왜 안 되나 — **되는데, 재면서 하자**

긁어온 자소서 몇 편을 프롬프트에 넣고 "이렇게 만들어줘" 라고 하는 것은 자연스럽고
대개 잘 된다. 사실 **우리도 그것을 하고 있다** — `beats.py` 가 캔 차례를 프롬프트에
싣는 것이 바로 그것이고, `refine.py` 는 이전 벌을 그대로 다음 프롬프트에 얹는다.

다른 것은 **무엇을 싣느냐** 하나다.

| | 싣는 것 | 오는 것 |
|---|---|---|
| "그렇게 만들어줘" | 남의 **본문** | 형식 + **표현** |
| 우리 | 본문에서 잰 **차례와 눈금** | 형식만 |

모델은 맥락에 있는 문장을 되쓴다 — 그것이 in-context 학습이 되는 이유이기도 하다.
그래서 예시를 넣으면 형식만 오는 것이 아니라 **표현도 온다.** 조금이면 참고이고 많으면
표절인데, **그 선이 어디인지 재지 않으면 모른다.**

그래서 자를 만들고 후보로 넣었다.

```bash
python3 jaso/bench.py --표 원장.json --문항 "<원문>" --예시글 "<긁어온 글>" --맨
```

```
문법            성한비율   hard   soft   앵커     칸  죽음   겹침
기본                100%   0.00   1.00   9.0    54%     0    0%
보기(그렇게)         100%   0.00   1.00   4.0    48%     0   36%

  **예시를 베낀 것: 보기(그렇게) 36%**
  겹침은 관문이 아니다 -- 관문은 **당신의 원장**과 대조하지 예시와
  대조하지 않는다. 그런데 표절 검사는 예시 쪽을 본다. 이 수는 사람이 봐야 한다.
```

**관문이 이것을 못 잡는다는 것이 요점이다.** `gate.py` 는 원장과 대조하므로, 남의
문장을 그대로 옮겨도 그 문장이 당신 경험을 말하고 있으면 통과한다. 표절 검사는 정반대
쪽을 본다. 그래서 `echo.py` 를 따로 두고, **판정이 아니라 사람이 보는 수**로 낸다.

예시는 프롬프트에만 들어가고 어디에도 저장되지 않는다. 그리고 이 자가 **못 잡는 것**:
뜻을 바꿔 쓴 것은 안 잡힌다 — 낱말 다섯 이어짐으로만 본다.

### 그러면 무엇으로 재나 — 관문

바깥에 심판이 하나 있다: `gate.py`. LLM 이 아니고, 생성자가 그 존재를 모르며,
`mutate.py` 로 RED/GREEN 을 이미 확인했다.

```bash
python3 jaso/forms.py                                   # 문법 후보
python3 jaso/bench.py --표 원장.json --문항 "<원문>" --벌 3 --되풀이 2 --맨
python3 jaso/run.py --이름 <작업> --문법 <이긴 것>       # 이긴 것을 쓴다
```

```
문법          성한비율   hard   soft   앵커     칸  죽음
기본              100%   0.00   1.00   9.0    54%     0
두괄               50%   0.50   2.00   5.0    31%     0
장면                0%   1.50   3.00   1.0    28%     0
```

`mathgen` 이 생성기를 진화시키고 **sympy** 가 채점한 자리, `compression` 이 코덱을
탐색하고 **심판**이 채점한 자리와 같다 — **무엇이 더 나은가를 LLM 이 정하지 않는다.**
그리고 `--맨`(문항만 던지기) 대조군을 같이 돌린다. 없으면 우리 수가 좋은지 알 수 없다.

### "학습" 은 경사하강이 아니라 **탐색**이다

라벨이 없으니 내려갈 기울기가 없다. 대신 **후보를 늘어놓고 심판이 고른다** — 이 저장소가
두 군데에서 이미 쓰는 꼴이고, 라벨 없이도 도는 유일한 꼴이다. 문법을 늘리려면
`jaso/forms.py` 에 한 줄 더하고 `bench.py` 를 돌리면 된다.

### 이 수를 합격률로 읽지 않는다

`bench.py` 는 화면 끝에 늘 그렇게 적고, 표본이 작으면 **작다고 적는다** — 두 벌짜리
순위를 결론처럼 내지 않는다. `tests/test_jaso_bench.py` 가 그 줄이 실제로 찍히는지 본다.

## 정제 루프 — 무엇이 바깥인가

```
문항 ─> 프롬프트(**도출**) ─> n벌 ─(관문)─> 점수 ─> 최선을 든다
            ↑                            │
            └── 위반이 가리키는 **원장 사실** ┘      나빠진 바퀴는 버린다
```

`run.py` 가 문항마다 `--바퀴`(기본 3) 만큼 돈다. `jaso/refine.py --궤적` 으로 따로 볼 수 있다.

### 프롬프트를 모델이 짓지 않는다 — 계산한다

    프롬프트 = 문항 요구 × 원장 사실 × 남은 위반이 가리키는 사실

모델이 프롬프트를 짓고 같은 계열 모델이 답하고 그것을 루프 돌리면 **바깥이 없는 닫힌
고리**다. 이 저장소가 두 번 덴 자리다(`mathdrift/spread.py` — 발산 프롬프트에 심판을
실었더니 발산이 사양서가 됐다). 바깥은 둘뿐이다: **원장(사실)** 과 **관문(코드)**.

### 위반 이름 대신 **사실**을 되먹인다

| | |
|---|---|
| 안 준다 | "J002 위반이다. 원장에 있는 수만 써라" |
| **준다** | "이 문장의 수는 제 기록에 없습니다. 제 기록은 클릭률 2.1% → 2.6% (2주 A/B, n=48,000)입니다. 그 값으로 다시 쓰거나 수 없이 쓰십시오" |

앞엣것을 주면 모델은 **원장의 수를 아무 데나 끼워 넣어 관문을 통과시킨다.** 그 문장은
통과했는데 틀린 문장이다 — 관문이 사양서가 되는 순간이다.

그리고 고칠 때도 **재료를 안 뺀다.** 빼고 "이것만 고쳐라" 라고 하면 모델이 나머지를
기억으로 다시 채우고, 그 순간 원장 밖이 들어온다.

### 정제됐다는 말을 검사받게 한다

    점수 = (hard 수, soft 수, -앵커 수, -글자 채움)   사전식. 작을수록 좋다

**나빠진 바퀴는 버린다** — 최선을 늘 들고 간다(`mathdrift/mono.py` 의 단조량과 같은
자리다). 그냥 돌리면 그것은 정제가 아니라 그냥 도는 것이다.

### 루프가 못 고치는 것이 있다 — 그때는 사람에게 돌아간다

같은 hard 가 두 바퀴를 살아남으면 대개 **재료가 없는 것**이다. 원장에 없는 것을 모델이
채우면 그것이 지어낸 것이므로, 그런 위반만 남으면 **더 돌리지 않고** `ask.py` 로 무엇을
물어야 하는지 낸다. 안 움직이는 바퀴가 둘 이어져도 멈춘다 — 바퀴마다 호출이 나간다.

## 포트폴리오는 문항이 다른 자소서다

```bash
python3 jaso/folio.py --표 원장.json --사실만        # LLM 0회. 원장 그대로
python3 jaso/folio.py --표 원장.json --낼곳 포트폴리오.md   # 산문 (Gemini)
```

재료가 같다 -- 둘 다 원장의 항목에서 나오고, 둘 다 지어낸 수와 승격된 역할에서
무너진다. 다른 것은 **무엇을 묻느냐**뿐이라, `folio.py` 는 항목마다 문항을 하나씩
만들고 그 뒤는 `write.py` 와 `gate.py` 가 그대로 받는다. **새 생성자도 새 관문도
만들지 않는다** -- 두 벌은 언젠가 갈라진다(`brain/README.md`).

`--사실만` 이 기본에 가깝다. 포트폴리오는 기간·역할·쓴 것·잰 값과 재는 법을 **늘어놓는
편이 읽히고**, 그러면 LLM 을 한 번도 안 부르므로 지어낼 자리가 아예 없다.

## 왜 이 모양인가

일반 LLM 이 자소서에서 지는 자리는 문장력이 아니라 **대조**다. 여섯 가지가 있고
여섯 다 기계가 볼 수 있다 — 수치 창작 · 역할 승격 · 기간 충돌 · 문항 빗나감 ·
치환 가능 · 글자 수. 그런데 **일반 LLM 은 자기가 자기를 검사하지 않는다.**
한 방에 쓰고 끝낸다.

`law/` 를 그대로 옮겼다. 거기서는 조문 원문이 밖에 있었고, 여기서는 **사용자의 경험
원장**이 밖에 있다.

| law | jaso |
|---|---|
| 조문 원장 (`law/corpus/`) | 경험 원장 (`jaso/ledger.py`) |
| L001 인용한 조문이 실재하는가 | J001 원장에 없는 해·기술을 적었는가 |
| L003 법정형이 그 조문의 것인가 | **J002 잰 값이 원장의 그 값인가** |
| W005 '준용' 을 '적용' 으로 바꿨는가 | **J004 '참여' 를 '주도' 로 올려 썼는가** |
| 생성자는 관문을 모른다 | `write.py` 도 모른다 (검사로 고정) |

## 한 명령으로 -- `run.py`

```bash
python3 jaso/run.py --이름 누리하나 --회사 누리하나 --직무 "데이터 분석" \
    --문항 "직무에 필요한 역량은 …(1000자)" --문항 "지원 이유와 포부는 …(800자)"
#   -> 물음이 나오고 **멈춘다** (끝값 2)

python3 jaso/run.py --이름 누리하나 --답글 "1) … 2) …"
#   -> 답을 넣고, 아직 물을 것이 있으면 또 멈춘다

python3 jaso/run.py --이름 누리하나
#   -> 재료가 찼으면 여기서부터 **끝까지 자동** (여러 벌 · 관문 · 고르기 · 근거 기록)
```

끝값이 다음에 무엇을 할지다: `0` 냈다 · **`2` 사람 차례** · `1` hard 남음 · `3` 못 갔다.

### 왜 끝까지 자동으로 안 도나

**답할 사람이 있어야 하기 때문이다.** 그리고 그 자리를 기계로 메우면 이 파이프라인은
스스로를 무력화한다.

실측으로 한 번 그럴 뻔했다 — *"`내원장.json` 이 없으면 방금 수집한 정보를 토대로
구조를 잡고 진행하겠습니다."* **수집한 것은 남의 공고문이다.** 그것으로 원장을 만들면
그 사람의 이력을 지어내는 것이고, J001~J004 와 P001 이 전부 미검증이 되며, 나오는
글은 정확히 이 파이프라인이 막으려던 그 글이다 — 관문이 있다는 착각만 얹은 채로.

그래서 못을 박았다: **`run.py` 는 경험 항목을 만들지 않는다.** 항목이 원장에 들어가는
길은 `intake.py` 가 사람의 답에서 넣는 것 하나뿐이고, 그때도 I001 이 답 원문과
대조한다(`tests/test_jaso_run.py`).

**자동인 것은 사람이 답을 준 다음의 모든 것이다** — 넣기 · 다시 묻기 · 다 찼는지 판정 ·
여러 벌 생성 · 관문 · 고르기 · 작성 근거 기록.

### 작업 폴더

    jaso/작업/<이름>/
      원장.json    경험 원장 (사람의 답이 쌓이는 곳)
      문항.json · 물음.json
      답.txt       **사람이 채우는 칸** -- 여기만 사람 차례다
      답_01.txt …  처리된 답 (지우지 않는다 -- 작성 근거 기록의 재료다)
      자소서.md · 근거.md · 기록.md

**`jaso/작업/` 은 저장소에 안 담긴다**(`.gitignore`). 경험 원장 · 인터뷰 답 원문 ·
자소서가 다 그 사람 것이고, 한 번 담기면 이력이 공개 저장소에 남는다.

## 한 바퀴 (걸음마다 따로 부르기)

```bash
# 1. 문항을 받는다 (**VM 에서** -- 이 컨테이너는 나가는 길이 막혀 있다)
python3 jaso/fetch.py --질의 "2026 상반기 자기소개서 문항" --몇 8
python3 jaso/corpus.py --갈래                      # 무엇이 들어왔나

# 2. 무엇을 물을지 계산한다 (LLM 0회)
python3 jaso/ask.py --문항원장 --표 내원장.json --json > 물음.json
python3 jaso/ask.py --문항원장 --표 내원장.json    # 사람이 읽을 꼴

# 3. 답을 원장에 넣는다 (대조하면서)
python3 jaso/intake.py --물음 물음.json --답 답.txt --표 내원장.json --넣기

# 4. 아직 물을 것이 있나 -- 없어질 때까지 2~3 을 되풀이한다
python3 jaso/ask.py --문항원장 --표 내원장.json

# 5. 쓴다 (Gemini · 여러 벌 · 관문이 고른다)
python3 jaso/write.py --표 내원장.json --문항원장 --벌 4 --낼곳 자소서.md
python3 jaso/write.py --표 내원장.json --문항 "..." --프롬프트만   # 무엇을 주는지

# 6. 심판과 기록
python3 jaso/gate.py 자소서.md --표 내원장.json -v
python3 jaso/trace.py 자소서.md --표 내원장.json --낼곳 근거.md
python3 jaso/mutate.py 자소서.md --표 내원장.json   # 관문이 진짜 잡는가 (RED)
```

끝값: `0` 통과 · `1` hard 위반 · `3` 못 읽었다.

## 물음은 생성물이 아니라 도출물이다

```
물을 것 = 문항이 요구하는 것 − 원장이 이미 가진 것
```

`law/METHOD.md` 의 **쟁점은 도출물**, `brief/` 의 **수는 도출물**과 같은 자리다.
그래서 물음마다 `왜` 가 붙는다 — 어느 관문이 지금 그 자리를 못 보고 있는지.

```
[Q2] [추천 개편] 의 '클릭률' 를 **어떻게 쟀습니까?**
     왜: E004 -- 잰 방법이 없으면 그 수는 원장에 남아도 자소서에 못 쓴다(J002 가
         막는다). 안 잰 수를 쓰는 것이 자소서에서 제일 흔한 거짓말이다
```

모델에게 물음을 지어내게 하면 이 줄이 사라진다. 그럴듯한 물음이 나오고, **왜 그것을
묻는지는 아무도 모르며**, 답을 받아도 무엇이 채워졌는지 셀 수가 없다.

**안 묻는 것**: "당신의 강점은?"(사실에서 나올 결론이지 재료가 아니다 — 물어서 받으면
그대로 옮겨 적게 되고 그것이 P002 다) · 계산되는 것(개월 수 · 글자 수 · 어느 문항에
어느 경험을 쓸지).

## 답이 들어올 때도 대조한다

물음이 **답이 갈 자리(`칸`·`대상`)를 이미 알고 있으므로** LLM 없이 넣는다. 자유 서술을
통째로 모델에게 주고 "원장으로 만들어" 라고 하면 모델이 빈칸을 메우고, **메운 것이 곧
그 사람의 이력이 된다.** 원장은 이 파이프라인의 유일한 바깥이라 거기가 오염되면 아래
관문이 전부 오염된 것을 대조하게 된다.

`--모델` 을 줘도 마찬가지다 — 뽑은 값이 답 원문에 실제로 있는지 **I001** 이 대조하고,
없는 값은 고쳐 넣지 않고 **버린다**(무엇을 버렸는지 화면에 적는다).

## 원장이 첫 재료다

없으면 J001~J004 와 P001·P002·P006 이 **전부 미검증**이 되고, 미검증 위에 쓴 자소서는
그냥 일반 LLM 출력이다 — 관문이 있다는 착각만 얹힌 채로. 그래서 보고서가 대조한 수와
못 한 수를 **늘 같이** 적는다.

꼴은 `jaso/보기.json` 을 베끼면 된다. 규약이 셋이고, 셋 다 관문을 먹여 살린다.

- **`역할` 은 닫힌 목록이다** — `주도`·`참여`·`보조`·`관찰`. 자유 서술이면 J004 가 눈이 없다.
- **`잰것` 은 재는 법(`어떻게`)까지 적는다.** 없으면 원장에는 남지만 **자소서에는 못 쓴다**(J002).
- **`언제` 는 `YYYY-MM` 구간이다.** J003 이 이것으로 기간을 잰다.

`갈래`(프로젝트·인턴·동아리…)는 **열려 있다.** 닫으면 남의 이력이 목록에 안 맞는 순간
잘려 나가고, 그것이 `brain/README.md` 가 한 번 잘못 짰다고 적어 둔 하드코딩이다.

| J007 | 구조 | 무엇이 달라졌는지가 있는가 | soft |
| J008 | 자기모순 | 같은 경험에 다른 기간을 달았는가 | hard (원장 필요) |
| **P001** | **치환 가능** | **회사 이름을 갈아 끼워도 그대로인가** | hard/soft (원장 필요) |
| P002 | 주장-근거 | '열정적' 뒤에 근거가 붙었는가 | soft |
| P003 | 상투구 | 돌려쓰는 말이 몇 개인가 | soft |
| P004 | 수동·명사화 | 행위자가 사라졌는가 | soft |
| P005 | JD 대조 | 공고의 요구역량에 닿았는가 | **아직 미검증** (2차) |
| P006 | 재탕 | 여러 문항이 같은 경험을 돌려 쓰는가 | soft |
| D001 | 문장 고름 | 문장 길이가 다 비슷한가 | soft |
| D002 | 이음말 | '또한' · '이를 통해' 로 굴러가는가 | soft |
| D003 | 고유 밀도 | 100자에 원장에서 온 것이 몇 개인가 | soft (원장 필요) |
| D004 | 문단 고름 | 문단이 다 같은 크기인가 | soft |
| D005 | 문항 되풀이 | 첫 문장이 문항을 되풀이하는가 | soft |
| I001 | 넣기 대조 | 답에 없는 값이 원장에 들어갔는가 | hard (`intake.py`) |

**P001 이 이 관문의 서명이다.** 회사·직무 이름은 앵커가 아니다 — 그것이 바로 갈아
끼우는 자리이므로. 원장에서 온 것이 하나도 안 박힌 답변은 어느 회사에나 들어간다.

지원동기·포부 문항에도 P001 이 그대로 걸린다. 일부러 그렇게 두었다 — 앞을 보는 글도
**무엇을 보고 그렇게 생각하게 됐는지**는 뒤를 보는 사실이고, 그것이 없는 포부가 바로
어느 회사에나 들어가는 문단이다. `write.py` 는 그 문항에도 원장 항목을 같이 준다.

## AI 판별 프로그램에 대한 대비 — 두 갈래, 그리고 안 하는 것

채용·입시 쪽에서 AI 작성 여부를 재는 프로그램을 쓴다. 대개 이런 것들이다.

| 무엇을 보나 | |
|---|---|
| 통계값 | 다음 낱말이 얼마나 잘 맞춰지나(perplexity) · 문장마다 얼마나 들쭉날쭉한가(burstiness) |
| 분류기 | 사람 글과 모델 글로 학습시킨 판별기 |
| 워터마크 | 만들 때 심는 것. **글만 받은 채용 시스템은 못 쓴다** |
| (한국 실무) | 표절 검사(기존 자소서 대조)에 'AI 의심' 지표가 붙는 꼴이 흔하다 |

**그리고 이것들은 틀린다.** 오탐이 잘 알려져 있고 특히 정형화된 글쓰기에서 그렇다.
그러니 "판별을 통과한다" 는 애초에 겨눌 수 없는 과녁이다 — 어느 프로그램을 쓰는지도
모르고, 알아도 그 점수를 여기서 재현할 수 없다.

### 갈래 1 — 판별기가 보는 것 중 **글의 질과 겹치는 것**만 고친다 (D001~D005)

판별기가 모델 글을 알아보는 까닭과, 사람이 읽고 "누구나 쓸 수 있는 글" 이라고 느끼는
까닭이 같다. 문장이 다 비슷한 길이고, 이음말로 굴러가고, 그 사람만 아는 것이 없다.
D 계열은 **그것**을 잰다. 판별 점수를 예측하지 않는다.

```
$ python3 jaso/gate.py 일반론.md --표 원장.json -v
  [D001] 문장 길이가 고르다 (변동 0.17)
  [D002] 문장 12개에 이음말이 10개다
  [D003] 312자에 원장에서 온 것이 0종뿐이다 (100자당 0.0)
  [D004] 문단 4개가 다 같은 크기다 (변동 0.09)
  [D005] 첫 문장이 문항을 되풀이한다
```

원장에 붙은 글에는 **하나도 안 켜진다**(`tests/test_jaso_write.py` 의 대조군).
지어내지 않으면 이 값이 저절로 좋아지기 때문이다 — 고치려고 고친 것이 아니다.

**D 계열은 전부 soft 다.** 통계값으로 사람의 글을 기각하면 이 자가 바로 오탐하는
판별 프로그램이 된다.

### 갈래 2 — **오탐에 대비한다.** 이쪽이 진짜다

걸렸을 때 필요한 것은 회피가 아니라 **근거**다. `jaso/trace.py` 가 그것을 낸다.

```
2. 무봉테크 데이터플랫폼팀 인턴으로 사내 추천 시스템 개편에 참여하며…
   - 원장 항목: `P-2025-추천` 사내 추천 시스템 개편 (참여 · 2025-03 ~ 2025-08)
   - 이 문단에 박힌 것: 2.1, 2.6, 24000, 35, 데이터플랫폼팀
   - 증빙: 커밋 로그 · 인턴 최종 보고서 PDF
   - 잰 방법: 추천 클릭률 2.1% -> 2.6% (2주간 A/B, 대조군 24,000 · 실험군 24,000명)
```

**없는 것을 새로 만들지 않는다** — 원장과 물음·답이 이미 그 기록이었고, 문단에 맞춰
늘어놓기만 한다. 원장에 안 닿은 문단도 숨기지 않고 그렇게 적는다.

그리고 더 확실한 자가 따로 있다. **면접이다.** 원장에 있는 것만 썼으므로 되물으면
답할 수 있다. J002(안 잰 수를 막는 것)와 J004(역할 승격을 막는 것)가 애초에 그 자리를
겨냥한 관문이다 — 판별 프로그램보다 훨씬 자주, 훨씬 확실하게 거짓을 잡는 것이 사람이다.

### 안 하는 것

- **탐지를 피하는 손질을 안 만든다.** 동의어를 바꾸고 문장을 흔들어 점수를 낮추는 일.
  사실은 하나도 안 바뀌면서 저작자만 속이는 짓이고, 걸리면 그때는 '지어냈다' 가 아니라
  **'숨겼다'** 가 된다.
- **생성자에게 판별 이야기를 안 한다.** `write.py` 프롬프트에 `AI` · `판별` · `탐지`
  가 한 글자도 없다(`tests/test_jaso_write.py` 가 고정). 실으면 탐지를 피하려는 글이
  나오고, 그것은 문항에 답하는 글이 아니다.
- **점수를 약속하지 않는다.** D 계열이 다 조용해도 어떤 프로그램은 걸 수 있다.
  그때 내밀 것이 갈래 2 다.

## 좋은 자소서를 수집한다? — **작법만 받는다**

"양질의 검증된 자소서를 모아 원장에 쓰자" 는 자연스러운 생각이고, **파이프라인을
뒤집는다.** 도덕론이 아니라 세 군데가 동시에 깨진다.

| | |
|---|---|
| 원장에 넣으면 | J001~J004 가 **남의 이력**을 대조한다. 생성자는 남의 경험을 당신 것처럼 쓴다 |
| **표절 검사** | 한국 채용 실무의 주력은 AI 판별이 아니라 표절 검사이고, 그 DB 가 정확히 '인터넷에 도는 합격 자소서' 다. **가장 확실히 걸리는 길이다** |
| 면접 | 되물으면 답할 것이 없다. `trace.py` 가 낼 근거가 없다 |

그래서 밖에서 받는 것은 **문항**(공고문)과 **작법**(공개 작성 가이드)뿐이다.

```bash
python3 jaso/learn.py --질의 "자기소개서 피해야 할 표현" --몇 8   # VM 에서
python3 jaso/learn.py --배운것
```

가이드는 "이런 표현은 피하라" 를 실제로 열거한다. 그것을 캐서 **P003 상투구 사전을
실측으로 늘린다** — 남의 글을 베끼는 것이 아니라 **판정기를 강화**하는 방향이다.

### 사전을 늘리다가 관문을 못 쓰게 만들지 않는다

'저는' 이 상투구로 들어오면 모든 자소서가 P003 을 문다. 그래서 배운 낱말은 세 관문을
지나야 붙는다.

| | | |
|---|---|---|
| C001 | 뽑은 표현이 **출처 원문에 글자 그대로** 있는가 | hard — 없으면 버린다 |
| C002 | 출처가 적혔는가 | hard |
| **C003** | **성한 표본을 걸지 않는가** | hard — 걸면 안 받는다 |

**C003 이 요점이다.** 실측: 가이드가 `지표를 의심하는` 을 식상하다고 지목했는데, 그
말이 `tests/fixtures/자소서_성한것.md` 에 있다. 받았으면 **원장에 붙은 성한 글이
P003 에 걸렸을 것이다.** `law/mutate.py` 의 GREEN 과 같은 규율이다.

`--모델` 을 주면 Gemini 가 자유 서술에서 뽑는다. 그때도 C001 이 원문과 대조하고 없는
것은 고쳐 넣지 않고 **버린다** — `intake.py` I001 과 같은 수다. 프롬프트에 판정
이야기는 한 글자도 없다(실으면 통과하는 것만 뽑아 온다).

## 관문이 진짜 잡는가 — 두 방향을 같이 본다

```
$ python3 jaso/mutate.py tests/fixtures/자소서_성한것.md --표 jaso/보기.json
돌연변이                심음    잡음    놓침
J002 수치창작            2     2     0
J004 역할승격            2     2     0
J003 기간부풀림           4     4     0
J001 없는해             4     4     0
P001 치환가능            4     4     0
P003 상투구             4     4     0
합계                  20    20     0
```

그리고 같은 문서에 **hard 가 0** 이다. 한쪽만 보면 뜻이 없다 — 다 잡는 관문은
`return ["위반"]` 으로도 만들 수 있고, 조용한 관문은 `return []` 으로도 만들 수 있다.

## 자가 고장났던 자리

관문을 짜면서 성한 문서에 빨간불이 네 번 켜졌다. **넷 다 관문이 아니라 자가 고장난
것이었고**, 둘은 같은 고장으로 지어낸 수를 놓치기까지 했다.

| 무엇 | 어떻게 드러났나 |
|---|---|
| 문장 자르는 자가 **소수점을 문장 끝으로** 읽었다 | `2.1%에서 2.6%로` 가 `2`/`1%에서 2`/`6%로` 로 갈렸다. 성한 문장이 J002 위반이 됐다 |
| 성과 동사 사전에 **활용형 `늘었`·`올랐`** 이 없었다 | 그 문장의 수를 아예 안 견주었고, J007 은 "결과가 없다" 고 잘못 보고했다 |
| J006 이 **표지말 어림으로 hard** 를 냈다 | "어려웠던 경험" 을 "문제를 만났습니다" 로 쓴 성한 답변이 기각됐다 |
| J008 이 **인원**을 봤다 | 한 문단의 `24000명`(표본)과 `4명`(팀)을 모순으로 봤다. 뜻을 읽어야 갈리는데 이 관문은 뜻을 안 읽는다 |

**자를 먼저 의심해야 한다**(`law/mutate.py` 가 같은 자리에서 데었다). 그래서 넷 다
`tests/test_jaso_gate.py` 에 회귀 못으로 박혀 있다.

## 안 하는 것

- **합격을 약속하지 않는다.** 전망은 관할 밖이다(`brain/README.md` R004).
- **원장에 없는 것을 채우지 않는다.** 빈칸은 빈칸으로 두고 무엇이 없는지 말한다.
- **뜻을 읽지 않는다.** 그래서 J008 은 인원을 안 보고, J006 의 이음 요건은 soft 다.
  못 보는 것을 못 본다고 적는 것이 이 관문이 하는 일의 절반이다.

## 아직 없는 것

| 무엇 | |
|---|---|
| P005 JD 대조 | 공고의 요구역량 대조. 지금은 위반이 아니라 **미검증**으로 셈에 남는다 |

수집(`fetch.py`)과 생성(`write.py`)은 **VM 몫이다.** 이 에이전트 컨테이너는 Gemini
키가 0개이고 나가는 길이 막혀 있다(프록시 CONNECT 403). 여기서 도는 것은 관문·분해·
물음·넣기와 배선 검사뿐이고, `tests/test_jaso_find.py` 는 `dig.fetch.한번` 을,
`tests/test_jaso_write.py` 는 LLM 을 갈아 끼워 그 배선을 붙든다.
