# 제어 정책 래퍼 설계 — 센서 → SSM → 행동 (2026-09-25)

**노선.** 갈래 B / 서사 ⓑ. 코어는 `ssm/` 의 selective-scan 유닛(측정 완료). 여기서는 그
유닛을 **무인체계 제어 루프**에 맞는 껍질로 감싼다. 아직 짓기 전 설계 — 수는 재고 나서 채운다.

## 1. 제어 루프에서 SSM 이 하는 일

무인체계(4족 로봇·드론)의 한 제어 스텝, 한 채널 관점:
```
관측 o_t (센서 융합: 관절각 + 시각 특징)  --입력투영-->  (delta_t, B_t, C_t)
   --selective-scan-->  h_t = Abar·h_{t-1} + Bbar·o_t   (ssm/scan_mac·scan_seq)
   --출력투영-->  a_t (행동: 관절 토크 / 조향)
```
- **스트리밍**: 한 관측이 들어올 때마다 상태 h 하나만 들고 행동 하나를 낸다 — LocoMamba/
  VLA-Mamba 가 하는 인과적 한 스텝. FPGA 의 단일표본·결정론적 지연에 그대로 맞는다.
- **재사용**: 재귀(scan)·이산화 exp 는 `ssm/` 것을 그대로. 여기서 **새로 필요한 것은
  입력투영·출력투영** 둘뿐이다.

## 2. 무엇을 재사용하고 무엇을 새로 짓나

| 조각 | 어디 | 상태 |
|---|---|---|
| 이산화 exp 근사 | `ssm/rtl/exp_unit.v` | 측정됨 (순수 LUT, DSP0) |
| 상태갱신 MAC (병렬/순차) | `ssm/rtl/scan_mac.v`·`scan_seq.v` | 측정됨 (DSP=6N / DSP=2) |
| **입력투영** o→(Δ,B,C) | `ctrl/rtl/` (새로) | 미착수 |
| **출력투영** h→a | `ctrl/rtl/` (새로) | 미착수 |
| 제어 스트리밍 인터페이스 | `ctrl/rtl/` (새로) | 미착수 |

입력·출력 투영은 **행렬곱(MAC 배열)** 이다 — FFT 나비·scan MAC 과 같은 성질이라 DSP 로
간다(이미 확인된 유리한 자리). 크기는 (관측차원 × 상태차원 N).

## 3. 제어 특유의 측정 타깃 (서사의 핵심 수)

`ssm/` 는 유닛 자원을 쟀다. 제어 래퍼에서 **새로 재야 할 것**:
1. **행동 한 스텝의 결정론적 지연** — 관측 입력부터 행동 출력까지 몇 사이클/몇 ns.
   이게 "결정론적 지연" 서사의 근거다. **주장 말고 STA 로 잰다**(house SYN 직무).
2. **투영을 포함한 전체 자원** — 입력·출력 투영 DSP + scan DSP. 목표 FPGA 예산 대비.
3. **end-to-end 제어 오차** — 고정소수 정책 출력 vs float 기준. 동작점이 성한지 먼저 본다.

## 4. 고정소수 (초안, 측정으로 조정)
- 관측 o, 행동 a: Q1.15 (센서·액추에이터 정규화 범위). 상태 h: Q4.12 (ssm/ 와 동일).
- 투영 가중치: INT8~16 (Mamba FPGA 선행이 INT8; 우리는 16b 로 상한부터).

## 5. 아직 안 정한 것 (사용자·측정으로)
- **관측/상태/행동 차원** — LocoMamba 급 소형부터. N=16 상태로 자원 여유 확인 후.
- **입력투영을 회로에 넣나, 미리 계산해 넣나** — scan_mac 은 (Δ,B,C)를 입력으로 받는다.
  투영까지 회로에 넣으면 완제품성↑·자원↑. 파레토로 결정.
- **입력 신호(선택)** — 합성 관측 스트림 / 실제 정책 가중치(LocoMamba 오픈소스가 있으면).
