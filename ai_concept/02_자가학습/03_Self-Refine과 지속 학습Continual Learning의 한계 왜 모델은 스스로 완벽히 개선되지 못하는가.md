# 03. Self-Refine과 지속 학습(Continual Learning)의 한계: 왜 모델은 스스로 완벽히 개선되지 못하는가

## 1. 왜 알아야 하는가

LLM이 스스로 코드를 수정하고 지속적으로 학습하여 완벽한 인공지능이 될 것이라는 낙관적 기대와 달리, 실제 시스템에서는 치명적인 인지적 정체와 파괴적 망각이 발생합니다. 시니어 엔지니어는 자가 개선 루프의 한계를 정확히 파악해야만 실무에서 신뢰할 수 없는 무한 루프에 리소스를 낭비하지 않고, 보다 안정적인 하이브리드 아키텍처를 설계할 수 있기 때문에 이 주제를 반드시 이해해야 합니다.

## 2. 정의와 구조

### 1. Self-Refine의 메커니즘과 한계
Self-Refine은 LLM이 생성한 초안(Draft)을 스스로 평가(Feedback)하고 이를 반영하여 수정본(Refinement)을 도출하는 반복 알고리즘입니다. 이 방식은 외부 피드백이 없는 폐쇄적 시스템(Closed System)에서 동작하기 때문에, 모델이 최초에 생성한 오답에 포함된 인지적 오류나 편향을 스스로 발견하지 못하고 오히려 자신의 오답을 옹호하는 방향으로 피드백을 왜곡하는 '확증 편향(Confirmation Bias)'을 극복하기 어렵습니다.

### 2. 지속 학습(Continual Learning)과 파괴적 망각
지속 학습은 모델이 이미 학습한 작업(Task A)의 지식을 잃지 않으면서 새로운 작업(Task B)을 점진적으로 학습하는 프로세스를 의미합니다. 그러나 심층 신경망은 새로운 목적 함수를 최적화하는 과정에서 기존 최적점(Optimal Point)을 유지하던 가중치(Weight)를 전반적으로 재조정하기 때문에, 기존 도메인의 성능이 급격히 저하되는 '파괴적 망각(Catastrophic Forgetting)' 현상을 필연적으로 겪게 됩니다.

### 3. 모델 붕괴(Model Collapse)의 수학적 원리
모델이 생성한 데이터를 다시 학습 데이터로 사용하는 재귀적 자가 학습(Recursive Self-Training)을 반복할 경우, 실제 데이터 분포가 가진 극값(Tail Distribution)의 정보가 유실되고 최빈값(Mode) 위주로 데이터 분포가 왜곡됩니다. 외부 엔트로피의 주입 없이 시스템 내부의 정보만을 재순환시키기 때문에, 세대가 거듭될수록 출력 분포의 엔트로피가 감소하고 결국에는 모델이 다양성을 잃고 무의미한 패턴만 반복 출력하는 상태에 수렴합니다.

## 3. 핵심 사실 (Killing Fact)

$$ \boxed{\ \lim_{n \to \infty} D_{\text{KL}}(P_{\text{true}} \parallel P_n) = \infty \quad \text{if } P_n = \mathcal{M}(P_{n-1}) \text{ and } I(\mathcal{M}, \text{Oracle}) = 0\ } $$

외부의 정답(Oracle) 또는 실제 세계와의 상호작용 정보량($I$)이 0인 상태에서 모델이 자가 생성 데이터($P_{n-1}$)를 재귀적으로 학습하여 새로운 상태($P_n$)로 전이될 경우, 매 단계 누적되는 미세한 오차가 지수적으로 확장되어 실제 참 분포($P_{\text{true}}$)와의 정보 손실량(KL 발산)이 결국 무한대로 발산하며 시스템이 붕괴함을 보여줍니다.

## 4. 핵심 기법

### 기법 A: Experience Replay (경험 재생 버퍼링)

새로운 도메인을 미세조정(Fine-Tuning)할 때, 과거에 학습했던 대표 데이터셋의 일부(Buffer)를 일정 비율로 혼합하여 배치(Batch) 손실 함수를 계산합니다.

**왜 이렇게 설계했는가:** 가중치 업데이트 벡터가 신규 데이터 방향으로만 편향되는 것을 막고, 과거 데이터 분포에 대한 손실을 동시에 역전파함으로써 기존 표현 공간(Representation Space)의 급격한 파괴를 방지하기 위함입니다.

### 기법 B: Elastic Weight Consolidation (EWC, 탄성 가중치 통합)

이전 작업 학습 후 가중치들의 피셔 정보 행렬(Fisher Information Matrix)을 계산하여 중요도를 측정하고, 중요 가중치가 변경될 때 강한 페널티(L2 규제)를 부여합니다.

**왜 이렇게 설계했는가:** 과거 학습의 핵심 가중치 변화량을 명시적으로 제한함으로써 신규 학습의 가소성(Plasticity)과 기존 지식의 안정성(Stability) 사이의 구조적 균형을 유지하기 위함입니다.

### 기법 C: External Verification Anchoring (외부 검증 앵커링)

Self-Refine 루프 내에서 자체 평가 대신 코드 인터프리터 실행 결과, API 응답, SQL 쿼리 실행기 등의 실시간 런타임 피드백을 주입하여 에러 메시지를 생성합니다.

**왜 이렇게 설계했는가:** 모델 내부 파라미터에 저장된 왜곡된 지식에 의존하지 않고, 외부 환경의 '객관적 참값(Ground Truth)' 피드백을 통해 닫힌 루프의 인지적 정체를 깨뜨리기 위함입니다.

## 5. 자주 하는 오해 / 주의할 점

가장 흔히 저지르는 실수는 LLM에게 프롬프트만으로 "스스로 결과물의 오류를 검토하고 수정하라"고 지시하면 해결 능력이 비약적으로 상승할 것이라 믿는 것입니다. 모델이 이미 해당 연산이나 논리 전개 능력이 부족하여 오답을 낸 상태라면, 외부 검증 장치 없이 스스로 재평가하더라도 자신의 오답 논리에 속아 넘어가 '수정할 부분이 없다'고 판단하거나 더 정교한 오답(Hallucination)을 생산해 냅니다. 또 다른 실수는 기존 성능을 유지하겠다며 사전 학습 데이터 없이 신규 업무 매뉴얼 세트만으로 전체 모델 가중치를 파인튜닝하는 것으로, 이는 파괴적 망각을 유발하여 시스템의 기본 대화 태스크 수행력을 완전히 망가뜨리는 원인이 됩니다.

## 6. 대표예제 (추론 연습)

### 예제 1

수학 공식을 전개하고 답을 구하는 에이전트 루프가 작동 중이나, 모델이 계산 과정에서 $3 \times 7 = 24$라는 사소한 산술 오류를 발생시킨 후 Self-Refine 루프에 들어가서도 '나의 논리와 연산은 완벽하다'라며 틀린 수식을 계속 고집하고 있습니다. 이 문제를 완화할 수 있는 자가 개선 시스템 구조를 설계하십시오.

**풀이:**

1단계 — 모델에게 스스로의 논리를 말로 검증하라고 요청하는 단순 텍스트 프롬프트를 배제합니다. 2단계 — 시스템 구조를 확장하여 모델이 작성한 중간 단계의 수식을 Python `sympy`나 `eval`이 실행할 수 있는 코드 형태로 변환하도록 유도합니다. 3단계 — 실제로 코드를 독립된 런타임 샌드박스에서 실행하여 얻은 수학적 결과값(예: False 혹은 실제 오답 값)을 피드백 메시지로 수집합니다. 4단계 — 모델에게 '너의 풀이는 틀렸다'는 텍스트 대신 '시스템 실행 결과: 3 * 7의 실행 값은 21입니다. 코드가 일치하지 않습니다'라는 객관적 런타임 결과값을 피드백으로 전달하여 자기 수정을 강제합니다.

**답: 텍스트 기반 자가 검증을 배제하고, 중간 계산 수식을 실제 코드 실행 환경과 연동하여 얻은 실행 시간 피드백(Execution-time Feedback)을 프롬프트에 주입하는 하이브리드 검증 아키텍처를 도입하여 확증 편향을 차단한다.**

### 예제 2

전문 의료 상담 챗봇을 고도화하기 위해 최신 종양학 연구 가이드라인 데이터로 미세조정(Fine-Tuning)을 수행했습니다. 그 결과 신규 가이드라인 답변율은 상승했으나, 기존에 완벽하게 처리하던 감기, 가벼운 외상 등 일반 내과 질문에 대해 챗봇이 횡설수설하거나 비정상적인 답변을 출력하기 시작했습니다. 원인을 규명하고 해결책을 제시하십시오.

**풀이:**

1단계 — 특정 도메인 데이터(신규 가이드라인) 위주로만 목적 함수가 편향 최적화되면서, 일반 내과 지식을 보유하고 있던 기존 가중치 영역이 과도하게 덮어씌워지는 파괴적 망각(Catastrophic Forgetting)이 발생했음을 인지합니다. 2단계 — 가중치 변경을 전면 허용하는 풀 파인튜닝 대신, 기존 일반 의학 상식 질의응답 세트(General Dataset) 중 대표 데이터 15%를 신규 종양학 가이드라인 데이터셋에 혼합(Experience Replay)하여 병렬 학습 배치를 만듭니다. 3단계 — 추가적으로 파라미터 공간 전체를 건드리지 않도록 LoRA(Low-Rank Adaptation)와 같은 매개변수 효율적 미세조정(PEFT) 기법을 사용하여 기존 가중치 공간을 얼려두고(Freeze) 새로운 지식만 국소적으로 학습시킵니다.

**답: 원인은 파괴적 망각이며, 이를 해결하기 위해 기존 일반 상식 데이터를 일부 혼합한 복합 데이터셋을 구성하고 가중치 업데이트 범위를 고립시키는 PEFT 기법을 적용하여 해결한다.**

## 7. 유제 (면접 예상 질문)

1. 합성 데이터(Synthetic Data) 생성 모델 $A$와 이를 이용해 파인튜닝을 진행하는 학습 모델 $B$가 있을 때, 사람의 개입 없이 이 루프를 10회 이상 반복했을 때 학습 모델 $B$의 최총 출력 다양성이 상실되는 수학적 이유는 무엇입니까? *(힌트: 데이터 생성 및 학습이 반복되면서 누적되는 표본 추출 오차(Sampling Error)와 데이터 분포의 극값 유실 및 엔트로피 감소 현상을 고려하여 분석해 보세요.)*
2. LLM 가중치 업데이트가 아닌 RAG(검색 증강 생성) 기법을 도입함으로써 지속 학습의 '파괴적 망각' 문제를 우회하는 아키텍처적 장점과 실무적 의의는 무엇입니까? *(힌트: 모델 파라미터 내부의 가중치로 기억되는 암묵적 지식(Implicit Knowledge)과 외부 검색 모듈의 명시적 지식(Explicit Knowledge)의 업데이트 주체 및 안전성을 비교해 보세요.)*
3. Self-Refine 에이전트 시스템에서 무한 루프(Infinite Loop)나 무의미한 자가 수정을 조기 종료(Early Stopping)하기 위해 도입해야 하는 실질적인 메트릭(Metric)과 상태 제어 메커니즘은 어떻게 구성합니까? *(힌트: 매 루프 피드백의 응답 변화량 임계값(Cosine Similarity of Outputs) 설정과 외부 오케스트레이터 계층의 카운터 변수 설정을 중심으로 생각해 보세요.)*

## 8. 다음 챕터와의 연결

결국 스스로의 닫힌 루프 속에서는 인지적 한계를 극복하거나 왜곡 없이 지속 학습할 수 없기 때문에, 모델은 반드시 외부와 상호작용해야 합니다. 다음 챕터에서는 이러한 폐쇄형 시스템의 한계를 극복하고 모델의 인지 범위를 극대화하는 '도구 사용(Tool Use)과 외부 API 연동을 통한 에이전트 액션 루프'에 대해 다룹니다.
