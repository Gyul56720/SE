# 01. In-Context Learning과 Fine-tuning: 가중치를 바꾸지 않는 학습과 바꾸는 학습

## 1. 왜 알아야 하는가

LLM을 활용한 시스템 아키텍처 설계 시, 새로운 도메인 지식을 주입하거나 특정 태스크를 수행하도록 조정하는 방식은 크게 '가중치 고정(ICL)'과 '가중치 업데이트(Fine-tuning)'로 나뉩니다. 두 방식의 비용, 지연 시간(Latency), 그리고 치명적 망각(Catastrophic Forgetting) 등의 트레이드오프를 명확히 이해하지 못하면, 프로덕션 환경에서 리소스를 낭비하거나 데이터 오염이 발생하기 때문에 이 개념의 비교는 실무 설계와 기술 면접에서 매우 중요합니다.

## 2. 정의와 구조

### In-Context Learning (ICL): 비파라미터적 적응\nIn-Context Learning(ICL)은 모델의 가중치 $W$를 업데이트하지 않고, 추론(Inference) 시점에 입력 프롬프트(Context)를 통해 원하는 작업의 예시(Few-shot)나 지침을 제공하여 올바른 출력을 유도하는 방법입니다. 이는 Transformer의 Self-Attention 메커니즘을 통해 입력 시퀀스 내의 토큰 간 상관관계를 추론 과정에서 동적으로 활용하기 때문에 가능합니다. 즉, 학습 데이터가 가중치 파라미터가 아닌 활성화 상태(Activation State) 상에 일시적으로 보존됩니다.\n\n### Fine-tuning (FT): 파라미터적 적응\nFine-tuning은 사전 학습된(Pre-trained) 모델에 추가적인 데이터셋을 학습시켜 가중치 파라미터 $W$ 자체를 직접 업데이트하는 과정입니다. 역전파(Backpropagation) 알고리즘을 수행하여 손실 함수 $L$을 최소화하는 방향으로 모델 내부의 상태를 영구적으로 조율합니다. 결과적으로 모델 자체의 지식 저장 공간(Parametric Memory)에 도메인 지식이나 스타일 규칙이 내재화됩니다.

## 3. 핵심 사실 (Killing Fact)

$$ \boxed{\ \theta_{\text{ICL}} = \theta_{\text{frozen}} \quad \text{vs.} \quad \theta_{\text{FT}} \leftarrow \theta_{\text{FT}} - \eta \nabla L(\theta_{\text{FT}})\ } $$

이 수학적 표현은 두 패러다임의 근본적인 연산적 차이를 나타냅니다. In-Context Learning은 모델의 파라미터인 가중치 $\theta$를 완전히 고정한 채 활성화 상태 제어만으로 가동되지만, Fine-tuning은 경사하강법을 통해 가중치 $\theta$ 자체를 물리적으로 업데이트하여 모델의 상태 공간을 영구적으로 변형시킵니다.

## 4. 핵심 기법

### 기법 A: Few-shot Prompting (ICL)

프롬프트 내에 '질문-답변' 쌍의 예시(k-shot)를 직접 배치하여 Transformer가 Attention 맵을 그릴 때 입력 문맥의 패턴을 따르도록 설계합니다.

**왜 이렇게 설계했는가:** 가중치를 변경하지 않기 때문에 하나의 공유 모델 인스턴스에서 서로 다른 프롬프트만으로 동시에 여러 이종 태스크를 유연하게 처리할 수 있기 때문입니다.

### 기법 B: LoRA (Low-Rank Adaptation) (FT)

사전 학습된 기저 가중치를 고정한 상태에서 가중치 변화량 $\Delta W$를 두 개의 저차원 행렬 $A$와 $B$로 분해하여 이들만 학습을 진행하고 업데이트합니다.

**왜 이렇게 설계했는가:** 전체 가중치를 업데이트할 때 발생하는 과도한 메모리 연산 비용을 수십 분의 일 수준으로 줄이면서도 파라미터적 최적화 효과를 얻을 수 있기 때문입니다.

### 기법 C: Instruction Fine-tuning (FT)

지시문(Prompt)과 이상적인 응답(Response)으로 구성된 정렬 데이터셋을 구축한 후 역전파를 통해 모델 전체 또는 일부 레이어의 가중치를 업데이트합니다.

**왜 이렇게 설계했는가:** 단순 텍스트 완성 모델에서 벗어나 인간의 의도(Intent)에 부합하는 형태로 가중치의 활성화 전반을 영구적으로 교정하기 위함입니다.

## 5. 자주 하는 오해 / 주의할 점

가장 흔한 실수는 In-Context Learning으로 주입된 정보가 모델에 영구적으로 '학습'되었다고 생각하는 것입니다. ICL은 프롬프트 세션이 종료되는 순간 정보가 완전히 소실됩니다. 반대로, 미세조정(Fine-tuning)을 단순히 새로운 사실 정보를 주입하는 수단으로만 신뢰하는 경우도 많습니다. 파라미터 미세조정은 사실 주입보다 출력의 스타일, 말투, 형식(Format) 교정에 강력한 효과를 발휘하며, 새로운 사실을 억지로 주입하려고 할 경우 기존 지식을 유실하는 '치명적 망각' 현상과 함께 심각한 환각(Hallucination)이 발생할 수 있습니다.

## 6. 대표예제 (추론 연습)

### 예제 1

금융 투자사에서 실시간으로 변동되는 환율 규칙 및 국가별 규제 사항을 반영하여 고객 문의에 답변하는 챗봇을 설계하려 합니다. 매일 지침이 수시로 업데이트되는 상황일 때, RAG(Retrieval-Augmented Generation)를 결합한 ICL 아키텍처와 Fine-tuning 아키텍처 중 어떤 설계를 선택해야 합니까?

**풀이:**

1단계 - 데이터 변경 빈도를 파악합니다. 규정과 환율 정보는 수시로 변경되므로 가중치를 수정하는 Fine-tuning을 매번 수행하는 것은 비용 및 시간적 관점에서 실현 불가능합니다.\n2단계 - 지식의 소거 및 교정 효율을 비교합니다. Fine-tuning은 이전에 주입된 지식을 지우는 것이 어렵지만, ICL은 프롬프트 컨텍스트에 삽입된 내용만 참조하므로 정보 교체가 단순 문자열 치환 수준으로 쉽습니다.\n3단계 - 최종 의사결정을 내립니다. 최신화된 규제 규정을 벡터 데이터베이스에서 실시간 검색하여 프롬프트에 주입하는 RAG와 ICL 결합 솔루션이 가중치를 지속적으로 업데이트해야 하는 FT 솔루션보다 적합합니다.

**답: 실시간 데이터 변경 및 신속한 최신화 요구사항으로 인해, 모델의 가중치를 바꾸지 않고 컨텍스트를 동적으로 업데이트하는 RAG 기반의 In-Context Learning(ICL) 아키텍처를 채택해야 합니다.**

### 예제 2

사내 법무팀이 수만 건의 비정형 계약서 원문에서 '계약 당사자', '체결일', '위약금 조항'을 정밀하게 추출하여 완벽한 형식의 JSON 포맷으로 저장하는 파이프라인을 구축하려고 합니다. 고도의 일관된 포맷 유지와 더불어 대용량 계약서 처리 시 토큰 당 추론 비용(Inference Cost) 절감이 중요할 때, 무엇을 선택해야 합니까?

**풀이:**

1단계 - 작업의 특성을 파악합니다. 계약서에서 특정 속성을 추출하는 작업은 출력 스키마(JSON 구조)의 엄격성과 일관성이 핵심이며, 도메인 고유의 계약서 형태를 지속적으로 인지하고 있어야 합니다.\n2단계 - 비용 측면을 고려합니다. ICL을 사용하여 복잡한 스키마 정의 및 Few-shot 예시를 매번 모든 계약서 프롬프트에 넣으면 컨텍스트 길이가 길어져 토큰 소비 비용이 기하급수적으로 증가합니다.\n3단계 - 최종 의사결정을 내립니다. 가중치를 업데이트하는 Fine-tuning을 활용하여 모델 자체가 JSON 스키마 구조를 완벽하게 학습하도록 함으로써, 추론 시 프롬프트 길이를 대폭 줄이고 토큰 처리 효율을 극대화합니다.

**답: 출력 포맷의 고도화된 고정과 장기적인 추론 비용 최소화를 위해, 사전에 스키마 데이터를 바탕으로 파라미터를 최적화하는 Fine-tuning(미세조정) 방식을 채택해야 합니다.**

## 7. 유제 (면접 예상 질문)

1. Fine-tuning 과정을 진행할 때, 특정 태스크 성능은 극대화되지만 모델의 범용적인 대화 능력 및 상식 수준이 급격히 저하되는 '치명적 망각(Catastrophic Forgetting)' 현상이 일어나는 근본적인 수치 최적화 관점의 이유는 무엇인가요? *(힌트: 특정 태스크의 손실 함수(Loss Function) 경사도만을 반영하여 가중치가 이동하면서, 기존 대규모 데이터셋으로 형성된 다목적 최적점(Global Optima) 영역을 벗어나기 때문입니다.)*
2. Few-shot Prompting(ICL)을 적용할 때, 예시(Exemplar)의 순서를 다르게 배치하는 것만으로 모델의 최종 예측 결과 분포가 크게 왜곡되는 현상이 발생합니다. 이 현상을 방어하기 위한 시스템 엔지니어링 관점의 평가 기법은 무엇인가요? *(힌트: 다양한 순서 조합으로 프롬프트를 주입하여 출력의 불확실성을 측정하는 캘리브레이션(Calibration) 기술을 탐색해 보세요.)*
3. 시스템 프롬프트 주입 공격(Prompt Injection)을 방어하기 위한 기법을 설계할 때, 프롬프트 내부의 지시 사항 강화(ICL 방식)보다 가중치 수준에서 안전 가이드라인을 미세조정(FT 방식)하는 것이 왜 더 본질적이고 완고한 보안 경계를 제공합니까? *(힌트: 런타임 컨텍스트는 공격 입력에 의해 Self-Attention 우선순위가 뒤바뀔 수 있으나, 가중치는 입력 데이터와 상관없이 활성화 흐름의 임계값을 직접 제어하기 때문입니다.)*

## 8. 다음 챕터와의 연결

In-Context Learning의 강점을 활용하여 실시간 지식을 확장하기 위해서는 제한된 컨텍스트 윈도우 크기를 극복해야 합니다. 이를 위해 다음 챕터에서는 외부 데이터베이스에서 의미적으로 연관된 정보를 실시간으로 추출하여 프롬프트에 주입하는 'Retrieval-Augmented Generation (RAG)의 기본 아키텍처와 최적화'에 대해 배웁니다.
