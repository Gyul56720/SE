# 01. 해킹의 분류와 윤리적 해킹(모의침투) 방법론

## 1. 왜 알아야 하는가

시스템을 방어하기 위해서는 공격자의 관점과 체계적인 침투 프로세스를 이해해야 합니다. 해킹의 범주를 명확히 구분하고 표준화된 모의침투 방법론을 습득하는 것은, 보안 취약점을 탐지할 때 임의적이고 위험한 행위를 배제하고 안전하며 법적 테두리 내에서 시스템을 보호하는 체계를 구축하기 위함입니다.

## 2. 정의와 구조

### 1. 해커의 분류와 윤리적 해킹
해킹(Hacking)은 본래 기술적 한계를 극복하고 시스템을 깊이 이해하는 행위를 의미했으나, 현대에는 시스템의 보안 취약점을 탐색하고 이용하는 행위 전반을 지칭합니다. 주체의 목적과 법적 합의 여부에 따라 다음과 같이 분류됩니다.

* **화이트햇 해커(White Hat Hacker)**: 소유자의 명시적 동의 하에 보안 취약점을 찾고 이를 보완하는 윤리적 해커입니다.
* **블랙햇 해커(Black Hat Hacker)**: 개인적 이득이나 파괴를 목적으로 승인되지 않은 시스템에 침입하는 악의적 해커입니다.
* **그레이햇 해커(Gray Hat Hacker)**: 동의 없이 시스템의 취약점을 탐색하지만, 이를 악용하지 않고 공개하거나 수정을 요구하는 과도기적 해커입니다. 법적으로는 불법 침입에 해당할 수 있어 주의가 필요합니다.

### 2. 모의침투(Penetration Testing) 표준 방법론
조직의 보안을 체계적으로 검증하기 위해 임의적인 공격이 아닌 합의된 국제 표준 방법론을 사용합니다. 대표적으로 **PTES(Penetration Testing Execution Standard)**가 있으며, 다음과 같은 단계적 절차를 준수합니다.

1. **사전 계약 및 범위 설정(Pre-engagement Interaction)**: 테스트 대상 범위(IP, 도메인, API), 수행 시간, 공격 기법의 한계를 법적 계약서로 명문화합니다.
2. **정보 수집(Intelligence Gathering)**: 대상 시스템의 IP 대역, 열린 포트, 사용 중인 OS 및 소프트웨어 버전을 파악합니다.
3. **취약점 분석(Vulnerability Analysis)**: 수집된 정보를 바탕으로 알려진 취약점(CVE)이나 논리적 오류가 있는지 진단합니다.
4. **침투 시도(Exploitation)**: 취약점을 안전하게 검증하여 실제로 침입이 가능한지 증명(PoC)합니다. 시스템 가용성에 영향을 주지 않는 선에서 수행됩니다.
5. **포스트 익스플로잇(Post-Exploitation)**: 침투 후 권한 상승, 내부 네트워크 이동(Lateral Movement) 등을 통해 추가 위협을 평가합니다.
6. **보고서 작성(Reporting)**: 발견된 취약점, 위험도 수준, 구체적인 패치 및 대응 방안을 문서화하여 고객에게 인도합니다.

## 3. 핵심 사실 (Killing Fact)

$$ \boxed{\ \text{Legality} = \text{Explicit Written Authorization} \land \text{Adherence to Agreed Scope}\ } $$

윤리적 해킹과 범죄로서의 해킹을 가르는 유일한 기준은 '기술의 난이도'가 아니라, 대상 조직으로부터 사전에 서면으로 승인받은 '합법적 권한'과 약속된 '범위'의 준수 여부이기 때문입니다.

## 4. 핵심 기법

### 기법 A: 수동적 정보 수집 (Passive Reconnaissance)

대상 시스템에 직접 패킷을 보내지 않고 OSINT(Open Source Intelligence), DNS 레코드 조회, Shodan 검색 등을 통해 정보를 획득합니다.

**왜 이렇게 설계했는가:** 대상 시스템 방어 장비(IDS/IPS)에 탐지되지 않고 공격 표면(Attack Surface)을 안전하게 정찰하기 위해서입니다.

### 기법 B: 능동적 정보 수집 및 포트 스캐닝 (Active Reconnaissance)

Nmap 등의 도구를 사용해 대상 서버에 TCP SYN 패킷 등을 전송하고 돌아오는 응답을 통해 활성화된 포트와 서비스 데몬의 버전을 파악합니다.

**왜 이렇게 설계했는가:** 특정 포트에서 실행 중인 서비스의 정확한 버전을 알아야 해당 버전에 존재하는 알려진 취약점(CVE)을 매핑할 수 있기 때문입니다.

### 기법 C: 취약점 개념 증명 (Proof of Concept, PoC)

공격 코드가 대상 시스템을 파괴하지 않고 안전하게 동작함을 보여주기 위해, 단순한 알림창을 띄우거나 무해한 환경 변수값을 출력하는 최소한의 셸 코드를 주입합니다.

**왜 이렇게 설계했는가:** 실제 서비스 장애를 유발하지 않으면서도 해당 취약점이 실제로 악용될 수 있음을 증명하기 위해서입니다.

### 기법 D: 침투 테스트 범위 통제 (Scoping & Containment)

작업 시작 전에 타깃 IP 리스트와 화이트리스트(보안 장비 우회용 IP)를 등록하고, 업무 시간 외 또는 트래픽이 적은 시간에 테스트를 수행합니다.

**왜 이렇게 설계했는가:** 운영 중인 비즈니스 서비스의 가용성(Availability)을 해치지 않고 실제 운영 환경에서의 보안 수준만을 측정하기 위해서입니다.

## 5. 자주 하는 오해 / 주의할 점

초보 엔지니어들은 자동화된 취약점 스캐너(예: Nessus, OpenVAS)의 결과 리포트를 그대로 출력하는 것을 모의침투라고 오해합니다. 하지만 스캐너는 오탐(False Positive)이 많고 비즈니스 로직 취약점을 잡지 못하기 때문에, 반드시 사람이 수동으로 검증하고 연계 공격 시나리오를 구성해야 합니다. 또한, 긴박한 상황에서 구두 동의만 얻고 테스트를 진행했다가 법적 분쟁에 휘말리는 실수가 빈번하므로, 반드시 서명된 서면 계약서 확보 후에만 작업을 시작해야 합니다.

## 6. 대표예제 (추론 연습)

### 예제 1

한 주니어 보안 연구원이 오픈소스 프로젝트의 취약점을 찾던 중, 특정 쇼핑몰 사이트의 관리자 페이지가 인증 없이 접근 가능한 것을 발견했습니다. 이 연구원은 선의를 가지고 이 취약점을 상세히 분석하여 관리자 DB 내 정보까지 조회한 뒤 쇼핑몰 담당자에게 이메일로 제보했습니다. 이 행위는 윤리적 해킹의 관점에서 정당한가요?

**풀이:**

1단계 — 법적 동의 여부 확인: 해당 쇼핑몰 소유주로부터 사전 분석이나 모의침투에 대한 명시적 서면 합의(Scope 및 Authorization)를 받지 않았습니다.
2단계 — 행위의 범위 검토: 단순 페이지 노출 확인을 넘어 실제 DB 내부 정보까지 조회한 것은 권한 없는 데이터 접근 행위에 해당합니다.
3단계 — 결론 도출: 비록 선의(Good Faith)를 가지고 제보했더라도, 사전 합의가 없었으며 허용 범위를 넘어서는 침해 행위를 동의 없이 수행했기 때문에 이는 윤리적 해킹이 아닌 불법적 침입으로 간주됩니다.

**답: 정당하지 않습니다. 사전에 서면 동의를 받지 않은 상태에서 타인의 자산에 접근하고 데이터를 조회한 행위는 법적 처벌의 대상이 될 수 있습니다.**

### 예제 2

A 기업에서 대고객 웹 애플리케이션에 대한 모의침투를 의뢰받았습니다. 테스트 수행 중 특정 입력창에 SQL Injection 취약점이 존재함을 확인하였으나, 이 시스템은 실시간 결제 DB와 직접 연동되어 있습니다. 모의침투 엔지니어로서 취해야 할 가장 올바른 후속 조치는 무엇입니까?

**풀이:**

1단계 — 위험성 평가: SQL Injection 공격 코드를 강하게 수행할 경우 데이터베이스 무결성 손상이나 서비스 마비(DDoS)를 초래할 위험이 큽니다.
2단계 — PoC 최적화: 데이터베이스를 파괴하거나 대량으로 유출하는 대신, 시스템 버전을 조회하는 수준($\text{SELECT @@version}$)의 무해한 쿼리로 취약점 존재 여부만 증명합니다.
3단계 — 보고 및 조율: 취약점 발견 사실을 고객사 담당자에게 즉시 알리고, 안전한 테스트 환경(Staging)이 있는지 파악하거나 가용성에 무리가 없는 한도 내에서 검증을 마칩니다.

**답: 서비스 운영과 무결성에 영향을 주지 않도록 무해한 쿼리를 통한 개념 증명(PoC)만 안전하게 수행한 후, 발견 즉시 고객사에 통보하고 완화 조치 방안을 제시해야 합니다.**

## 7. 유제 (면접 예상 질문)

1. 모의침투 프레임워크인 PTES의 7개 단계 중 'Post-Exploitation(포스트 익스플로잇)' 단계의 주 목적은 무엇이며, 단순한 시스템 침투 성공 단계와 어떻게 구별되나요? *(힌트: 침투 성공은 시스템 권한을 얻는 순간 끝나지만, 그 이후 공격자가 비즈니스에 줄 수 있는 실질적인 영향력(데이터 유출, 권한 상승 등)의 크기를 확인하는 과정에 집중해야 합니다.)*
2. 화이트박스(White-box) 모의침투와 블랙박스(Black-box) 모의침투의 정보 제공 수준 차이를 설명하고, 소스코드 검증과 연계된 내부 보안 진단 시 어떤 방식이 더 효율적인지 인과관계와 함께 제시하세요. *(힌트: 블랙박스는 사전 정보 없이 공격자 관점에서 진행되며, 화이트박스는 소스코드 및 아키텍처 정보를 사전에 제공받아 시간 대비 깊이 있는 진단이 가능합니다.)*
3. 웹 애플리케이션 모의침투 도중 발견한 취약점을 보고서에 작성할 때, 정량적인 위험도를 평가하기 위해 널리 사용되는 기준 시스템(Framework)은 무엇이며 어떤 요소들을 기준으로 점수를 매기나요? *(힌트: CVSS(Common Vulnerability Scoring System) 표준을 참고하여 취약점의 공격 복잡성, 필요 권한, 기밀성/무결성/가용성 영향도를 분석해 보세요.)*
