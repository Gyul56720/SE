# law/ -- 법 학습자료 오케스트레이션

지금 있는 것은 **심판과 원장뿐이다.** 생성기는 아직 없다.

생성기를 먼저 만들지 않은 이유는 `novel/` 에서 겪은 것 때문이다. 거기서는 관문을 나중에
붙였고, 붙이고 나니 원고가 관문을 통과하려고 균질해졌다(`novel/gate.py` 의 관문 축소 기록).
무엇을 잡을지 정해두고 생성기를 붙이는 쪽이 순서다.

## 왜 법이 이 저장소에 맞나

이 저장소의 원칙은 하나다 -- **생성자와 심판을 분리하고, 심판은 LLM 이 아니다.**
소설에서 이 원칙을 지키기 어려웠던 것은 기계가 대조할 원장을 인공적으로 쌓아야 했기
때문이다(관계·비밀·설정). 법은 그 원장이 이미 밖에 있다. **조문 원문이 그것이다.**

그래서 여기 관문들은 소설의 어떤 관문보다 판정이 확실하다. "인용한 조문이 실재하는가" 는
취향이 아니다.

## 원장부터 채운다

    export LAW_API_OC=발급받은키          # open.law.go.kr 에서 무료 발급
    python3 law/fetch.py 형법 민법        # 받아서 law/corpus/ 에 저장
    python3 law/fetch.py 형법 --list      # 무엇이 검색되는지 먼저 본다

`law/fetch.py` 는 **검색 -> 이름이 정확히 같은 것 고르기 -> 본문 -> 검사 -> 저장** 으로
간다. '형법' 을 검색하면 군형법·형법 시행령이 같이 나오기 때문이다. 이름이 같은 것이
여럿이면 시행일자가 늦은 것을 고른다.

받은 것을 그대로 믿지 않는다. 조문 머리(`제N조`)가 하나도 없으면 **저장하지 않고**(인증키
오류 XML 이 원장에 들어가면 심판이 그것을 정답으로 삼는다), 저장한 뒤에는 원장으로 다시
읽어 조문이 몇 개 잡히는지 보고한다 -- 받는 것과 파싱되는 것은 다른 일이다. 파일 첫 줄에
시행일자와 받은 날짜를 적는다. **언제 것인지 모르는 원장은 못 쓴다.**

인증키는 URL 에만 들어가고 로그·오류 메시지에는 가려서만(`te********`) 나간다.

## 문언 -- 낱말 하나가 결론을 바꾼다

`law/wording.py` 는 **`novel/wording.py` 를 뒤집은 것**이다. 소설의 말맛 장부는 같은 뜻
다른 꼴을 세어 **적게 쓴 쪽으로 민다** -- 거기서 다양성은 미덕이다. 법은 정반대다.
**문언은 바꿔 쓰면 안 된다.**

| 조문 | 문서 | 무엇이 바뀌나 |
|---|---|---|
| 명할 수 **있다** | 명하여야 한다 | 재량 -> 기속 |
| 등록 **및** 신고 | 등록 또는 신고 | 요건 둘 -> 하나 |
| 3년 **이내** | 3년 이전 | 그 날이 안에 드는가 |
| **준용**한다 | 적용한다 | 그대로 -> 고쳐서 |
| **재산상 이익** | 재물 | 배임 -> 횡령 |

다섯 줄 전부 낱말 하나 차이인데 결론이 갈리고, 다섯 줄 전부 **조문 원문과 대조하면 기계가
판정한다.** 가져온 방법은 novel 과 같다 -- 뜻이 아니라 **꼴**로 가른다. 다른 것은 판정뿐이다:
소설은 원고 안의 분포를 보고, 법은 조문과 견준다.

    W001 서법(기속/재량/금지) · W002 접속(및/또는) · W003 경계(이내/이전) ·
    W004 법효과어(적용/준용/간주/추정) · W005 용어 치환(짝 106쌍)

W005 의 짝 목록은 민법 총칙·물권·채권 / 민사소송 / 형법 / 형사소송 / 헌법·행정으로 갈라
**106쌍**을 담았다. 각하와 기각, 증명과 소명, 증거능력과 증명력, 위법성조각과 책임조각,
제한과 침해, 즉시와 지체 없이 -- 전부 같은 자리에서 갈음될 수 있고 갈음하면 결론이
달라지는 것들이다. 그냥 뜻이 다른 두 낱말(원고/피고)은 넣지 않는다. 헷갈릴 자리가 없다.

늘리려면 `law/wording.py` 의 `PAIRS` 에 한 줄을 더한다. 다만 **짧은 용어를 품은 긴 낱말은
`MASKS` 에 같이 넣어야 한다** -- 안 그러면 '무과실' 안의 '과실', '제척기간' 안의 '기간',
'소유권이전' 안의 '소유' 가 따로 잡혀 멀쩡한 문장이 기각된다(실측으로 확인했다). 스캐너가
긴 것부터 먹으므로 `MASKS` 에 든 낱말이 먼저 소비된다. 띄어쓰기는 지우고 견주므로
'재산상 이익' 과 '재산상이익' 은 같은 낱말이다.

```bash
python3 law/wording.py 법이론서            # 위반
python3 law/wording.py 법이론서 --trace    # 낱말이 어느 조문에 근거하는지
```

판정 규칙은 하나다: **문서가 쓴 값이 인용한 조문에 하나도 없으면 위반.** 조문에 그 범주가
아예 없으면 판정하지 않는다 -- 견줄 것이 없는데 기각하면 맞는 답도 버린다.

`--trace` 가 "글자 하나하나를 근거를 바탕으로" 가 실제로 어디까지 되는지를 보여준다.
문장마다 근거 있는 값과 근거 없는 값을 갈라 늘어놓는다.

판정은 통과/기각 둘이 아니라 **셋**이다. 세 번째가 **미검증** -- 원장이 그 법령을 안
담고 있어 아직 아무도 안 본 것이다. 통과가 아니다. 코퍼스가 비었는데 인용을 통과시키면
심판이 있다는 착각만 생기고 환각은 그대로 나간다. 그래서 보고서가 검증 수와 미검증 수를
항상 같이 적는다.

## 쟁점 -- 뽑지 않고 도출한다

`law/METHOD.md` 가 독일 법학방법론 · 미국 판례론 · 한국법 다섯 갈래 · NLP 벤치마크에서
절차를 출처와 함께 끌어온 문서다. 결론 한 줄: **쟁점은 판단이 아니라 계산이다.**

독일 Relationstechnik 은 같은 요건표를 원고 쪽에서 한 번(Klägerstation), 피고 쪽에서 한
번(Beklagtenstation) 돌린다. 두 결론이 갈리는 자리가 쟁점이다. 그러면 LLM 에게 "쟁점을
뽑아줘" 라고 물을 이유가 없다.

    LLM 이 한다   조문에서 요건 뽑기 · 사실에서 주장 뽑기 · 요건별 포섭 서술
    코드가 한다   두 정거장 돌리기 · 쟁점 도출 · 결과 의존성 검사

```bash
python3 law/issue.py law/cases/대여금_예시.json          # 쟁점표
python3 law/issuegate.py law/cases/대여금_예시.json      # 쟁점표 + 관문 J001~J010
```

| | 관문 | 근거 (METHOD 절) |
|---|---|---|
| J001 | 요건이 실재하는 조문에 걸려 있는가 | 1-1 Gutachtenstil Obersatz |
| J002 | 단계가 그 갈래의 단계표에 있는가 | 3-6 다섯 갈래 표 |
| J003 | 증명책임이 단계에서 따라 나오는가 | 3-2 법률요건분류설 |
| J004 | 양측 주장이 있고 서로 반대인가 | 2-4 factor 대립 구조 |
| J005 | **답이 갈릴 때 결론이 갈리는가** | 2-3 holding · 3-3 민소법 제216조 |
| J006 | 원용해야 하는 항변을 원용 없이 세웠는가 | 1-2 Einrede · 3-2 권리저지 |
| J007 | 청구원인이 애초에 충분한가 | 1-4 Klägerstation |
| J008 | 해석기법이 닫힌 목록에 있는가 | 1-6 Savigny canones |
| J009 | 같은 요건에 쟁점을 두 번 세웠는가 | -- |
| J010 | 사람/LLM 의 쟁점표가 도출 결과와 같은가 | 이 파일의 전제 |

J005 가 심장이다. "중요해 보이는가" 는 취향이지만 "답이 갈릴 때 결론이 갈리는가" 는
계산이다. 순서 의존성(구성요건->위법성->책임, 적법요건->본안)도 여기서 자동으로 나온다 --
앞 단계가 깨지면 뒤 단계는 결론을 못 바꾸므로 도출에서 빠진다.

기계 관문이 **내적 정당화**(Alexy)까지만 보고 "법리가 타당한가" 는 안 보는 것도 METHOD 1-7
에 근거가 있다. 전제가 옳은가는 외적 정당화의 문제이고 기계의 관할이 아니다.

## 지시문 튜너 -- 관문 점수로 프롬프트를 고친다

`novel/tuner.py` 를 옮긴 것이다. 옮기면서 하나가 좋아졌다: 소설의 축은 취향이라 목표값을
표본에서 끌어와야 했지만(`novel/targets.py`), **법의 축은 관문 규칙이고 목표값은 전부 0**
이다. 표본이 필요 없다.

```bash
python3 law/tuner.py plan        # 무엇을 고칠지만 (LLM 호출 0)
python3 law/tuner.py try         # 제일 걸린 규칙의 지시문만 고쳐 넣는다 (claude 1회)
(생성기를 다시 돌린다)
python3 law/tuner.py keep        # 다시 잰 점수로 채택/되돌림
python3 law/tuner.py log
python3 law/tuner.py block       # 지금 프롬프트에 실을 지시문 덩어리
```

지시문은 `law/directives.json` 에 규칙마다 한 줄씩 있다 -- **코드가 아니라 데이터다.**
`block()` 은 **걸린 규칙의 지시문만** 싣는다(전부 실으면 걸리는 것이 묻힌다).

novel 이 사고로 배운 계약 셋을 그대로 지킨다: 산출물 본문은 프롬프트에 안 들어간다 ·
시도마다 결론은 한 번 · 내리 되돌린 규칙은 여섯 바퀴 쉰다. 여기에 하나를 더 넣었다 --
**재생성 없이는 심판하지 않는다.** 지시문만 고치고 점수를 다시 재면 같은 값이 나오고,
같은 값은 되돌림이라 무엇을 써도 되돌아간다. 그래서 잰 파일들의 지문을 견주고 안 바뀌었으면
판정을 거부한다.

## 하지 않는 것

이 시스템은 **정확한 법률 자문을 만들지 못한다.** 만드는 것은 공급된 조문 범위 안에서
환각 없이 정리된 학습 자료다. 관문은 인용의 실재성과 일치를 보증할 뿐, 법리 해석의
타당성은 보증하지 않는다. 그건 기계가 볼 수 있는 것이 아니다.

## 넓히기 -- 세 법이 아직 안 돌아 봤다

원장에는 여섯 법령 3,022 조문이 들어 있다(민법 1192 · 형사소송법 610 · 민사소송법 521 ·
형법 402 · 도시정비법 167 · 헌법 130). 그런데 **검사받는 문서는 민법·도시정비법·형법
세 분야뿐**이다. 민사소송법·형사소송법·헌법은 조문은 있는데 그것을 인용하는 문서가 없어,
자가 그 세 법 위에서는 **한 번도 돌아 본 적이 없다.**

`law/write.py` 가 그 자리를 메운다. 조문 원문을 재료로 주고 법이론서 한 편을 받는다.

    python3 law/write.py --계획 law/plan.json --법 민사소송법 --프롬프트만  # 무엇을 주는지 먼저 본다
    python3 law/write.py --계획 law/plan.json --법 민사소송법              # 네 편
    python3 law/gate.py 법이론서                                          # 그리고 심판

**생성자는 관문을 모른다.** 프롬프트에 L001 도 W004 도 없다 -- `novel/gate.py` 와
`mathdrift/spread.py` 에서 두 번 데인 자리다(관문을 알려 주면 원고가 관문을 통과하려고
균질해지고, 발산이 사양서가 된다). `tests/test_law_write.py` 가 닫힌 목록으로 그것을
고정한다.

## 밖의 자 -- 변호사시험

    python3 law/ocr.py 시험지.pdf --쪽 1-3            # 몇 쪽만 시험 삼아 옮겨 본다
    python3 law/ocr.py 시험지.pdf --out law/exam/2026_민사법_선택형.txt
    python3 law/exam.py law/exam/2026_민사법_선택형.txt --보기   # 몇 문항을 읽었나
    python3 law/exam.py law/exam/2026_민사법_선택형.txt --답 답표.txt

`law/exam/2026_민사법_선택형_손옮김.txt` 은 **사람이 눈으로 읽어 옮긴 문 1~14** 다.
OCR 이 지어냈는지는 이것과 대 보면 안다. **덮어쓰지 말 것** -- 견줄 기준이 없어진다.

지금 우리 점수는 우리가 만든 관문의 위반 수뿐이다. 자기가 만든 자로 자기를 재면 관문이
놓친 것은 영영 안 보인다. 변호사시험은 **우리가 안 만든 자**다.

**시험지에는 관문이 댈 것이 적다.** 선택형 지문은 조문 번호를 거의 안 쓰고 문항마다
"다툼이 있는 경우 판례에 의함" 이 붙는다. 그래서 재는 자리를 시험지가 아니라 **답안**으로
옮긴다 -- 근거를 조문으로 쓰라고 시키면 그 근거가 원장과 대조된다.

    정답률   밖의 자      어긋남   안의 자

**둘이 같이 움직이는지가 핵심이다.** 어긋남이 내려가는데 정답률도 같이 내려가면, 그
지시문은 관문만 통과시키는 쪽으로 답안을 균질화한 것이다.

옮겨 적는 자도 지어낸다. `law/ocr.py` 의 프롬프트는 "보이는 대로만, 안 보이면
`[읽을 수 없음]`" 하나만 시키고, 메웠는지는 `law/exam.py --보기` 가 되짚는다
(선택지를 못 읽은 문항, 번호가 빠짐없이 이어지는지).
