  * 표시가 이 구조의 두 핵심이다.

    · 원본 삭제 + 프로세스 분리
        코덱이 전역 변수나 파일을 경유해 원본을 decode 쪽으로 넘길 경로를 닫는다.
        decode 는 blob 말고 아무것도 볼 수 없다.

    · verifier 교체
        planner(LLM)가 쓴 채점표를 버리고 밖에서 만든 심판을 계획에 주입한다.
        plan.json 의 verifier 가 경로 문자열이라 가능하다.
        만드는 쪽과 채점하는 쪽이 분리된다.


--------------------------------------------------------------------------------
 채택 규칙
--------------------------------------------------------------------------------

  두 축을 동시에 이겨야 한다.

      압축력  bits/weight 가 기준선보다 작다
      복원력  함수 오차가 기준선보다 작다

  한 축만 이기면 기각.
      ternary_b158  압축력 4.7배 승 / 복원력 31배 패  -> 기각
      fp16          복원력 승 / 압축력 2배 패          -> 기각

  통과한 코덱은 설계 과정이 본 적 없는 holdout 셋으로 다시 채점한다.
  holdout 은 텐서 '종류'별로 층화한다 -- 한 종류가 통째로 한쪽에 몰리면
  그 종류에 과적합한 코덱을 잡지 못한다.


--------------------------------------------------------------------------------
 심판이 막는 것 / 못 막는 것
--------------------------------------------------------------------------------

  막는다 (회귀 검사로 고정)
      원본을 모듈 전역에 숨기기      encode/decode 가 다른 프로세스라 전역이 사라진다
      blob 에 원본 경로만 담기       decode 전에 원본 .npy 를 지운다
      임시 디렉토리에 원본 은닉      encode 전후 파일 스냅샷 비교
      실행마다 다른 결과             두 번 encode 해서 blob 이 같아야 한다
      decode 가 모양을 잃음          원본 shape 과 비교
      비트 수 속이기                 실제 blob 길이로만 잰다
      설계한 행렬로 채점             holdout 셋은 설계 과정이 보지 못한다

  못 막는다
      코덱이 /tmp 밖 절대경로에 원본을 숨기는 것.
      진짜 격리는 컨테이너/네임스페이스가 필요하다.
      여기서 막는 것은 "무심코 새는" 경로와 "그럴듯하게 속이는" 경로다.


--------------------------------------------------------------------------------
 파일별 역할
--------------------------------------------------------------------------------

  judge.py         독립 심판. 프로세스 격리 + 원본 삭제 + 결정성 검사
  weights.py       safetensors Range 로 행렬 캐시. 종류별 층화 분리
  activations.py   실제 활성치 표본. 심판이 왜곡을 재는 '방향'을 정한다
  bounds.py        이론 한계와 그 한계가 선 가정을 분리해서 잰다. 코덱은 안 만든다
  rans.py          인터리브 rANS 엔트로피 부호기. 정수 연산만 써서 결정론적
  search.py        자가개선 루프. 최종 노드 verifier 를 심판으로 갈아끼운다
  codecs/*.py      코덱들. encode(W)->bytes, decode(blob)->W' 계약만 지키면 된다


--------------------------------------------------------------------------------
 코덱 계약
--------------------------------------------------------------------------------

      def encode(W: np.ndarray) -> bytes      # W 는 2차원 float32
      def decode(blob: bytes) -> np.ndarray   # 같은 모양의 float32

  decode 는 blob 말고 아무것도 받지 않는다.
  shape·스케일 등 복원에 필요한 모든 것이 blob 안에 있어야 한다.
  표준 라이브러리 + numpy 만.

  회전 행렬 H 는 blob 에 담지 않는다 -- n 하나로 결정되는 상수이기 때문이다.
  같은 크기의 서로 다른 두 행렬이 똑같은 H 를 받으므로 H 를 통해 W 의 정보가
  샐 수 없다. 이것이 "저장 0비트"의 정확한 의미다.

  판별 기준:  그 대상이 W 에 의존하는가?
      H = sylvester(n)   W 에 무관   -> 저장 불필요, 0 비트
      정수 코드 q        W 에 의존   -> 저장 필요
      블록 스케일 s      W 에 의존   -> 저장 필요
      학습된 회전 Q      W 에 의존   -> 저장 필요 (n=896 이면 12.8M 비트)
