# XOR 게이트 최소화 — 노드 분해 설계

F₂ 위의 행렬 M 이 주어졌을 때 y = Mx 를 계산하는 **가장 짧은 XOR 회로**를 찾는다.
Shortest Linear Program (SLP) 문제이고 NP-hard 다. 암호의 선형 계층(MDS 행렬,
AES MixColumns 등) 구현 비용이 곧 이 값이라 기록이 계속 갱신된다.

## 왜 이 문제가 이 시스템과 맞는가

랭크 22 설계에서 얻은 필터 셋을 전부 통과한다.

**검증이 정확하고 싸다.** 회로를 기저 벡터에 돌려 행렬을 복원하고 대조하면 끝이다.
O(게이트 수 × n) 이라 즉시고, 허용오차가 없어 근접 오답이라는 개념 자체가 없다.

**눈금이 촘촘하다.** 게이트 수가 진척 축이고 94 → 93 → 92 로 한 칸씩 내려간다.
랭크 22 가 죽은 이유가 "잔차 ≠ 0" 하나뿐인 이진 신호였는데, 여기는 래칫에 계단이 있다.

**최전선이 전용 대규모 계산이 아니라 휴리스틱이다.** Boyar-Peralta 와 그 변종들이 SOTA 고,
개선은 **더 나은 탐색 프로그램을 쓰는 것**으로 이뤄진다. 이 시스템이 하는 일과 같다.

## 두 단계로 나눈다

오케스트레이터를 탐색기로 쓰지 않는다. **하니스를 짓는 데 쓰고, 탐색은 래칫 루프가 한다.**

    [1단계] 오케스트레이터 DAG  -- 심판·벤치마크·기준선 휴리스틱을 짓는다 (유한, 끝이 있다)
    [2단계] 래칫 루프           -- 챔피언 휴리스틱을 LLM 이 개선하고 심판이 채택을 정한다

2단계는 mathgen/evolve.py 와 compression/search.py 의 기계를 그대로 쓴다. design/holdout
분리도 compression 에서 이미 만든 것이다.

## 계약

```python
def minimize(matrix, seed=0, budget_seconds=60.0) -> dict:
    """matrix: m x n 리스트(0/1). 결정적이어야 한다 -- 같은 (matrix, seed) 에 같은 출력.
    반환 {"ops": [(a,b), ...], "outputs": [wire_idx, ...]}

    배선 번호: 0..n-1 은 입력 x_0..x_{n-1}. k번째 연산의 결과는 n+k.
    각 (a,b) 는 t_{n+k} = t_a XOR t_b 이고 a,b 는 자기보다 앞선 배선이어야 한다.
    outputs[j] 는 M 의 j번째 행을 계산하는 배선 번호다."""
```

검증:

    배선[0..n-1] = e_0..e_{n-1}          (입력에 대한 비트마스크)
    (a,b) 마다   배선.append(배선[a] ^ 배선[b])
    모든 j 에 대해  배선[outputs[j]] == M 의 j행     ← 통과 조건
    게이트 수 = len(ops)                             ← **심판이 직접 센다**

## 1단계 DAG

| 노드 | deps | 내는 것 | 심판이 보는 것 |
|---|---|---|---|
| `n1 evaluator` | — | 회로 → 행렬 복원기 | 알려진 회로 왕복 + 고의 오류 검출 |
| `n2 verifier` | n1 | 정확 검증 + 독립 게이트 계수 | 부정행위 목록 전부 (아래) |
| `n3 benchmark` | — | design / holdout 행렬 집합 | 두 집합의 분리·재현성 |
| `n4 baseline` | n1,n2 | Boyar-Peralta 구현 (챔피언 0세대) | 무작위 행렬 전부에서 정확 |
| `n5 harness` | n2,n3,n4 | 격리 실행 + 예산 + 결정성 | 부정행위 시나리오를 실제로 잡는가 |
| `n6 calibration` | n5 | 알려진 인스턴스 재현 결과 | **공표된 수치와 대조** |

### n1 evaluator

`ops`/`outputs` 를 받아 배선을 비트마스크로 굴려 행렬을 복원한다. 형식 검사도 여기서 한다 --
앞선 배선만 참조하는가, 출력 번호가 범위 안인가.

심판: 알려진 작은 회로(예: 4×4 항등, 단순 합)를 넣어 복원 결과가 맞는지 보고, **고의로
망가뜨린 회로**(배선 하나를 바꾼 것)를 넣어 반드시 불일치를 내는지 본다. 통과만 시키는
평가기는 평가기가 아니다.

### n2 verifier ← **여기가 급소다**

랭크 22 의 급소는 인코딩 정확성이었다. **여기 급소는 암기다.** LLM 은 AES MixColumns 의
공표된 회로를 학습 데이터에서 봤을 가능성이 높다. 심판이 이것을 못 막으면 "기록 갱신" 이
사실은 표를 되뱉은 것이 된다.

막아야 할 것:

| 부정행위 | 어떻게 막나 |
|---|---|
| **공표된 회로를 하드코딩** | holdout 을 **채점 시각에 숨은 seed 로 생성**한다. 휴리스틱은 그 행렬을 미리 볼 수 없다 |
| 벤치마크 파일을 읽음 | 격리된 임시 디렉토리에서 실행하고 행렬은 stdin/argv 로만 준다 |
| 네트워크로 조회 | 서브프로세스에 네트워크 차단 + 표준 라이브러리만 |
| 게이트 수를 거짓 보고 | **심판이 `ops` 를 직접 센다.** 보고된 숫자는 읽지도 않는다 |
| 시간 무제한 | 인스턴스마다 예산. 초과는 실격이지 "느린 성공" 이 아니다 |
| 난수로 운 좋은 한 판 | 같은 (matrix, seed) 로 두 번 돌려 **같은 회로**가 나오는지 |
| 출력만 맞추고 회로는 엉터리 | 복원한 행렬을 **전 행** 대조. 부분 일치는 실패 |

mathgen 심판의 "생성기를 임포트조차 안 한다" 와 같은 수다. 검증하는 프로세스가 후보 코드를
전혀 모르게 한다.

### n3 benchmark

두 종류를 섞는다. **구조화된 행렬**(MDS, 순환행렬, 암호 선형 계층)과 **무작위 행렬**.
무작위에서만 좋은 휴리스틱은 실제로 쓸모가 없고, 구조화된 것에서만 좋으면 암기를 의심해야
한다.

- `design` : 고정 집합. 탐색이 본다.
- `holdout` : **채점 시각에 숨은 seed 로 생성.** 채택 판정은 여기서 한다.

compression 에서 design/holdout 을 나눈 이유가 그대로 적용된다 -- 탐색이 보는 집합으로
채택까지 정하면 그 집합에만 좋은 것이 챔피언이 된다.

### n4 baseline

Boyar-Peralta 를 구현해 챔피언 0세대로 둔다. 개선을 주장하려면 기준선이 있어야 하고,
기준선이 남의 논문 숫자가 아니라 **같은 조건에서 우리가 돌린 것**이어야 한다.

### n5 harness

후보 휴리스틱을 격리 서브프로세스로 띄우고, 인스턴스마다 예산을 걸고, 결정성을 확인하고,
나온 회로를 n2 로 검증하고, 게이트 수를 직접 센다.

심판: **부정행위 시나리오를 실제로 심어서 잡히는지 본다.** 하드코딩 표를 넣은 가짜 휴리스틱,
게이트 수를 거짓 보고하는 것, 무한 루프 -- 셋 다 harness 가 잡아야 통과다. 막는다고 적어둔
것과 실제로 막는 것은 다르다.

### n6 calibration ← 최종 노드

알려진 인스턴스(AES MixColumns 등)에서 우리 기준선이 **공표된 수치 근처를 재현하는가**.
벤치의 `b0` 이 하는 일과 같다 -- 여기서 어긋나면 시스템이 아니라 계약·조건 해석이 틀린 것이다.

**조건을 명시하지 않은 비교는 전부 무효다.** 논문마다 전제가 다르다:

- 2입력 XOR 인가, 다입력 XOR 를 허용하는가
- 깊이 제한이 있는가
- in-place 인가 (레지스터 수 제한)
- F₂ 위 비트 단위인가, F₂^k 위 워드 단위인가

**조건이 다른 숫자와 비교해 "기록 갱신"이라고 말하는 것이 이 분야에서 기록을 위조하는
가장 쉬운 방법이다.** calibration 노드는 조건을 결과에 함께 박아 넣는다.

## 2단계 래칫

    챔피언 휴리스틱 ──> LLM 이 개선안 제안 ──> harness 가 격리 채점 ──> 래칫

채택 조건 (전부 동시에):

1. **정확성 100%** -- design·holdout 의 모든 행렬에서 회로가 검증된다. 축이 아니라 관문이다
2. **design 총 게이트 수**가 챔피언보다 작다
3. **holdout 총 게이트 수**가 챔피언보다 작다
4. 예산 초과 인스턴스가 없다

2 와 3 을 둘 다 요구하는 이유: design 에서만 좋아지는 것은 과적합이고, 한 축만 좋아지는
교환을 허용하면 루프가 곧 퇴화한다 -- 압축에서 3진 양자화가 그 지점이었다.

깊이는 축이 아니라 **상한 제약**으로 둔다. 크기만 최소화하면 깊이가 길어지고, 응용에서는
깊이가 곧 지연이라 쓸모가 떨어진다. 다만 깊이까지 축으로 만들면 래칫이 너무 빡빡해져
아무것도 채택되지 않는다.

## 이 설계가 재지 않는 것

- **게이트 수는 실제 속도가 아니다.** 기술 매핑, 팬아웃, 배치·배선은 다른 축이다
- **무작위 행렬의 성적이 암호 행렬의 성적을 보장하지 않는다.** 그래서 둘 다 넣는다
- SLP 는 NP-hard 다. 이 루프는 **더 나은 휴리스틱**을 찾지 최적해를 증명하지 않는다
- 이 분야는 20년 넘게 갈렸다. 새로움은 새 휴리스틱 아이디어에서 나오지 파이프라인에서
  나오지 않는다 -- 파이프라인이 하는 일은 **주장을 검증 가능하게 만드는 것**이다
