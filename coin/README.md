# coin — 시황을 **짓지 않고 잰다**

```
사람의 물음 ("암호화폐 …")
   │
   ├─ 24시간 뉴스     news.py    ← dig/ 가 받는다. 미국·중국·일본·한국 + GDELT
   ├─ 가격 이력       price.py   ← 일봉. 진입일 규칙이 여기 있다
   ├─ 돈 흐름         flow.py    ← 자금조달률·미결제약정·대형이체·공포탐욕
   │
   ├─ 사건 유형       tag.py     ← 규칙 사전. **LLM 아님**
   ├─ 뭉치기          news.py    ← 같은 사건의 여러 나라 기사 → **제일 이른 시각**
   │
   ├─ 사건 연구       event.py   ← **메인.** "그 뉴스 뒤 D+n 에 얼마"
   │    └ 널 모형     null.py    ← 기저율. 이것이 없으면 위의 수는 전부 거짓말
   ├─ 시나리오        scenario.py← 확률 = 표본 비율. 칸은 널 분포가 갈랐다
   ├─ 장세·거래량     regime.py  ← 문턱 없음. 전부 자기 역사의 백분위
   ├─ 종목 훑기       screen.py  ← 초과 **하나로만** 줄 세운다. 종합 점수 없음
   │
   ├─ 프롬프트        prompt.py  ← 원장의 수만 옮긴다
   ├─ Gemini          ask.py     ← orchestrator/llm_pool 재사용
   ├─ **관문**        gate.py    ← C001~C015. **심판자는 LLM 이 아니다**
   └─ 정제 루프       loop.py    ← 멈춤 조건이 기계다
                      run.py     ← 한 명령
```

## 한 명령

```bash
python3 coin/run.py --물음 "비트코인 시장 분석해줘"
python3 coin/run.py --물음 "SOL -12.4% 왜 이래?" --상황만   # 모델 없이
python3 coin/run.py --채우기                                # 원장 채우기
scripts/coin.sh watch 24                                    # 24시간 계속 모으기
```

끝값: `0` 냈다 · `1` **어긋난 자리가 남아 안 냈다** · `2` 암호화폐 물음이 아니다 ·
`3` 못 돌렸다(원장이 비었다 · 키가 없다 · 망이 막혔다)

## 이 파이프라인이 내는 수 한 줄

```
규제금지 BTC D+7  n=42(유효42)  관측 -7.18%  널 +0.61%  **초과 -7.79%p**  p=0.055  승률 19%  나라 2
```

**관측만 보면 안 된다.** 이 저장소가 이 파이프라인을 이렇게 지은 까닭이 저 `널` 칸
하나다. 신호를 **하나도 안 심은** 무작위 걸음에서 같은 자로 재면 이렇게 나온다
(`tests/test_coin_event.py` 가 실제로 돌린다):

```
관측 +0.97%   ← "규제 뉴스 뒤에 오른다" 로 읽힌다
널   +1.22%   ← 아무 날이나 골라도 그렇다
초과 -0.25%p  ← 남는 것은 없다.  p=0.876
```

그래서 **기저율 없는 수익률은 틀린 수가 아니라 뜻이 없는 수**이고, 관문 C004 가
그런 답을 기각한다.

## 왜 LSTM 이 아닌가

사용자가 먼저 그렇게 말했고, 그 판단이 맞다. 값으로 값을 맞히는 모형은 여기서 셋을
다 못 준다.

| | 시퀀스 모형 | 사건 연구 |
|---|---|---|
| 되짚기 | 왜 그 수인지 못 말한다 | 잰 값마다 **날짜 목록**이 붙는다 |
| 표본 | 수천 개를 먹는다 | 유형별 수십 개로 **잰다고 말할 수 있다** |
| 기저율 | 추세를 신호로 읽는다 | 널이 걷어낸다 |

그리고 관문이 대조할 것이 없으면 심판자가 LLM 이 되든지 아무도 아니게 된다.

## 조용히 틀리는 길 다섯, 그리고 각각을 어디서 막나

| 어긋남 | 무슨 일이 나나 | 막는 자리 |
|---|---|---|
| 미리보기 | D0 가 사건보다 앞서 **부호가 뒤집힌다** | `price.진입일` (유예 2시간) |
| 영어만 봄 | D0 가 몇 시간 늦어 이미 끝난 움직임을 잰다 | `news.뭉치기` (최초 보도) |
| 피드 시각 거짓 | 시간대 버그가 미리보기를 만든다 | `본때` · `앞선시각` |
| 기저율 빠짐 | 추세를 신호로 읽는다 | `null.널` (이동 순열) |
| 여러 번 재기 | 325번 재고 걸린 것만 말한다 | `null.보정` (BH) + 시험수 기록 |

## 다국적 수집이 '더 많이' 의 문제가 아닌 까닭

값을 제일 크게 움직인 사건들이 아시아에서 먼저 났다 — 2017 중국 ICO 금지, 2021 중국
채굴 금지, 2018 코인체크 유출. **원문은 중국어·일본어이고 영어 기사는 몇 시간 뒤다.**
영어 시각으로 D0 를 잡으면 그 몇 시간이 통째로 빠지고, 잰 것은 "사건 뒤 수익률" 이
아니라 "이미 빠진 뒤의 되돌림" 이 된다.

`tests/test_coin_loop.py` 가 그 자리를 재현한다 — 같은 사건에서 D0 가 09:00 과 16:00
로 갈린다.

그리고 이 뭉치기는 틀릴 수 있으므로 **두 기준으로 재고 부호가 갈리면 그 값을 미검증으로
내린다**(`event.흔들기`). 한 번 재고 믿지 않는다.

## 관문 (C001~C015) — 심판자

| | | |
|---|---|---|
| C001 | 답의 수가 원장에 있는가 | hard |
| **C002** | **원장의 날짜로 다시 세도 같은 값인가** | hard |
| C003 | 표본 수를 밝혔는가 · 미검증을 근거로 단정했는가 | hard |
| **C004** | **기저율을 같이 적었는가** | hard |
| C005 | 며칠 뒤인지 밝혔는가 | hard |
| C006 | "반드시" 로 미래를 말했는가 | hard |
| C007 | 사전에 없는 사건 유형을 지어냈는가 | hard |
| C008 | 진입가가 사건 뒤인가 | hard |
| C009 | 몇 번 쟀는지 밝혔는가 | hard(유의 주장 시)/soft |
| C010 | 말한 방향이 잰 부호와 같은가 | hard |
| C011 | 원장에서 온 것이 하나라도 있는가 | soft |
| C012 | 투자 권유 | hard |
| C013 | 그 값이 한 나라 기사에서만 왔는가 | soft |
| C014 | 장세가 아래 칸인데 밝혔는가 | hard |
| C015 | 거래량·포지션을 **지갑처럼** 말했는가 | hard |

**C002 가 요점이다.** 나머지는 꼬리표를 보지만 C002 는 값을 본다 — 원장의 날짜와 씨로
가격 원장에서 다시 세서 견준다. `tests/test_coin_gate.py` 가 값을 일부러 바꿔치기해
놓고 잡히는지 본다(`brief` 의 B004, `law/mutate.py` 의 RED/GREEN 과 같은 자리).

## 정제 루프의 멈춤은 기계다

```
바퀴마다:  프롬프트 ← 원장 + 앞 바퀴에서 **사실과 어긋난 자리**
           답      ← Gemini
           점수    ← (hard 수, soft 수, -짚은 잰것 수, 글자 수)
멈춘다:    hard 0 이고 soft 0 · 안 나아짐 · 바퀴 다 씀
낸다:      점수가 제일 낮은 답. **hard 가 남으면 안 낸다**
```

"가장 좋은 답" 을 모델에게 물으면 모델은 늘 자기 답이 좋다고 한다. 여기서 그것은
**원장과의 어긋남**이 정한다.

되먹임에는 **관문 이름도 문턱도 안 실린다** — 알려 주면 관문을 통과하는 문장이 나오지
맞는 문장이 나오지 않는다(`law/write.py` 와 같은 규율). 검사가 그 자리를 붙든다.

## 하드코딩을 뺀 자리

| 박으면 생기는 일 | 대신 |
|---|---|
| 종목표 | 새 종목이 나오면 "그런 거 없다" | 거래소 심볼 목록(`price.심볼목록`) |
| 자산 별명 | 코드를 고쳐야 는다 | `corpus/aliases.json` (데이터) |
| "약세장 = -20%" | 그 20 이 어디서 왔는지 못 말한다 | **자기 역사의 백분위**(`regime`) |
| "+5% 넘게 오름" 칸 | 그 5 가 순위를 정한다 | **널 분포의 오분위**(`scenario`) |
| 종합 점수 무게 | 무게가 순위를 전부 정한다 | 초과 **하나로만** 줄 세움(`screen`) |

마지막이 특히 그렇다. `초과×0.5 + 승률×0.3 + 거래량×0.2` 는 측정처럼 보이는 자리에
취향을 숨기는 일이다.

## 받는 일은 `dig/` 가 한다

헤더벌 돌려쓰기 · 곁문(모바일·AMP·JSON 끝점) · gzip · **charset 감지(cp949 포함)** ·
HTTP 오류에도 몸통 읽기 · 병렬. 중국·일본·한국 매체는 이것 없이는 그냥 실패한다 —
나라를 늘려 놓고 받는 자리를 안 고치면 **늘린 나라가 조용히 0건으로 들어온다.**

## 24시간 계속 모으기

```bash
scripts/coin.sh watch 24     # 얕은 바퀴 5분(RSS) · 깊은 바퀴 1시간(GDELT·흐름)
scripts/coin.sh status
scripts/coin.sh stop
```

RSS 는 **지금 걸려 있는 것**만 준다(대개 최근 20~50건). 하루 한 번 받으면 나머지가
통째로 빠지고 **빠졌는지 아무도 모른다** — 원장은 그냥 좀 작을 뿐이니까.

자주 볼수록 `본때`(우리가 본 시각)가 참 발행 시각에 가까워지고, `시각 > 본때` 인 줄이
드러난다. 그런 줄은 D0 후보에서 빠진다.

## 지금 이 저장소에서 확인된 것과 안 된 것

**돈다(검사가 실제로 돌린다):** 진입일 규칙 · 널 모형(RED/GREEN) · 겹침 · 다중비교
보정 · 시나리오 확률과 신뢰구간 · 장세 백분위 · 관문 15개 전부(바꿔치기 포함) ·
정제 루프 · 트리거 · 다국적 뭉치기 · 모으기 한 바퀴.

**확인 안 됐다:** **출처 주소가 실제로 답하는지 한 곳도 못 봤다.** 이 에이전트
컨테이너는 프록시가 CONNECT 단계에서 403 을 준다(binance · coingecko · cryptopanic ·
coindesk · gdelt 전부). 그래서 `source.py` 의 `확인` 칸이 **전부 비어 있다** — 확인된
적이 없다는 뜻이고 그것이 사실이다.

VM 에서 이것부터 돌려라:

```bash
python3 coin/news.py --탐침      # 어느 출처가 답하나 (나라별)
python3 coin/flow.py --탐침      # 어느 흐름 자료가 답하나
```

**답하는 것만 세라.** 확인 안 된 출처를 확인된 것처럼 세면 이 파이프라인은 "여러
나라를 본다" 고 말하면서 실제로는 한 나라만 보게 된다 — 그리고 그것이 바로 이 설계가
막으려던 오류다.
