# mathdrift — 후보가 아니라 **탐색공간**을 낳는다

목표: 행렬곱 복잡도(b=3, m=22)의 **새 형식화**를 찾는다. 답을 찾는 것이 아니라
**답을 찾을 수 있는 공간**을 찾는다.

```
씨앗 공간 ──> 연산자 하나 ──> 새 공간 ──> 원장
     ↑                                      │
     └──────────  다음 세대의 부모  ─────────┘
```

## 왜 한 층 올렸나

b=3 m=22 는 같은 공간(실수 CP 분해)을 CP-ALS · 무작위 재시작 · 강화학습 · flip graph 로
여러 번 훑어 소진됐다. **고정된 공간 안의 탐색은 정의상 최적화이고, 최적화는 자기가 받은
형식화를 떠나지 못한다.**

역사적으로 이 문제를 움직인 것은 전부 공간을 갈아탄 것이었다:

| 누가 | 무엇에서 무엇으로 |
|---|---|
| Strassen 1969 | 산술회로 → 텐서 랭크 |
| Schönhage 1981 | 랭크 → **경계 랭크** (ε 허용) |
| Coppersmith–Winograd | 정확 분해 → 점근 퇴화 |
| Cohn–Umans 2003 | 텐서 → **군대수 매장** (연속 탐색이 이산 군론 문제가 됨) |

넷 다 사람이 냈다. **기계가 형식화를 낸 사례는 아직 없다** — FunSearch도 AlphaTensor도
주어진 공간 **안에서** 찾았다. 그래서 이건 미답 영역이고, 실패해도 이상하지 않다.

## 공간은 틀릴 수 없다 — 쓸모없을 뿐이다

| 틀렸을 때 | |
|---|---|
| 틀린 **정리** | 독이다. 원장에 들어가면 그 뒤가 전부 오염된다 |
| 틀린 **공간** | 그냥 빈 공간. 탐색해봐야 아무것도 안 나올 뿐 |

그래서 **발산 단계에는 게이트를 안 건다.** 엄밀성은 나중에 요구한다. `novel/DRIFT.md` 의
첫 규칙 그대로 — *과잉 기각은 글 자체를 없앤다.*

## 인과성은 검사하지 않는다 — 구성으로 보장한다

`mathgen` 의 거꾸로 만들기와 같은 수다(거기서는 답 F 를 먼저 골라 f = F' 를 문제로 내니
정답이 구성상 확실했다).

```
새 공간 = 연산자(원장에 이미 있는 공간)
```

모델에게 "공간을 발명하라" 고 묻지 않는다. **"여기 공간 S 가 있다, 여기 *경계화* 를 걸어라,
무엇이 되나"** 라고 묻는다. 부모는 항상 원장에 있고 연산자는 고정 목록에서 나오므로
계보 칸은 비거나 지어낼 수가 없다. `space.add()` 가 원장에 없는 부모를 거절한다 —
내용을 판정해서가 아니라 **계보가 끊긴 것을 원장이 못 받게** 하는 것이다.

한 번에 연산자 **하나**만 건다 (`mathgen` 이 Evol-Instruct 에서 가져온 규칙). 멀리 있는
공간에는 여러 세대를 거쳐서만 간다.

## "완전히 다르면 안 된다" 를 재는 법

`novel/diffusion.py` 의 두 계수를 공간 층으로 옮겼다.

| | 0 이면 |
|---|---|
| **새것** (부모에 없던 구조) | 이름만 바꾼 것 |
| **물려받음** (부모에서 그대로 온 것) | 인과성 없음 — 남의 공간 |

둘 다 있어야 확산이다. 그리고 원문의 규율 그대로 — **재서 숫자를 돌려주되 죽이지 않는다.**

한 낱말 겹친 것은 물려받은 것이 아니다(실측: 아무 상관 없는 "날씨/기압" 도 "연속" 하나로
확산으로 셌다). 그래서 겹친 낱말 2개 이상이라는 바닥을 뒀다.

### 몫의 분모는 부모다

처음에는 `겹친 낱말 / 자식 어휘` 로 쟀는데, 그러면 **새 낱말을 많이 쓴 자식이 벌을 받는다**
— 그리고 그것이 바로 우리가 원하는 것이다.

VM 첫 15개(2026-09-07)에서 드러났다. 알려진 갈아타기 넷 중 셋이 **첫 3호출 안에** 나왔는데:

| 나온 공간 | 실제로 무엇인가 | 옛 자의 판정 |
|---|---|---|
| 완비화 → **자리스키 닫힘** | 경계 랭크의 이웃 (Schönhage) | 남의 공간 |
| 매장 → **비가환 군대수** | Cohn–Umans 그 자체 | 확산 |
| 점근화 → **행렬곱 지수** | Coppersmith–Winograd 방향 | 확산 |

물어야 할 것은 "자식이 부모 말을 얼마나 썼나" 가 아니라 **"부모의 무엇을 가져왔나"** 다.
분모를 부모 어휘로 바꾸면 새것을 많이 더한 것이 안 깎인다. `자식몫` 도 원장에 같이 적어
둔다 — 옛 자가 무엇을 보고 있었는지 대조할 수 있어야 바닥값을 고칠 때 근거가 남는다.

### 낱말 겹침 자는 **두 번** 뒤집혔다 — 그래서 판정에서 뗐다

**두 번째** (VM 50개, 10호출 33초, 식으로 바꾼 뒤):

```
S27 순환 불변 행렬곱 지수 식     가져온 말 14  부모의 0.933   ← 최고점
S31 위상 구조를 지운 ... 지수 식  가져온 말 14  부모의 0.933
S51 ε-근사 하에서의 행렬 곱셈 오차 가져온 말  0  부모의 0.0     ← 경계 랭크인데 바닥
S10 그로텐디크 군의 오일러 지표    가져온 말  0  부모의 0.0
```

S27–S31 은 부모 이름("행렬곱 지수 식")을 그대로 달고 수식어만 바꾼 것이다. **이름에서
식으로 옮겼는데 장식이 식 쪽으로 따라왔다.**

그래서 **세 번째 자를 만들지 않는다.** 숫자는 남기되 "확산 / 인과 약함 / 남의 공간"
같은 판정 낱말을 뗐다. 대신 거르지 않는 **찾기**를 붙였다 (`--known`, 아래).

### 첫 번째로 뒤집혔을 때 — 확산 0.85 는 좋은 소식이 아니었다

VM 60개(2026-09-07). 확산 51/60. 그런데 이름을 보면:

```
S32  멀티리니어 랭크 스펙트럼의  특성류 코호몰로지 공간
S33  점근적 멀티리니어 랭크 스펙트럼의  극한 공간
S34  텐서 범주 내의 멀티리니어 랭크 스펙트럼  대상 모임
```

부모 이름에 연산자 어휘를 **덧붙인 것**이다. 이주가 아니라 작명이고, 낱말 겹침을 재는 자는
**정확히 그것을 최고점으로 준다**(S9 0.529 · S8 0.471 · S34 0.370).

반대로 바닥에는 이런 것들이 깔렸다:

| id | 부모몫 | 이름 | 실제로 |
|---|---|---|---|
| S44 | 0.095 | 오차 허용 지수 영역 | 경계 랭크 쪽 |
| S6 | 0.077 | **지수 대역 (Exponent Cone)** | Strassen 의 점근 스펙트럼 |
| S3 | 0.038 | 점근적 스펙트럼과 사영 다양체 | 자리스키/경계 랭크 |

**진짜 이주일수록 이름이 바뀌고, 이름이 바뀌면 자가 깎는다.** 자가 노이즈가 아니라
뒤집혀 있다. 그래서 **바닥값을 올리면 안 된다** — 올리면 남는 것이 장식뿐이다.

`--remeasure` 가 `장식` 칸과 그 총수를 같이 찍는다. 판정이 아니라 **자를 의심하는
눈금**이다 — 아무것도 기각하지 않는다. 이 수가 높으면 자를 고칠 것이 아니라 자를 버리고
①재현(Strassen·Laderman 을 이 공간의 점으로 적을 수 있는가)으로 가야 한다.

### 자를 고치면 다시 뽑지 않는다 — 다시 잰다

```bash
python3 mathdrift/spread.py --remeasure     # 호출 0회
MATHDRIFT_KEEP_SHARE=0.15 python3 mathdrift/spread.py --remeasure
```

잰 것은 원장에 다 있으므로 다시 계산하면 된다. 분포(최소·4분위·중앙·3분위·최대)를 같이
찍으므로 **바닥값을 실측으로 정한다.** 자가 틀린 채로 300개를 뽑으면 어느 것이 쓸 만한지
못 고른다 — 자를 먼저 맞추고 그 다음에 크게 돈다.

## 칸 — **오로지 수학적 기호만 오간다**

세 번 데었다. 전부 같은 자리였다 — **낱말**.

| | 무엇을 했나 | 무슨 일이 났나 |
|---|---|---|
| 1차 (85개) | 이름과 산문으로 주고받음 | `멀티리니어 랭크 스펙트럼` + 연산자 어휘로 수렴 |
| 2차 (50개) | `식` 칸으로 바꿈 | 식 칸에 한국어가 들어옴 — `"같은 식을 F_2 위에서"` |
| 3차 | 자와 찾기를 만듦 | 그 둘도 한국어 낱말을 세고 있었다 |

이제 표류 통로에 **한국어가 한 글자도 안 흐른다.**

| 칸 | | |
|---|---|---|
| **`식`** | **본체** | `sum_{r=1}^{m} lam_r U[(i,k),r] V[(k',j),r] W[(i',j'),r] = d(k,k') d(j,j') d(i,i')` |
| `점` | | `(U,V,W,lam) in F^{n^2 x m} x ... x F^m` |
| `정의역` | | `F = R` · `F = F_2` · `F = {-1,0,1}` |
| `치수` | 선택 | 점이 수 몇 개인가 |
| `해독` | 선택 | `def decode(p)` — 점 → (U, V, W, λ) |
| `부호화` | 선택 | `def encode(U,V,W,lam)` — 그 역함수 |
| `왜` | 사람용 | **다음 세대에게 전달되지 않는다.** 여기만 한국어 |

### `이름` 칸을 없앴다

두 번 다 거기서 장식이 시작됐다. **자식이 부모 이름을 못 보면 덧붙일 것도 없다** —
검출기를 두느니 원인을 없애는 편이 낫다. 부를 것이 필요하면 `식` 을 잘라 쓴다.

### 기호로 받자 겹침의 뜻이 뒤집혔다

VM 20개(2026-09-07, 한국어를 뺀 뒤). 겹침 0.80 인데 이번에는 **좋은 신호**다:

```
S3   \lim_{N\to\infty}\inf\{ m \mid ... \}
S10  \lim_{N\to\infty}\sup\{ m \mid ... \}    쌍대    부모몫 0.938   ← inf → sup
S16  \hat{H}_*(...) \cong \hat{H}_*(Id)        완비화  부모몫 1.0     ← 모자 하나
S12  S^{-1} H_*(...) \cong S^{-1} H_*(Id)      국소화  부모몫 1.0     ← S^{-1}
S21  \sum_r \lambda_r \rho(U_r)... \equiv ...  이산화  부모몫 0.778   ← = → ≡
```

**연산자가 식에 제대로 작용한다.** 앞서 높은 겹침은 장식이었지만 지금은 **보존적 확장**이다 —
식이 거의 그대로이고 구조 하나만 바뀌는 것이 맞는 모습이다. (S5 는 `Σ λ_r ρ(U_r)ρ(V_r)ρ(W_r)
= ρ(Id)` — Cohn–Umans 를 기호로 쓴 것이고, S6 는 ω 의 정의 그대로다.)

그래서 `--diff` 를 붙였다. 화면이 70자에서 잘려 무엇이 바뀌었는지 볼 수가 없었다:

```
S10  <- S3 / 쌍대
  바뀐 것:  - \inf   + \sup
  그대로 둔 토큰 24/25
```

**판정이 아니다.** 연산자가 식에 무엇을 했는지 기호 단위로 보여 줄 뿐이다.

### `act` — 연산자가 자국을 남겼는가

낱말 겹침 자가 두 번 뒤집힌 뒤로 **아무것도 세지 않고** 있었다. 이유는 하나였다 —
연산자가 무슨 일을 했는지를 **한국어로** 물었기 때문이다. 기호로 물으면 그 문제가 사라진다:

| 연산자 | 자국 |
|---|---|
| 경계화 | `\lim` `\epsilon` `\overline` |
| 완비화 | `\hat` `\widehat` `\varprojlim` |
| 국소화 | `S^{-1}` `\mathfrak` |
| 쌍대 | `+\sup` **와 함께** `-\inf` |
| 표수 이동 | `\bmod` `\mathbb{F}` |
| 탈범주화 | `\dim` `\chi` `\mathrm{rank}` |

diff 의 **더한 쪽과 뺀 쪽을 둘 다** 본다 — 쌍대는 `\sup` 을 더하면서 `\inf` 를 뺀다.

**망각은 자국을 정하지 않았다.** 구조를 지우는 것이라 자국이 "없어짐" 인데, 무엇이
없어져야 하는지는 부모 식마다 다르다. 억지로 목록을 채우면 그 자가 또 뒤집힌다 —
그런 것은 `없음` 이 아니라 **`미정`** 이다.

그리고 이것도 **판정이 아니라 눈금이다.** 자국이 없다고 기각하지 않는다 — 목록에 없는
방식으로 같은 일을 할 수 있고(경계화를 `\overline{R}` 로 쓰는 것처럼), 그것을 벌하면
발산이 목록을 채우는 쪽으로 균질해진다. `novel/` 에서 이미 겪은 그것이다.

### LaTeX 이 JSON 을 깬다

`\lambda` 는 JSON 파서에게 잘못된 이스케이프다 — 식을 기호로 받기 시작하자 **다섯 묶음 중
하나를 통째로 잃었다(20%).** 모델에게 "역슬래시를 두 번 써라" 라고 시키지 않는다(프롬프트를
사양서로 만드는 길이고 이미 데었다). **읽는 쪽에서 고친다.**

함정 하나가 더 있다: `\t` `\b` `\f` `\n` `\r` 은 JSON 이스케이프이면서 **LaTeX 명령의
머리**다. 그냥 고치면 `\to` 가 탭이 되고 `\big` 이 백스페이스가 된다. 그래서 **글자가
뒤따르면 LaTeX 로 본다** — `\to` `\rho` `\frac` `\beta` `\nabla` 가 다 산다.

### 낱말 겹침 자는 판정에서 뗐다

두 번 뒤집혔다. 2차(50개)에서:

```
S27 (부모 식에 수식어만 덧붙임)  가져온 말 14  부모의 0.933   ← 최고점
S51 ε-근사 하에서의 행렬곱 오차    가져온 말  0  부모의 0.0     ← 경계 랭크인데 바닥
```

숫자는 남기되 `확산`·`인과 약함`·`남의 공간` 같은 판정 낱말을 뗐다. **세 번째 자를
만들지 않는다.** 알려진 갈아타기를 찾아 주던 `--known` 도 뗐다 — 찾는 방식이 한국어
낱말 grep 이었다. 식을 기호로 견주는 법이 생기기 전까지는 아무것도 안 센다.

## 왜 산문이 아니라 칸인가

만 개를 자유 산문으로 뽑아 두면 검증할 때 만 번을 다시 파싱해야 한다 — 생성 비용만큼이
다시 든다. `novel/flow.py` 와 같은 배치다: **모델은 자유롭게 쓰고, 받는 것은 칸이다.**

## 쿼터 — 묶어서 부른다

무료 티어에서 병목은 일일 한도가 아니라 **분당 한도(RPM)** 다. 구글 문서 기준으로 한도는
**프로젝트** 단위이고(같은 프로젝트에서 키만 늘려도 한도는 그대로다) RPM 은 모델별로 따로
걸린다. 공간 하나에 호출 하나면 300개에 30분 이상이고, 그 시간의 대부분은 쿨다운을
기다리는 것이다.

그래서 **한 번에 여러 개를 받는다.** 부모 하나를 보여 주고 연산자 K 개를 함께 걸어 K 개를
받는다.

| | 호출 | 출력 |
|---|---|---|
| 하나씩 | 300회 | 300 × 250토큰 |
| 묶음 5 | **60회** | 60 × 1,250토큰 |

토큰 총량은 비슷하고 **호출 수만 1/5** 이 된다 — RPM 이 병목일 때 이것이 곧 시간이다.
`llm_pool` 의 출력 상한이 8,192 토큰이라 묶음 5는 여유가 많다.

공짜로 얻는 것이 하나 더 있다. 모델이 K 개를 **한 자리에서 보므로 서로 다르게 쓴다.**
따로 부르면 비슷한 것이 K 벌 나온다.

하나가 깨져도 나머지는 건진다 — 배열로 못 읽으면 중괄호 덩어리를 낱낱이 읽는다. 묶어
부르는 것의 값이 한 글자 때문에 다섯을 잃는 데서 사라지면 안 된다. 그리고 짝은 **순서가
아니라 연산자 이름으로** 맞춘다(모델이 하나를 빼먹으면 이후가 전부 어긋난 부모-연산자로
원장에 박히기 때문).

풀은 `orchestrator/llm_pool.py` 를 그대로 쓴다 — (키 × 모델) 후보 풀, 429 소진 표시,
RPM 60초 쿨다운, 404/403 영구 dead, 성공 후보 pin. 이 저장소가 이미 갖고 있는 것을 새로
짜지 않는다.

## 쓰는 법

```bash
python3 mathdrift/spread.py --check         # 지금 무엇을 쓸 수 있나 (호출 0회)
python3 mathdrift/spread.py --n 300         # 300개 (묶음 5 → 호출 60회)
python3 mathdrift/spread.py --n 300 --batch 8
python3 mathdrift/spread.py --n 5 --dry     # 호출 없이 프롬프트만 본다
python3 mathdrift/spread.py --show          # 원장 · 확산 몫 · 연산자 쓰임새
python3 mathdrift/spread.py --remeasure     # 새 자로 다시 잰다 (호출 0회)
python3 mathdrift/spread.py --lineage S17   # 씨앗까지의 사슬
python3 mathdrift/spread.py --card S34      # 공간 하나를 칸째로 (부모와 나란히)
python3 mathdrift/spread.py --diff S10      # **연산자가 식에 무엇을 했나** (기호 단위)
python3 mathdrift/spread.py --act          # **연산자가 자국을 남겼나** -- 원장 전체 (호출 0회)
python3 mathdrift/spread.py --known         # 알려진 갈아타기 넷이 나왔나 (거르지 않는다)
python3 tests/test_mathdrift.py             # 배선 검사 (LLM·네트워크 불필요)
```

`--check` 는 **호출을 한 번도 안 하고** 후보 · 키 · 남은 것으로 추정되는 양을 보여 준다.
쓸 수 있는 후보가 하나도 없으면 `3` 으로 끝난다(`scripts/quota_show.py --brief` 와 같은
약속) — 밤새 도는 쪽이 물어볼 수 있게. 300개를 걸기 전에 이것부터 본다.

원장은 **걸음마다 저장된다.** 중간에 죽어도 지금까지 낳은 것은 남고, 같은 명령으로 이어
돌리면 원장 끝에서부터 계속 붙는다.

### 원장은 추적하지 않는다

`mathdrift/ledger.json` 은 `.gitignore` 에 있다. 씨앗(`seed.json`)만 코드고 원장은 런타임
상태다 — `compression/ledger.json` 과 `novel/*.json` 이 같은 이유로 이미 빠져 있다.

실측 2026-09-07: 그 규약을 안 따라 원장을 커밋했더니 **VM 이 낳은 공간 15개가 `git pull`
한 번에 씨앗만 든 커밋본으로 되돌아갔다.** 원장이 없으면 씨앗에서 새로 세우고, 있으면
씨앗이 그것을 덮지 않는다.

모델 배치는 `CLAUDE.md` 그대로. 발산은 호출 수가 전부이므로 **Gemini** 다.
에이전트 세션에서 직접 공간을 지어내 원장에 넣지 않는다 — 파이프라인이 만든 것이
아니면 발산율도 계보도 거짓이 된다.

## ①재현 — 이 식이 Strassen 을 품는가. **호출 0회, 그리고 나중에 따로**

```bash
python3 mathdrift/recall.py            # 검증가능한 것만 (코드 칸이 있는 것)
python3 mathdrift/recall.py --all      # 나머지도
python3 mathdrift/recall.py --show
```

**발산과 완전히 분리된 뒤 단계다.** 생성기는 이 심판이 있다는 것도 몰라야 한다.

0. `시금석점` 이 없으면 `부호화` 로 **만든다** (Strassen 을 그 인코딩으로 옮긴다)
1. `decode(시금석점)` 을 **격리해서 돌린다** (`_child.py`. 부모는 그 코드를 임포트하지
   않는다 — `mathgen/_worker.py` 가 생성기를 임포트조차 안 하는 것과 같은 이유)
2. 나온 (U, V, W, λ)를 `ExactArithVerifier` 로 **정확 검산**한다
3. 시금석점을 **흔들어** 다시 돌린다. 결과가 같으면 **하드코딩**이다

판정: `재현` · `틀림` · `못돎` · `못읽음` · `없음`.

**`없음` 은 실패가 아니다** — 코드 칸이 없어서 아직 안 본 것이다. 발산은 그것을 안 벌한다.
`하드코딩` 은 판정과 별개로 붙는 표다 — 재현이어도 붙을 수 있고, 그때는 재현이 아니라
**외운 답을 적은 것**이다.

### 통과가 여전히 약한 증거인 이유

흔들기는 "해독기가 입력을 쓰는가" 만 본다. 입력을 쓰면서도 식과 무관한 인코딩일 수 있다
(점을 재배열해 놓고 식은 딴소리). 그래서 이 축은 증명이 아니라 **필요조건 거르개**다 —
강한 신호는 `틀림` · `못돎` · `하드코딩` 쪽이다. 확산 0.85 를 좋은 소식으로 읽었다가
겪은 일이 있어서, 이 한계를 코드와 여기 양쪽에 못 박아 둔다.

## `--known` — 알려진 갈아타기 넷을 재발견하는가

사람이 낸 답이 있는 이주들이라, 파이프라인이 그 자리에 도달하는지 볼 수 있다.
`novel/world_probe.py` 와 같은 자리다 — 밤을 걸기 전에 배선을 싸게 확인한다.

**실측 2026-09-07 (50개, 10호출, 33초): 넷이 전부 나왔다.**

| 역사 | 원장에 나온 것 |
|---|---|
| 경계 랭크 (Schönhage) | 점근적 텐서 랭크의 **극한** · **엡실론 오차**를 허용한 근사 불변 · **ε-근사** 행렬곱 오차 |
| 군대수 매장 (Cohn–Umans) | **군대수 환으로의 텐서 매장** · 유한 격자 상의 군대수 매장 |
| 점근 퇴화 (CW · ω) | **점근적 행렬곱 지수 식** · 행렬곱 지수 결정 |
| 표수 이동 (F₂) | **유한체 표수 2**에서의 행렬곱 지수 식 |

**아무것도 거르지 않는다.** 세어 보여 줄 뿐이다 — 여기 없는 것이 새 이주일 수도 있다.

## 아직 없는 것 — 나머지 3축

다음 커밋이다. 발산과 **별도의 배치**로 돌린다.

| 축 | 묻는 것 | 있는 것 |
|---|---|---|
| ② 비자명성 | 옛 공간과 동형이 아닌가 | 없음 |
| ③ 압축 | 탐색공간이 줄었나 (연속 → 이산이면 큰 승리) | 없음 |
| ④ 실행 가능 | 이 안의 후보를 채점할 수 있는가 | `verifier.py` 에 `verify_approx` 와 유한체 검산이 이미 있다 |

①은 `recall.py` 로 있다(위). 나머지 셋은 아직 없다 — ①의 판정 분포를 보고 짠다.

첫 시금석은 "새 형식화를 내라" 가 아니라 **"알려진 갈아타기 넷(경계화 · 매장 · 점근화 ·
표수 이동)을 파이프라인이 재발견하는가"** 다. 사람이 낸 답이 있으니 도달했는지 볼 수
있고, 재발견도 못 하면 새 것은 당연히 못 낸다. `novel/world_probe.py` 와 같은 자리다.

## 정직하게 남기는 한계

- **확산 두 계수는 대리값이다.** 낱말 집합으로 재므로, 같은 구조를 다른 낱말로 쓰면
  물려받음을 못 보고 그 반대도 있다. 제대로 재려면 두 공간 사이의 사상을 실제로 만들어야
  하고 그건 검증 단계의 일이다
- **통과한 형식화가 답을 주지 않는다.** 나오는 것은 새 미해결 문제다
- **밀레니엄급은 이 경로로 안 된다.** 형식적 증명이 필요하고 그건 다른 규모의 공사다
- 이 파이프라인이 낼 수 있는 최선은 *새 구성 · 새 하한 · 게재된 추측의 반례* 크기다
