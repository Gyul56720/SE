# 관측모델 현장 캘리브레이션 프로토콜 (Phase 2, 하드웨어 준비)

이 문서는 sim 의 **model = truth 가정**(정책이 쓰는 어댑터가 곧 실제 물리)을 실측으로
대체하기 위한 절차다. RESULTS.md 한계①("어댑터 `p_useful` 곡선 실측 캘리브 — 하드웨어 필요")의
설계서. 하드웨어가 오기 전에 짤 수 있는 유일한 ① 준비물이다.

## 0. 무엇을 채우는가 (딱 두 함수)

정책 코어는 센서를 모르고 `PC_ObsModel` 함수포인터 둘만 본다. 캘리브레이션이 채울 것도 이 둘뿐:

```c
float p_useful(const void *cfg, float range_m, float angle_rad, const PC_Env *e); /* 1회 관측 유용탐지 확률 */
float precision(const void *cfg, float range_m);                                  /* 국소화 정밀도 σ[m] */
```

지금 sim 은 이것을 **양식화된 추측**으로 둔다(예: 카메라 `0.92·e^{-(r/25)²}·illum·health`,
`σ=0.30+0.010r`). 캘리브레이션은 이 상수/형태를 **실측 데이터에 적합한 곡선**으로 바꾼다.
적합 결과는 어댑터의 `const void *cfg`(사설 파라미터 슬롯 — 이 목적으로 이미 존재)에 로드한다.
**코어는 재컴파일 없음.**

## 1. 왜 필요한가 (sim 이 못 주는 것)

sim 에서 정책은 자기 모델로 관측하고 자기 모델로 성공을 판정한다(model = truth). 실기에선
모델 ≠ 진실이라, 캘리브 없이 나온 절대 성공률(83.5% 등)은 **그대로 현장에 못 옮긴다**. sim 이
준 것은 *상대적 구조*(창발·강건성·예산 의존성)이고, *절대값*은 이 캘리브가 정한다.

## 2. 센서-불가지 캘리브 구조 (프로토콜은 하나)

추상 인터페이스 덕에 **캘리브 절차 자체가 센서-불가지**다. 어느 센서든:

> 표적을 **알려진 자세(거리 r·각도 θ)** 에 두고, **통제된 환경**에서 관측을 **여러 번** 하여
> (a) 탐지 성공 비율 → `p_useful`, (b) 보고 위치 오차의 산포 → `precision` 을 잰다.

센서마다 다른 것은 **환경 축**뿐이다. 새 센서 = 같은 프로토콜 + 그 센서의 환경 축.

| 센서 | 지배 환경 축 (env 로 실어 나름) | 물리 앵커(§6) |
|---|---|---|
| Camera(EO) | 조도 illum[lux] · 건강도 health(렌즈오염/역광) | 광학 1/R², Koschmieder 소광 β=3.912/V |
| Thermal(IR) | 표적-배경 온도차 ΔT[K] · 대기 습도 | 열복사, 대기 IR 감쇠 |
| LiDAR | 반사율 ρ · 입사각 · 안개 가시거리 | 1/R²(+비콘), Mie 산란 |
| FMCW-SAR(레이다) | 날씨 w(안개/비) · 표적 RCS | SNR 1/R⁴, 방위해상도 δ_az=λR/2·L_sa, 77GHz 안개감쇠 ≈0.25·w dB/km(ITU-R P.840) |

(물리 앵커 출처는 `paper/선행조사/센서불가지_능동탐색.md` 의 접지 절.)

## 3. 측정 프로토콜

### 3.1 지표 진리(ground truth)
표적 실제 위치를 **센서 정밀도보다 훨씬 정확히** 알아야 한다(≪ σ). 실내: 측량 마커/줄자.
야외: RTK-GPS(㎝급) 또는 측량한 고정 표지. **진리 오차가 σ 에 근접하면 그 σ 측정은 버린다.**

### 3.2 거리·각도 격자
- 거리 r: {5, 10, 15, 20, 25, 30, 35, 40, 45} m (코어 `r_max`=45 m 까지).
- 각도 θ: 먼저 보어사이트 0°만. 여유되면 {0, ±15, ±30, ±45}°.
- 각 (r, θ) 를 **셀**로 본다. p_useful 은 셀마다 하나의 확률.

### 3.3 환경 조건 축
§2 표의 센서별 축을 **몇 개 이산 수준**으로 쓸기. 예 Camera illum: {주간 10⁴, 박명 10², 야간 10⁰, 무광 0} lux + health {정상, 열화}. **한 번에 한 축만** 바꿔 교란을 막는다(과장방지: 교란 통제).

### 3.4 표준 표적
p_useful 은 표적에 상대적이다. **정규 표적**을 정해 기준화: 광학=알려진 크기·반사율 판,
열=알려진 ΔT 발열체, 레이다=알려진 RCS 코너리플렉터. 문서에 표적 사양을 박는다. 다른 표적은
별도 캘리브(외삽하지 않는다).

### 3.5 셀당 시행 수 N 과 신뢰구간
p_useful 은 베르누이 → N 회 관측 중 탐지 d, p̂ = d/N. **점추정만 쓰지 말고 Wilson 95% CI** 를 같이 낸다:

> p̂ ± z·√(p̂(1−p̂)/N + z²/4N²) / (1 + z²/N),  z=1.96

- 실무 절충: **셀당 N = 30~50**. p≈0.5 근처면 CI 폭이 ±0.14~0.18(넓음)이니, 결정적 셀(교차점 부근)은 N 을 키운다(±0.05 목표면 N≈400).
- precision: 탐지된 건들의 보고위치 오차 e_i = ‖ẑ_i − z_true‖. σ̂ = 표본표준편차, **CI 는 χ² 로**. 셀당 탐지 ≥ 20 건 권장.

### 3.6 데이터 스키마 (CSV, 한 행 = 한 관측)
```
sensor, r_m, theta_deg, env_axis, env_level, trial, detected(0/1), zx_m, zy_m, ztrue_x, ztrue_y, ts
```
이 원자료가 원장이다. p_useful/precision 은 여기서 **집계로 도출**(추측 아님).

## 4. 곡선 적합과 물리 앵커 (§6 겸)

- **p_useful(r)**: 조건별로 단조감소 형태 적합. 후보: `p0·exp(−(r/r_c)²)`(현 sim 형태) 또는 로지스틱
  `1/(1+e^{(r−r_50)/s})`. **적합보다 룩업표가 단순·안전**하면 셀 표를 그대로 어댑터 `cfg` 에 싣는다.
- **precision(r)**: 선형 `a+b·r` 또는 √r. 물리상 각도오차×거리라 대체로 r 에 증가.
- **물리 앵커(필수 위생)**: 적합 곡선을 물리와 **교차확인**한다. 레이다 SNR 은 1/R⁴, 광학은 1/R²,
  안개는 ITU-R 감쇠. 적합이 물리와 **정성적으로도 어긋나면**(예: 거리 늘수록 탐지율 증가) 측정
  오류를 의심하고 그 데이터를 재검한다. 물리는 사전(prior)·검산이지 데이터를 덮어쓰는 것이 아니다.

## 5. 검증 (적합이 진짜인지)

1. **Hold-out**: 시행을 학습/검증으로 나눠, 검증셋에서 곡선이 탐지를 맞추는지 본다.
2. **신뢰도 곡선(reliability diagram) + Brier 점수**: p_useful 이 예측한 확률 vs 실제 빈도.
   대각선에서 벗어나면 미보정. (분류 보정과 같은 도구.)
3. **precision RMSE**: σ̂ 곡선의 예측 오차 vs 관측 오차.
4. **model=truth 잔차를 명시**: sim 에 이 곡선을 넣고, **같은 하드웨어 실측**과 성공률/시간을 비교한다.
   차이가 곧 남은 sim-현실 괴리다. 0 이라 우기지 않고 **그 잔차를 보고**한다.

## 6. 코드 연결 (캘리브 → 정책)

1. 적합 산출물 = 센서별 계수/룩업표 파일(예 `calib/camera.tbl`).
2. 어댑터가 이를 `cfg` 로 로드하고 `p_useful`/`precision` 이 참조. **코어 불변**(센서-불가지).
3. `./sim` 을 새 어댑터로 재실행 → 캘리브된 절대 성능. 이전 양식화 결과와 **나란히** 보고(무엇이
   바뀌었는지). n_look·β 등은 캘리브된 곡선 위에서 재튜닝될 수 있음.

## 7. 단계 실행 (indoor → outdoor → drift)

- **2a 실내 벤치**: 통제 거리·조도, 정지 표적. 초기 곡선. 진리는 줄자/마커.
- **2b 야외**: 실제 조도·날씨, RTK 진리. 재적합. 날씨 축(안개/비)이 여기서 산다.
- **2c 드리프트 점검**: 센서는 시간·온도로 변한다. **주기적 재캘리브**, 곡선에 측정일자 태그.
  하루짜리 곡선을 영원한 진리로 쓰지 않는다.

## 8. 정직한 한계 & 과장방지 체크리스트

캘리브 결과를 보고하기 전 넷(ctrl/과장방지.md 정신):
- [ ] **재려던 걸 쟀나** — p_useful 은 *정규 표적*에 상대적이다. 다른 표적으로 외삽 안 함.
- [ ] **동작점이 성한가** — 진리 오차 ≪ σ 인가. 아니면 그 σ 셀 버림.
- [ ] **독립 대조** — 적합 곡선을 물리(1/R⁴ 등)로 교차확인했나. hold-out 잔차를 냈나.
- [ ] **사소한 설명 죽였나** — "탐지율 높음"이 표적이 너무 크거나 배경이 유리해서는 아닌가. 교란
  한 축씩 통제했나.
- [ ] 각 p̂ 에 **CI** 를 달았나. N 이 작은 셀을 점추정처럼 말하지 않았나.
- [ ] **model=truth 잔차**(§5.4)를 0 이라 우기지 않고 수치로 남겼나.

넷 중 하나라도 못 했으면 곡선을 확정하지 말고, 못 한 것이 무엇인지 적는다.

---

**요약**: 캘리브레이션은 *새 이론*이 아니라 *두 함수를 실측으로 채우는 규율 잡힌 절차*다.
센서-불가지 인터페이스 덕에 절차는 하나이고, 어느 센서든 같은 표(거리×각도×환경)를 채우면
정책 코어는 그대로 돈다. 하드웨어가 오면 §3 격자부터 채운다.
