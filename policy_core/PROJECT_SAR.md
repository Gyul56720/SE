# 프로젝트 정의서 — 재난 수색구조(SAR) 능동수색 로버

**한 줄**: 붕괴·연기·야간 환경에서 **생존자(열/움직임 신호)를 자율로 능동탐색해 위치를 보고**하는,
센서를 안 가리고 값싼 MCU에서 도는 임베디드 인지 시스템. 무기·타격이 아니라 **찾아내고 알린다**가 본령.

이 문서는 `paper/센서불가지_능동탐색.html`(방법·결과)·`CALIBRATION.md`(현장 캘리브)·`RESULTS.md`(측정)를
하나의 응용으로 묶는 상위 정의서다.

## 1. 왜 SAR 인가 — 우리 기술의 존재 이유

우리가 쌓은 능력과 SAR 의 요구가 **일대일로 맞는다**:

| 우리가 만든 것 | SAR 에서 왜 필연인가 |
|---|---|
| 센서-불가지 정책(창발적 센서선택) | 연기서 카메라 죽음 → **열화상**, 잔해·벽 뒤 → **레이다(호흡·미세움직임)**. 상황마다 최적 센서가 바뀌는데 손코딩 불가 |
| 물리 접지 관측모델 | "왜 지금 이 센서?"를 **물리로 설명**(연기 소광·1/R⁴ 등) — 구조 판단의 근거가 됨 |
| 타이트 예산서 격차 벌어짐(측정됨) | SAR 은 **배터리·골든타임**이 곧 예산. 시간이 없을수록 옳은 센서 선택이 생사를 가름 |
| RTA(keep-out 안전집합) | **2차 붕괴 구역·구조대 위치**를 진입금지로 강제 — 로봇이 위험지대·사람에 안 부딪게 |
| belief-적응 비용(cold-start 고침) | 초기 정보 거의 없는(확산 prior) 현장서도 안 얼고 탐색 시작 |
| OS-독립 bare-metal | 값싸고·가볍고·결정적 → 다수 소형기 투입, 통신두절서도 자립 동작 |

## 2. 문제 정의

재난 현장 수색의 실제 어려움:
- **단일 센서가 다 못 봄**: 연기·먼지·어둠·잔해가 각각 다른 센서를 죽인다.
- **조건이 시시각각 변함**: 실내→연기구간→야외, 한 임무 안에서.
- **시간·배터리 제약**: 골든타임, 소형기 항속.
- **안전**: 2차 붕괴·유독가스 구역, 구조대원과의 충돌 회피.
- **조작자 부담**: 재난 통제관이 센서 스위칭까지 손으로 못 한다 → **자율 선택 필요**.

## 3. 시나리오 (3종)

1. **실내 붕괴 + 연기**: 로버가 방을 훑으며 조명 꺼진·연기 낀 구간서 카메라→열화상 전환, 열원(생존자 대역) 위치 보고. keep-out=붕괴 위험 구역.
2. **산악·야외 야간**: 조작자가 "능선 북쪽" seed 제공. 야간이라 카메라 무력 → 열화상/레이다로 수색, RTK 로 좌표 보고.
3. **잔해 뒤 생존자**: mmWave 레이다로 벽·잔해 뒤 미세움직임(호흡) 탐지 — 광학이 원리적으로 못 하는 것.

## 4. 시스템 구성 (기존 스택 재사용)

```
  자연어/조작자 seed (지상 1회) ── prior belief 업로드(UART/SD/BLE, OS 없음)
        │
  ┌─────▼─────────────────────────────────────────┐
  │  policy_core (Teensy/STM32, bare-metal)         │  ← 이미 만든 것
  │  물리→관측모델→belief→능동정책→RTA 안전행동      │
  └───┬───────────────┬───────────────┬────────────┘
   Camera(EO)      Thermal(IR)      Radar/LiDAR   ← 스마트 센서 = 어댑터(탐지+위치만 버스로)
   섀시·엔코더·IMU   ·  측위: 실내 ArUco / 실외 RTK  ·  텔레메트리(LoRa)로 좌표 보고
```

정책 코어는 센서·HW·OS 를 모른다. 새 센서 = 어댑터 추가, **코어 재컴파일 없음**(센서 교체 실험 E4 로 증명).

## 5. 실험 계획 (6-Phase → SAR 매핑)

| Phase | SAR 실험 | 검증 가설 | 연결 |
|---|---|---|---|
| 1 Sim | (완료) 창발·강건성·예산·freeze | 정책 구조 성립 | RESULTS.md |
| 2 벤치 캘리브 | 열원·발열체로 `p_useful`(ΔT·연기) 실측 | model=truth 잔차 | CALIBRATION.md |
| 3 실내(연기) | 연기 구간서 카메라→열화상 창발 | 손코딩 없이 옳은 센서 | E1 |
| 4 야외(야간) | 조명 조건 강건성 + 배터리(타이트예산) | Proposed floor 최고, 격차↑ | E2 |
| 5 센서 열화/교체 | 렌즈오염·안개 → 적응 / 레이다 어댑터 추가 | 코어 불변, hand-rule 짐 | E3·E4 |
| 6 동적/UAV | 실내→연기→야외 주행 중 전환 / 비행 이식 | 에피소드 내 전환>0 | E5·E6 |

## 6. 평가 지표 (SAR 용 J_score — 필드 측정 가능한 것만)

과장방지: belief 는 구동만, 채점은 필드 측정값만.
- **발견율** P_find: 예산 내 생존자 대역(열원) 위치를 tol 안에 국소화한 비율. **헤드라인.**
- **발견까지 시간** T_find: 골든타임 대비.
- **커버/이동** C_motion: 배터리·거리.
- **오경보 처리**: 스퓨리어스 열원(난방기 등) 배제 — ⚠ RESULTS ③-a 대로 순진한 pfa 모델은 무효, **순차 확인**이 SAR 에선 특히 중요(구조대 헛출동 방지).
- **안전 개입** RTA: 위험구역·구조대 진입 차단 횟수.
- **센서 전환** switch: 조건 변화 시 자율 전환(E5).

각 지표는 baseline(Fixed-Camera/Fixed-Thermal/Hand-rule/Random/Proposed)을 **같은 하드웨어로 나란히**.

## 7. 하드웨어 (요약 — 상세 BOM 별도)

Teensy 4.1 / STM32H7 + OpenMV/HuskyLens(사람 검출) + MLX90640·FLIR Lepton(열) + (+RPLiDAR/IWR6843 레이다)
+ 엔코더 섀시 + IMU + 실내 ArUco / 실외 ZED-F9P RTK + LoRa 텔레메트리 + 포그머신(연기 축).
최소 실증 30~60만원, +RTK 50만, +레이다 25만.

## 8. 기존 산출물과의 연결

- **논문**(paper/): 방법·결과·캘리브 계획 — SAR 은 그 응용 서사.
- **CALIBRATION.md**: SAR 센서(열 ΔT·연기 소광·레이다 RCS) 곡선 실측 절차.
- **RESULTS.md**: sim 이 예측한 것(창발·강건성·예산·전환)을 SAR 실기로 검증할 대상.
- **EXPERIMENTS**(예정): 위 6-Phase 를 사전등록형 실험 프로토콜로.

## 9. 정직한 한계 (과장방지)

- **생존자 = 열원 대역**으로 실험(윤리·안전상 사람 실측 아님). 실제 인체 탐지율은 별도 검증 필요.
- **오경보(순차 확인)**가 SAR 에선 안전문제(헛출동) — RESULTS ③-a 대로 아직 미해결, 우선 과제.
- **개방어휘 NL** 은 지상서 prior seed 로만(온보드 실시간 VLM 아님) — 앞 논의대로.
- **측위 진리**(ArUco/RTK)가 실험 성패의 실질 난관 — CALIBRATION §3.1.
- sim 절대값은 캘리브 후 바뀜. 방향성(창발·강건성)은 강건.

---

**요약**: 우리가 만든 센서-불가지·물리접지·안전한 임베디드 능동탐색은 **재난 수색구조**에서 필연적 값어치를
갖는다 — 연기·어둠·잔해마다 옳은 센서를 물리로 골라, 배터리 안에서, 위험구역을 피해, 생존자를 찾아
좌표를 보고한다. 6-Phase 로드맵이 그대로 SAR 실증 경로가 된다.
