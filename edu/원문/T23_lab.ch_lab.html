실습흐름 · 회귀기준

The five chapters before this one computed the flow's quantities from models. This one runs it. The design is a small MAC with a control FSM, a two-flop synchroniser and a gated accumulator; it is synthesised by yosys against a cell library generated from the RC model of T2, and the remaining eight stages are implemented in this repository because the machine has no commercial place-and-route tool. That constraint turned out to be an advantage: every intermediate quantity is visible and re-measurable, which is exactly what a commercial tool does not give you.

Reproduce everything in this chapter with one command: python3 lab/run.py. It takes about eight seconds. Individual stages: python3 lab/run.py --stage sta (or fp place cts route signoff dft dv). The numbers below are read from lab/기준.json, which that command writes, and tests/test_lab.py re-runs the flow and checks they still agree — so if this chapter goes stale, a test goes red.

T23.2 The four results worth arguing with

T23.2 The four results worth arguing with

유도 — 1. Pre-route timing is not optimistic by a little
이렇게 된다왜냐하면
1Synthesis and pre-route STA report 158.04  MHz with 3,672.4  ps of slack.No wire RC at all — the optimistic bound of T17.2.
2After routing, the same endpoints report 99.31  MHz and -69.14  ps.Same netlist, same library, same constraints. The only new information is where the wires actually went.
3That is 37.2  % of Fmax, and the average endpoint moved -1,155.5  ps.Average, not worst. Every endpoint got worse, because every net acquired resistance and capacitance it did not have.
4The design now fails: 1 endpoint(s) violate at the target period.Which is the honest outcome of running a flow without a physically-aware synthesis step — and the quantitative argument for having one.
Kill the trivial explanation. A 37.2  % drop could just mean the wire model is too pessimistic. Two things say otherwise. The detour factor is 1.217 × over HPWL, which is in the range real routers produce; and the wire delay comes from the same R and C per micron used to size the power grid, where the resulting IR drop came out sane. Neither is proof. What would be proof is a second extraction method, and this lab does not have one — so the number is reported with that limitation attached.
유도 — 2. Skew is bought, not given
이렇게 된다왜냐하면
1The tree as built by geometry alone has 122.7  ps of skew on 832.14  ps of insertion delay — 14.74  %.Clustering by position minimises wire, not arrival time. Nothing in the construction balances anything.
2Balancing it to about 2 % costs 25 extra buffers.Delay is added to the early branches until they match the late one. That is what a CTS tool does after it builds the tree.
3Those buffers raise the clock network's power by 21.09  %.They switch every cycle, like everything else on the clock. The trade is skew against power and it is quantitative.
4Result: 19.6  ps, i.e. 2.35  % of insertion delay.Which is the figure the industry quotes, and now it has a price tag attached.

The sequence is [2, 4, 15, 16, 13, 7, 10, 7, 9] and the ratios rise above 1 repeatedly, so the loop is moving violations rather than repairing them — the exact signature T19.4 describes. Two consequences were built into the lab because of it. The router keeps the best solution it has seen rather than the last one (best 2, last 9), which is what a real router does and what turns "more iterations make it worse" from a conclusion into an artefact. And the correct response to a non-converging loop is not another pass: it is to go back up the flow — lower the utilisation, spread the placement, add a layer.

실제로 난 일
The m3_pulse mutation — replacing the one-cycle pulse with a level — was not caught by the first regression, and it was not caught after adding a directed test that holds start high for twenty cycles either. The reason is instructive: with a level, the FSM re-triggers as soon as it returns to idle, and the first completion's accumulator value is still correct. A value comparison cannot see it. The hole was in the checking, not in the stimulus, and it closed only when the scoreboard began asserting that each transaction produces exactly one done. That single protocol check is what takes the campaign from one escape to 0.

T23.3 What this lab does not do

표 68. Honest limits — read these before quoting any number above
Not doneWhy it mattersWhat would fix it
No commercial P&RThe placer, router and CTS here are teaching implementations. Their absolute quality is not comparable to a production toolOpenROAD would run this same netlist; the flow is deliberately structured so it could be swapped in
One extraction modelWire R and C come from a single per-micron constant. The 37.2  % Fmax drop therefore has no independent controlA second extraction (field solver, or a different model) and a comparison of the two
No DRC, no LVSRouting produces track counts, not geometry, so nothing here can assert manufacturability (T20.1)A real layout database and a rule deck — neither of which exists on this machine
Stuck-at onlyThe 99.19  % coverage is stuck-at coverage. Transition and bridging faults are not simulatedAt-speed patterns and a layout-extracted bridging list (T22.1)
Random ATPG only9 faults remain and random patterns will not reach them — this is T21.3's rare-bin problem in its test formDeterministic ATPG (a D-algorithm or a SAT call) for the residue
Power is assumed, not measuredThe floorplan's current comes from an assumed W/mm², so the IR and EM conclusions inherit that assumptionToggle rates from the DV run, fed back into the power estimate — the two stages are in the same repository and are not yet connected
That last row is worth dwelling on, because it is the kind of gap that survives for years. The verification run knows exactly how often every node toggles. The floorplan needs exactly that number. They are in the same program, in the same language, eight seconds apart — and they are not connected, so the power number is an assumption while the information that would replace it is sitting in the next directory. Most of what looks like missing analysis in a real flow is this: two stages that have what the other needs and no path between them.

Run it, then break something on purpose: raise the utilisation in lab/se/floorplan.py until legalisation fails; weaken the spreading force until legalisation destroys the placement; delete the done-count check in lab/se/dv.py and watch a mutation escape. Each of those is a lesson from an earlier chapter arriving as a failure you caused, which is the only way this material stops being a list of facts. The one command is python3 lab/run.py; the one file that holds the flow honest is tests/test_lab.py.
