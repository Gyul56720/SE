Z1. The Two-Member IP Team: You and the Agent

This volume is written for a specific arrangement: one engineer and one automated verification agent, producing IP that is good enough to sell. That is a smaller team than any company would assign to the job, and it can work — but only if the division of labour is decided deliberately rather than by what happens to be convenient. This part sets it out, and every claim about the agent in it is measured by running the agent while this page is rendered.

Z1.1 The rule that decides who does what

Why the boundary falls where it does
StepJustification
1The agent can only act where there is an oracle — something that says right or wrong without a human.A golden model, a standard's test vectors, a compiler, a timing report.
2Where an oracle exists, the agent's work is search plus check, and search with a good oracle is reliable and improves with compute.This is the regression, the shrink, the repair attempt and the mutation score.
3Where no oracle exists, any output must be read by a human, and the failure mode is work that looks right.Which is the expensive kind of failure, because it is found late.
4So: the agent owns everything downstream of a model; you own the model and everything upstream of it.Reading the specification, deciding what the block should do, deciding which side of a disagreement is wrong — none of these has an oracle.
5The corollary is where to invest: make the oracle better and the agent gets better for free.A stronger golden model, a wider stimulus, a throughput bound, a lint rule — each one extends the region the agent can work in, permanently.

The temptation to let the agent write the model is the one thing that destroys the arrangement. If the model and the RTL come from the same process, they share its misunderstandings and their agreement proves nothing — this is the independence argument of Part Y11, and it does not change because one of the two authors is a machine. The agent may write stimulus, may write checkers derived from the model, and may repair RTL; it must not be the source of the reference. Your reading of the specification is the asset the business is built on, and it is the one part that cannot be delegated.

Each mutant is a single-token edit to the DUT — not to the testbench, and not inside a comment, because mutating either produces escapes that mean nothing. An escape is a finding, not a defect in the score: it is either an equivalent mutant or a place the stimulus does not reach, and both need a human to say which. Every block reads 100 % with zero unjudged escapes, which is the state the release gate of Part Z3 requires — a column that is constant because the bar was met, not because the measurement is stuck. It was not always so: the register file scored 58.3 % until the escapes were read.

Z1.3 A worked morning: what the escapes actually told us

The mutation score is not a grade; it is a pointer. The following happened while this book's own register-file block was being built, and it is the clearest illustration in the book of why the number is worth measuring.

Note what the green regression was worth before the mutation score ran. It was not wrong — those 400 accesses really did match — and it was nearly worthless, because the stimulus never reached the logic that was broken. This is the difference between ‘the tests pass’ and ‘the tests would fail if the design were wrong’, and only the second is evidence. For a one-person house it is also the only affordable substitute for a verification team's scepticism: you cannot review your own work with fresh eyes, and the mutation score does not need fresh eyes.
Problem. You are one person. How much of the day should go to verification?
Solution. More than feels reasonable, and the arithmetic from Part Y1's effort table says roughly how much: verification and everything downstream of RTL is about three quarters of the work in a sellable block. But the useful answer for a day rather than a project is a shape, not a fraction. Verification infrastructure is built once and runs forever, so it belongs early and its cost is amortised; the agent runs it while you sleep, so the marginal cost of running verification is zero and only the marginal cost of improving it is real. That changes the allocation: spend your hours on the golden model, the stimulus and the checkers — the things that decide what the agent can catch — and almost none on running or triaging, which the agent does. A practical daily target is that every session leaves the oracle stronger than it found it: one more property checked, one more corner in the stimulus, one more bound measured. That compounds, and it is the only thing in a one-person house that does.
