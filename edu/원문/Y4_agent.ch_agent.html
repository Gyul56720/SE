Y4. A Verification Agent That Runs While You Sleep

A one-person design house has one engineer and twenty-four hours in a day, and the engineer needs some of them. The only way the arithmetic works is for verification to run unattended overnight and to leave behind something better than a log file. This part documents such a system, which lives in this repository under edu/agent/ and which is exercised by tests/test_verif_agent.py. It is deliberately small — roughly the size one person can maintain — and it is deliberately suspicious of itself.

Y4.1 The design, and the two failures it is built around

An unattended regression can fail in two directions, and the second is far more dangerous than the first. It can report a failure that is not there, which wastes a morning. Or it can report success while checking nothing, which wastes a tape-out. The loop is structured so that the second is caught by construction.

Table 414. What each stage is for, and what would go wrong without it
StageWhat it doesWithout it

Three gatesOriginal seed, an unused seed, and the self-checkAn edit that special-cases the failing input passes. The overfitting gate is the reason this can be left running unattended
The overfitting gate deserves its own sentence, because automated repair without it is actively harmful. A search that accepts any edit making the failing test pass will, given a large enough rule library, eventually find one that hard-codes the answer. Such an edit is worse than the original bug: the bug was visible and the patch is not. The rule here is that a candidate must pass a seed that was never used during the search, which is the same train/test separation that any honest empirical claim requires. This book's Part X8 makes the same point about a bug-find-rate curve, and Part X1 about a range justified by simulation: a number validated on the data that produced it is not validated.

Why the CRC block's golden model is zlib and not a hand-written CRC. If the reference and the design are written by the same person from the same understanding, they share that person's misunderstandings, and the comparison certifies the misunderstanding rather than detecting it. This is not hypothetical: reflected versus non-reflected CRC, initial value, and final XOR are four independent conventions and a hand-written reference gets at least one of them wrong about as often as the RTL does. An independent reference is worth more than a more accurate one. The same argument is why a modelling team is organisationally separate from the design team — the independence is the product.

What this system is not. It is not a bug finder for logic it has no golden model of, and it is not a substitute for a verification plan. The rule library covers the small syntactic faults that a tired engineer introduces at two in the morning — an inverted comparison, a shift the wrong way, an index off by one — and nothing else. A missing state in a state machine, a protocol rule that was never implemented, or a specification misread will all pass the repair search untouched, because there is no single-token edit that fixes them. The value is not that it repairs everything; it is that it removes the trivial failures from the morning's queue, with a patch and a minimal reproducer attached to each of the rest.

Y4.4 Running it for twenty-four hours

The launcher follows this repository's rule for background work, which exists because the obvious way does not work: a process started with a bare & from inside an agent session is reaped when that session's process exits, and the evidence for that is a night in which nothing ran and a message the next morning saying it had.

edu/agent/run.sh — the launcher
#!/usr/bin/env bash
# 24시간 회귀 에이전트를 **부모가 죽어도 사는** 방식으로 띄운다.
#
# CLAUDE.md 의 백그라운드 규칙 그대로다: setsid + nohup + disown, 그리고
# stdin/stdout/stderr 를 전부 리다이렉트한다.  claude -p 가 응답 직후 끝나도
# 이 프로세스는 남는다.
#
#   사용:  bash run.sh [--적용] [시간]
#
# 확인은 `ps -p $!` 가 아니라 `pgrep -af agent.py` 로 한다 -- setsid 가 fork 하므로
# $! 는 이미 끝난 래퍼다.  셸 변수명에 한글을 쓰지 않는다 (bash 는 받지 않는다).
set -u

HERE="$(cd "$(dirname "$0")" && pwd)"
LOGDIR="${SE_AGENT_LOG:-/home/user/SE/logs}"
mkdir -p "$LOGDIR"
LOG="$LOGDIR/verif_agent.log"

APPLY=""
HOURS="24"
for a in "$@"; do
  case "$a" in
    --적용|--apply) APPLY="--적용" ;;
    *) HOURS="$a" ;;
  esac
done

setsid nohup python3 "$HERE/agent.py" --시간 "$HOURS" ${APPLY:+$APPLY} \
       > "$LOG" 2>&1 < /dev/null &
disown

sleep 3
if pgrep -af "agent.py" > /dev/null; then
  echo "살아 있다:"
  pgrep -af "agent.py"
  echo "로그: $LOG"
  sleep 2
  echo "--- 로그 첫 줄 ---"
  head -3 "$LOG"
else
  echo "띄우지 못했다.  로그:"
  cat "$LOG"
  exit 1
fi
Table 417. The three things that make an unattended launch survive
ElementWhat it detaches fromWhat happens without it
setsidThe parent's session and process groupThe process dies with the session that started it
nohupSIGHUPThe process dies when the terminal closes
disownThe shell's job tableThe shell may still signal it on exit
< /dev/null and redirected outputThe terminal's pipesA write to a closed pipe kills the process, often hours later
pgrep -af agent.py—ps -p $! reports nothing even when the job is running, because setsid forks when it is already a group leader, so $! is the wrapper that has already exited. Believing it leads to starting a second copy that overwrites the first one's files
Do not put non-ASCII text in a pgrep -f pattern. The pattern is matched against /proc/<pid>/cmdline, whose bytes may not decode in the current locale; a pattern containing characters that cannot be decoded matches nothing, and a match of nothing reads as ‘finished’. A job that is running is then reported as done, or started a second time. Wait on a PID with kill -0, or match an ASCII-only fragment of the command line.
Worked example 64. What a night actually buys
Given. The loop measured above runs roughly 900–2000 regression rounds per minute on this container for these small combinational blocks, each round a fresh seed.

How this is got wrong. By reading the round count as coverage. A million rounds of the same random distribution explore the same region a thousand times. Part X8's coupon-collector arithmetic says where the return flattens, and the answer is far below a million for any of these blocks. The honest use of an overnight run is not volume but variety: rotate the constraint sets, inject faults deliberately to measure whether the suite still bites, and re-run the previous night's minimal reproducers as a growing regression. A loop that only turns the seed is a loop that stops learning after the first hour.
Problem. You arrive in the morning to nine failures, all in one block, all with the same minimal reproducer shape. What do you do first?
Solution. Deduplicate before debugging. Nine reports with one shape are one bug, and the first task is to confirm that by checking whether a single edit makes all nine reproducers pass — which the repair search has already attempted and logged. If it found an edit and the overfitting gate rejected it, that rejection is the most informative line in the whole night's ledger: it says a plausible local fix exists and is wrong, which usually means the bug is one level up from where it manifests. If the search found nothing, read the minimal reproducer and ask which of the four X8 categories it belongs to before opening the RTL. The failure the agent cannot repair is the one worth your morning; the ones it repaired are worth only a review of the patch.
Problem. Your manager asks whether the agent could write the RTL as well as fix it. What is the honest answer?
Solution. The honest answer distinguishes two things this chapter has kept separate. Search over a small edit space with a strong oracle is reliable, and that is what this agent does: the golden model is the oracle, the edit space is a dozen rules, and the three gates bound the false-accept rate. Generation without an oracle is not, because nothing is checking the result except a human reading it, and the failure mode is code that looks right. The useful framing for a design house is therefore: let generation propose and let the oracle dispose, and invest in the oracle. A team with an excellent golden model and a mediocre generator will out-ship a team with the reverse, because the first can accept help from any source and the second cannot tell good help from bad. That is also why the modelling role — the one this book is written for — becomes more valuable as generation improves, not less.
