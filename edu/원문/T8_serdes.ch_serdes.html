Everything in a serial link is a consequence of one fact: the channel is a low-pass filter with far less bandwidth than the symbol rate, so each symbol arrives smeared across its neighbours. The receiver's job is to undo that smearing well enough that a slicer can decide, and the measurements below — run with this repository's own channel and link model — show both how much equalisation buys and, more usefully, where it buys nothing at all.

Read the last column carefully. At every loss — including 10 dB, where the link runs essentially error-free — the worst-case eye is negative. That is not a contradiction: worst-case (peak-distortion) analysis assumes the data pattern that maximises every interferer simultaneously, and that pattern is astronomically rare. Peak distortion is a bound, not a prediction. A design signed off on it alone is over-designed; a design that ignores it has no bound at all. Both numbers belong in the deliverable.
유도 — Why loss shows up as post-cursors, and why that matters
이렇게 된다왜냐하면
1A lossy channel attenuates high frequencies more than low ones.Skin effect (∝√f) and dielectric loss (∝f). Both are physics of the medium, not of the driver.
2A sharp edge is therefore spread in time: the pulse response develops a long tail.Measured at 20 dB: the first post-cursor is 1.035 against a main cursor of 1.693 — 61.1 % of the signal arrives one symbol late.
3The tail is causal and past — it depends on symbols already decided.That is exactly what makes a decision-feedback equaliser possible: the receiver already knows those bits, so it can subtract their contribution without amplifying noise.
4Pre-cursors are not, so they can only be handled by a filter that looks ahead — an FFE, which is linear and therefore amplifies noise along with signal.Measured pre-cursor at 20 dB is 0.547, a third of the post-cursor. This asymmetry is why receivers use both kinds of equaliser rather than one.

실제로 난 일
The 30 dB row is not a result — it is a broken operating point. Every configuration sits at a BER of roughly 0.2, which is what a slicer does when the eye is fully closed: it guesses. Comparing equalisers there is comparing coin flips, and the apparent finding that FFE is worse than CTLE alone (0.25 against 0.23) is noise, not physics.

This repository has a rule for exactly this, learned the hard way: check the operating point is healthy before reporting anything measured on it. A BER near 0.5, an equaliser that did not converge, a wrong sampling phase — all of them produce numbers that look like data.

3의 법칙 — what zero errors is allowed to mean

Two rows above report zero errors. Zero errors is not a BER of zero; it is an upper bound. With no errors in n bits, the 95 % confidence upper bound on the error rate is 3/n — the rule of three. For the 630,000-bit runs that is 4.76×10-6.

So the measurement says CTLE + FFE and CTLE + FFE + DFE are both below 4.76×10-6, and it says nothing about which is better. Reporting that DFE 'made no difference' would be a claim the data does not support; the honest statement is that this run could not distinguish them, and that distinguishing them needs roughly 100× more bits or a worse channel.

어디에 쓰나Every BER measurement, every compliance report, and every datasheet line that contains the letters BER.
언제 쓰나Whenever the error count is small — which, for any link worth shipping, is always.
어떻게 쓰나Report errors and bits, not just the ratio. If errors = 0, quote the 3/n bound and the confidence level. To claim 1e-12 you must observe at least 3e12 bits, which at 25 Gb/s is two minutes — and at 1e-15, a day.
실제 코드는 이렇게 생겼다
# The line that belongs in every link report.
#   errors = 0 in 6.30e5 bits  ->  BER < 4.8e-6 (95% confidence, rule of three)
# NOT "BER = 0".
def ber_bound(errors, bits, conf=0.95):
    if errors == 0:
        import math
        return -math.log(1 - conf) / bits        # 3.0/bits at 95%
    return errors / bits                         # point estimate; add a CI for small n
# And the check that catches the broken operating point before any of this matters:
assert 0.0 <= ber < 0.2, f"BER {ber} -- the eye is closed; this run measured nothing"
여기서 틀린다. A BER of exactly 0.5 usually means a polarity or alignment bug, not a bad channel — the receiver is comparing against an inverted or misaligned reference. A BER near 0.25 with PAM4 means the same thing one level up. Check for these before blaming the equaliser: they are far more common than a genuinely closed eye.

오류전파 (error propagation), and why DFE is still worth it

A DFE subtracts the contribution of symbols it has already decided. If a decision is wrong, it subtracts the wrong thing, which makes the next decision more likely to be wrong — errors arrive in bursts rather than singly.

The effect is real and it is smaller than intuition suggests: for a one-tap DFE the burst length is short because the error has to survive the next correct decision. What matters downstream is not the BER but the burst structure, because the FEC that follows was designed for a burst length. A link that meets its BER and violates the assumed burst distribution will fail after decoding while every pre-FEC measurement looks fine.

어디에 쓰나Every receiver above ~10 dB of loss, and every conversation with the FEC designer.
언제 쓰나Whenever the post-cursor tail is significant relative to the main cursor — at 20 dB in this model the first post-cursor alone is 61.1 % of the main.
어떻게 쓰나Measure the burst-length distribution, not just BER, and hand it to whoever sizes the interleaver. Unrolling (speculation) removes the feedback multiply from the critical path — the T2 argument — at the cost of 2k parallel slicers for k unrolled taps.
실제 코드는 이렇게 생겼다
// Unrolled (speculative) first DFE tap: both outcomes are precomputed,
// and the previous decision only selects. The multiply leaves the loop.
always_comb begin
    d_if_prev0 = (sample >  +c1) ;      // precomputed thresholds
    d_if_prev1 = (sample >  -c1) ;
end
always_ff @(posedge clk) prev <= prev ? d_if_prev1 : d_if_prev0;   // 2:1 mux only
// The loop now contains a mux and a flop instead of a multiply-add.
// Cost: one extra slicer per unrolled tap, and 2^k for k taps.
여기서 틀린다. Unrolling is only a win if the loop was the critical path. Measure first: in this repository's own measurement of a DFE at a realistic operating point the feedback taps were |c| ≤ 0.041 — the loop was idle, and the real critical path was the slicer. Optimising an idle loop is the most expensive kind of correct work.

T8.4 Recovering the clock, and the jitter that decides whether you can

클럭데이터복원 (CDR) — the PLL of T7 with the data as its reference

There is no separate clock wire. The receiver extracts timing from the data's own transitions using a phase detector (Alexander/bang-bang, or a linear Mueller-Müller) driving the same second-order loop as T7. Everything from that chapter applies, with two changes: the 'reference' arrives only when the data transitions, and the loop must track the transmitter's spread-spectrum modulation while rejecting high-frequency jitter.

That is the jitter tolerance mask: below the CDR bandwidth the receiver follows the jitter (so large amplitudes are tolerated); above it, the receiver cannot follow and the jitter eats the eye directly.

어디에 쓰나Every receiver in every serial standard — PCIe, USB, Ethernet, MIPI, SATA, HDMI.
언제 쓰나CDR bandwidth is fixed by the standard's jitter-tolerance mask and by the spread-spectrum profile it must track; it is not a free parameter.
어떻게 쓰나Take the standard's mask, place the CDR bandwidth so the tolerance curve sits above it with margin, and check that the transmit PLL's jitter (T7) plus the residual falls inside the budget.
실제 코드는 이렇게 생겼다
# The budget is a SUM, and each term has an owner.
#   TX PLL jitter (T7)          0.30 ps rms   <- clock design
#   TX driver / ISI (DJ)        0.15 UI pp    <- output stage and package
#   Channel ISI residual        0.20 UI pp    <- equalisation, this chapter
#   RX CDR tracking error       0.05 UI pp    <- loop bandwidth
#   Sampler aperture (T5)       0.10 ps rms   <- sampling network
# Random terms add in QUADRATURE, deterministic ones LINEARLY -- mixing the two
# rules is the most common budgeting error, and it always errs optimistic.
여기서 틀린다. Spread-spectrum clocking is a requirement to track, not a disturbance to reject: a CDR whose bandwidth is too low to follow a 33 kHz SSC profile loses lock on a compliant transmitter. A receiver that works on the bench with a clean generator and fails against real hosts is usually this.

Two measured results to carry. At 20 dB of loss and SNR 34 dB, CTLE alone takes the link from 0.13 to 6.35×10-5 — a factor of about 2,037 — and adding FFE pushes it below what 630,000 bits can resolve. And at 30 dB of loss with the same SNR, no equaliser does anything at all, because the operating point itself is broken. Reporting the second table without that sentence would be the exact failure this book's rules exist to prevent.

The next chapter goes underneath the model used here and asks where the channel's loss actually comes from — and what a package, a via and a connector do to the numbers above.

특허로 가는 길 — 이 주제에서 발명이 일어나는 자리
Link patents concentrate where the loop is: speculative (unrolled) DFE that removes the feedback multiply from the critical path; adaptation schemes that converge without a training sequence; CDR phase detectors that tolerate more ISI; and, lately, ADC-based receivers whose equalisation is entirely digital. This repository's own research sits in that first family, and the argument there is the one from T2: the invention is where the delay was moved, not how fast the transistor is.
