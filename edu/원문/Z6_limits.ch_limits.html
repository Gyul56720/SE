Z6. What the Agent Cannot Do

A tool's limits are more useful than its features, because the limits decide where your attention has to go. This part states the agent's honestly, each with the evidence from this repository's own use of it, and then says what to do about each one.

Z6.1 The limits, named

Table 513. What the agent does not do, and why not
LimitWhyWhat you do instead
It cannot decide what the block should doNo oracle exists for a specification readingYou read the standard. This is the asset
It cannot write the golden modelThe model is the oracle; a machine-written oracle checked by the same machine proves nothingYou write it, from the standard, before the RTL
It cannot architectArchitecture is a judgement against cost, and the cost model is yoursParts X1, X2, X6, X13 give the arithmetic; you apply it
Its repairs are single-token edits from a narrow libraryA wider library finds something for every failure and most of it is wrongStructural bugs come to you with a minimal reproducer — which is the valuable part
It cannot judge an equivalent mutantBehavioural equivalence is undecidable in generalYou judge each escape once and record the reason
It does not know what the stimulus is missingIt measures what the stimulus reaches, not what it should reachThe mutation escapes point at the holes — read them
It cannot verify timing, area or powerThose need a library and a flow, not a comparisonThe release gate runs lint and synthesis; sign-off is the customer's
It cannot talk to a customer—Part Y5. This is most of whether the business works
The limit that does the most damage when forgotten is the second. Under deadline it is very tempting to have the machine write the reference too — it is faster, it looks like the same kind of work, and the result will agree with the RTL. It will agree because both came from the same reading, which is the one thing the reference exists to be independent of. Every disagreement you delete this way is a check you cannot get back, and nobody will remember six months later which checks were deleted or why. Part Y11 states the rule for a human team; it does not change when one member is a machine.

Read the last two rows together. The compute is free and the bound is not; the agent contributed the checking and a human contributed the number being checked against. Every one of the agent's real finds in this repository traces back to a human decision about what to compare, what to drive, or what bound to declare. That is not a complaint about the agent — it is the investment thesis. An hour spent on the oracle is repaid every night indefinitely; an hour spent running the agent is repaid once and would have happened anyway.

Worked example 93. Detecting the first failure mode before it costs a month
Given. Plot, weekly: lines of DUT code, number of mutants generated, mutation score, and distinct outputs in the regression.
Method. Each pair of series answers a question that neither answers alone.
Lines rising, mutants flatthe suite covers a shrinking fraction
Mutants rising, score flathealthy — new code is being checked
Score rising, escapes flat at zerohealthy
Score 100 %, mutants flat for weeksthe library has stopped growing, not the design
Distinct outputs fallingthe stimulus is narrowing
Everything flatyou are not working on this block — fine, if deliberate
How this is got wrong. By watching the score alone. A mutation score is a ratio, and a ratio hides both of its terms: 100 % of eight mutants on a block that has grown to four thousand lines is a much weaker statement than 90 % of two hundred. Plot the numerator and the denominator, which costs nothing because the agent already records both, and the failure mode announces itself weeks before it matters.
Problem. Should the agent be allowed to apply its own patches unattended?
Solution. Yes for a narrow class, and the class is worth defining precisely rather than deciding by feel. Allow it when all four hold: the edit is a single token from the declared library; it passed a seed never used during the search; the self-check confirms the comparison still bites; and the block is one whose golden model you trust because it is independent. Refuse it otherwise, and in particular refuse it on any block whose reference model you wrote by reading the RTL — there the whole gate structure rests on nothing. Two practical additions make the yes safe. Keep the default as report-only (`--적용` is opt-in, which is how this repository ships it), so an unattended night cannot silently change the design. And require that every applied patch be reviewed in the morning with the one question of Part Z2: what was the original defect? If you cannot state it, the patch is masking something, and the right response is to extend the stimulus rather than to keep the patch.
