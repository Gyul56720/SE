Z20. The Free Toolchain, Command by Command

Every number in Parts Z14–Z19 was produced by tools that cost nothing and install from a package manager. A one-person design house can take a block from C++ to a placed-and-routed netlist with a timing number without a single licence. This part is how, command by command, with the real output each one produces.

Table 483. The toolchain, as measured in this container

Two things are missing from that list and it is worth being honest about them. There is no free sign-off static timing analyser for ASICs (OpenSTA exists but was not available here), and there is no free formal equivalence checker. For FPGA work the gap does not bite; for an ASIC tape-out it does, and Part Y13 covers what that means commercially.

Z20.1 Step one: lint, because it is the cheapest

verilator --lint-only -Wall --top-module fir4_hand edu/model/fir4_hand.v
Table 484. What the flags do
FlagMeaningWhy
--lint-onlyParse and check; do not build a simulator.Runs in well under a second. This is the whole point.
-WallEnable all the style and width warnings.The default set is too quiet. -Wall is what industry actually turns on.
--top-moduleName the top of the hierarchy.Without it, a file with several modules gives confusing 'no top' errors.

The warnings that matter most, and what each is telling you:

Table 485. Verilator warnings you will actually see
WarningMeansTake it seriously?
WIDTHEXPAND / WIDTHTRUNCAn assignment or operation changes bit width implicitly.Yes, always. This is the class of bug Z16.7 spent five derivation steps preventing. Every silent truncation lives here.
UNUSEDSIGNALA signal is declared or driven and never read.Usually. Either it is dead logic (remove it) or you forgot to connect something. Suppress deliberately with a comment when a port is genuinely reserved.
LATCHCombinational block does not assign in all paths.Yes. Almost never intended. See Z18.5.
MULTIDRIVENTwo blocks drive one signal.Yes. This is a hard bug: x in simulation, contention in silicon.
BLKSEQ / COMBDLYBlocking assignment in sequential logic, or vice versa.Yes. The race of Z18.4.
DECLFILENAMEModule name does not match file name.Cosmetic, but fix it — every build system assumes the convention.
GENUNNAMEDUnnamed generate block.Fix it. Hierarchical names shift when loop bounds change.
SYNCASYNCNETA net is used as both sync and async reset.Investigate. Usually a real reset-architecture problem.
Worked example 83. Reading a lint report on generated code
Given. Running the command above on Bambu's generated fir_top.v returns 19 warnings: 7 WIDTHEXPAND, 6 UNUSEDSIGNAL, 3 WIDTHTRUNC, 1 UNUSEDPARAM, 1 SYNCASYNCNET, 1 DECLFILENAME.
Method. Separate warnings that indicate a defect from warnings that indicate a generator's house style.
Numbers. Effectively all 19 are style, not defects. Generated RTL uses parameterised width-adapter modules, so WIDTHEXPAND and UNUSEDSIGNAL appear wherever a generic module is instantiated narrower than its maximum.
The same reasoning applies to hand-written RTL with a different conclusion: there, a clean -Wall report is achievable and should be a release gate. edu/model/fir4_hand.v is clean.
How this is got wrong. The wrong conclusion is “lint is useless on generated code.” The right one is that you must lint the generator's output once, triage it, and then watch for new warning types. A WIDTHTRUNC that was not there yesterday is a real signal; the same six UNUSEDSIGNAL every build is noise. Counting warnings by type — which is what synth.sh prints — makes the difference visible.

Verilator can also simulate, and it is 10–100× faster than Icarus because it compiles to C++ rather than interpreting events. The trade is that Verilator's simulation is 2-state and cycle-based: it will not show you x propagation, which is exactly the thing you want to see when debugging a reset problem. Use Icarus to find the bug and Verilator to run the regression.

Z20.3 Step three: synthesise with Yosys

yosys -p "read_verilog -sv edu/model/fir4_hand.v; \
                hierarchy -check -top fir4_hand; \
                proc; opt; fsm; opt; memory; opt; techmap; opt; \
                stat"
Table 486. The Yosys script, pass by pass
PassWhat it does
read_verilog -svParse. -sv enables SystemVerilog; without it always_ff is a syntax error.
hierarchy -check -top MResolve the module tree from M downward. -check makes a missing module an error rather than a black box — without it, a typo in a module name silently synthesises to nothing.
procConvert always blocks into multiplexers and registers. This is where <= becomes a flip-flop.
optConstant folding, dead-code removal, simplification. Run it between every other pass; it is cheap.
fsmDetect state machines and re-encode them.
memoryTurn array accesses into RAM primitives.
techmapMap to generic gates ($_AND_, $_XOR_, …).
statPrint the cell count. Do not pass -q to yosys — it swallows this output, which was measured here the hard way.

The real output for the hand-written filter:

=== fir4_hand ===

   Number of wires:                268
   Number of wire bits:           1681
   Number of public wires:          14
   Number of public wire bits:      97
   Number of cells:                780
     $_AND_                        340
     $_MUX_                         15
     $_NOT_                         10
     $_OR_                         142
     $_SDFF_PP0_                     9
     $_XOR_                        264
Reading that report without guessing
StepJustification
1$_SDFF_PP0_ × 9 — nine synchronous flip-flops, positive edge, positive reset, reset-to-0.The design has exactly nine state bits: done_port (1) plus return_port (8). The number matching the count you expected is the first thing to check — a surprise here means inferred state you did not intend.
2$_XOR_ × 264 dominates the combinational logic.XOR is the sum output of a full adder (Z17.6). Two 9-bit adds plus a 17-bit add plus the constant-multiply shift-add network accounts for it.
3$_AND_ × 340 and $_OR_ × 142 are the carry logic.cout = (a AND b) OR (cin AND (a XOR b)) — two ANDs and an OR per bit.
4$_MUX_ × 15 is the saturation.Two comparisons selecting between three 8-bit values. This is the gate-level price of saturating rather than wrapping, as Z17.7 predicted.
5But 780 generic cells is not the area of the design.These are technology-independent gates. The device has 4-input lookup tables and a dedicated carry chain, so the mapping in the next step collapses this dramatically — 780 generic cells became 257 iCE40 cells. Never quote generic cell counts as area.

Z20.4 Step four: map to a real device

yosys -p "read_verilog -sv fir4_hand.v; \
                synth_ice40 -top fir4_hand -json fir4_hand.json; \
                stat"

# synth_ice40 은 위의 긴 스크립트를 **대신한다** -- 읽기부터 기술 매핑까지
# 한 명령이다.  다른 판을 쓰면 명령만 바꾼다:
#   synth_ice40     Lattice iCE40
#   synth_ecp5      Lattice ECP5   (더 크다.  nextpnr-ecp5 와 짝)
#   synth_gowin     Gowin
#   synth_xilinx    Xilinx 7-series (nextpnr-xilinx 는 실험적이다)
#   synth_intel     Intel/Altera
#   ABC9 기반 매핑을 쓰려면 `-abc9` 를 붙인다 (보통 더 작고 빠르다)
=== fir4_hand ===
   Number of cells:                257
     SB_CARRY                       48
     SB_DFFSR                        9
     SB_LUT4                       200

Now the numbers mean something physical. SB_LUT4 is a 4-input lookup table, SB_CARRY is one bit of the dedicated carry chain, SB_DFFSR is a flip-flop with set/reset. The 48 carry cells are the adders using hardware the fabric provides for free — which is why the generic 780 collapsed to 257, and why the gate-counting exercise in Z17.6 explains the structure but not the number.

Z20.5 Step five: place, route, and get a real frequency

nextpnr-ice40 --hx8k --package ct256 --json fir4_hand.json \
              --pcf-allow-unconstrained --placer heap --freq 300 --seed 1
Table 487. The flags that change the answer
FlagMeaningWhy it matters
--hx8k --package ct256Device and package.Pin count is a real constraint. Measured here: up5k/sg48 has 39 I/O and refused to place a design needing 43, with Unable to find a placement location. That is not a quality problem with the design.
--pcf-allow-unconstrainedAllow pins with no physical assignment.Needed when you are measuring a block rather than building a board.
--placer heapAnalytic placer.Better and more repeatable than the default SA placer.
--freq 300Target frequency in MHz.Without this the target defaults to 12 MHz and the tool stops optimising the moment it passes — the reported Fmax then reflects routing luck, not the design.
--seed NPlacement random seed.Run three and report the spread. A single seed is a sample of one.
Info:          ICESTORM_LC:   211/ 7680     2%
Info: Max frequency for clock 'clock$SB_IO_IN_$glb_clk': 455.79 MHz (PASS at 12.00 MHz)
Worked example 84. Why that 455.79 MHz was not usable and 47 MHz was
Given. Placing the hand-written filter directly gives 455.79 MHz. Wrapping it in a registered timing shell and re-placing gives 47.4 MHz. Same design.
Method. Ask which paths the tool is measuring in each case.
Numbers. Without the shell the design has 9 flops, all at the output. The only register-to-register paths are trivial, and the real datapath runs from an input pin to those flops — unconstrained, therefore unreported. With the shell, every path starts and ends at a flop, so the 47.4 MHz is the actual combinational depth of the filter.
The general rule: a frequency number is meaningless unless you can say which two registers the path runs between. Ask that question of every Fmax anyone quotes you, including your own.
How this is got wrong. The 455.79 MHz figure is stable across seeds and looks entirely credible. A reproducible measurement of the wrong path is the most dangerous kind, because every instinct says to trust it. What exposed it was a contradiction, not a tool warning: adding pipeline registers made the reported frequency fall, and more registers cannot make a design slower.

Z20.7 One command that runs all of it

edu/house/synth.sh is the whole flow in one script. It is written to be read as well as run, and two of its choices came from being wrong first.

bash edu/house/synth.sh <file.v> <top_module> [--pnr]

# 예
bash edu/house/synth.sh edu/model/fir4_hand.v fir4_hand --pnr

# 출력
#   == 1. verilator lint ==
#      경고+오류 0
#      lint rc=0
#   == 2. yosys 기술독립 합성 ==
#      Number of cells:  780 ...
#   == 3. yosys iCE40 매핑 ==
#      SB_LUT4 200, SB_CARRY 48, SB_DFFSR 9
#   == 4. nextpnr 배치·배선 ==
#      ICESTORM_LC: 211/7680,  Max frequency 47.4 MHz
Table 488. Two things the script does that look fussy and are not
ChoiceWhat went wrong without it
Tool output goes to a file, then is filtered — never piped straight into head.head closes the pipe, the tool dies of SIGPIPE, and the exit code comes back 141. A lint that passed and a lint that crashed became indistinguishable. Measured here.
Cell counts are extracted from inside the stat block, not by grepping the whole log.Yosys prints Generating RTLIL representation for module \SB_LUT4 while loading its cell library. A naive grep SB_LUT4 counts those lines as if they were cells.

Both are the same failure in different clothes: a measurement harness that reports a plausible number when it has actually failed. That is the defect this whole book is organised against, and it turns out to be just as easy to build into a twelve-line shell script as into a verification environment.

The install list is short and the whole thing fits on a laptop. That is the point of this part: the barrier to running a real IP flow is not money any more. What the free tools do not give you is ASIC sign-off timing, formal equivalence, and somebody to call — and those are exactly the things Part Y13 says to budget for when a block stops being an exercise and starts being a product.
