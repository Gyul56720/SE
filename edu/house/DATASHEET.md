# CRC-32 Streaming Engine — Datasheet

**`crc32_stream`** · v1.0 · 2026-09-19

이 문서는 **이 저장소에 실제로 있는 블록**의 데이터시트다. 교안 Y5·Z3 장이
"산출물 꾸러미" 라고 부르는 것의 본보기이자, `edu/house/release.sh` 가 존재를
확인하는 세 문서 중 하나다.

---

## 1. 무엇인가

IEEE 802.3 FCS 다항식(0x04C11DB7, 반사 입출력, 초기값·최종 XOR 0xFFFFFFFF)으로
바이트 스트림의 CRC-32 를 계산한다. AXI-Stream 꼴 핸드셰이크로 데이터를 받고,
`s_last` 로 패킷이 끝나면 그 패킷의 CRC 를 낸다.

**용도.** 이더넷 MAC 의 FCS 생성·검사, 저장 장치의 블록 무결성, 패킷 파이프라인의
end-to-end 검사(교안 X16 장이 안전 기능으로 권하는 그것).

## 2. 인터페이스

| 신호 | 방향 | 폭 | 설명 |
|---|---|---|---|
| `clk` | in | 1 | 상승 에지 |
| `rst_n` | in | 1 | **동기** 리셋, 낮을 때 유효 |
| `s_data` | in | 8 | 입력 바이트 |
| `s_valid` | in | 1 | 입력 유효 |
| `s_last` | in | 1 | 이 바이트가 패킷의 마지막 |
| `s_ready` | out | 1 | 입력 수락 |
| `m_crc` | out | 32 | 패킷 CRC |
| `m_valid` | out | 1 | 출력 유효 |
| `m_ready` | in | 1 | 출력 수락 |

**핸드셰이크 규칙(교안 X37 장).** `s_ready` 는 `s_valid` 를 **조합으로 보지
않는다** — 두 방향이 서로를 보면 조합 고리가 된다. `m_valid` 는 세워지면
`m_ready` 가 올 때까지 유지되고 `m_crc` 는 그동안 안 바뀐다.

## 3. 잰 성능

| 항목 | 값 | 어떻게 쟀나 |
|---|---|---|
| 처리량 | **1 바이트 / 사이클** (back-pressure 없을 때) | 구조상 |
| 실측 처리량 | **2.18 사이클 / 바이트** | 무작위 공백·back-pressure 자극, 씨앗 1·7·99 |
| 선언된 한계 | **2.6 사이클 / 바이트** + 200 | `성능한계()`; 관문이 매번 잰다 |
| 지연 | 패킷 마지막 바이트 수락 후 1 사이클 | 구조상 |

**실측 조건을 같이 적는다**(교안 X7·Y5 장): 위 숫자는 테스트벤치가 입력에
무작위 공백을, 출력에 무작위 back-pressure 를 거는 조건에서 나왔다. 고객의
트래픽이 다르면 숫자가 다르다.

## 4. 면적과 주파수

**아직 재지 않았다.** `release.sh` 가 yosys 로 셀 수를 내지만, 그것은 개방
라이브러리의 셀 수이지 고객 공정의 면적이 아니다. 교안 Y14 장의 규칙대로
**라이브러리와 도구와 버전을 적지 않은 면적 수치는 내지 않는다.**

## 5. 검증

| 관문 | 결과 |
|---|---|
| 독립 골든모델 | 파이썬 `zlib.crc32` — **우리가 쓴 것이 아니다** |
| 회귀 | 씨앗 20개, 불일치 0 |
| 자해검사 | 통과 (골든을 일부러 망치면 비교가 문다) |
| **변이 점수** | **100.0 %** (변이 8개 중 8개), 판정 안 된 탈출 0 |
| 처리량 | 선언된 한계 안 |

변이 점수가 이 표에서 가장 중요한 줄이다 — 나머지는 "이 자극에서 안 틀렸다" 이고,
이 줄만이 "틀리면 잡는다" 를 말한다.
