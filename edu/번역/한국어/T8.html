직렬 링크의 모든 것은 한 가지 사실에서 나온다. 채널은 심볼률보다 대역폭이 훨씬 좁은 저역통과 필터라서, 심볼 하나하나가 이웃에 번진 채로 도착한다. 수신기가 할 일은 그 번짐을 슬라이서가 판정할 수 있을 만큼 되돌리는 것이고, 아래의 측정 — 이 저장소 자신의 채널·링크 모형으로 돌린 것 — 은 등화가 얼마나 사 주는지와, 더 쓸모 있게는 어디서 아무것도 사 주지 않는지를 둘 다 보여 준다.

T8.1 펄스 응답, 그리고 거기서 나오는 수들

커서 (cursor) — 채널의 펄스 응답을 심볼 간격으로 뽑은 표본들. 주커서는 슬라이서가 쓰는 것이고, 그보다 앞의 것은 모두 선행커서, 뒤의 것은 모두 후행커서다. 주커서가 아닌 것들의 크기를 다 더한 것이 최악의 심볼간간섭이다.

30 dB 줄은 결과가 아니다 — 망가진 동작점이다. 어느 구성이든 BER 이 대략 0.2 인데, 이것은 아이가 완전히 닫혔을 때 슬라이서가 하는 일이다. 찍는 것이다. 거기서 등화기를 견주는 것은 동전 던지기를 견주는 것이고, FFE 가 CTLE 하나보다 나쁘다고 보이는 것(0.25 대 0.23)은 물리가 아니라 잡음이다.

이 저장소에는 바로 이것을 두고 호되게 배운 규칙이 있다. 그 위에서 잰 것을 무엇이든 보고하기 전에 동작점이 성한지부터 본다. 0.5 근처의 BER, 수렴하지 않은 등화기, 틀린 표본 위상 — 모두 데이터처럼 보이는 수를 낳는다.

3의법칙 (rule of three) — 오류 0 이 무엇을 뜻해도 되는가

위의 두 줄이 오류 0 을 보고한다. 오류 0 은 BER 이 0 이라는 뜻이 아니다. 상한이다. n 비트에서 오류가 하나도 없을 때 오류율의 95 % 신뢰 상한은 3/n 이다 — 3의법칙이다. 630,000 비트 실행에서는 그것이 4.76×10-6 이다.

그러니 이 측정이 말하는 것은 CTLE + FFE 와 CTLE + FFE + DFE 가 둘 다 4.76×10-6 아래라는 것뿐이고, 둘 중 어느 쪽이 나은지는 아무것도 말하지 않는다. DFE 가 '아무 차이도 안 냈다' 고 보고하는 것은 데이터가 받쳐 주지 않는 주장이다. 정직한 진술은 이 실행이 둘을 가려내지 못했다는 것, 그리고 가려내려면 비트가 대략 100배 더 있거나 채널이 더 나빠야 한다는 것이다.

어디에 쓰나모든 BER 측정, 모든 준수 보고서, 그리고 BER 이라는 글자가 들어가는 모든 데이터시트 줄.
언제 쓰나오류 수가 적을 때마다 — 출하할 만한 링크라면 그것은 늘이다.
어떻게 쓰나비율만이 아니라 오류 수와 비트 수를 보고한다. 오류 = 0 이면 3/n 한계와 신뢰수준을 같이 적는다. 1e-12 를 주장하려면 적어도 3e12 비트를 봐야 하는데, 25 Gb/s 에서 그것은 2분이고 — 1e-15 에서는 하루다.
실제 코드는 이렇게 생겼다
# The line that belongs in every link report.
#   errors = 0 in 6.30e5 bits  ->  BER < 4.8e-6 (95% confidence, rule of three)
# NOT "BER = 0".
def ber_bound(errors, bits, conf=0.95):
    if errors == 0:
        import math
        return -math.log(1 - conf) / bits        # 3.0/bits at 95%
    return errors / bits                         # point estimate; add a CI for small n
# And the check that catches the broken operating point before any of this matters:
assert 0.0 <= ber < 0.2, f"BER {ber} -- the eye is closed; this run measured nothing"
여기서 틀린다. 정확히 0.5 인 BER 은 대개 나쁜 채널이 아니라 극성이나 정렬 버그를 뜻한다 — 수신기가 뒤집혔거나 어긋난 기준과 견주고 있는 것이다. PAM4 에서 0.25 근처의 BER 은 한 층 위에서 같은 뜻이다. 등화기를 탓하기 전에 이것부터 봐라. 진짜로 닫힌 아이보다 훨씬 흔하다.

DFE 는 이미 판정한 심볼들의 몫을 뺀다. 판정이 틀렸으면 틀린 것을 빼게 되고, 그러면 다음 판정도 틀릴 확률이 높아진다 — 오류가 하나씩이 아니라 다발로 온다.

그 효과는 실제로 있고, 직관이 말하는 것보다는 작다. 탭 하나짜리 DFE 에서는 다발 길이가 짧은데, 오류가 다음의 옳은 판정을 살아 넘겨야 하기 때문이다. 뒷단에서 중요한 것은 BER 이 아니라 다발의 구조다. 뒤따르는 FEC 가 어떤 다발 길이를 가정하고 설계됐기 때문이다. BER 은 맞추면서 가정된 다발 분포를 어기는 링크는 디코딩 뒤에 지는데, 그동안 FEC 전의 모든 측정은 멀쩡해 보인다.

어디에 쓰나손실 ~10 dB 가 넘는 모든 수신기, 그리고 FEC 설계자와의 모든 대화.
언제 쓰나후행커서 꼬리가 주커서에 견주어 무시할 수 없을 때마다 — 이 모형의 20 dB 에서는 첫 후행커서 하나가 주커서의 61.1 % 다.
어떻게 쓰나BER 만이 아니라 다발 길이 분포를 재서, 인터리버 치수를 잡는 사람에게 넘긴다. 언롤링(추측)은 되먹임 곱셈을 임계경로에서 빼낸다 — T2 의 논증 — 대신 탭 k 개를 언롤하면 슬라이서가 2k 개 나란히 든다.
실제 코드는 이렇게 생겼다
// Unrolled (speculative) first DFE tap: both outcomes are precomputed,
// and the previous decision only selects. The multiply leaves the loop.
always_comb begin
    d_if_prev0 = (sample >  +c1) ;      // precomputed thresholds
    d_if_prev1 = (sample >  -c1) ;
end
always_ff @(posedge clk) prev <= prev ? d_if_prev1 : d_if_prev0;   // 2:1 mux only
// The loop now contains a mux and a flop instead of a multiply-add.
// Cost: one extra slicer per unrolled tap, and 2^k for k taps.
여기서 틀린다. 언롤링은 그 고리가 임계경로였을 때만 이득이다. 먼저 재라. 이 저장소 자신이 현실적인 동작점에서 DFE 를 잰 것에서는 되먹임 탭이 |c| ≤ 0.041 이었다 — 고리가 놀고 있었다. 그리고 진짜 임계경로는 슬라이서였다. 노는 고리를 다듬는 것은 가장 비싼 종류의 옳은 일이다.

T8.4 클럭 되찾기, 그리고 그게 되는지를 가르는 지터

클럭데이터복원 (CDR) — 데이터를 기준으로 삼는 T7 의 PLL

따로 난 클럭선이 없다. 수신기는 데이터 자신의 천이에서 타이밍을 뽑아낸다. 위상 검출기(알렉산더/뱅뱅, 또는 선형 뮐러–뮐러)가 T7 과 같은 2차 고리를 몬다. 그 장의 모든 것이 그대로 들어맞되 두 가지가 다르다. '기준' 은 데이터가 천이할 때만 오고, 고리는 송신기의 확산 스펙트럼 변조를 따라가면서 고주파 지터는 물리쳐야 한다.

그것이 지터허용 마스크다. CDR 대역폭 아래에서는 수신기가 지터를 따라가므로 큰 진폭도 견뎌진다. 그 위에서는 따라갈 수 없어서 지터가 아이를 곧장 갉아먹는다.

어디에 쓰나모든 직렬 규격의 모든 수신기 — PCIe, USB, 이더넷, MIPI, SATA, HDMI.
언제 쓰나CDR 대역폭은 규격의 지터허용 마스크와 따라가야 하는 확산 스펙트럼 프로파일이 정한다. 마음대로 고르는 값이 아니다.
어떻게 쓰나규격의 마스크를 가져다 허용 곡선이 그 위에 여유를 두고 앉도록 CDR 대역폭을 놓고, 송신 PLL 의 지터(T7)에 잔차를 더한 것이 예산 안에 드는지 본다.
실제 코드는 이렇게 생겼다
# The budget is a SUM, and each term has an owner.
#   TX PLL jitter (T7)          0.30 ps rms   <- clock design
#   TX driver / ISI (DJ)        0.15 UI pp    <- output stage and package
#   Channel ISI residual        0.20 UI pp    <- equalisation, this chapter
#   RX CDR tracking error       0.05 UI pp    <- loop bandwidth
#   Sampler aperture (T5)       0.10 ps rms   <- sampling network
# Random terms add in QUADRATURE, deterministic ones LINEARLY -- mixing the two
# rules is the most common budgeting error, and it always errs optimistic.
여기서 틀린다. 확산 스펙트럼 클러킹은 따라가야 하는 요구사항이지 물리쳐야 할 교란이 아니다. 33 kHz SSC 프로파일을 따라가기에 대역폭이 모자란 CDR 은 규격을 지키는 송신기 앞에서 락을 잃는다. 깨끗한 발생기를 쓰는 벤치에서는 되는데 진짜 호스트 앞에서 지는 수신기는 대개 이것이다.

가지고 갈 잰 결과 둘. 손실 20 dB, SNR 34 dB 에서 CTLE 하나가 링크를 0.13 에서 6.35×10-5 로 데려간다 — 대략 2,037 배다 — 그리고 FFE 를 더하면 630,000 비트로 가려낼 수 있는 아래로 내려간다. 그런데 손실 30 dB 에서 같은 SNR 이면 어느 등화기도 아무 일도 하지 않는다. 동작점 자체가 망가져 있기 때문이다. 그 문장 없이 두 번째 표를 보고하는 것이 이 책의 규칙들이 막으려고 있는 바로 그 실패다.

다음 장은 여기서 쓴 모형 밑으로 내려가, 채널의 손실이 실제로 어디서 오는지를 묻는다 — 그리고 패키지와 비아와 커넥터가 위의 수들에 무슨 짓을 하는지를 묻는다.

특허로 가는 길 — 이 주제에서 발명이 일어나는 자리
링크 특허는 고리가 있는 자리에 몰린다. 되먹임 곱셈을 임계경로에서 빼내는 추측(언롤) DFE, 훈련열 없이 수렴하는 적응 방식, ISI 를 더 견디는 CDR 위상 검출기, 그리고 요즘은 등화가 전부 디지털인 ADC 기반 수신기. 이 저장소 자신의 연구가 그 첫 갈래에 있다. 그리고 거기서의 논증은 T2 의 것이다. 발명은 지연을 어디로 옮겼는가이지 트랜지스터가 얼마나 빠른가가 아니다.
