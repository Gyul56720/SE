# seek — 식이 아니라 **문제**를 적는다

`mathdrift` 는 식을 낳았다. 51개를 재 보니 **41개가 뜻이 안 정해진 기호를 갖고 있었다.**

```
S5 [매장]  \Phi(U) \cdot \Phi(V) \cdot \Phi(W) = \Phi(\delta)
```

Φ가 무엇인지 아무 데도 없다. 그런 것은 공간이 아니라 공간의 **이름**이다. 답을
아무도 검산할 수 없다. 그리고 51개에 도약은 없었다.

## 문법 하나가 그것을 막는다

> **문제 하나 = (물음, 표본, 판정).** 셋이 다 **도는 코드**여야 원장에 오른다.

`space.add()` 가 부모 없는 공간을 검사해서 거절하는 것이 아니라 아예 못 받게 되어
있는 것과 같은 수다. 판정기를 못 적으면 문제가 아니다. **어제의 41개가 입구에서
걸린다** — Φ를 못 적으면 판정기를 못 쓰고, 판정기가 없으면 원장이 안 받는다.

비었는지만 보지 않는다. **돌려 보고, 돌려준 것까지 본다.**

| 이런 판정기 | 비었나 | 도나 | 참/거짓인가 |
|---|---|---|---|
| `def judge(x): pass` | 아니 | 돈다 | **아니다 → 거절** |
| `def nope(x): ...` | 아니 | **안 돈다 → 거절** | |
| `def judge(x): 1/0` | 아니 | **터진다 → 거절** | |

`pass` 가 요점이다. 비었는지만 보면 통과하고, 돌려 보기만 해도(`bool(None)` 이
`False` 다) 통과한다. **돌려준 것을 봐야 잡힌다.**

## 도약을 사람이 아니라 기계가 판정한다

```
보존   부모의 답 x 를 옮겨서 자식 판정기에 넣으면 받는다   → 옛 해가 살아남았다
확장   자식의 답 y 를 부모 판정기가 **읽지도 못한다**      → 새 점이 생겼다
```

둘 다여야 도약이다. 보존만이면 **재작성**, 확장만이면 **딴 문제**.

`옮김`(embed)이 그 열쇠다. mathdrift 에서 Φ가 자유 기호로 남았던 자리가 여기서는
**코드**다. 부모의 해가 새 문제 안에서도 해로 남는지를 실제로 돌려서 확인한다.

### 실측 — 눈으로 본 도약

씨앗 `P1`: 5선 정렬망을 비교기 **9개**로 (9는 알려진 최적).

```
찾았다 (20,097개 봤다)
  [[3,4],[0,1],[0,2],[0,3],[2,3],[3,4],[1,4],[1,3],[1,2]]
```

`P2` = 경계화. **하나까지 틀려도 좋다**고 하고 길이 제약을 푼다. Schönhage 가 경계
랭크에서 한 수 그대로다.

```
찾았다 (301개 봤다 · 11개 -> 8개로 줄였다)
  [[3,4],[1,2],[0,3],[3,4],[2,3],[0,1],[1,2],[3,4]]
```

**9개가 최적인데 하나를 틀려도 좋다고 하니 8개가 됐다.** 그리고 `reach` 의 판정:

```
보존  예     부모의 답을 옮겨서 자식 판정기에 넣으면 받는다
확장  예     부모가 못 읽는다: ValueError: 비교기가 9개가 아니다
**도약**
```

### 대조군이 있어야 판정이 뜻을 갖는다

`P3` = 쌍대(내림차순). **진짜 수학적 연산이지만 후보꼴이 그대로다.**

```
보존  예
확장  아니오   부모가 자식의 답을 읽는다 -- 부모의 후보꼴 안이다
**재작성**
```

초록불이 아무 데나 안 켜진다.

### 이 자의 한계 — 놓치는 쪽으로 틀린다

"부모가 읽지도 못한다" 로 확장을 재므로, **부모 판정기가 입력 꼴을 안 보면 확장이
영영 안 잡힌다.** 실측: `return sum(x) == 12` 는 세 수든 네 수든 읽는다. 그러면 네
수로 넓힌 자식이 `재작성` 으로 나온다.

그러니 **도약이라고 하면 도약이 맞다. 재작성이라고 한 것 중에 도약이 섞여 있을 수
있다.** 씨앗의 판정기가 후보꼴을 먼저 보게 쓰는 것이 그래서 중요하다.

## 판정기가 있으면 줄일 수 있다

문제에 판정기가 딸려 오니 "자원을 줄여라" 가 공짜다. `--짧게` 가 하나씩 빼 보고,
막히면 **한 칸 짧은 길이에서 다시 찾는다**. 빼기만 하면 지금 답의 이웃에 갇힌다
(실측: 9에서 멈췄는데 8이 있었다).

부모 `P1` 에는 이 수를 못 쓴다. 길이가 문제 정의에 박혀 있다. **자원을 문제 밖으로
꺼낸 것 자체가 P2 의 도약이다.**

## 격리 — 샌드박스가 아니다

`exec` 는 임의 코드를 실행한다. 판정기는 `_child.py` 자식에서 돈다. 부모는 그 코드를
임포트조차 안 한다. **다만 코드는 실제로 돈다** — 검사가 그것을 파일 하나 써서
확인한다. 부모의 임포트·전역·원장에 못 닿을 뿐, 같은 기계 위에서 돈다.

## 쓰는 법

```bash
python3 seek/solve.py P1                    # 답을 찾는다 (호출 0회)
python3 seek/solve.py P2 --짧게              # 찾고 나서 자원을 줄인다
python3 seek/reach.py P2                    # 도약인가
python3 seek/reach.py                       # 원장 전체
python3 tests/test_seek.py                  # 배선 검사
```

## 낳는 쪽 — 프롬프트가 **판정기**를 달라고 한다

```bash
python3 seek/spread.py --n 9 --dry     # 호출 없이 프롬프트만 본다
python3 seek/spread.py --n 20 --점검    # 호출 없이 쓸 수 있는 후보와 잔량을 본다
python3 seek/spread.py --n 20          # 낳는다
python3 seek/spread.py --show
```

mathdrift 의 프롬프트에는 이 줄이 있었다.

```
· **엄밀할 필요 없다.** 정리도 증명도 아니다. **그럴듯한 식이면 된다**
```

41/51 이 자유 기호를 갖고 돌아온 것은 규칙 위반이 아니라 **규칙을 지킨 것**이다.
그럴듯한 식은 Φ를 안 정해도 그럴듯하고, 정하는 것보다 싸다.

여기서는 그 문장이 성립하지 않는다.

```
· 판정기 안에 "그럴듯한" 것은 없다. **돌거나 안 돌거나다**
· **판정기가 돌지 않으면 원장이 안 받는다.** 부탁이 아니라 문법이다
· **판정이 후보의 꼴을 먼저 봐라.** 안 그러면 나중에 확장을 잴 수가 없다
```

마지막 줄이 재밌다. `reach` 의 한계(부모가 후보꼴을 안 보면 확장이 안 잡힌다)를
**프롬프트가 미리 막는다.** 자를 고치는 대신 자가 볼 수 있는 것을 낳게 하는 쪽이다.

### 안 받는 것은 세어서 보여 준다

가짜 모델로 셋을 내게 해 봤다. 멀쩡한 것 하나, `pass` 판정기 하나, 터지는 것 하나.

```
[낳기] P2 <- P1 / 자원 풀기 : 자원 풀기 로 넓힌 것
[낳기] 국소화     안 받았다 -- 판정기가 안 돈다: 판정이 참/거짓이 아닌 것을 돌려준다: None
[낳기] 제약 더하기 안 받았다 -- 판정기가 안 돈다: ZeroDivisionError
```

**하나만 올랐고 묶음은 안 버렸다.** 안 받은 것도 왜인지 적힌다. 기각이 아니라
문법이라 조용히 사라지지 않는다.

### 연산자 열둘

후보꼴을 바꾸는 것(자원 풀기 · 차원 올리기 · 표현 바꾸기 · 제약 더하기), 판정을
바꾸는 것(경계화 · 국소화 · 무작위화 · 증인 요구 · 물음 바꾸기 · 뒤집기), 둘 다인
것(합성 · 역문제). 급발진 몫은 0.12 로 낮다 — 멀리 던진 문제는 판정기를 못 써서
원장이 안 받고, 그건 발산이 아니라 버려지는 것이다.

**골라 낸 목록이 아니다.** 실측으로 도약을 낸 것(경계화)과 재작성을 낸 것(뒤집기)이
둘 다 있어야 자가 뜻을 갖는다.

## 받은 것이 진짜 문제인가 — `audit.py`

**실측 2026-09-09.** VM 에서 `--n 20` 한 번에 21개가 낳아지고 **21개가 다
받아들여졌다.** 100% 는 두 가지로 읽힌다 — 프롬프트가 좋거나, **거르는 데가
없거나.** 확인해 보니 뒤쪽이었다.

```
def judge(x): return True     -> 원장이 받았다
def judge(x): return False    -> 원장이 받았다
```

둘 다 "돈다". 원장이 보던 것은 그것뿐이었다. **도는 것과 거르는 것은 다른
물음이다.**

그래서 둘을 갈랐다.

| | 원장 | 왜 |
|---|---|---|
| 뽑은 것을 **다 받는다** | **안 받는다** | 아무것이나 답이면 찾을 것이 없다 |
| 하나도 안 받는다 | **받는다** | P1 이 그렇다 — 22,991개를 봐야 하나가 걸린다 |

막힘을 자동으로 버리지 않는 이유가 이것이다. 어려운 것과 틀린 것을 기계가 여기서
가를 수 없다. 세어서 보여만 주고 버리는 것은 사람이 한다 — 과잉 기각은 이 저장소가
싫어하는 쪽이다.

```bash
python3 seek/audit.py            # 원장 전체. 호출 0회
python3 seek/audit.py --n 500    # 더 흔들어 본다
python3 seek/audit.py P7         # 하나만
```

```
id     등급           적중    터짐  물음
P1     막힘        0/200     0  5선 정렬망을 비교기 9개로 만들 수 있는가 (크기)
P2     문제        1/200     0  5선에서 비교기 몇 개로 2^5 중 31개 이상을 정렬하는가
```

`부모 판정기를 글자 그대로 쓴 것` 도 같이 센다. 판정기가 부모와 같으면 물음만 바꿔
적은 것이라 도약은커녕 새 문제도 아니다.

## 막힘을 가르는 법 — `sweep.py`

**실측 2026-09-09, 100개 감사:** 공허 9 · **막힘 52** · 문제 39.

막힘 52개가 제일 큰 덩어리인데 그 안에 두 가지가 섞여 있다.

| | |
|---|---|
| **어렵다** | 해가 있는데 무작위 200개로는 안 걸린다. P1 이 그렇다 — 22,991개째 |
| **모른다** | 표본이 판정기에 영영 못 닿는 꼴일 수도 있다 |

**감사는 그 둘을 못 가른다.** 200개를 흔들어 0개인 것과 20만 개를 봐서 0개인 것은
같은 말이 아닌데 같은 칸에 들어간다. 실제로 찾아 봐야 갈린다 — 찾으면 **해가 있다는
것이 증명된다**(찾은 것이 증거다). 못 찾으면 여전히 모르지만, 몇 개를 봤는지가
원장에 남는다. **못 찾은 것을 없다고 말하지 않는다.**

```bash
python3 seek/sweep.py                    # 안 푼 것을 다 푼다. 호출 0회
python3 seek/sweep.py --만 막힘 --초 20   # 막힘만, 한 문제당 20초
python3 seek/sweep.py --다시             # 이미 푼 것도 다시
```

한 문제를 풀 때마다 저장한다 — 중간에 끊겨도 앞의 것이 남고, 다시 걸면 이어서 돈다.
**공허는 안 푼다** — 아무것이나 답이면 찾은 것이 아무 말도 안 한다. 등급을 원장에
적어 두므로 `spread.py` 도 공허를 부모로 삼지 않는다(공허에서 파생하면 공허를
물려받는다).

다 돌고 나면 `reach.py` 를 원장 전체에 걸어 **도약을 센다.** 보존은 부모의 답을,
확장은 자식의 답을 필요로 하므로 — 푼 것이 쌓이기 전에는 잴 데가 없다.

## 그 자가 계보를 재기는 하나 — `control.py`

**실측 2026-09-09, 100개 훑기:** 도약 22 · 재작성 16 · 딴 문제 11 · 모름 50.
99걸음 중 22%다. 반가운 수인데 **21개 중 21개가 다 받아들여졌던 것과 같은
모양**이라, 세기 전에 자를 검사한다.

`reach` 의 확장 판정은 "부모 판정기가 자식의 답을 **읽지도 못한다**" 이다.
그런데 그건 두 문제의 **후보꼴이 다르다**는 말이기도 하고, 꼴은 아무 두 문제나
다르다. 게다가 옮김은 LLM 이 쓰는데, 제 문제의 꼴은 알아도 부모가 누구인지는
프롬프트에 없으니 **받은 것을 제 꼴로 우겨넣는** 옮김을 쓰기 쉽다. 그러면 부모가
누구든 보존이 선다.

검사법은 하나뿐이다 — **계보를 흔들어 보고 숫자가 변하는가.**

```bash
python3 seek/control.py          # 진짜 짝과 무작위 짝을 나란히 센다. 호출 0회
python3 seek/control.py --씨 3   # 다른 흔들기로 다시
```

| | |
|---|---|
| 진짜 22% · 무작위 2% | 자가 계보를 본다. **22개는 무언가를 뜻한다** |
| 진짜 22% · 무작위 20% | 자가 계보를 안 본다. **22개는 아무 뜻이 없다** |

무작위 짝을 고를 때 **조상과 후손은 뺀다** — 그것도 계보라서 대조가 안 된다.
이 파일은 아무것도 기각하지 않는다. 숫자를 만들 뿐이다.

### 대조군 결과 — 자는 섰다

**실측 2026-09-09, 씨 셋:**

| | 진짜 짝 | 무작위 짝 |
|---|---|---|
| 씨 1 | 22.2% (22/99) | 2.0% |
| 씨 3 | 22.2% | 2.0% |
| 씨 7 | 22.2% | 1.0% |

11~22배 차이가 세 번 다 유지된다. **이 자는 꼴 차이가 아니라 계보를 본다.**
22개는 무언가를 뜻한다.

## 어느 연산자가 냈나 — `tally.py`

자가 섰으니 다음 물음은 이것뿐이다. 12개 연산자 중 어디에 몰렸나. 고르게 나왔으면
연산자 표는 아무 말도 안 하는 것이고, 몇 개에 몰렸으면 그것이 `spread.py` 가 더
자주 걸어야 할 것이다.

```bash
python3 seek/tally.py            # 연산자별 · 깊이별 · 모름 가르기. 호출 0회
```

**연산자마다 대조군을 나란히 놓는다.** "이 연산자가 도약을 많이 낸다"는 "이 연산자가
후보꼴을 많이 바꾼다"일 수 있다. 둘이 같이 높으면 연산자의 공이 아니라 꼴 바꾸기의
그림자이고, 그런 연산자는 이름으로 지목한다.

**모름은 판정이 아니라 아직 못 잰 것**이라 도약률의 분모에서 뺀다. 넣으면 도약이
절반으로 깎여 보인다. 어느 쪽 답이 없어서인지도 갈라 센다 — 부모만/자식만/둘 다에
따라 할 일이 다르다.

## 결과를 옮기는 법 — `report.py`

원장(`seek/ledger.json`)은 **무시 목록에 있다.** VM 이 계속 쓰는 파일이라 추적하면
배포의 `git pull` 이 매번 충돌한다(`compression/ledger.json` 과 같은 부류). 그렇다고
화면 출력을 사람이 요약해 옮기면 **옮기는 사이에 잃는다.**

> 실측 2026-09-09, 세 번 연달아: 표를 요약해 전달하니 `무작위` 열이 사라졌다.
> 그 열이 없으면 도약률 100%가 연산자의 공인지 꼴 바꾸기의 그림자인지 알 수 없는데,
> 그 구분을 하려고 대조군을 만든 것이었다.

그래서 **파생물**을 남긴다. 원장이 아니라 결과만 저장소에 올린다.

```bash
python3 seek/report.py --쓰기        # seek/report.md 를 만든다. 호출 0회
git add seek/report.md && git commit -m "seek 결과" && git push -u origin main
```

`report.md` 는 감사 · 대조군 · 셈을 한 파일에 담고, **도약으로 판정된 걸음의 부모와
자식 물음을 글자 그대로 적는다** — 숫자만 남기면 22개가 무엇인지 아무도 못 본다.
이 명령을 칠 때만 쓰이므로 계속 쓰이는 원장과 달리 충돌하지 않는다.

## 100개를 읽고 나서 — 이 파이프라인의 진짜 한계

**실측 2026-09-09, 원장 100개를 직접 읽었다.**

### 자는 섰다

| | 도약 | 재작성 | 딴 문제 | 모름 |
|---|---|---|---|---|
| 진짜 짝 | **22** | 16 | 11 | 50 |
| 무작위 짝 | 2 | 0 | **41** | 56 |

무작위 짝은 대부분 `딴 문제`로 떨어진다 — 남의 답을 옮겨 넣으면 보존이 깨지기
때문이다. 그 자리에서 진짜 짝은 보존을 지킨다. **자는 계보를 본다.**

연산자별로도 갈린다.

| 연산자 | 걸음 | 도약률 | 무작위 |
|---|---|---|---|
| 자원 풀기 | 8 | **100%** (6/6) | 0% |
| 증인 요구 | 12 | **86%** (6/7) | 8% |
| 표현 바꾸기 | 10 | 60% (3/5) | 0% |
| 무작위화 | 9 | 38% | 11% |
| 국소화 | 12 | 20% | 0% |
| 차원 올리기 · 뒤집기 · 경계화 | 31 | **0%** | 0% |

`뒤집기` 12걸음이 전부 모름이다 — 한 번도 못 쟀다.

### 그런데 100개가 전부 5선 정렬망이다

깊이 3까지 내려가도 물음이 이렇다.

```
P1   5선 정렬망을 비교기 9개로 만들 수 있는가
P54  5선 정렬망이 '0이 하나인 입력'과 '1이 하나인 입력'들로만 이루어진 부분 집합에
     대해서 정렬을 수행하는가?
```

연산자가 바꾸는 것은 **술어**뿐이다. 대상은 한 번도 안 바뀐다. 그래서 `도약 22개`는
자로 재면 참이지만 — 그 자가 재는 것은 "부모의 후보꼴 밖에 점이 생겼나"이지
**"새로운 대상으로 갔나"가 아니다.** 22개는 한 동네 안에서의 도약이다.

씨앗이 하나뿐인 것이 그 원인이다. 모든 부모가 P1 의 후손이고, 프롬프트는 부모의
판정기를 보고 쓴다. 대상을 갈아타려면 **씨앗을 여럿 두거나**, 대상 자체를 바꾸는
연산자(현재 12개 중 없다)가 있어야 한다.

## 씨앗 다섯 — 대상을 갈랐다

100개가 전부 5선 정렬망이었던 원인은 **씨앗이 하나**였던 것이다. 그래서 다섯으로
늘렸다. 각각 다른 분야의 다른 대상이고, 모두 **완전 판정**(표본이 아니라 전수)이다.

| 씨앗 | 분야 | 대상 | 완전한 이유 |
|---|---|---|---|
| 정렬망 | 조합 최적화 | 비교기 목록 | 0/1 원리로 2^5 전수 |
| 그래프 색칠 | 그래프 이론 | 정점의 색 | 그래프 고정, 변 15개 전수 |
| 불 회로 | 계산 복잡도 | 게이트 목록 | 입력 2^3 전수 |
| 유한 반군 | 대수 | 곱셈표 | 결합법칙 4^3 전수 |
| 부분집합 합 | 수론 · NP-완전 | 0/1 마스크 | 더해 보면 끝 |

**다섯 다 실제로 풀린다** — 못 푸는 씨앗을 심으면 그 가지는 영영 모름이다.
검사가 매번 찾아서 보인다(정렬망 22,991개째 · 반군 277,796개째).

### 대상이 갈렸다는 것을 어떻게 아나

물음 문장이 다른 것으로는 모자란다. **후보꼴이 달라야 계보가 안 섞인다.** 그래서
서로의 답을 먹여 본다 — 20쌍 중 어느 것도 남의 답을 받지 않고, 19쌍은 **읽지도
못한다.** 그것이 확장 판정이 서는 조건이다.

### 소스는 파이썬, 원장은 JSON

`seek/seeds/*.py` 가 원본이고 `seek/seed.json` 은 만들어진 것이다. JSON 안의
`\n` 투성이 문자열을 손으로 고치면 반드시 틀린다(G017 이 그런 자리를 이미 한 번
잡았다). 둘이 어긋나면 검사가 잡는다.

```bash
python3 seek/seeds/build.py          # seed.json 을 새로 쓴다
python3 seek/seeds/build.py --확인    # 어긋났는지만 본다
```
