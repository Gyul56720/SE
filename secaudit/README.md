# secaudit -- 로컬 호스트 보안 자가점검 (읽기 전용)

사용자 규정(2026-09-11)의 5단계를 잇는다:

```
1 수집   dig/harvest 로 점검 방법론·권고를 모은다 (제2의 뇌)        [--뇌, 선택]
2 정제   수집한 자연어를 '어떤 점검을 돌릴지' 로 푼다
3 대조   search_memory(graph/ask) 로 지난 규칙·예외와 맞춘다         [--뇌, 선택]
4 점검   secaudit/checks 의 읽기 전용 진단을 실측 -- **판정은 코드가 한다**
5 보고   심각도별 구조화 보고 + 원장(secaudit/ledger.jsonl)
```

## 무엇을 하고 무엇을 안 하나

- **한다**: 돌고 있는 **호스트 자신**의 열린 포트(`/proc/net/tcp`, ss 없이) · 파일/키 권한 ·
  SUID · 세계 쓰기 · 위험 계정(UID 0 중복·빈 비밀번호) · 방화벽을 **열거하고 평가**한다.
- **안 한다**: 남의 기계 접속 · 익스플로잇 실행 · 상태 변경. 전부 읽기뿐이다(`find`·`stat`·
  `/proc`·`iptables -L`). "내 노트북" 을 점검하려면 그 노트북에서 이 봇을 돌려라 -- 여기서
  남의 기계로 건너가지 않는다.

## 판정

각 낱낱은 심각도를 **코드 규칙**으로 매긴다(모델이 '안전해 보인다' 고 말하는 것은 근거가
아니다). 도구가 없어 못 본 것은 **'못잼'** 이지 '안전' 이 아니다 -- 검사하지 않은 초록불이
검사한 빨간불보다 나쁘다. 거짓 양성은 점검의 신뢰를 깎으므로 소스(.py)·템플릿(.env.example)은
비밀 파일로 세지 않는다.

```bash
python3 secaudit/run.py              # 점검만 (network 불필요)
python3 secaudit/run.py --뇌          # dig 수집 + search_memory 대조까지
python3 secaudit/run.py --json
python3 tests/test_secaudit.py
```

디스코드: `!점검` (배경) · `!점검 뇌` (관리 채널) · `!점검 상태`. 에이전트: `security_audit(deep)` 도구.
끝값: 0 높음 없음 · 1 높음 있음 · 3 전부 못잼(안 잰 것 -- 도구·권한이 되는 호스트에서 다시).
